# Trace Debugging Contract

This document outlines the developer contract for the NL2SQL trace observability layer.

## `generated_sql`
Only populated when the final SQL is completely valid and has passed all semantic and guardrail checks. If generation fails, this remains `null`.

## `last_generated_sql`
The last SQL generated by the model during the pipeline execution, regardless of whether it is valid or invalid. Useful for debugging what the model attempted right before a final failure.

## `sql_valid`
A tri-state field indicating the overall validation status:
- `null`: SQL generation did not run (e.g., failed early at input validation or schema pruning).
- `true`: The final generated SQL is valid.
- `false`: SQL generation ran, but the pipeline failed to produce a valid SQL.

## `attempts`
Contains the full history of all generation attempts in the pipeline, including intermediate failures before a successful retry.

## `sql_validation_errors`
Contains the top-level validation errors representing the **final state** of the pipeline.
- If the pipeline succeeds (even after retries), this list is empty.
- If the pipeline fails finally, this list contains the errors of the last failed attempt.

## Debug API Examples

**Get traces with pagination and filtering:**
```bash
curl -H "X-API-Key: YOUR_API_KEY" \
  "http://localhost:8000/api/debug/traces?limit=10&offset=0&sql_valid=false&error_type=sql_generation_exhausted"
```

**Get a specific trace:**
```bash
curl -H "X-API-Key: YOUR_API_KEY" \
  "http://localhost:8000/api/debug/traces/trace-12345"
```
