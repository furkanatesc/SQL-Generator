## 1. Purpose & motivation

Phase 12 matures the Vue 3 frontend (`frontend/`, Vite + TypeScript + Tailwind). 31.0 improves the **Query Composer** — `src/components/ChatView.vue`, the natural-language→SQL chat where the user composes queries, streams generation logs, and reads the produced SQL.

**Pre-existing state discovered (important):** the frontend does **not** type-check cleanly on `main` — `npm run build` (`vue-tsc -b && vite build`) fails with pre-existing TypeScript errors: one in `ChatView.vue` (`'Job'` imported but unused, TS6133) and several in `SchemaManager.vue` (`meta` is `unknown`, an unused var). There is **no frontend CI**, so this went uncaught. 31.0 fixes the **ChatView** error (its own file); the `SchemaManager` errors are the Schema Explorer's concern (31.1) and are left as a documented known-issue.

## 2. Scope decisions (author-decided under the user's "finish all phases, no questions" directive)

1. **Query Composer (ChatView.vue) only.** UX + type-health of the composer; `SchemaManager.vue` build errors deferred to 31.1.
2. **Replace the blocking `alert()` copy-confirmation** with an inline, transient, accessible "Copied" state on each SQL block's copy button (frontend-design: never trigger a blocking browser dialog; give inline feedback; active-voice, sentence-case copy).
3. **Harden the clipboard action** — `navigator.clipboard.writeText` returns a promise that can reject (permissions / insecure context); handle failure with a transient error state instead of an unhandled rejection.
4. **Fix the ChatView type error** (`'Job'` unused import) so the composer contributes no `vue-tsc` errors.
5. **Verification (no frontend CI, build pre-broken):** `npm run build`'s error set after 31.0 must contain **only** the pre-existing `SchemaManager.vue` errors — the `ChatView.vue` error is gone and no new error is introduced. (Full green build awaits 31.1's SchemaManager fixes.)

## 3. Existing landscape

- `frontend/src/components/ChatView.vue` (423 lines): Vue 3 `<script setup lang="ts">`, dark themed. NL→SQL chat: message list, SSE streaming logs accordion, SQL result block with a "Kopyala" button (`copyToClipboard` → `alert(...)`), file upload, dialect selector (`PlanetDbSelector`), autosizing textarea.
- `copyToClipboard(sql: string)` currently: `navigator.clipboard.writeText(sql); alert('SQL Panoya Kopyalandı!')`.
- The copy button: `<button @click="copyToClipboard(msg.sql)">…Kopyala</button>` (`msg.sql` is `string | undefined`, guarded by `v-if="msg.sql"`).
- Stack: Vue `^3.5`, Vite `^8`, TypeScript `~6`, Tailwind `^3.3`. Scripts: `dev`/`build`/`preview`. **No test runner, no frontend CI.**

## 4. Design (frontend-design informed)

The composer's visual identity is already established (indigo/violet on near-black, rounded-2xl surfaces, monospace SQL). 31.0 does not restyle — it fixes one jarring interaction. The copy button is the touch point: today a modal `alert()` interrupts the flow to say "copied"; the fix is the standard, quiet inline confirmation the rest of the UI's language would expect.

**Per-message copy state** (a chat can hold many SQL blocks, so state is keyed by message id):
- `copiedMessageId: ref<number | null>` and `copyErrorMessageId: ref<number | null>`.
- `copyToClipboard(sql, messageId)` → `await navigator.clipboard.writeText(sql)`; on success set `copiedMessageId = messageId` for ~1.6s then clear; on rejection set `copyErrorMessageId` transiently.
- The button swaps label/icon by state: default "Kopyala" (copy icon) → success "Kopyalandı" (check icon, emerald) → error "Kopyalanamadı" (retry). `aria-live="polite"` on the state text so assistive tech announces the change; no blocking dialog.

**Type fix:** remove the unused `import type { Job }` (the composer uses `apiService` types elsewhere; `Job` is not referenced).

## 5. Testing / verification

- `cd frontend && npm run build` → the reported `vue-tsc` errors must be **only** the pre-existing `SchemaManager.vue` set (ChatView's `'Job'` error gone; no new errors). Recorded baseline before 31.0: `ChatView.vue(4,1) TS6133 'Job'` + `SchemaManager.vue` ×6.
- Manual reasoning: copy button cycles default→copied→default; a rejected clipboard shows the error state and never throws; multiple SQL blocks track state independently.
- (No automated frontend tests — no runner is configured; setting one up on the Vite 8 / vue-tsc 6 toolchain is deferred to TECH-DEBT §35 to avoid a toolchain rabbit hole in a UX sprint.)

## 6. Deliberately out of scope (→ TECH-DEBT §35)

- **`SchemaManager.vue` build errors** (`meta: unknown` ×5, unused var) — the frontend build stays red until 31.1 (Schema Explorer UX) fixes them. Documented, not silently ignored.
- **Frontend test infrastructure** (vitest + @testing-library/vue) — deferred (unusual Vite 8 / TS 6 toolchain; risk of a compat rabbit hole in a UX sprint).
- **Frontend CI job** — none exists; adding one is deferred (would gate on the currently-red build).
- **Restyle / broader composer redesign, streaming-UX, error-panel redesign** — 31.0 is one focused interaction fix.
- **A toast system** — the inline per-button state is sufficient and lower-risk than introducing a global toast component (a later sprint may add one for cross-cutting notifications).
