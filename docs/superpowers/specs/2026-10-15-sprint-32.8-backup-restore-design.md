# Sprint 32.8 — Backup / Restore (Design)

Phase 13 · Branch `feat/32.8-backup-restore` · Önceki: 32.0 (named volume'lar), 32.3 (migration'lar).

## 1. Problem & karar

Kalıcı durum (32.0'dan beri named volume'larda): SQLite app DB, trace DB, uploads, gömülü Qdrant store. Tek yedekleme
yolu runbook'taki elle `tar` (stack çalışırken SQLite/WAL dosyasını kopyalamak **tutarsız** yedek üretebilir). Geri
yükleme prosedürü, bütünlük doğrulaması ve "bu yedek bu sürümle uyumlu mu?" kontrolü yok; migration'lar öncesi
otomatik yedek yok (TECH-DEBT §36.5/§39.2).

**Karar (kapsam):** `python -m app.backup create|verify|list|restore|prune` + **migration öncesi otomatik DB yedeği**.
- **create**: `.tar.gz` arşivi; SQLite DB'ler **`sqlite3` online backup API'siyle** (çalışan stack'te tutarlı anlık
  görüntü, WAL dahil), uploads dosyaları, Qdrant store (opsiyonel, **best-effort** — aşağıda); `manifest.json`:
  format sürümü, oluşturma zamanı, app sürümü, her DB'nin migration sürümü, dosya başına SHA-256 + boyut.
- **verify**: manifest checksum'ları + her DB için `PRAGMA integrity_check`.
- **restore**: önce verify; yedeğin migration sürümü koddan yeniyse **reddet** (aksi halde `DB_SCHEMA_AHEAD`);
  restore öncesi mevcut durumun **güvenlik yedeği** (`pre-restore-*`); DB'ler geçici dosyaya yazılıp `os.replace`
  ile atomik değiştirilir; uploads üzerine yazılır (fazla dosya silinmez); Qdrant yalnız `--include-qdrant` ile.
  `--yes` olmadan çalışmaz (yıkıcı). Uygulama/worker durdurulmuş olmalı (runbook; kod uyarır).
- **prune `--keep N`**: en yeni N `sqlgen-backup-*` dışındakileri siler.
- **Migration öncesi yedek**: `init_db` bekleyen migration görürse ve DB boş değilse (sürüm > 0) önce
  `<db>.pre-v<N>-<ts>.bak` (online backup API); `NL2SQL_BACKUP_BEFORE_MIGRATION` (true). Son 3 tutulur.

Seçilmeyen:
- (a) Dosya kopyası / `tar` ile DB yedeği — WAL modunda (trace DB) ve yazma sırasında tutarsız.
- (b) Qdrant snapshot API'si — gömülü `QdrantClient(path=...)` modunda snapshot yok; Qdrant verisi büyük ölçüde
  yeniden üretilebilir (şema embedding'leri yeniden indekslenir), API ile eklenen iş kuralları/SQL geçmişi ise
  tutarlılık garantisiz dosya kopyasıyla alınır ve manifest'te `qdrant: best_effort` işaretlenir. Harici Qdrant
  gelince snapshot API (§36.5).
- (c) Zamanlanmış (cron) yedek / uzak depoya (S3) gönderim — operatör zamanlayıcısı + `docker compose exec`;
  runbook örneği. (TECH-DEBT §44)

## 2. Design
- `app/backup/paths.py`: `app_db_path()`, `trace_db_path()`, `upload_dir()`, `qdrant_dir()`, `backup_dir()`
  (`NL2SQL_BACKUP_DIR`, varsayılan `<backend>/backups`).
- `app/backup/core.py`: `sqlite_snapshot(src, dest)`, `create_backup(dest_dir, include_qdrant=True) -> Path`,
  `read_manifest`, `verify_backup -> VerifyResult(ok, errors)`, `restore_backup(archive, include_qdrant, safety_backup=True)`,
  `list_backups`, `prune_backups(keep)`, `backup_db_before_migration(db_path, target_version)`.
  Arşiv içi yollar sabit: `app.db`, `trace.db`, `uploads/...`, `qdrant/...`, `manifest.json`; extraction yalnız
  bu önekler, mutlak/`..` yollar reddedilir (tar path traversal koruması).
- `app/backup/__main__.py`: CLI; JSON çıktı; hata → exit 1.
- `init_db`: inspect → pending & current>0 & ayar açık → `backup_db_before_migration`.
- Prod compose: `sqlgen_backups:/app/backups` (backend), `NL2SQL_BACKUP_DIR=/app/backups`; Dockerfile `/app/backups`
  dizini (non-root sahiplik).

## 3. Verify
`backend/tests/test_backup.py`: create (DB anlık görüntüsü WAL'lı DB'de dahi tutarlı, uploads, qdrant, manifest
sürümleri/checksum), verify (bozuk checksum, bozuk DB), restore (veri geri gelir, güvenlik yedeği, ahead reddi,
`--yes` zorunlu, path traversal reddi, qdrant yalnız istenince), list/prune, migration öncesi yedek (yeni DB'de yok,
mevcut DB'de var, ayar kapalıyken yok, retention 3), CLI exit kodları. Full suite + CI smoke: workspace oluştur →
yedek → verify → workspace sil → stack'i durdur → `compose run` ile restore → başlat → workspace geri.

## 4. Out of scope (TECH-DEBT §44)
- Zamanlanmış yedek, uzak/off-host depolama, şifreleme.
- Tutarlı Qdrant snapshot'ı (gömülü modda yok).
- Point-in-time recovery / artımlı yedek.
- Restore sırasında çalışan process'leri otomatik durdurma.
