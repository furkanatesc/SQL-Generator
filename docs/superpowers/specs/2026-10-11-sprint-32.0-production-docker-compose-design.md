# Sprint 32.0 — Production Docker Compose (Design Spec)

> Phase 13 (Deployment / Cloud / Ops) ilk sprint'i. **Backend/DevOps domaini** — pytest + backend CI
> rigoru geri döndü. Kullanıcı: soru sorma, kapsam kararını kendin ver (gerekçe burada).

## 1. Problem / Brainstorm (karar)
Bugün SQLGen'in tek resmi dağıtım modeli `docs/production-runbook.md`'de "tek backend container,
`docker run`" ve **Docker Compose orkestrasyonu açıkça "Not Supported Yet"**. Kökteki
`docker-compose.yml` yalnız **test/CI parity** içindir (Postgres/Oracle/MySQL/MSSQL integration DB'leri,
sabit test parolaları) — prodüksiyon için değil. Mevcut imajda prodüksiyonu bozan somut boşluklar:

1. **Kalıcılık yok** — SQLite uygulama DB'si (`SQLGEN_DB_PATH` varsayılanı `/app/sqlgen.db`), trace DB
   (`NL2SQL_TRACE_DB_PATH` varsayılanı `data/nl2sql_traces.db` → `/app/data`), Qdrant disk store
   (`/app/qdrant_data`, sabit yol) ve uploads container katmanında yaşıyor → container yeniden
   yaratılınca tüm veri (workspaces/connections/query_runs/feedback/api-keys, embedding'ler) kaybolur.
2. **Healthcheck yok** — ne `Dockerfile`'da `HEALTHCHECK` ne orkestrasyonda; `python:3.11-slim`'de `curl` yok.
3. **Frontend imajı yok** — Vue 3/Vite SPA yalnız `npm run dev`/Electron ile çalışıyor.
4. **Prod-güvenli env varsayılanları zorlanmıyor** — `NL2SQL_ENVIRONMENT=production`,
   `NL2SQL_DEBUG_ENDPOINTS_ENABLED=false`, wildcard olmayan CORS, zorunlu `NL2SQL_API_KEY` elle hatırlanmalı.

**Karar (kapsam):** 32.0 = **ayrı bir `docker-compose.prod.yml`** (test compose'una dokunulmaz) +
backend imajının prod-sertleştirmesi (kalıcı dizinler + `HEALTHCHECK`) + **frontend prod imajı**
(multi-stage node build → nginx statik servis) + `.env.prod.example` + **pytest kontrat guard'ı** +
**CI'da gerçek boot smoke job'ı** (`docker compose up --build --wait` → `/health`, `/ready`, frontend `/`).
Uygulama (`app/`) kodu **değişmez** — tüm yollar mevcut env değişkenleriyle (`SQLGEN_DB_PATH`,
`NL2SQL_TRACE_DB_PATH`, `NL2SQL_UPLOAD_DIR`) veya sabit yollara volume mount ile çözülür.

Seçilmeyen alternatifler: (a) mevcut `docker-compose.yml`'a profil eklemek — test parolaları ve prod
servisleri aynı dosyada karışır, kontrat guard'ı zorlaşır; (b) reverse-proxy ile tek origin (nginx
`/api` proxy) — frontend `api.ts` backend'i `http://<host>:8000` olarak varsayıyor; tek-origin geçişi
frontend kodu + CORS modelini değiştirir → 32.x'e (TECH-DEBT). (c) Harici Qdrant/Postgres servisleri —
uygulama embedded Qdrant + SQLite kullanıyor; servisleştirme 32.3 (migration) / ileriki sprint işi.

## 2. Design
### 2.1 `docker-compose.prod.yml` (repo kökü)
- **`backend`**: `build: ./backend`, `image: sqlgen-backend:${SQLGEN_IMAGE_TAG:-latest}`,
  `restart: unless-stopped`, `security_opt: [no-new-privileges:true]`,
  port `${SQLGEN_BACKEND_PORT:-8000}:8000`.
  - Env (prod-güvenli sabitler): `NL2SQL_ENVIRONMENT=production`, `NL2SQL_DEBUG_ENDPOINTS_ENABLED=false`,
    `NL2SQL_UPLOAD_DIR=/app/uploads`, `SQLGEN_DB_PATH=/app/data/sqlgen.db`,
    `NL2SQL_TRACE_DB_PATH=/app/data/nl2sql_traces.db`.
  - Env (zorunlu, `${VAR:?msg}` ile compose seviyesinde fail-fast): `NL2SQL_API_KEY`,
    `NL2SQL_CORS_ALLOW_ORIGINS`.
  - Env (opsiyonel): `NVIDIA_API_KEY=${NVIDIA_API_KEY:-}`.
  - Named volume'lar: `sqlgen_data:/app/data`, `sqlgen_uploads:/app/uploads`,
    `sqlgen_qdrant:/app/qdrant_data`.
  - Healthcheck: `python -c` urllib → `http://127.0.0.1:8000/health` (liveness; curl gerekmez).
- **`frontend`**: `build: ./frontend`, `image: sqlgen-frontend:${SQLGEN_IMAGE_TAG:-latest}`,
  `restart: unless-stopped`, port `${SQLGEN_FRONTEND_PORT:-8080}:8080`,
  `depends_on: backend: condition: service_healthy`, healthcheck `wget -qO- http://127.0.0.1:8080/`.
- Hiçbir literal secret yok (`sqlgen_secret_dev_key` vb. yasak); test DB servisleri yok.

### 2.2 `backend/Dockerfile` (additive)
Mevcut kontrat satırları korunur (`test_docker_contract.py`). Ek: `mkdir -p /app/uploads /app/data
/app/qdrant_data` (chown app — named volume ilk mount'ta sahipliği imajdan devralır → non-root yazabilir)
ve `HEALTHCHECK` (python urllib `/health`). Böylece tek başına `docker run` da healthcheck kazanır.

### 2.3 Frontend imajı (`frontend/Dockerfile`, `frontend/nginx.conf`, `frontend/.dockerignore`)
- Stage 1 `node:22-alpine` (Vite 8 → Node ≥20.19/22.12): `npm ci` + `npm run build`.
- Stage 2 `nginxinc/nginx-unprivileged:1.27-alpine` (non-root, port 8080): `dist/` → html root;
  `nginx.conf`: SPA fallback (`try_files $uri $uri/ /index.html`), `/assets/` uzun cache (hash'li),
  `index.html` no-cache, temel güvenlik başlıkları (`X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`).
- `.dockerignore`: `node_modules`, `dist`, `tests`.

### 2.4 `.env.prod.example` (repo kökü)
Compose'un referans verdiği **her** `${VAR}` belgelenir (drift guard testi bunu zorlar); gerçek değer
yok, placeholder. `.env` zaten `.gitignore`'da.

### 2.5 Kontrat guard'ı — `backend/tests/test_prod_compose_contract.py` (PyYAML, zaten bağımlılık)
- Servis kümesi tam olarak `{backend, frontend}`; test DB imajı (postgres/oracle/mysql/mssql) yok.
- Backend: build context `./backend`, restart politikası, prod env sabitleri (production / debug false),
  `NL2SQL_API_KEY` + `NL2SQL_CORS_ALLOW_ORIGINS` `:?` ile zorunlu, `SQLGEN_DB_PATH`/
  `NL2SQL_TRACE_DB_PATH`/`NL2SQL_UPLOAD_DIR` **mount edilmiş bir volume'un altında**, `/app/qdrant_data`
  mount'lu, tüm volume'lar top-level `volumes:`'ta named, healthcheck `/health`.
- Frontend: build context `./frontend`, `depends_on.backend.condition == service_healthy`, healthcheck.
- Literal secret yok (bilinen dev/test parolaları yok).
- `.env.prod.example` ⊇ compose'daki tüm `${VAR}` isimleri.
- Backend Dockerfile: `/app/data` + `/app/qdrant_data` oluşturuluyor + `HEALTHCHECK` + `/health`.
- Frontend Dockerfile: multi-stage (`AS build`), `npm ci`, `npm run build`, non-root nginx; nginx.conf
  SPA fallback; `.dockerignore` `node_modules`.

### 2.6 CI — `backend-ci.yml` yeni additive `prod-compose-smoke` job'ı
`docker compose -f docker-compose.prod.yml config -q` → `up -d --build --wait` (test env değerleriyle) →
`curl -fsS :8000/health`, `curl -fsS :8000/ready` (200 = prod config + key + writable uploads + DB),
`curl -fsS :8080/` → başarısızlıkta `logs` → `down -v` (always). Mevcut job'lara dokunulmaz.

### 2.7 Docs
`production-runbook.md`: Compose artık destekli (Not Supported listesinden çıkar) + "Docker Compose
(Production)" bölümü (env, up, smoke, volumes, upgrade/backup notu). `env-contract.md`: `SQLGEN_DB_PATH`,
`NL2SQL_TRACE_DB_PATH`, `NVIDIA_API_KEY` satırları + compose değişkenleri; ayrıca CORS/debug uyarı
severity'si dokümanda `warning` yazıyor, kod `critical` üretiyor → doküman koda hizalanır (drift fix).

### 2.8 Ek (CI smoke'un yakaladığı güvenlik açığı) — prod API key sertleştirmesi
İlk CI koşusunda `prod-compose-smoke` `/health`+`/ready`+SPA'yı geçti ama `NL2SQL_API_KEY` ile
`POST /api/v1/workspaces` **403** döndü. Kök neden: `init_db` public dev key'i
(`sqlgen_secret_dev_key`, frontend varsayılanı da bu) koşulsuz `configs.api_key`'e seed ediyor ve
`verify_api_key` DB key'ini env'e tercih ediyor → **prodüksiyonda operatör key'i yok sayılıyor, herkesin
bildiği dev key API'yi açıyordu** (ve `/ready` "key configured" diyordu). "app/ değişmez" kararı bu
yüzden revize edildi (dar, TDD):
- `app/settings.py`: `DEV_DEFAULT_API_KEY` sabiti + `is_production_like_environment` buraya taşındı
  (`startup_validation` aynı adı re-export eder; import uyumluluğu korunur).
- `init_db`: production-like ortamda dev key **seed edilmez** (local/ci davranışı aynı).
- `validate_runtime_config`: production-like + efektif key (DB > env) == dev default → yeni
  **`API_KEY_INSECURE_DEFAULT` (critical)** → `/ready` 503. Eski prod DB'leri dev key taşıyorsa görünür olur.
- Testler: `backend/tests/test_prod_api_key_hardening.py` (seed yok/var, prod auth operatör key'iyle
  geçer + dev key 403, uyarı matrisi, sızdırmazlık).
Bilinçli kapsam dışı: mevcut prod DB'sindeki dev key'i otomatik silmek/rotate etmek (veri mutasyonu;
operatör `POST /api/configs/api_key` ile değiştirir) ve DB>env önceliğini değiştirmek (32.2 Secrets).

## 3. Verify
- `cd backend && pytest tests/test_prod_compose_contract.py tests/test_docker_contract.py tests/test_docs_contract.py`
  → yeşil; full suite (fastapi 0.115.12 pin) regresyonsuz.
- Yerel Docker daemon yok → gerçek boot doğrulaması **CI `prod-compose-smoke` job'ında** (zorunlu yeşil).

## 4. Out of scope (TECH-DEBT §36 — sessiz düşürme yok)
- Tek-origin reverse proxy (`/api` → backend) + frontend API base'in build-time/runtime config'i.
- TLS sonlandırma, domain/sertifika.
- Secrets dosyası / Docker secrets (`NL2SQL_API_KEY` env ile) → **32.2 Secrets Management**.
- Harici Qdrant/Postgres servisleştirme, migration → **32.3**; backup/restore → **32.8**.
- Registry'ye imaj push / release tag'leme → **32.11**.
- `schema_cache.json` hâlâ `/app` kökünde (kalıcı değil, yeniden üretilebilir cache) — yol
  env'leştirmesi kod değişikliği gerektirir.
- `read_only: true` root FS (schema_cache.json + Qdrant lock dosyaları `/app`'e yazıyor).
- Frontend'in `DEFAULT_API_KEY='sqlgen_secret_dev_key'` varsayılanı (kullanıcı UI'dan girmeli).
