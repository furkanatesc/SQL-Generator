# Sprint 26.8 — Prompt-Injection / NL Abuse Defense Contract · Design

**Phase 7 (Security & Governance) · Contract-first, no execution · 2026-06-25**

## 1. Purpose

Define a deterministic, static (no-execution) backend contract that **detects**
prompt-injection / natural-language abuse in the text that flows into the
text-to-SQL model, and reports *what kind* of attack, *from which source*, *with
what confidence*, plus an advisory **disposition** (`ALLOW` / `REVIEW` / `BLOCK`).

This is the first Phase 7 contract that inspects **natural language** (the user's
request and the content embedded into the prompt) rather than SQL. Where 26.0–26.5
answer questions about a *SQL statement* and 26.6/26.7 record/orchestrate
governance, 26.8 answers, one layer earlier:

* Does this natural-language input attempt to subvert the model — override its
  instructions, exfiltrate its system prompt, hijack its role, break out of the
  prompt envelope, smuggle hidden instructions via obfuscation, or coerce
  destructive/out-of-scope SQL — and how should governance treat it?

It is a **hybrid detector**: a typed signal (categories + source + confidence)
**plus** a graded advisory disposition. It is **not a hard gate**. A sound gate
over free-form natural language is impossible — heuristics over NL both
under-detect (novel/paraphrased attacks) and over-detect (benign text resembling
an attack), so a binary block would wrongly cut legitimate user requests. The
disposition mirrors 26.4's graded decision (`ALLOW`/`REVIEW`/`BLOCK`) but is
explicitly **advisory**: downstream governance (approval 26.7, audit 26.6, the
request pipeline) decides what to enforce. The detector feeds those layers; it
never competes with them.

Grounded in **OWASP LLM Top 10 (2025) — LLM01 Prompt Injection**, which
distinguishes **direct** injection (malicious instructions in the user's own
input), **indirect** injection (instructions embedded in external/retrieved
content the model later processes), and **jailbreaking** (MITRE ATLAS AML.T0054).
26.8 covers all three over the text-to-SQL surface.

## 2. Scope

**In scope:** the contract — category/source/confidence/disposition/reason-code
enums, an immutable source-tagged input segment, an immutable request/result, a
stateless detector, JSON-safe **secret-free** `to_dict()`, text normalization
(NFKC + control/zero-width stripping + whitespace collapse + casefold), six
deterministic denylist pattern families, a source-aware disposition policy, an
audit interlock (`AuditCategory.PROMPT_INJECTION` + `from_prompt_injection`
builder), and exhaustive unit tests.

**Out of scope (later sprints / deliberate):** any *enforcement* (26.8 emits an
advisory disposition; the pipeline wires actual blocking), result-set/row privacy
over returned data (26.9), credential vault (26.10), policy eval (26.11). Also out
of scope: semantic / LLM-based classification (this is regex over normalized text,
no model), multilingual pattern coverage beyond English, full recursive decoding
of nested encodings, denial-of-wallet / input-size limits (a size concern, closer
to 26.9), any I/O, DB driver, adapter execution, API/UI wiring, tenant/RBAC/AuthN.

## 4. Enums

```python
class InjectionCategory(str, Enum):
    INSTRUCTION_OVERRIDE = "instruction_override"   # "ignore previous instructions"
    SYSTEM_PROMPT_EXFIL  = "system_prompt_exfil"    # "reveal your system prompt"
    ROLE_HIJACK          = "role_hijack"            # "you are now / act as / DAN"
    DELIMITER_BREAKOUT   = "delimiter_breakout"     # fake fences / "---END OF PROMPT---"
    OBFUSCATION_EVASION  = "obfuscation_evasion"    # zero-width / base64 blob / homoglyph
    SQL_ABUSE_INTENT     = "sql_abuse_intent"       # NL coercion toward destructive SQL

class InjectionSource(str, Enum):
    DIRECT   = "direct"      # the user's own NL request
    INDIRECT = "indirect"    # text embedded into the prompt (schema comments, few-shot, retrieved)

class InjectionConfidence(str, Enum):   # ordered low -> high
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"

class InjectionDisposition(str, Enum):  # ordered severity; ADVISORY, not a gate
    ALLOW = "allow"
    REVIEW = "review"
    BLOCK = "block"

class InjectionReasonCode(str, Enum):
    NO_INJECTION_DETECTED = "no_injection_detected"   # -> ALLOW
    INJECTION_SUSPECTED   = "injection_suspected"     # -> REVIEW
    INJECTION_DETECTED    = "injection_detected"      # -> BLOCK
    NO_INPUT              = "no_input"                # empty/unusable -> ALLOW (nothing to inject)
```

Module-level `_CONFIDENCE_ORDER` and `_DISPOSITION_ORDER` maps give a total order
so the result can report the **max** confidence and the **most severe**
disposition deterministically.

## 5. Input — source-tagged segments

```python
@dataclass(frozen=True)
class PromptSegment:
    text: str
    source: InjectionSource

    def __post_init__(self) -> None: ...   # source must be a real enum member; text must be a str
```

The caller wraps each piece of text with its provenance: the user's question is a
`DIRECT` segment; schema/column comments, few-shot examples, or retrieved context
embedded into the prompt are `INDIRECT` segments. A single uniform list expresses
both direct and indirect surfaces, and lets the disposition policy weigh indirect
matches more heavily (see §8).

```python
@dataclass(frozen=True)
class PromptInjectionDefenseRequest:
    version: str
    segments: Sequence[PromptSegment]
```

- `version` mismatch → raises `PromptInjectionDefenseContractError` (contract
  violation). A non-`PromptSegment` item, or a `PromptSegment` whose `text` is not
  a string, is a contract violation → raises (the caller built the request wrong).
- All *content-level* malformation that is not a structural error — an empty
  segment list, every segment empty/whitespace — yields a fail-closed **result**
  (`NO_INPUT`), never a raise (mirrors 26.3 / 26.5).

## 6. Result (immutable, audit-grade, secret-free)

```python
@dataclass(frozen=True)
class InjectionMatch:
    category: InjectionCategory
    source: InjectionSource
    confidence: InjectionConfidence
    pattern_label: str        # e.g. "instruction_override/ignore_previous" — a family/rule id, NEVER raw text
    segment_index: int        # which request segment matched (for correlation, not content)
    def to_dict(self) -> Dict[str, Any]: ...

@dataclass(frozen=True)
class PromptInjectionDefenseResult:
    version: str
    detected: Tuple[InjectionMatch, ...]
    categories: Tuple[InjectionCategory, ...]   # sorted, de-duplicated
    highest_confidence: Optional[InjectionConfidence]
    disposition: InjectionDisposition
    reason_code: InjectionReasonCode
    reason: str
    input_sha256: str          # sha256 over the normalized, source-tagged segment join — for audit correlation
    segment_count: int
    def to_dict(self) -> Dict[str, Any]: ...     # JSON-safe; enum .value's; no raw text, no matched substring
```

- Carries **no raw input text and no matched substring** — only the stable
  `pattern_label` (a rule identifier the operator can look up), the matched
  category/source/confidence, the segment index, and `input_sha256`.
- `input_sha256` is computed over a canonical join of the **normalized** segments
  each prefixed by its source tag, so the same logical input hashes stably for
  audit correlation regardless of incidental whitespace/encoding.
- `detected` is de-duplicated on `(category, source, pattern_label, segment_index)`
  and ordered deterministically: source (`INDIRECT` before `DIRECT` — the more
  serious surface first), then category value, then confidence desc, then
  pattern_label, then segment_index.

## 7. Normalization + detection engine

**Normalization (per segment, before matching):**

1. Unicode **NFKC** normalization (folds homoglyph/compatibility forms).
2. Strip zero-width and disallowed control characters (keep `\t`/`\n`).
3. Collapse runs of whitespace to single spaces.
4. Casefold for case-insensitive matching.

The normalization **delta is itself a signal**: if step 1–2 removed zero-width /
control characters, or the segment contains a long base64/hex blob, or it carries
a high ratio of non-ASCII homoglyph characters, that segment raises an
`OBFUSCATION_EVASION` match (an attacker hiding instructions inside encoded /
invisible text). 26.8 *flags* obfuscation; it does not fully decode nested
payloads (documented limitation §9).

**Six pattern families (curated, documented, NON-exhaustive denylists)** run as
deterministic regexes over the normalized text:

- **INSTRUCTION_OVERRIDE** — `ignore (all )?previous|prior|above instructions`,
  `disregard (your|the) (rules|instructions)`, `forget (everything|the prompt)`,
  `override your (instructions|guardrails)`.
- **SYSTEM_PROMPT_EXFIL** — `(reveal|print|show|repeat|output) (your|the) (system )?(prompt|instructions|rules)`,
  `what (are|were) your (instructions|rules)`, `everything above this line`.
- **ROLE_HIJACK** — `you are now`, `act as (a |an )?`, `pretend (to be|you are)`,
  `developer mode`, `\bDAN\b`, `no (restrictions|limitations|filters)`,
  `jailbreak`.
- **DELIMITER_BREAKOUT** — fenced/sentinel breakout markers: `-{3,}\s*end of prompt`,
  triple backticks adjacent to instruction text, fake role tags
  (`<\s*/?\s*(system|assistant|user)\s*>`), `\[/?(INST|SYS)\]`.
- **OBFUSCATION_EVASION** — from the normalization delta (see above): zero-width /
  control chars present, base64 blob (`[A-Za-z0-9+/]{24,}={0,2}`), long hex run,
  high homoglyph ratio.
- **SQL_ABUSE_INTENT** — NL coercion toward destructive / out-of-scope mutation:
  `drop (the )?(table|database|schema)`, `delete (all|every) (row|record|user)`,
  `truncate `, `grant (me )?(admin|all|superuser)`, `disable (rls|row level security|read.?only)`,
  `update .* set .* (password|role|is_admin)`. (NL-layer intent signal that
  complements 26.2/26.3, which only ever see the *generated SQL*.)

**Confidence:** a well-anchored, unambiguous phrase → `HIGH`/`MEDIUM`; a loose or
single-token match → `LOW`. **An `INDIRECT` source elevates a match's confidence
by one notch** (capped at `HIGH`): instruction-like text appearing in *data the
user did not type* is inherently more suspicious than the same words in a direct
request.

## 8. Disposition policy (aggregate, source-aware, fail-closed-leaning)

Computed from the full match set:

- **BLOCK** — any match at `HIGH`, **OR** any `INDIRECT` match at `MEDIUM` or
  above. (Indirect instructions are auto-serious: the user never asked for them.)
- **REVIEW** — any other match present (the detected set is non-empty but nothing
  rises to BLOCK). A single `LOW` direct match is enough to warrant REVIEW: any
  pattern hit is worth a human/governance look, and REVIEW is advisory, not a block.
- **ALLOW** — no matches at all. ALLOW always implies an empty `detected` set, so
  `NO_INJECTION_DETECTED` never co-occurs with a recorded match.
- Empty / unusable input (no segments, or all empty after normalization) →
  `reason_code = NO_INPUT`, `disposition = ALLOW`, empty `detected` (text the user
  did not write cannot be an injection).

`reason_code` follows disposition: `INJECTION_DETECTED` (BLOCK),
`INJECTION_SUSPECTED` (REVIEW), `NO_INJECTION_DETECTED` (ALLOW with matches=∅),
`NO_INPUT` (ALLOW, no usable input). `highest_confidence` = max over matches
(`None` if none).

> The §8 strictness (indirect ≥ MEDIUM → BLOCK) is intentionally conservative for
> the high-risk indirect surface and is the single tunable knob; if production
> shows excess false positives it can be relaxed to REVIEW without touching the
> detection layers.

## 9. Detection flow

1. Validate request type & version (mismatch raises). Validate each segment type
   (non-`PromptSegment` / non-string text raises).
2. If no segments, or every segment is empty/whitespace after normalization →
   return `NO_INPUT`, `ALLOW`, empty `detected`, `highest_confidence = None`,
   `input_sha256` over the (possibly empty) canonical join, `segment_count`.
3. Normalize each segment; record obfuscation deltas.
4. Run the six pattern families over each normalized segment; build `InjectionMatch`
   entries with source, confidence (indirect-elevated), `pattern_label`,
   `segment_index`.
5. Aggregate: de-duplicate + deterministically order `detected`; `categories` =
   sorted/de-duplicated; `highest_confidence` = max; `disposition` + `reason_code`
   per §8.
6. Build the immutable result.

The contract surface is a stateless class
`PromptInjectionDefenseContract` with `.evaluate(request) -> PromptInjectionDefenseResult`
(mirrors the 26.3 classifier / 26.5 detector class shape).

## 11. Documented limitations (26.3/26.5-style honesty)

- **Heuristic denylist, both directions:** regex over normalized text
  **under-detects** novel, paraphrased, or translated attacks (no semantics, no
  model) and **over-detects** benign text that resembles a pattern (e.g. "ignore
  the rows where status is closed" can trip `INSTRUCTION_OVERRIDE`). It is a
  **signal + advisory disposition, never a sound gate.**
- **English-centric:** pattern families target English; multilingual coverage is
  out of scope this sprint.
- **Obfuscation is flagged, not defeated:** 26.8 raises a signal on zero-width /
  base64 / homoglyph evasion but does not recursively decode nested encodings; a
  determined attacker can encode around the patterns.
- **No semantic understanding:** a sound fix requires an LLM-based guard/classifier
  model (a later phase). 26.8 is explicitly MVP — a cheap, deterministic, auditable
  first line that makes the common attacks visible.

## 12. Test matrix

- Benign NL request (`"show me last month's orders by region"`) → `ALLOW`,
  `NO_INJECTION_DETECTED`, empty `detected`, `highest_confidence = None`.
- Each of the six categories: a positive direct sample and (where meaningful) a
  positive indirect sample → correct category/source/confidence/`pattern_label`.
- Indirect elevation: a `MEDIUM` pattern in an `INDIRECT` segment → `BLOCK`; the
  same text as a `DIRECT` segment → `REVIEW`.
- Obfuscation layer: zero-width-character smuggling, a long base64 blob, and a
  homoglyph-heavy segment each raise `OBFUSCATION_EVASION`.
- Disposition aggregation: HIGH direct → BLOCK; single MEDIUM direct → REVIEW;
  single LOW direct → REVIEW; no matches → ALLOW (empty `detected`).
- `NO_INPUT`: empty segment list, and all-whitespace segments → `NO_INPUT`,
  `ALLOW`, empty `detected`.
- Version mismatch (request & result) → raises. Bad segment (non-`PromptSegment`,
  non-string text, bad source enum) → raises.
- Immutability (`FrozenInstanceError`); `detected` de-dup & deterministic order
  (`INDIRECT` before `DIRECT`); `categories` sorted & de-duplicated;
  `highest_confidence` = true max; `disposition` = most severe.
- **Secret-free:** `to_dict()` JSON-serializable; a known attack string embedded in
  the input is **absent** from the dict (only `pattern_label` + `input_sha256`
  present). Same secret-free assertion for the audit `from_prompt_injection` event.
- Case-insensitivity / normalization: mixed-case and zero-width-split variants of
  the same attack both match.
- Audit interlock: `from_prompt_injection` maps BLOCK/REVIEW/ALLOW to the right
  `AuditOutcome`/`AuditSeverity`, is hash-chain-linkable, and is secret-free.
