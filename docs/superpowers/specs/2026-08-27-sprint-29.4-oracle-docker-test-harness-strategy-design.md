# Sprint 29.4 — Oracle Docker / Test Harness Strategy — Design

**Status:** Approved (brainstorm) — pending user spec review → writing-plans
**Date:** 2026-08-27
**Phase:** 10 (Real Database Adapter Layer)
**Predecessor:** 29.3 Oracle Contract Adapter (PR #164); mirrors 29.0 PostgreSQL Docker Integration Adapter pattern.

## 1. Purpose & boundaries

Sprint 29.3 delivered a real, local-Docker-only, read-only Oracle execution path
(`oracledb` thin mode, driver-isolated, standalone/inert). Its `oracle`-marked
integration tests **safe-skip on every CI run today** because there is no Oracle
Docker image, seed schema, or CI job. This sprint provides that harness so those
tests run **live**, and closes the deferred bridge→low-level unit test (TECH-DEBT
§21.4).

This is a **harness / test sprint**: it adds test infrastructure, a seed schema,
and CI wiring. It introduces **no new execution behavior** — the 29.3 adapters
(`oracle_adapter.py`, `oracle_connection_resolver.py`, `oracle_execution_adapter.py`)
are **not modified** (except possibly a docstring). The adapters stay
standalone/inert; they are **not** wired into the live request pipeline.

### Explicitly out of scope (deferred, no silent drops — TECH-DEBT §21)

- **§21.2** Oracle schema introspection adapter (`ALL_TAB_COLUMNS` / `ALL_CONSTRAINTS`
  / `ALL_CONS_COLUMNS` → `DatabaseSchema`; Postgres 29.0 equivalent) → later sprint.
- **§21.3** Oracle EXPLAIN-only mode (`EXPLAIN PLAN FOR` + `DBMS_XPLAN.DISPLAY`;
  29.2 equivalent) → later sprint.
- **§21.5** Connection registry / remote & production connections / wallet / TNS
  → Phase 11 · 30.2.
- **§21.6** Live HTTP pipeline wiring / central execution router registry
  → 30.2 / 30.4 / 30.x.
- **§21.7** `oracledb` thick mode / Oracle Instant Client → deferred until needed.
- **§21.8** Deferred minors (harmless; Postgres precedent) → left as-is.

## 2. Image choice

**`gvenzl/oracle-free:23-slim-faststart`** (pinned tag).

Rationale:

- The 29.3 resolver already defaults to `FREEPDB1` / port `1521` / `sqlgen`/`sqlgen`
  — these are exactly the `gvenzl/oracle-free` conventions, so the resolver needs
  no change.
- `-faststart` is pre-initialized → CI health in ~30–60s (vs 2–4 min for the
  official `container-registry.oracle.com/database/free`).
- `-slim` keeps the image smaller.
- No licensing barrier (Oracle Database Free).

Image env:

- `ORACLE_PASSWORD` — SYS/SYSTEM password (CI + compose provide it; value `sqlgen`).
- `APP_USER=sqlgen`, `APP_USER_PASSWORD=sqlgen` — gvenzl creates this app user in
  `FREEPDB1`; the seed and tests connect as `sqlgen`, matching the resolver default.

**Identifier casing:** Oracle folds unquoted identifiers to UPPERCASE. Seed tables
become `CUSTOMERS`, `ORDERS`, … and result column keys come back uppercase. This is
consistent with the existing 29.3 bare-Oracle tests (which already assert `["N"]`
and `{"A", "B"}`). Seeded tests must reference uppercase names.

**Tag-pinning note:** pinned to `23-slim-faststart` for a stable major line while
still receiving patch fixes. If full determinism is later required, pin to a
specific patch tag (e.g. `23.5-slim-faststart`) in a follow-up — noted, not done
here.

## 3. Seed schema — `backend/tests/fixtures/oracle/seed.sql` (new)

Mirrors the **shape** of the 29.0 Postgres seed
(`backend/tests/fixtures/postgres/seed.sql`), translated to Oracle dialect, with
the **same deterministic rows**:

- `customers` / `orders` / `order_items` — single-column PK/FK.
- `product_variants` / `variant_stock` — composite PK/FK (`(product_id, sku)`).

Dialect translation:

| Postgres | Oracle |
|---|---|
| `INTEGER` | `NUMBER` |
| `TEXT` | `VARCHAR2(n)` |
| `TIMESTAMP` literal `'2020-01-01 00:00:00'` | `TO_TIMESTAMP('2020-01-01 00:00:00','YYYY-MM-DD HH24:MI:SS')` |
| `NUMERIC(10,2)` | `NUMBER(10,2)` |
| `DROP TABLE IF EXISTS x CASCADE` | `DROP TABLE x CASCADE CONSTRAINTS` (guarded — see below) |
| inline `REFERENCES` | inline `REFERENCES` (same) |

Idempotency: Oracle has no `DROP TABLE IF EXISTS`. The seed is applied on **first
container init only** (compose init-script / CI seed step run once against a fresh
DB), so plain `DROP TABLE` is unnecessary — the seed uses straight `CREATE TABLE`
(+ `INSERT`) with **no PL/SQL block**, keeping the statement splitter trivial. Drop
statements are omitted rather than wrapped in an `EXCEPTION` block (which would
require PL/SQL and complicate splitting).

Row data is byte-for-byte the same values as the Postgres seed (Ada/Alan customers,
3 orders, 4 order_items, 2 product_variants, 2 variant_stock).

## 4. Seed application — one file, two paths (mirrors the Postgres pattern)

- **Local compose:** the seed is mounted at `/container-entrypoint-initdb.d/` so
  gvenzl auto-runs it on first startup as `APP_USER`.
- **CI:** GitHub Actions service containers cannot mount workspace files (checkout
  runs after the service starts — the same reason the Postgres job uses a `psql -f`
  step). Oracle has no `psql`/`sqlplus`/Instant Client available, so seeding uses
  **pure Python + `oracledb` thin mode** (already pinned `oracledb==2.5.1`).

New shared helper: **`backend/tests/fixtures/oracle/apply_seed.py`**

- `split_statements(sql: str) -> list[str]` — **pure**, deterministic. Splits the
  seed into individual statements on `;` terminators (and standalone `/` lines),
  strips comments/blank statements. No PL/SQL support needed (seed is DDL+INSERT
  only). Unit-tested in isolation (no DB, no driver).
- `apply_seed(connection, sql: str) -> int` — executes each statement via a cursor,
  commits once, returns the count applied. Takes an already-open DB-API connection
  (dependency-injected; testable with a fake).
- `main()` — CI entry-point: builds an `oracledb` connection from the `ORACLE_TEST_*`
  env contract (reusing `resolve_local_docker_connection`), reads `seed.sql`,
  calls `apply_seed`. Invoked as `python -m tests.fixtures.oracle.apply_seed`.

The `oracledb` import stays **lazy** (inside `main()`), so importing the module for
the pure-function unit test does not require the driver — consistent with 29.3's
driver-isolation posture.

## 5. CI — new job in `.github/workflows/backend-ci.yml`

A new **`oracle-integration`** job, independent of and parallel to `backend-tests`
(the fast main job is **unchanged** — Oracle's slow/heavier bring-up never slows or
risks the main job's 10-min budget).

```yaml
oracle-integration:
  name: Oracle integration
  runs-on: ubuntu-latest
  timeout-minutes: 20
  defaults:
    run:
      working-directory: backend
  services:
    oracle:
      image: gvenzl/oracle-free:23-slim-faststart
      env:
        ORACLE_PASSWORD: sqlgen
        APP_USER: sqlgen
        APP_USER_PASSWORD: sqlgen
      ports:
        - 1521:1521
      options: >-
        --health-cmd healthcheck.sh
        --health-interval 20s
        --health-timeout 10s
        --health-retries 10
        --health-start-period 90s
  steps:
    - checkout / setup-python 3.11 / pip install -r requirements.txt
    - name: Seed Oracle integration schema   # python -m tests.fixtures.oracle.apply_seed
      env: { ORACLE_TEST_* }
    - name: Run Oracle integration tests      # pytest -m oracle
      env: { NL2SQL_DEBUG_ENDPOINTS_ENABLED, ORACLE_TEST_* }
```

`ORACLE_TEST_*` env: `ORACLE_TEST_HOST=localhost`, `ORACLE_TEST_PORT=1521`,
`ORACLE_TEST_SERVICE=FREEPDB1`, `ORACLE_TEST_USER=sqlgen`,
`ORACLE_TEST_PASSWORD=sqlgen` (all already the resolver defaults; set explicitly for
clarity/robustness).

`pytest -m oracle` runs only the Oracle-marked tests in this job (the bare-Oracle
29.3 tests + the new seeded tests). They no longer safe-skip here because a live
Oracle is present.

## 6. Tests

- **New** `backend/tests/evaluation/test_oracle_execution_adapter_seeded_integration.py`
  (`integration` + `oracle`, safe-skip when no Docker Oracle) — Oracle equivalent of
  the 29.0 Postgres seeded test:
  - Real multi-table `JOIN` `CUSTOMERS ⋈ ORDERS ⋈ ORDER_ITEMS` → named uppercase
    dict rows, expected deterministic values.
  - Composite-FK `JOIN` `PRODUCT_VARIANTS ⋈ VARIANT_STOCK` on `(PRODUCT_ID, SKU)`.
  - `max_rows` truncation against seeded rows.
  Reuses the same `_local_docker_oracle_available()` skip-guard shape as the
  existing 29.3 integration module.

- **§21.4 closure** — add a **unit test** to
  `backend/tests/evaluation/test_oracle_execution_adapter.py` that injects a fake
  `oracledb` module and a resolver returning a **non-None** connection, exercising
  `OracleDatabaseExecutionAdapter.execute`'s resolver-non-None branch (which builds
  a real `SQLOracleAdapterExecutionRequest` and delegates to the low-level adapter).
  This locks the full bridge→low-level path **without Docker**, using the fake-driver
  technique already present in the 29.3 unit tests.

- **New** unit test for `split_statements` (pure, no DB) verifying correct splitting
  of the seed SQL, comment stripping, and empty-statement elimination.

- Existing bare-Oracle integration tests (DUAL / CONNECT BY LEVEL) now execute for
  real in the `oracle-integration` job.

## 7. `docker-compose.yml`

Add an `oracle` service next to `postgres`:

```yaml
oracle:
  image: gvenzl/oracle-free:23-slim-faststart
  environment:
    ORACLE_PASSWORD: sqlgen
    APP_USER: sqlgen
    APP_USER_PASSWORD: sqlgen
  ports:
    - "1521:1521"
  volumes:
    - ./backend/tests/fixtures/oracle/seed.sql:/container-entrypoint-initdb.d/seed.sql:ro
  healthcheck:
    test: ["CMD", "healthcheck.sh"]
    interval: 20s
    timeout: 10s
    retries: 10
    start_period: 90s
```

Usage comment: `docker compose up -d oracle` → `cd backend && pytest -m oracle`.

## 10. Risks

- **Oracle CI startup time.** Mitigated by `-faststart` image + `--health-start-period 90s`
  + `timeout-minutes: 20` + a separate job so the main suite is never blocked.
- **Statement splitting.** Kept trivial by forbidding PL/SQL in the seed; the pure
  `split_statements` is unit-tested against the actual seed content.
- **Image pull weight.** `-slim` variant; single separate job; relies on the runner's
  layer cache. Acceptable for an integration-only job.
- **First-run-only seed.** Compose init-script and the CI seed step both target a
  fresh DB; re-seeding an already-seeded local container is not supported (drop
  `docker compose down -v` to reset) — documented in the compose usage comment.
