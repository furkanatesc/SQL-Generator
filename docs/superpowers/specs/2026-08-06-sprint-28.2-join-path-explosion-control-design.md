# Sprint 28.2 — Join Path Explosion Control · Tasarım (Design Spec)

**Phase:** 9 — Large Schema Production Scale (28.1'in ardılı)
**Tarih:** 2026-08-06
**Tür:** Üretim algoritma optimizasyonu (branch-and-bound) + deterministik emniyet bütçesi + benchmark v3
**Önceki:** 28.1 Schema Graph Performance Profiling (PR #151) · **Sonraki:** 28.3 Table Selection Cost Model

---

## 1. Amaç ve bağlam

28.0 büyük şemalarda maliyetin **ne kadar**, 28.1 **nerede** olduğunu ölçtü. 28.1'in
deterministik sayaçları (`dfs_visit`, `adjacency_edge`, `path_recorded`) tek bir hot-path'i
somut şekilde işaret etti: `find_join_paths` (`backend/app/schema/graph_traversal.py`).

Bugünkü algoritma **exhaustive DFS**'tir: `max_depth`'e kadar *her* yolu enümere eder,
hepsini `all_paths`'e ekler, global sıralar (weakest-link priority ↓, confidence ↓,
length ↑, lexical tiebreak), sonra `max_paths`'e keser. Sorun: yalnız `max_paths` (üretimde
selector için **1**, doğrudan çağrıda **5**) yol tutmasına rağmen **tüm enümerasyon
maliyetini öder**. Hub-ağırlıklı büyük şemalarda `adjacency_edge`/`dfs_visit` sayaçları
kombinatoryel patlar — 28.1'in ölçtüğü tam olarak budur.

28.2 bu patlamayı **iki katmanla** kontrol eder ve mümkün olan her yerde **çıktıyı
byte-for-byte korur**.

### Merkezi tasarım kararı — exact-preserving fast-path + deterministik emniyet kemeri
1. **Fast-path (branch-and-bound):** DFS sırasında ispatlanabilir şekilde hedefe
   ulaşamayan veya tutulan en iyi kümeyi (kept-set) geçemeyen dalları budar. Budama
   **admissible** olduğundan `find_join_paths(...).paths` çıktısı pre-28.2 exhaustive
   sonucuyla **tüm girdilerde birebir aynı** kalır — yalnız ziyaret sayısı düşer.
2. **Emniyet kemeri (node-visit bütçesi):** Yalnız patolojik hub patlamalarında devreye
   giren, cömert varsayılanlı deterministik bir üst sınır. Aşılınca DFS deterministik
   durur ve `budget_truncated=True` işaretlenir. Normal (gated) şemalarda **asla
   tetiklenmez**.

## 3. Fast-path: branch-and-bound (çıktı korunur)

Aşağıdaki iki budama da **admissible**'dır — yalnız top-`max_paths` çıktısında *asla* yer
alamayacak dalları keser. Bu yüzden çıktı, tüm girdiler için pre-28.2 exhaustive sonuçla
birebir aynıdır.

### 3.1 BFS mesafe-alt-sınırı (A\*-tarzı depth pruning)
Çağrı başına **bir kez**, `target_table`'dan ters-BFS ile `hop[node]` = hedefe unweighted
minimum hop sayısı hesaplanır. BFS, DFS'in kullandığı **aynı** adjacency üzerinden yürür
(aynı `allow_fuzzy` / `DISABLED` filtreleme; kenarlar undirected gezilir).

- Partial path `current` düğümünde `len_so_far` kenarla bittiğinde, herhangi bir tamamlama
  en az `hop[current]` kenar daha gerektirir. `len_so_far + hop[current] > max_depth` ise
  dal budanır.
- `hop` gerçek bir alt sınırdır (cycle-avoiding gerçek yol ≥ kısıtsız hop mesafesi) →
  budama admissible → **çıktı korunur**.
- `hop[current] == ∞` (hedefe erişilemez) → dal anında budanır.
- **Erken çıkış:** `hop[source_table] == ∞` veya `hop[source_table] > max_depth` →
  `paths=[]` (exhaustive de boş dönerdi).

### 3.2 Kept-set dominance pruning
Bulunan tam yolların o ana kadarki top-`max_paths`'i **kept** olarak tutulur (mevcut
sort anahtarına göre). Kept dolu (`len == max_paths`) olduğunda `worst` = kept içindeki en
kötü (sort anahtarına göre en büyük) yol.

Partial path'in **iyimser tamamlama prefix'i**:
```
(-pri_so_far, -conf_so_far, len_so_far + hop[current])
```
çünkü tamamlama:
- `min_priority ≤ pri_so_far` → `-min_pri ≥ -pri_so_far` (iyimser = `-pri_so_far`),
- `min_confidence ≤ conf_so_far` → iyimser = `-conf_so_far`,
- `length ≥ len_so_far + hop[current]` → iyimser = `len_so_far + hop[current]`.

Bu iyimser 3-prefix, `worst`'ün 3-prefix'inden (`-worst.min_priority`,
`-worst.min_confidence`, `worst.path_length`) **kesin (strict) büyükse** (= kesin kötü),
dal budanır. Eşitlikte lexical tiebreak kazanabileceğinden **budanmaz** (sound). Karşılaştırma
yalnız 3-prefix üzerinde ve strict yapılır → lexical eşitlik hiçbir zaman yanlış budamaz.

### 3.3 Neden doğru (invariant)
Kept-set, o ana dek tamamlanmış yolların gerçek top-`max_paths`'idir; budanan hiçbir dal
top-`max_paths`'e giremeyecek yol üretmez. Dolayısıyla traversal bittiğinde toplanan
yolların top-`max_paths`'i == exhaustive'in top-`max_paths`'i. Nihai `sort()[:max_paths]`
aynı sonucu verir. DFS gezinme sırası deterministiktir (adjacency `schema.relationships`
sırasıyla kurulur) → çıktı sıralaması da birebir korunur.

## 4. Emniyet kemeri: node-visit bütçesi (deterministik)

- Yeni keyword-only parametre `node_budget: int`, modül sabiti
  `DEFAULT_JOIN_PATH_NODE_BUDGET` ile **cömert** varsayılan (gated 100/500/1000
  ölçeklerinde **asla** tetiklenmeyecek büyüklükte; kesin değer plan aşamasında benchmark
  ölçümleriyle sabitlenir).
- `dfs` girişindeki ziyaret sayacı (== `dfs_visit`) bütçeyi aşınca:
  `budget_truncated=True` set edilir ve tüm rekürsiyon deterministik durur (bayrak `dfs`
  girişinde ve adjacency döngüsünde kontrol edilir). O ana dek toplananın top-`max_paths`'i
  döner.
- Determinizm: DFS gezinme sırası deterministik olduğundan, aynı `(schema, source, target,
  node_budget)` girdisi aynı truncated çıktıyı verir.
- Cömert varsayılan sayesinde **üretim davranışı pratikte değişmez**; kemer yalnız
  patolojik bir kaçış kapısıdır.

## 5. Kontrat değişikliği (kırıcı tek-API)

`find_join_paths` artık `list[JoinPathCandidate]` yerine `JoinPathSearchResult` döner:

```python
class JoinPathSearchResult(BaseModel):
    paths: list[JoinPathCandidate]
    budget_truncated: bool = False
    node_visits: int = 0        # deterministik; harcanan dfs_visit sayısı
    node_budget: int            # uygulanan bütçe
    branches_pruned: int = 0    # deterministik; budanan dal sayısı
```

**Neden kırıcı tek-API (additif ikinci fonksiyon değil):** tek net API, uzun vadede daha
temiz; churn 13 çağrı yerinde kapanır (disiplinli test suite); truncation'ı sessizce yok
saymak imkânsızlaşır (çağıran `.paths` almak için sonucu açmak zorunda).

### 5.1 Çağrı yerleri (13)
- **Üretim (1):** `schema_context_selector.select_schema_context` — `.paths` okur;
  `budget_truncated`'ı `SchemaContextSelection`'a yeni **opsiyonel** alan
  `join_search_truncated: bool = False` olarak taşır (çiftler üzerinden OR); tüketiciler
  için non-breaking. Ayrıca opsiyonel `node_budget` keyword-only passthrough kazanır
  (test/konfig için; iç `find_join_paths` çağrılarına iletilir).
- **Benchmark (1):** `bench_runner.py` — `.paths` kullanır; `branches_pruned` /
  `budget_truncated` metriğe akar (aşağıda §6).
- **Testler (11):** `test_graph_traversal.py` (8) + `test_graph_traversal_probe.py` (3) —
  `.paths` erişimine güncellenir + yeni testler eklenir (§7).

## 7. Test stratejisi

- **Çıktı-koruma invariantı (kritik):** Mevcut `tests/schema/test_graph_traversal.py` ve
  `test_graph_traversal_probe.py` `.paths` erişimine güncellenip **yeşil `+N/-0`** kalır
  (davranış birebir). Ek olarak: orta-boy sentetik şemada **brute-force referansa karşı**
  "pruning preserves output" testi (branch-and-bound sonucu == naive exhaustive sonucu).
- **BFS bound doğruluğu:** erişilemez hedef → `paths=[]`; derinlik-sınırlı dallanma;
  `hop[source] > max_depth` erken çıkış.
- **Emniyet kemeri (adanmış):** patolojik hub şeması + enjekte **düşük** `node_budget` →
  `budget_truncated=True`, deterministik truncated çıktı, `node_visits ≈ node_budget`.
- **Selector propagasyonu:** düşük `node_budget` passthrough ile
  `SchemaContextSelection.join_search_truncated == True` (çiftlerden biri truncate olunca).
- **Probe sayaçları:** `branches_pruned > 0` budamalı bir senaryoda; `join_budget_truncated`
  kemer tetiklenince.
- **Benchmark:** `test_bench_contract.py` v3 literal; gate CI adımı v3 baseline'a karşı geçer.

Her SDD görevi TDD (önce test) + iki-aşamalı review; final whole-branch opus review.
