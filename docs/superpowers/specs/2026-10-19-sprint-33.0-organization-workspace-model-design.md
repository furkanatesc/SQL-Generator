# Sprint 33.0 — Organization / Workspace Model (Design)

Phase 14 (SaaS / Multi-Tenant Readiness) İLK sprint'i · Branch `feat/33.0-organization-workspace-model` ·
Önceki: 30.1 (Workspace API), 30.2 (Connection Registry), 26.1 (Tenant/Workspace Boundary contract).

## 1. Problem & karar

Bugün tek kiracılı düz bir model var: `workspaces` (30.1) en üst kaynak; **slug global UNIQUE** (bir kiracının
`analytics` slug'ı başka kiracıya 409 olarak sızar); workspace silinince ona bağlı `connections.workspace_id`
sahipsiz kalır (kontrol yok). 26.1 `TenantWorkspaceBoundary(tenant_id, workspace_id)` sözleşmesi var ama veri
modelinde `tenant_id` karşılığı yok. Phase 14'ün geri kalanı (roller 33.1, RBAC 33.2, billing 33.3, metering 33.4,
plan limitleri 33.5) bir **Organization** (kiracı) varlığına dayanır.

**Karar (kapsam):**
1. **`organizations` tablosu** (migration v4 `organizations`): `id TEXT PK` (uuid4 hex), `name TEXT NOT NULL`,
   `slug TEXT NOT NULL UNIQUE` (global — organizasyon slug'ı kiracı kimliğidir), `description TEXT`,
   `created_at`, `updated_at` (ISO-8601 UTC; workspaces ile aynı).
2. **Workspace bir organizasyona aittir**: aynı migration'da `workspaces` tablosu yeniden kurulur (SQLite tablo
   rebuild: yeni tablo → kopya → drop → rename, tek transaction) — `organization_id TEXT NOT NULL`,
   **`UNIQUE(organization_id, slug)`** (global slug UNIQUE kalkar), `idx_workspaces_org`. Mevcut satırlar
   migration'da oluşturulan **default organizasyona** (`slug='default'`, `name='Default'`) atanır; default org
   workspace olmasa da her zaman oluşturulur (yeni kurulumlar dahil). FK constraint yok (repo genelinde FK
   kullanılmıyor, bütünlük repository katmanında — mevcut desen).
3. **`/api/v1/organizations` CRUD** (30.1 workspace router'ı ile aynı biçim: `ApiResponse` zarfı, `limit`/`offset`
   sayfalama, 201/404/409, `verify_api_key`): `POST`, `GET` liste, `GET /{id}`, `PATCH /{id}` (name/description;
   slug değişmez), `DELETE /{id}`. Silme kuralları: **default org silinemez (409)**; workspace'i olan org
   silinemez (409, kaskad yok).
4. **Workspace API (geriye uyumlu genişleme)**: `POST /workspaces` opsiyonel `organization_id` alır — verilmezse
   default org (mevcut istemciler kırılmaz); verilen org yoksa **400** (`connections.workspace_id` deseniyle aynı);
   aynı org içinde slug çakışması 409, farklı org'da aynı slug serbest. `WorkspaceResponse` +`organization_id`.
   `GET /workspaces?organization_id=` filtresi. Workspace org'lar arası taşınamaz (PATCH alanı yok).
5. **Bütünlük düzeltmesi**: bağlantısı (`connections.workspace_id`) olan workspace silinemez → **409** (bugün
   sessizce sahipsiz bağlantı bırakıyor).
6. **26.1 eşlemesi (dokümantasyon)**: `tenant_id ≙ organization_id`, `workspace_id ≙ workspaces.id`. Bu sprint
   canlı enforcement eklemez (kimlik/principal yok → 33.1/33.2); eşleme spec + TECH-DEBT'te kayıtlı.
7. Admin overview (30.7) sayaçlarına `organizations` eklenir. `/api/v1` sözleşme allowlist'i ve contract
   snapshot'ları güncellenir.

Seçilmeyen:
- (a) Global workspace slug'ını korumak — kiracılar arası bilgi sızıntısı, SaaS'ta yanlış birim.
- (b) İç içe URL (`/organizations/{id}/workspaces`) — mevcut düz `/workspaces` istemcilerini kırar; filtre yeterli.
- (c) Kaskad silme — veri kaybı riski; açık 409 tercih edildi.
- (d) Connection/query-run'lara `organization_id` kopyalamak — workspace üzerinden türetilir (denormalizasyon yok).

## 2. Verify
TDD: migration (boş DB'de default org + yeni şema; v3 DB'de mevcut workspace'ler default org'a taşınır, veriler
korunur, `UNIQUE(org, slug)` işler, global UNIQUE kalkmıştır; tekrar çalıştırma no-op), organization repository +
API (CRUD, 404/409, default/dolu org silme 409, sayfalama, zarf), workspace API (org'suz create → default, geçersiz
org 400, farklı org'da aynı slug 201, aynı org'da 409, filtre, yanıt alanı), workspace silme bağlantı varken 409,
admin overview sayacı, conformance allowlist + snapshot'lar. Full suite + CI 5/5. Prod compose smoke'taki
workspace adımları (backup/restore dahil) değişmeden geçer.

## 3. Out of scope (TECH-DEBT §49)
- Kullanıcı/üyelik, org rolleri (→ 33.1), RBAC ve 26.1 boundary'nin canlı enforcement'ı (→ 33.2).
- API key'lerin org'a kapsamlanması; key'ler hâlâ global (§26–§34 ile bağlantılı).
- Workspace'in org'lar arası taşınması; org slug değişikliği; soft delete.
- Frontend'de organizasyon/workspace seçici (frontend bugün workspace kullanmıyor).
- Legacy (pre-v1) uç noktalar ve job'lar org/workspace kapsamı dışında.
