# Sprint 28.7 — Incremental Schema Sync · Tasarım (Design Spec)

**Phase:** 9 — Large Schema Production Scale (28.6'nın ardılı)
**Tarih:** 2026-08-10
**Tür:** Üretim önbellek doğruluğu — DB **yapısal drift tespiti** + drift-aware sync; deterministik saf çekirdek + kirli kenar
**Önceki:** 28.6 Schema Cache Invalidation (PR #157) · **Sonraki:** 28.8 Embedding / RAG Re-Index Pipeline

---

## 1. Amaç ve bağlam

28.6, `SchemaManager.load_schema` (`app/schema_manager.py:469`) cache'ini bir **content
fingerprint** (`compute_cache_fingerprint`: `db_type` + `hidden_tables_*`/`hidden_columns_*`
config + embedding-model) ile otomatik geçersizler. Bu fingerprint **self-contained**'dır —
yeni DB sorgusu yapmaz, dolayısıyla **veritabanının gerçek yapısı** (tablo/kolon/tip/PK/FK)
değiştiğinde cache bunu göremez. Kullanıcı DB'de bir tablo ekler/siler, kolon tipi değiştirir
veya bir FK kaldırırsa cache sessizce **eski şemayı** sunmaya devam eder; tek çözüm
`force_refresh=True` (elle) veya cache dosyasını silmektir. Bu, TECH-DEBT §14.1'de (ham DB
şema drift'i) ve §14.3'te (explicit sync endpoint eksikliği) açık bırakılmıştı.

28.7 bunu bir **yapısal signature** ile kapatır: mevcut extractor'ın çıkardığı şema topolojisi
(tablo/kolon/tip/PK/FK) kanonik olarak normalize edilip sha256'lanır (kaynak seçimi — filtreli
`extract_schema_metadata` — merkezi kararda gerekçelendirilmiştir). Bu signature cache'e yazılır;
drift kontrolü açıkken load'da yeniden hesaplanıp karşılaştırılır, uyuşmazsa cache geçersizlenir.
Ayrıca drift'i raporlayan/senkronlayan debug endpoint'leri eklenir.

### Merkezi tasarım kararı — mevcut extractor reuse'lu yapısal signature, opt-in otomatik + endpoint

- Signature, **mevcut per-dialect extractor** üzerinden türetilir (YENİ SQL yok → DRY, tek
  doğruluk kaynağı, generation'ı besleyen aynı topolojiden). `load_schema`'nın asıl pahalı işi
  embedding + RAG indexlemedir; ham topoloji çıkarımı buna göre çok ucuzdur, dolayısıyla drift
  kontrolü full rebuild'den belirgin ucuzdur.
- **Kaynak: `extract_schema_metadata()` (filtreli), `get_raw_schema()` (filtresiz) değil.**
  `get_raw_schema` filtresiz ham topolojiyi; `extract_schema_metadata` onu `hidden_tables_*`/
  `hidden_columns_*` config'iyle filtreleyip verir ve cache'te saklanan `schema` **budur**. İki
  taraf (build-time saklanan signature vs. check-time canlı signature) **aynı** kaynaktan gelmeli;
  aksi halde hidden config boş değilken signature hep uyuşmaz. Bu yüzden signature **filtreli**
  şemadan hesaplanır. `extract_schema_metadata` de mevcut extractor'ı (`get_raw_schema` + filtre)
  reuse eder — yeni SQL yoktur. **Ek fayda:** hidden config değişimi zaten 28.6 `cache_fingerprint`
  ile yakalandığından, `schema_signature` yalnız **ham DB yapı drift'ini** taşır (filtre değişimi
  drift olarak raporlanmaz) — iki koşul dik/ayrık kalır, çift-tetik yok.
- Cache geçerliliği artık **iki bağımsız koşul**: `cache_fingerprint` (28.6) eşleşir **VE**
  (drift-check kapalı **VEYA** `schema_signature` eşleşir). 28.6 fingerprint'ine dokunulmaz.
- Drift kontrolü **opt-in**: config `auto_schema_drift_check` (default **OFF**) → default
  davranış 28.6-korumalı (cache-hit yolunda DB sorgusu yok). İki debug endpoint her zaman var.
- Drift tespit edilince **full** re-extract + re-embed (mevcut `force_refresh` yolu). True
  per-table incremental ve granular embedding re-index bilinçli **kapsam dışı** (bkz. §7).

## 2. Kapsam kararları (onaylı)

| Karar | Seçim |
|---|---|
| Birincil teslimat | **Yapısal DB drift tespiti + drift-aware sync endpoint** (§14.1 + §14.3) |
| Drift ne zaman çalışır | **Opt-in otomatik** (`auto_schema_drift_check`, default OFF) **+** her zaman var olan endpoint |
| Signature granularity | **Tablo + kolon(ad/tip/nullable) + PK + FK** (tam yapısal şekil) |
| Signature kaynağı | **`extract_schema_metadata()` (filtreli) reuse** (yeni SQL yok; cached `schema` ile aynı kaynak) |
| Drift'te aksiyon | **Full** re-extract + re-embed (mevcut `force_refresh` yolu) |
| Endpoint sayısı | **İkisi de**: read-only `GET .../drift` + drift-aware `POST .../sync` |
| Default davranış | 28.6-korumalı (drift-check OFF → cache-hit'te DB sorgusu yok) |

## 3. Saf çekirdek — `backend/app/schema/schema_signature.py`

stdlib-only, deterministik, **yan-etkisiz** (I/O yok, clock/random yok — benchmark purity guard
deseniyle uyumlu).

```
SCHEMA_SIGNATURE_VERSION = "v1"

normalize_structure(schema: dict) -> NormalizedSchema
    # extract_schema_metadata() sözlüğünü ({"tables": {...}, "graph": {...}}) kanonik,
    # dialect-bağımsız, sıra-bağımsız bir yapıya indirger. (Aynı {tables, graph} şekline
    # sahip her extract çıktısında çalışır; 28.7 filtreli varyantı besler — bkz. §1/§4.)
    #   { table_name: {
    #        "columns": tuple(sorted (name, type, primary_key, nullable)),
    #        "foreign_keys": tuple(sorted (column, referenced_table, referenced_column)),
    #     } }
    # graph.edges DEĞİL tables[].foreign_keys temel alınır (çıkarımın kaynağı; graph türev).
    # Eksik/None alanlar deterministik defaultlara ("" / False) normalize edilir.

compute_schema_signature(normalized: NormalizedSchema, *, version=SCHEMA_SIGNATURE_VERSION) -> str
    # Kanonik seri (tablolar sıralı, her tablo içi sıralı) + "\x1f"-join + sha256 hex.
    # version prefix'lenir → kod değişiminde toplu invalidation mümkün (28.6 deseni).

diff_structures(old_norm, new_norm) -> StructuralDrift
    # İki normalized yapıyı karşılaştırır (saf, I/O yok):
    #   added_tables / removed_tables: list[str]
    #   added_columns / removed_columns: list[{table, column}]
    #   changed_columns: list[{table, column, old_type, new_type}]  (tip veya pk/nullable değişimi)
    #   added_fks / removed_fks: list[{table, column, referenced_table, referenced_column}]
    # StructuralDrift.has_drift: bool (herhangi bir liste boş değilse True)
```

**Not:** `normalize_structure` + `compute_schema_signature` kompozisyonu, iki farklı kaynaktan
(cache'teki saklı filtreli şema vs. canlı yeni filtreli şema) **aynı** normalize'den geçtiği için
signature'lar doğrudan kıyaslanabilir; `diff_structures` de aynı normalized modeli tüketir.

### Test (saf)
- Determinizm: aynı şema → aynı signature (tekrarlı çağrı).
- **Sıra-bağımsızlık**: tablo/kolon/FK sırası karışık iki eşdeğer şema → aynı signature.
- Version bump: `version` değişince signature değişir.
- Boş şema, tek tablo, çok tablo.
- `diff_structures`: her sürüklenme türü (add/remove table, add/remove/change column, add/remove fk)
  + drift-yok senaryosu (`has_drift == False`).

## 4. Kirli kenar — `SchemaManager` yardımcıları (yeni SQL YOK)

`backend/app/schema_manager.py` içine:

```
def _current_normalized_structure(self) -> NormalizedSchema:
    return normalize_structure(self.extract_schema_metadata())

def _current_schema_signature(self) -> str:
    return compute_schema_signature(self._current_normalized_structure())
```

`extract_schema_metadata()` mevcut per-dialect extractor'ı (`get_raw_schema` + hidden-filtre)
reuse eder — 28.7 **yeni sorgu eklemez**. Embedding/RAG/relationship-dressing çalıştırılmaz →
full load'dan ucuz. Cache'te saklanan `schema` ile **aynı** kaynak olduğundan signature'lar
kıyaslanabilir (bkz. §1 merkezi karar).

## 5. Entegrasyon — `load_schema`

1. `auto_schema_drift_check` config'i `get_config` ile okunur (yoksa/`"false"`/`"0"` → OFF).
   Yardımcı: küçük bir `_is_truthy_config(value)` (28.x tolerant-parse deseni).
2. Cache payload'ına `schema_signature` alanı eklenir; **her (re)build'de** yazılır
   (`{cache_fingerprint, db_type, schema_signature, schema, embeddings}`). 28.6'nın
   `cache_fingerprint`'i **aynen** kalır.
3. Cache-hit yolu (`not force_refresh` ve `cache_fingerprint` eşleşiyor):
   - `auto_schema_drift_check` **OFF** → 28.6 davranışı birebir (DB signature sorgusu **YOK**).
   - `auto_schema_drift_check` **ON** → `_current_schema_signature()` hesaplanır; cache'teki
     `schema_signature` ile karşılaştırılır. Uyuşmazsa (veya cache'te alan yoksa — legacy) →
     `base_schema = None` işaretlenir → mevcut re-extract + re-embed yolu tetiklenir.
4. Re-build sırasında signature, **zaten çıkarılmış** `base_schema`'dan hesaplanır (ekstra DB
   sorgusu yok) ve payload'a yazılır.
5. Lock / cache-stampede / deepcopy / RAG indexleme / custom+implicit+disabled dressing
   **DEĞİŞMEZ**.

> **İnce nokta:** Drift-check ON iken cache-hit path artık bir kez `get_raw_schema()` çağırır.
> Bu bilinçli maliyettir ve opt-in olduğu için default davranışı etkilemez (§7 scope-out'ta not
> düşülür: gerçekten ultra-ucuz tek-sorgu sinyali — `updated_at`/DDL-versiyon — kullanılmadı).

## 6. Endpoint'ler — `backend/app/api/schema_sync_api.py`

Mevcut debug-router deseni (rule_suggestions_api/metrics_api): kendi `APIRouter`,
`dependencies=[Depends(verify_api_key)]`, her handler'da `ensure_debug_enabled()` (debug kapalı
→ 404). main.py'de mount. Response model'ler `backend/app/api/schemas.py`'de (Pydantic).

### 6.1 `GET /api/debug/schema/drift` — read-only, **yan-etkisiz**
- Canlı signature'ı (`_current_schema_signature`, filtreli) + cache'teki `schema_signature`'ı okur.
- Drift raporu için: **eski** = `normalize_structure(cache["schema"])` (saklı filtreli şema),
  **yeni** = `_current_normalized_structure()`; `diff_structures(eski, yeni)`.
- Rebuild **YAPMAZ**, cache'e **yazmaz**.
- Yanıt: `{status, drifted: bool, signature_version, cached_signature, current_signature, drift: StructuralDrift}`.
- Cache yoksa/legacy (signature alanı yok): `drifted=true`, `drift` = "no cached signature" işareti.

### 6.2 `POST /api/debug/schema/sync` — drift-aware
- Body/query: `force: bool = false`.
- Önce drift hesaplar (§6.1 mantığı). Drift **varsa veya `force=true`** →
  `SchemaManager().load_schema(force_refresh=True)` ile rebuild eder, uygulanan drift raporunu döner.
- Drift **yoksa** ve `force=false` → rebuild ETMEZ; `{status:"up_to_date", drifted:false}` döner.
- Mevcut `POST /api/schema/refresh`'ten farkı: **değişmediyse rebuild etmez** (drift-aware).
  `/api/schema/refresh` (koşulsuz rebuild) korunur — kaldırılmaz.

### Test (endpoint)
- Debug kapalı → her iki endpoint 404.
- `GET drift`: no-drift → `drifted=false`; drift senaryosu (extractor mock'lanır) → doğru
  `drift` şekli; legacy cache → `drifted=true`.
- `POST sync`: drift yok + `force=false` → rebuild yok; drift var → rebuild; `force=true` +
  drift yok → rebuild. `load_schema` çağrısının koşullu tetiklendiği doğrulanır (mock/spy).

## 7. Bilinçli kapsam-dışı (sessiz düşürme yok → TECH-DEBT §15)

1. **True per-table incremental re-extract/merge** — drift'te hala **full** re-extract; değişen
   tabloyu izole edip yalnız onu çıkarma/merge etme gelecek işi (§14.1'in tam "incremental" ruhu).
2. **Granular embedding-only re-index** — drift'te **full** re-embed; yalnız değişen tabloların
   embedding'ini güncelleme → **28.8** (Embedding / RAG Re-Index Pipeline; §14.4 devam).
3. **TTL/zaman-tabanlı invalidation** — yok (§14.2 açık kalır).
4. **Ultra-ucuz tek-sorgu drift sinyali** (DB `updated_at`/DDL-versiyon/`information_schema`
   sayacı) kullanılmadı; mevcut extractor (`extract_schema_metadata`) reuse tercih edildi
   (DRY/doğruluk uğruna). Çok büyük şemalarda auto-drift maliyeti bu yüzden full topoloji
   çıkarımı kadardır (embedding hariç).
5. Drift **yalnız yapısal** — satır/veri seviyesi (value-overlap, cardinality) kapsam dışı.
6. Drift-aware `POST sync`, rebuild'i **tümüyle** yapar (kısmi/tablo-bazlı değil) — item 1'e bağlı.

## 10. Kabul kriterleri

- `schema_signature.py` saf, deterministik, sıra-bağımsız; testleri yeşil.
- `auto_schema_drift_check` **OFF** iken `load_schema` davranışı 28.6 ile birebir (regresyon yok,
  cache-hit'te DB signature sorgusu yok).
- `auto_schema_drift_check` **ON** iken DB yapısal drift'i (tablo/kolon/tip/PK/FK) cache'i otomatik
  invalidate eder; legacy (signature'sız) cache bir kez yeniden çıkarılır.
- `GET /api/debug/schema/drift` yan-etkisiz doğru drift raporu; `POST /api/debug/schema/sync`
  drift-aware (değişmediyse rebuild yok, `force` her zaman rebuild); ikisi de debug kapalıyken 404.
