**Phase:** 9 — Large Schema Production Scale (28.7'nin ardılı)
**Tarih:** 2026-08-10
**Tür:** Üretim performans/doğruluk — granular embedding re-index + Qdrant eviction; saf plan çekirdeği + kirli executor
**Önceki:** 28.7 Incremental Schema Sync (PR #158) · **Sonraki:** 28.9 Semantic / Result Cache

---

## 1. Amaç ve bağlam

`SchemaManager.load_schema` cache'i (re)build ederken `SchemaEmbeddingIndex.build_index(base_schema)`
ile **TÜM** tabloları yeniden embed eder (her tablo bir NVIDIA API girdisi; büyük şemada pahalı) ve
`RAGManager.index_schema_batch` bunları Qdrant `schema_ddl` koleksiyonuna upsert eder. İki eksik:

- **Granülarite yok (TECH-DEBT §14.4 / §15.2):** herhangi bir drift/fingerprint değişimi → tüm
  embedding'ler yeniden hesaplanır; yalnız değişen tabloları yeniden embed edip kalanı koruyan bir yol yok.
- **Qdrant stale-point sızıntısı:** `index_schema_batch` yalnız upsert eder; şemadan **silinen** tablolar
  Qdrant'ta kalıcı olarak kalır (hiç delete edilmez).
- **(Bağlı kök hata) Non-deterministic point id:** point id = `int(hash(name) % 10**8)`; Python'ın string
  `hash()`'i process başına rastgeledir (PYTHONHASHSEED) → aynı tablo her restart'ta farklı id alır →
  duplicate point birikimi + id-tabanlı silme/upsert restart'lar arası tutarsız.

28.8 bunları bir **per-tablo embedding fingerprint** + **saf diff-tabanlı re-index planı** + **granular
executor** ile kapatır: yalnız bayat/yeni tablolar embed edilir, değişmeyenlerin vektörü korunur,
silinen tablolar hem cache embeddings hem Qdrant'tan düşürülür. Hem `load_schema` rebuild yoluna hem
yeni debug endpoint'lerine bağlanır. **Kapsam: yalnız `schema_ddl`** (business_rules / sql_history
farklı yaşam döngüsüne sahip, kapsam dışı).

### Merkezi tasarım kararları (onaylı)

| Karar | Seçim |
|---|---|
| Birincil teslimat | **Granular re-embed + Qdrant eviction + debug endpoint** (`POST /reindex` + `GET /reindex-status`) |
| Bayatlık sinyali | **Per-tablo embedding fingerprint** — `sha256(model \x1f embed_text)`; cache'te `embeddings.fingerprints={name:hash}` |
| Entegrasyon | **`load_schema` rebuild yolu + endpoint**; `force_refresh=True` tam re-embed (bypass) |
| Kapsam | Yalnız `schema_ddl` koleksiyonu |
| Point id | **Deterministik** (`sha256(name)` türevi) — mevcut non-deterministic `hash()` düzeltilir |
| Çıktı eşdeğerliği | Nihai `embeddings.tables` aynı (aynı model → aynı vektörler); yalnız API çağrı sayısı azalır |

## 2. Saf çekirdek — `backend/app/schema/reindex_planner.py`

stdlib-only, deterministik, **yan-etkisiz** (I/O yok, clock/random yok, embedder/qdrant/requests import YOK).
Source-scan purity guard (benchmark/28.7 deseni).

```
REINDEX_FINGERPRINT_VERSION = "v1"

build_table_embedding_text(table_name: str, table_meta: dict) -> str
    # Embed EDİLEN metni üretir — mevcut SchemaEmbeddingIndex._generate_table_fingerprint
    # mantığının BİREBİR aynısı: "Table: {name} | Columns: {name (type), ...}"
    #   + varsa " | Relations: references {ref_table}, ...".
    # SchemaEmbeddingIndex._generate_table_fingerprint bunu ÇAĞIRACAK şekilde refactor edilir
    # (tek doğruluk kaynağı; embed input string'i tek yerden). Davranış birebir korunur.

compute_embedding_fingerprint(text: str, model: str, *, version=REINDEX_FINGERPRINT_VERSION) -> str
    # sha256(version \x1f model \x1f text) hex. Model değişimi → tüm fingerprint'ler değişir.

stable_point_id(name: str) -> int
    # Deterministik Qdrant point id: int.from_bytes(sha256(name.encode()).digest()[:8], "big") % (10**12).
    # Process/restart'tan bağımsız — eviction ve idempotent upsert için gerekli.

@dataclass(frozen=True)
class ReindexPlan:
    to_embed: tuple[str, ...]   # yeni veya fingerprint-değişen tablolar (sıralı)
    to_keep:  tuple[str, ...]   # fingerprint aynı → eski vektör reuse (sıralı)
    to_delete: tuple[str, ...]  # eski fingerprint'te var, yeni şemada yok (sıralı)
    def as_dict(self) -> dict   # JSON-ready lists

plan_reindex(old_fingerprints: dict[str,str], new_schema: dict, model: str) -> ReindexPlan
    # new_schema.tables üzerinden her tablo için build_table_embedding_text +
    # compute_embedding_fingerprint(text, model) hesapla → new_fp.
    #   to_embed = new tablolar ∪ {name: new_fp[name] != old_fingerprints.get(name)}
    #   to_keep  = {name: name in old_fingerprints and new_fp[name] == old_fingerprints[name]}
    #   to_delete = old_fingerprints anahtarları - new_schema tabloları
    # Kanonik sıralı çıktı (determinizm).
```

**Not (kaynak birliği):** `build_table_embedding_text` saf modülde yaşar; `SchemaEmbeddingIndex`
(`schema_embedding.py`) onu import edip `_generate_table_fingerprint` içinde kullanır. Böylece embed
edilen metin ile fingerprint'lenen metin **her zaman aynıdır** (drift yok). Saf modül `schema_embedding`
veya `rag_manager`'ı import ETMEZ (tersine bağımlılık — embedder saf modüle bağımlıdır).

### Test (saf)
- `build_table_embedding_text`: bilinen şema → beklenen string; FK'li/FK'siz; mevcut
  `_generate_table_fingerprint` çıktısıyla **birebir aynı** (regresyon: refactor davranış-koruyucu).
- `compute_embedding_fingerprint`: determinizm; model değişince değişir; version bump.
- `stable_point_id`: determinizm (aynı ad → aynı id, çağrılar/süreçler arası), farklı ad → (pratikte) farklı id.
- `plan_reindex`: yeni tablo → to_embed; kolon/tip/FK değişimi → to_embed; değişmeyen → to_keep;
  silinen → to_delete; model değişimi → hepsi to_embed; boş old_fingerprints (legacy) → hepsi to_embed;
  boş şema.

## 3. Kirli kenar — `backend/app/schema_reindex.py`

Executor; embedder + Qdrant I/O'yu saf plandan ayırır.

```
@dataclass(frozen=True)
class ReindexReport:
    embedded: tuple[str, ...]
    kept: int
    deleted: tuple[str, ...]
    model: str
    def as_dict(self) -> dict

reindex_embeddings(*, old_embeddings: dict | None, new_schema: dict, model: str,
                   embedder: SchemaEmbeddingIndex, rag: RAGManager | None,
                   force: bool = False) -> tuple[dict, ReindexReport]
    # 1. old_fp = (old_embeddings or {}).get("fingerprints", {}); force veya old yoksa → old_fp={} (hepsi embed).
    # 2. plan = plan_reindex(old_fp, new_schema, model).
    # 3. to_embed için: yalnız o tabloların alt-şemasını embedder.build_index'e ver → yeni vektörler.
    #    (build_index tablo-alt-kümesiyle çağrılabilir; yeni bir "yalnız bu tablolar" yolu gerekirse
    #    build_index zaten schema.tables üzerinde çalışır → alt-şema dict'i geçilir.)
    # 4. to_keep için eski vektörleri (old_embeddings["tables"]) reuse.
    # 5. new_embeddings = {"model": model, "tables": {...merged...},
    #                      "fingerprints": {name: compute_embedding_fingerprint(text, model)}}.
    # 6. rag (varsa): YALNIZ eviction — to_delete tablolarını rag.delete_schema_points(to_delete)
    #    ile Qdrant'tan siler. UPSERT YAPMAZ (tek upsert yolu index_schema_batch — aşağıya bkz.).
    # 7. (new_embeddings, ReindexReport) döndür.
```

**Sorumluluk bölünmesi (net):** `reindex_embeddings` → (a) granular embed ile **cache embeddings dict**'ini
üretir, (b) Qdrant'tan **yalnız `to_delete`'i evict eder**. Qdrant **upsert'i** her zaman mevcut
`RAGManager.index_schema_batch(schema)` ile yapılır (idempotent, precomputed vektörleri reuse eder, API
çağırmaz, deterministik id) — böylece çift-upsert/çakışma yok. Her iki çağıran (load_schema §4, endpoint
§5.2) bu sırayı izler: `reindex_embeddings` (dict + evict) → `index_schema_batch` (upsert all).

**Qdrant eviction & deterministik id:** yeni `RAGManager.delete_schema_points(names: list[str])` — her ad
için `stable_point_id(name)` hesaplayıp `client.delete(collection_name="schema_ddl", points_selector=[ids])`.
`index_schema_batch` ve `index_ddl` de `stable_point_id`'ye geçer (kök düzeltme; §1 non-deterministic
`hash()`).

### Test
- Fake `embedder` (embed edilen tablo adlarını kaydeder) + fake `rag` (upsert/delete çağrılarını kaydeder):
  yalnız `to_embed` embed edildi; `to_keep` vektörleri reuse (embed edilmedi); `to_delete` Qdrant'tan
  silindi; `force=True` → hepsi embed; `old_embeddings=None`/legacy → hepsi embed; `fingerprints`
  payload'ı doğru yazıldı.

## 4. `load_schema` entegrasyonu — `backend/app/schema_manager.py`

- Cache `embeddings` payload'ı `fingerprints` alanını kazanır: `{"model", "tables", "fingerprints"}`.
- Rebuild yolunda (base_schema (re)extract edildi VEYA cache'ten geldi ama embeddings yeniden gerekli),
  mevcut koşulsuz `build_index` çağrısı `reindex_embeddings(...)` ile değiştirilir:
  - `force_refresh=True` → `force=True` (tam re-embed; açık "her şeyi yeniden kur" korunur).
  - Aksi halde eski cache'ten okunabilen `old_embeddings` (fingerprints dahil) planlayıcıya verilir →
    yalnız bayat/yeni embed, kalan reuse, silinen evict.
  - `old_embeddings` yok/legacy (fingerprints alanı yok) → `force`-benzeri tam embed (bir kez), sonra
    fingerprint'li yazılır.
- **28.7 drift yolu uyumu:** 28.7'de yapısal drift `base_schema=None` **ve** `embeddings=None` set eder.
  28.8 için, eski embeddings'i planlayıcıda reuse edebilmek adına drift dalı `base_schema=None` set eder
  ama **eski `embeddings`'i (fingerprints dahil) `old_embeddings` olarak bir değişkende tutar**;
  re-extract sonrası `reindex_embeddings(old_embeddings=..., new_schema=base_schema, ...)` çağrılır.
  Böylece yapısal drift artık yalnız değişen tabloları yeniden embed eder (çıktı-eşdeğer).
- RAG indexleme: mevcut `rag_mngr.index_schema_batch(schema)` çağrısı korunur (precomputed vektörleri
  kullanır); ek olarak `reindex_embeddings` içindeki eviction `to_delete`'i temizler. `index_schema_batch`
  deterministik point id'ye geçer.
- Lock / cache-stampede / deepcopy / custom+implicit+disabled dressing DEĞİŞMEZ.

> **Çıktı-eşdeğer invariant:** Aynı `model` + aynı `base_schema` için nihai `embeddings.tables`, tam
> `build_index` ile üretilene **birebir aynıdır** (to_keep vektörleri zaten aynı model+aynı text ile
> hesaplanmıştı; to_embed taze hesaplanır). 28.8 yalnız gereksiz API çağrılarını ve Qdrant stale-point'leri
> ortadan kaldırır.

## 5. Endpoint'ler — `backend/app/api/schema_sync_api.py`'ye eklenir

28.7 router deseni (aynı `APIRouter(prefix="/api/debug/schema")`, `verify_api_key`, `ensure_debug_enabled()`
→ 404). Response model'ler `schemas.py`'de.

**Ayrım (`/sync` vs `/reindex`):** `POST /sync` (28.7) **şema STRUKTÜRÜNÜ** DB ile uzlaştırır (drift →
`load_schema(force_refresh=True)`, tam re-embed). `POST /reindex` (28.8) **EMBEDDING katmanını** *cache'teki
mevcut şema* (`cache["schema"]`) üzerinde güncel modelle uzlaştırır — **DB re-extract YAPMAZ**. İkisi
ayrık: yapısal drift → `/sync`; embedding bayatlığı (model/text-version değişimi) + Qdrant temizliği →
`/reindex`.

### 5.1 `GET /api/debug/schema/reindex-status` — read-only, **yan-etkisiz**
- Cache'ten `old_embeddings` (fingerprints + model) ve `cache["schema"]`'yı okur; **güncel model** ile
  cache'teki şemanın her tablosu için fingerprint hesaplayıp cache'tekiyle kıyaslar (`plan_reindex`).
  DB'den yeniden çıkarım YAPMAZ.
- Qdrant orphan tespiti (best-effort): `schema_ddl` point'lerinin `table_name` payload'ları − cache şeması tabloları.
- Yanıt: `{status, model, fresh: int, stale: [...], new: [...], to_delete: [...], orphaned_qdrant: [...]}`.
- **Embed YAPMAZ, cache/Qdrant'a YAZMAZ.**

### 5.2 `POST /api/debug/schema/reindex?force=false` — granular embedding re-index
- `reindex_embeddings(old_embeddings=cache["embeddings"], new_schema=cache["schema"], model=güncel,
  embedder, rag, force=force)` → yeni embeddings dict + `to_delete`/orphan evict; sonra
  `rag.index_schema_batch(schema+merged)` ile upsert.
- Cache güncellemesi: yalnız `cache["embeddings"]` (yeni tables+fingerprints+model) yeniden yazılır;
  **`cache["schema"]`/`schema_signature` korunur**. Ek olarak `cache["cache_fingerprint"]` güncel modelle
  yeniden hesaplanıp yazılır (28.6 `compute_cache_fingerprint` reuse) — böylece bir sonraki `load_schema`
  model uyuşmazlığından ötürü gereksiz **re-extract** tetiklemez (embedding-only invalidation uçtan uca).
- Yanıt: `ReindexReport` (`embedded`, `kept`, `deleted`, `model`).
- `force=true` → cache şemasının tüm tablolarını yeniden embed.
- **DB re-extract YAPMAZ** — yalnız cache'teki şema üzerinde çalışır (yapısal drift `/sync`'in işidir).

### Test
- 404-gate (debug kapalı), 403 (api key yok).
- `GET reindex-status`: stale/new/to_delete/orphaned şekli; embed edilmediği (yan-etkisizlik) doğrulanır.
- `POST reindex`: fake embedder/rag ile yalnız bayat embed + evict; `force` full; rapor şekli.

## 6. Cache şema değişikliği & geriye uyumluluk

- Yeni: `cache["embeddings"]["fingerprints"] = {name: hash}`. Eski (legacy) cache'lerde bu alan yok →
  `plan_reindex` boş `old_fingerprints` görür → **bir kez** tam embed, sonra fingerprint'li yazılır
  (28.6/28.7 legacy-cache deseni). 28.6 `cache_fingerprint` ve 28.7 `schema_signature` alanları **korunur**;
  28.8 yalnız `embeddings` alt-nesnesine `fingerprints` ekler.
- `SCHEMA_CACHE_VERSION` (28.6) bump'ı GEREKMEZ (legacy cache graceful upgrade eder). `REINDEX_FINGERPRINT_VERSION`
  bump'ı (embed-text mantığı değişirse) tüm fingerprint'leri geçersizler → tam re-embed.

## 7. Bilinçli kapsam-dışı (sessiz düşürme yok → TECH-DEBT §16)

1. **business_rules / sql_history koleksiyonları** — farklı yaşam döngüsü (feedback, SQL history);
   granular re-index yalnız `schema_ddl`'e uygulanır.
2. **Re-extract'siz embedding-only invalidation — KISMEN sağlandı.** `POST /reindex` cache şeması üzerinde
   çalışıp modeli/embeddings'i re-extract yapmadan tazeler ve `cache_fingerprint`'i günceller → §14.4'ün
   "şemayı koru, yalnız embedding yenile" yönü **manuel/endpoint yoluyla** sağlanır. Ancak **otomatik**
   yol (model değişince bir sonraki `load_schema`) hâlâ 28.6'nın whole-cache invalidation'ıyla re-extract
   eder (endpoint proaktif çağrılmazsa) — otomatik embedding-only kısa devre kapsam dışı.
3. **Qdrant koleksiyon migrasyonu / vector_size değişimi** — kapsam dışı (2048 sabit).
4. **Embed text zenginleştirme** (sample values, açıklama, kolon istatistikleri) — schema-only kalır
   (28.5/28.7 schema-only kararlarıyla tutarlı).
5. **Adaptif/batch-boyutu tuning** — mevcut `batch_size=50` (embed) / `250` (Qdrant) korunur.

## 10. Kabul kriterleri

- `reindex_planner.py` saf, deterministik, sıra-bağımsız; testleri yeşil; `build_table_embedding_text`
  mevcut `_generate_table_fingerprint` çıktısıyla birebir (refactor davranış-koruyucu).
- `plan_reindex` doğru sınıflandırır (yeni/değişen → to_embed, aynı → to_keep, silinen → to_delete,
  model-change → hepsi).

- `reindex_embeddings` yalnız bayat/yeni tabloları embed eder, kalanı reuse, silineni Qdrant'tan evict eder;
  `force`/legacy → tam embed.

  **çıktı-eşdeğer**; `force_refresh=True` tam re-embed; 28.6/28.7 davranışı (fingerprint/signature) korunur.
- `GET /reindex-status` yan-etkisiz doğru rapor; `POST /reindex` granular + evict; ikisi debug kapalıyken 404.
- Full suite yeşil; benchmark gate yeşil (version bump gerekmeden).
- §16 scope-out'lar açıkça işaretli.
