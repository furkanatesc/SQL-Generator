# Sprint 31.1 — Schema Explorer UX (Design Spec)

> Frontend sprint (Vue 3). No pytest/CI — verify via `npm run build`.
> Phase 12'nin ikinci frontend sprint'i. Kullanıcı direktifi: soru sorma, kapsam kararını kendin ver.

## 1. Problem / Brainstorm (karar)
Schema Explorer (`frontend/src/components/SchemaManager.vue`, 1838 satır) tablo kartları, kolon/FK
listeleri, ilişki listesi ve D3 graph'ı gösteren ana keşif yüzeyi. **Şu an frontend build TAMAMEN
KIRIK** (TECH-DEBT §35): `npm run build` 6 hata veriyor ve **exit≠0** — bu, gelecekteki HER frontend
sprint'inin verify'ını (build-yeşil) ve olası frontend CI'ı bloke ediyor. 31.0 bu yüzden yalnız
"error-set delta" ile doğrulanabildi.

Kök neden tek: **`const schema = ref<any>(null)`** — şema tipsiz olduğundan `visibleTables` computed'ı
`Record<string, unknown>` üretiyor, template'te `(meta, name) in visibleTables` döngüsünde `meta`
`unknown` oluyor → `meta.columns` / `meta.foreign_keys` erişimleri `TS18046` (5 hata). Altıncı hata
`validCustomRelations` computed'ı tanımlı ama hiçbir yere bağlı değil (`TS6133` ölü kod).

**Karar (kapsam):** 31.1 = **Schema Explorer'ı tip-güvenli hale getirmek** — bu tek değişiklik §35'in
6 hatasının tamamını kapatır ve **build'i TAM YEŞİLE (0 hata, exit 0)** çevirir; bu, 31.0'ın "delta"
verify'ından kesin bir iyileşme ve tüm sonraki frontend işini unblock eder. En yüksek değerli,
en düşük riskli Schema Explorer işi budur. Ölü `validCustomRelations` **silinmez, canlandırılır**:
`allRelations`'ta custom-key seti onunla kurulur → düşmüş (dropped) bir tabloya işaret eden bayat
özel ilişki artık "custom" olarak sınıflanmaz/gösterilmez (gerçek bir keşif-doğruluk guard'ı).

Bilinçli olarak tek dosya (`SchemaManager.vue`) + salt tip/guard; görsel/davranış yeniden tasarımı
YOK (dar, düşük-risk, test altyapısı olmayan bir kod tabanında güvenli değişim).

## 2. Design
`SchemaManager.vue` script'ine şema tip arayüzleri eklenir ve `schema` tiplenir:
```ts
interface SchemaColumn { name: string; type: string; primary_key?: boolean; }
interface SchemaForeignKey { column: string; referenced_table: string; referenced_column: string; }
interface SchemaTable { columns: SchemaColumn[]; foreign_keys?: SchemaForeignKey[]; }
interface DbSchema {
  tables: Record<string, SchemaTable>;
  graph?: { nodes: string[]; edges: GraphEdgeInput[] };   // GraphEdgeInput utils/graphSelection'dan reuse
}
const schema = ref<DbSchema | null>(null);
```
- `GraphEdgeInput` `../utils/graphSelection`'dan `type` import edilir (yeniden tanımlanmaz).
- Bunun sonucu `visibleTables` → `Record<string, SchemaTable>`; template'te `meta` artık `SchemaTable`,
  `meta.columns` / `meta.foreign_keys` tipli → 5 `TS18046` düşer.
- `getSchema()`/`refreshSchema()` `Promise<any>` döndürdüğü için atama (`schema.value = ...`) uyumlu
  (any→DbSchema|null geçerli); mevcut runtime davranışı DEĞİŞMEZ.
- `incomingRelationsMap`'teki `(meta as any).foreign_keys` artık gereksiz → typed erişime sadeleşir.
- `validCustomRelations` `allRelations`'ın ÜSTÜNE taşınır (okunabilirlik; TDZ yok — computed lazy) ve
  `allRelations` içindeki custom-key seti `customRelations` yerine `validCustomRelations`'tan kurulur.
