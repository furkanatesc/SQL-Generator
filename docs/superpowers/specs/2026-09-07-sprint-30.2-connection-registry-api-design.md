# Sprint 30.2 — Connection Registry API (Design Spec)

**Date:** 2026-09-07
**Phase:** 11 (API / Backend Productization) — third sprint
**Branch:** `feat/sprint-30.2-connection-registry-api` (from `main` `af6fd9d`)
**Predecessor:** 30.1 Workspace API (PR #170). 30.2 adds the second resource on the 30.0 contract and the first to **link to a workspace**.

---

## 1. Purpose & motivation

Phase 11 roadmap: Workspace → **Connection Registry** → Schema Sync → Query Run → … A connection registry lets an operator register the databases the system may query. 30.2 exposes a **persistent, API-fronted connection registry** at `/api/v1/connections`, conforming to the 30.0 contract.

Crucially, a rich, self-validating connection domain model already exists from Phase 7 (`app/evaluation/connection_abstraction.py`): `SQLConnectionProfile` (READ_ONLY-enforced, `SQLConnectionEndpoint` host/port/database, `SQLConnectionAuthMode` SECRET_REF/IAM/NONE, `SQLConnectionSecretRef` provider/key), an in-memory `SQLConnectionRegistry`, plus the `connection_credential_vault` governance contract. 30.2 does **not** reinvent these — it **persists** profiles and reuses their validation.

**Secret handling is settled by the existing architecture: secret-by-reference.** A profile carries a `secret_ref` (a `{provider, key}` pointer — e.g. an env-var or vault key), never a raw password/connection-string; `SQLConnectionSecretRef.__post_init__` actively rejects URLs/connection-strings/raw secrets via `scan_secret_patterns`. The registry therefore **stores and returns only references, never a raw secret** — there is no plaintext-vs-encrypted decision, because raw secrets never enter the registry. Secret resolution stays with infrastructure outside this sprint.

## 2. Scope decisions (author-decided under the user's "full authority" directive; documented for veto)

1. **CRUD for a persistent `connections` resource** at `/api/v1/connections`, conforming to the 30.0 `ApiResponse` envelope + offset `PageMeta`, protected by `verify_api_key`.
2. **Reuse the Phase 7 domain model** — the repository validates every write by constructing a `SQLConnectionProfile` (so READ_ONLY enforcement, endpoint/port validation, auth-mode/secret_ref rules, and the raw-secret scan all apply); invalid input → 422.
3. **Secret-by-reference only** — persist `auth_mode` + optional `secret_ref` (`{provider, key}`); **never** a raw secret column. Responses expose the reference only.
4. **First cross-resource link:** each connection optionally belongs to a workspace via a nullable `workspace_id`; if provided it must reference an existing workspace (else 400). List is filterable by `workspace_id`.
5. **Standalone / inert:** the registry only stores profiles — it does **not** open live DB connections, run health checks, or resolve secrets (that stays with the 29.x resolvers / later pipeline wiring). Live connection-testing is deferred.
6. **Duplicate `connection_ref` → 409 CONFLICT** (reuses the error code 30.1 added).

## 3. Existing landscape (reused, not rebuilt)

- `app/evaluation/connection_abstraction.py`: `SQLConnectionProfile`, `SQLConnectionEndpoint`, `SQLConnectionSecretRef`, `SQLConnectionAuthMode{SECRET_REF,IAM,NONE}`, `SQLConnectionAccessMode{READ_ONLY}`, `SQLConnectionEnvironment{LOCAL,DEV,STAGING,PROD}`, in-memory `SQLConnectionRegistry` (dup-ref detection + `get_profile`). All self-validating; `SQLConnectionSecretRef` scans for and rejects embedded raw secrets.
- `app/security/connection_credential_vault.py`: governs whether a caller may *resolve* a `secret_ref` — confirms the secret-by-reference architecture (never stores/resolves raw secrets in this layer).
- `SQLDatabaseDialect` (`app/evaluation/multi_database_execution.py`): sqlite/postgresql/oracle/mysql/sqlserver.
- 30.0 contract (`app/api/contract.py`) + 30.1 patterns (`workspace_repository.py`, `api/workspaces.py`, guard `EXPECTED_V1_ROUTES`, snapshot regen, `database.py` table idiom, column-whitelist UPDATE).

## 4. Architecture

### 4.1 Persistence — `connections` table + repository

**Table** (`database.py::init_db`, additive):
```
connections(
  id            TEXT PRIMARY KEY,          -- uuid4 hex
  connection_ref TEXT NOT NULL UNIQUE,     -- user-provided business key
  workspace_id  TEXT,                      -- nullable; references workspaces(id)
  name          TEXT NOT NULL,
  dialect       TEXT NOT NULL,             -- SQLDatabaseDialect value
  environment   TEXT NOT NULL,             -- SQLConnectionEnvironment value
  host          TEXT NOT NULL,
  port          INTEGER NOT NULL,
  database      TEXT NOT NULL,
  access_mode   TEXT NOT NULL,             -- always "read_only"
  auth_mode     TEXT NOT NULL,             -- SQLConnectionAuthMode value
  secret_provider TEXT,                    -- secret_ref.provider (nullable)
  secret_key      TEXT,                    -- secret_ref.key (nullable) — NEVER a raw secret
  max_rows      INTEGER NOT NULL,
  timeout_seconds REAL NOT NULL,
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL
)
```
No raw-secret column exists by design.

**Repository** — `backend/app/connection_repository.py`:
- `class ConnectionRefConflict(Exception)`.
- `_row_to_profile(row) -> SQLConnectionProfile` and `_profile_from_fields(...) -> SQLConnectionProfile` — build the domain object so its validation runs (raises `SQLConnectionAbstractionContractError` on invalid input, which the router maps to 422).
- `create_connection(connection_ref, workspace_id, name, dialect, environment, host, port, database, auth_mode, secret_provider, secret_key, max_rows, timeout_seconds) -> dict` — validates via `SQLConnectionProfile`, inserts flattened columns (uuid id + timestamps), `access_mode` forced `"read_only"`; duplicate `connection_ref` → `ConnectionRefConflict` (UNIQUE + IntegrityError, single race-free guard).
- `get_connection(id) -> dict | None`, `get_by_ref(connection_ref) -> dict | None`.
- `list_connections(limit, offset, workspace_id=None) -> list[dict]` — optional workspace filter; `ORDER BY created_at DESC, id`.
- `update_connection(id, **fields) -> dict | None` — column-whitelist (`name`, `host`, `port`, `database`, `environment`, `auth_mode`, `secret_provider`, `secret_key`, `max_rows`, `timeout_seconds`); re-validates the resulting profile; `connection_ref`, `dialect`, `access_mode` immutable in 30.2.
- `delete_connection(id) -> bool`.
- Rows carry only the reference fields — a `dict` row never contains a raw secret.

### 4.2 API — `/api/v1/connections` router

`backend/app/api/connections.py`, `verify_api_key`-protected, mounted at `f"{API_V1_PREFIX}/connections"`.

**Models** (pydantic):
- `SecretRefModel{ provider: str, key: str }`.
- `ConnectionCreate{ connection_ref (pattern ^[a-z0-9]+(-[a-z0-9]+)*$), name, dialect (SQLDatabaseDialect), environment (SQLConnectionEnvironment), host, port(1..65535), database, auth_mode (SQLConnectionAuthMode), secret_ref: Optional[SecretRefModel], workspace_id: Optional[str], max_rows(>0, default 1000), timeout_seconds(>0, default 2.0) }` — a `model_validator` enforces the same secret_ref/auth_mode pairing the domain enforces (fail fast at 422).
- `ConnectionUpdate{ name?, host?, port?, database?, environment?, auth_mode?, secret_ref?, max_rows?, timeout_seconds? }` (≥1 field).
- `ConnectionResponse{ id, connection_ref, workspace_id, name, dialect, environment, endpoint:{host,port,database}, access_mode, auth_mode, secret_ref:{provider,key}|null, max_rows, timeout_seconds, created_at, updated_at }` — **no raw secret field**.

**Endpoints** (all canonical `ApiResponse`):
- `POST /api/v1/connections` → 201; if `workspace_id` given and no such workspace → 400; duplicate `connection_ref` → 409; domain-invalid → 422.
- `GET /api/v1/connections` → 200 list + `PageMeta`; optional `?workspace_id=` filter, `?limit`/`?offset`.
- `GET/PATCH/DELETE /api/v1/connections/{connection_id}` → 200 (missing → 404); DELETE returns the resource, gated on the delete's bool return (concurrent → 404).

Workspace existence is checked by importing `workspace_repository.get_workspace`.

## 5. Data flow

```
POST /api/v1/connections {connection_ref, dialect, endpoint..., auth_mode, secret_ref?, workspace_id?}
  → verify_api_key
  → if workspace_id: workspace_repository.get_workspace(...) is None -> 400
  → _profile_from_fields(...) builds SQLConnectionProfile  (validates READ_ONLY, endpoint,
      auth_mode/secret_ref pairing, raw-secret scan) -> invalid -> 422
  → create_connection(...) -> ConnectionRefConflict -> 409
  → 201 ApiResponse[ConnectionResponse]  (secret_ref pointer only; no raw secret)
```

## 6. Testing strategy

- **Repository unit tests**: create/get/get_by_ref/list(+workspace filter, paginate)/update(whitelist, re-validates)/delete; duplicate ref → `ConnectionRefConflict`; domain validation surfaced (non-READ_ONLY rejected, secret_ref required for SECRET_REF, raw-secret-in-key rejected).
- **Endpoint tests**: CRUD round-trip; canonical envelope + `X-Request-ID`; pagination + workspace filter; 201/404/409/400(unknown workspace)/422(domain-invalid, e.g. bad port / raw secret in key); **response never contains a raw secret**; 403 without API key.
- **Conformance**: guard now covers the connections routes. Marker-less, deterministic, `backend-tests`.
- `fastapi` pinned to `0.115.12`.

## 7. Deliberately out of scope (→ TECH-DEBT §28)

- **Live connection testing / health check / secret resolution / rotation** — the registry is inert; opening a connection or resolving a `secret_ref` stays with the 29.x resolvers / later pipeline wiring.
- **Non-READ_ONLY access modes** (domain enforces READ_ONLY only today).
- **Wiring the registry into the execution pipeline** (30.4 Query Run / later).
- **Per-workspace RBAC / connection sharing / ownership** (needs AuthN 30.8).
- **`connection_ref` mutation, soft-delete, cascade on workspace delete** (workspace delete does not cascade to connections yet — a dangling `workspace_id` is possible; documented).
- **IAM secret specifics, TLS/cert config, connection pooling.**
- **Cursor pagination / cross-page `total`** (inherits 30.0 offset-only).
