## 1. Amaç ve bağlam

Phase 10 "25.x stub'larının production karşılığı"dır. Ancak keşif sırasında **25.8'in beklenenden çok
fazlasını teslim ettiği** görüldü: `app/evaluation/postgres_adapter.py` gerçek `SELECT` çalıştırıyor
(local-docker-only, read-only, lazy `psycopg2`, credential-free hata, statement_timeout), `psycopg2-binary`
requirements'ta, `test_postgres_adapter_integration.py` gerçek entegrasyon testleri içeriyor ve
`backend-ci.yml` CI'da `postgres:16-alpine` service container'ı sağlayıp bu testleri **gerçekten çalıştırıyor**
(skip değil). Yani "Docker Integration"ın execution ekseni büyük ölçüde mevcut.

**Gerçekten eksik olanlar** (29.0'ın kapsamı):

1. **Lokal dev Docker paritesi yok** — repoda `docker-compose` dosyası yok. CI'da Postgres var ama bir
   geliştirici aynı DB'yi lokalde ayağa kaldıramıyor → `pytest -m postgres` lokalde hep skip.
2. **Seeded fixture şema yok** — CI'daki `sqlgen_test` DB boş; entegrasyon testleri yalnız `SELECT 1` /
   `generate_series` yapıyor. Gerçek tablo/PK/FK/JOIN'e karşı hiçbir test yok.
3. **Yeniden kullanılabilir connection-resolver yok** — `SQLPostgresLocalDockerConnection` her testte env'den
   ad-hoc kuruluyor; 29.1'in pipeline'a bağlanırken tüketeceği tek contract-first "config/env → connection
   (yoksa inert)" katmanı yok.
4. **Contract-first canlı şema introspection yok** — 25.8'in execution adapter'ının **introspection ikizi
   yok**. `schema_manager.py`'deki eski `_extract_postgres_metadata` `information_schema` okur ama
   güvenlik-gate'siz (keyfi host'a `get_connection()` ile bağlanır, read-only zorlaması yok, gerçek PG'ye
   karşı entegrasyon testi yok) ve legacy dict üretir — 25.x contract-first mimarisinin dışında.

29.0 bu dördünü kapatır: **altyapı paritesi + seed + saf resolver + güvenli contract-first introspection
adapter'ı** — hepsi 25.8 deseninde (local-docker-only, read-only, lazy driver, credential-free,
**non-breaking / inert-by-default**).

## 2. Lokal Docker paritesi — `docker-compose.yml` + seed

**Amaç:** CI'ın `services: postgres` bloğuyla **bit-uyumlu** bir lokal Postgres; `pytest -m postgres`
lokalde artık skip değil çalışsın.

- Repo kökünde `docker-compose.yml`:
  - Servis `postgres`: image `postgres:16-alpine` (CI ile birebir), env `POSTGRES_USER=sqlgen` /
    `POSTGRES_PASSWORD=sqlgen` / `POSTGRES_DB=sqlgen_test`, port `5432:5432`, healthcheck `pg_isready -U sqlgen`.
  - Seed init: `./backend/tests/fixtures/postgres/seed.sql` → `/docker-entrypoint-initdb.d/` (container ilk
    ayağa kalkışta otomatik uygular).
- Kullanım: `docker compose up -d postgres` → `POSTGRES_TEST_*` env (compose default'larıyla eşleşir) →
  `pytest -m postgres`. README/CONTRIBUTING'e kısa bir "PostgreSQL entegrasyon testlerini lokalde çalıştırma"
  notu.

### Seed fixture — `backend/tests/fixtures/postgres/seed.sql`

Deterministik, küçük, gerçekçi çok-tablolu şema (idempotent — `DROP TABLE IF EXISTS ... CASCADE` + `CREATE`):

```
customers(id PK, name, email, created_at)
orders(id PK, customer_id FK->customers.id, status, total, ordered_at)
order_items(id PK, order_id FK->orders.id, product_name, qty, unit_price)
```

- Kolon tipleri PG-native (INTEGER, TEXT, NUMERIC, TIMESTAMP, BOOLEAN vs.) — introspection `data_type`
  eşlemesinin gerçek değerleri döndürdüğünü doğrulayabilmek için çeşitli.
- Az miktarda sabit satır (JOIN sonuç determinizmi için) — execution testleri exact-row assert edebilsin.
- **Tek doğruluk kaynağı**: hem compose init hem CI aynı `seed.sql`'i uygular (drift yok).

## 3. Saf connection-resolver — `app/evaluation/postgres_connection_resolver.py`

stdlib-only, yan-etkisiz (DB'ye **bağlanmaz** — yalnız config/env'den bir connection **nesnesi** kurar).
Source-scan purity guard (28.6–28.9 deseni: driver/framework import yok).

```
POSTGRES_CONNECTION_RESOLVER_VERSION = "v1"

resolve_local_docker_connection(env: Mapping[str, str] | None = None)
        -> SQLPostgresLocalDockerConnection | None
    # env verilmezse os.environ. POSTGRES_TEST_HOST/PORT/DB/USER/PASSWORD okur (mevcut CI/test
    # env sözleşmesiyle birebir aynı isimler). Host local-docker değilse / zorunlu alan eksikse /
    # SQLPostgresLocalDockerConnection __post_init__ reddederse -> None (inert; asla raise ETMEZ).
    # Başarıda geçerli SQLPostgresLocalDockerConnection döner.
```

- **Neden None-döner (raise değil):** çağıran (test fixture / adapter) "connection yoksa inert" davranışını
  tek kontrol noktasından alır; 25.8'in `SQLPostgresAdapterContract(connection=None) -> NOT_IMPLEMENTED`
  inert deseniyle simetrik.
- `test_postgres_adapter_integration.py`'deki ad-hoc `_make_test_connection()` bu resolver'a delege eder
  (davranış korunur; tek doğruluk kaynağı).

### Test (saf, DB'siz)
- Geçerli local-docker env → doğru alanlarla `SQLPostgresLocalDockerConnection`.
- Uzak host (`db.prod.example.com`) → `None`.
- Eksik zorunlu alan (boş db/user) → `None`.
- Geçersiz port (`"abc"`, `0`, `70000`) → `None` (raise yok).
- Boş/`None` env → `None`.
- Enjekte edilebilir `env` mapping ile determinizm (os.environ'a bağımlı değil).

## 4. Contract-first canlı introspection — `app/evaluation/postgres_schema_adapter.py`

25.8 `postgres_adapter.py`'nin **introspection ikizi**. Aynı güvenlik sınırları, aynı inert-by-default deseni.
`information_schema`'dan okuyup doğrudan **`DatabaseSchema`** (Bölüm 8 contract) üretir.

### Kontrat yüzeyi

```
SQL_POSTGRES_SCHEMA_ADAPTER_CONTRACT_VERSION = "sql_postgres_schema_adapter_contract_v1"

class SQLPostgresSchemaAdapterStatus(str, Enum):
    NOT_IMPLEMENTED   # connection yok -> inert
    EXECUTION_ERROR   # driver yok / bağlantı/sorgu hatası (credential-free)
    EXTRACTED         # başarı

@dataclass(frozen=True)
class SQLPostgresSchemaAdapterConfig:
    connect_timeout_seconds: float = 5.0
    statement_timeout_seconds: float = 5.0
    schema_name: str = "public"        # sadece bu PG schema introspect edilir

@dataclass(frozen=True)
class SQLPostgresSchemaIntrospectionResult:
    version: str
    status: SQLPostgresSchemaAdapterStatus
    schema: DatabaseSchema | None      # EXTRACTED'da dolu, aksi None
    table_count: int = 0
    relationship_count: int = 0
    error: str | None = None           # credential-free
    duration_ms: float = 0.0

class SQLPostgresSchemaAdapterContract:
    def __init__(self, connection: SQLPostgresLocalDockerConnection | None = None,
                 config: SQLPostgresSchemaAdapterConfig | None = None): ...
    def introspect(self) -> SQLPostgresSchemaIntrospectionResult: ...
```

### Davranış

- **connection=None → `NOT_IMPLEMENTED`** (inert; hiçbir import/bağlantı denemesi yok). 25.8 ile simetrik →
  orchestrator/pipeline default yolu introspection kazanmaz.
- **Lazy driver import**: `import psycopg2` yalnız `introspect()`'in gerçek yolunda; yoksa `EXECUTION_ERROR`
  ("PostgreSQL driver (psycopg2) is not available.").
- **Read-only + timeout**: bağlantı `default_transaction_read_only=on` + `statement_timeout` ile açılır
  (25.8'le birebir); `set_session(readonly=True)`. Introspection zaten yalnız `SELECT information_schema`,
  ama savunma-derinliği için read-only zorlanır.
- **Sorgular** (`schema_name` parametreli, mevcut `_extract_postgres_metadata`'nın kanıtlanmış SQL şekli
  REUSE edilir ama **yeni, güvenli bağlantı** üzerinden):
  1. `information_schema.tables` (BASE TABLE, `table_schema=%s`) → tablo listesi.
  2. `information_schema.columns` → kolon adı/`data_type`/`is_nullable`/`ordinal_position`.
  3. `table_constraints`+`key_column_usage` (PRIMARY KEY) → PK kolonları.
  4. `table_constraints`+`key_column_usage`+`constraint_column_usage` (FOREIGN KEY) → FK kenarları.
- **`DatabaseSchema` inşası**: her tablo → `TableSchema` (`columns`, `primary_key_columns`); her FK →
  `RelationshipSchema(relationship_type=EXPLICIT, source=child, target=parent)` (contract'ın yön sözleşmesi:
  source=FK'yi tutan çocuk). `graph` **kurulmaz** (opsiyonel; `relationships` yeterli — contract graph
  verilmezse relationships'i doğrular). Deterministik sıralama (tablo/kolon/ilişki adına göre) → tekrarlanan
  introspect'ler byte-identical.
- **Credential-free hata**: bağlantı/sorgu exception'ı → `_sanitize_schema_error` (host/user/password/driver
  ham mesajı ASLA sızmaz; timeout ayrı mesaj). 25.8'in `_sanitize_db_error` deseni.
- **`finally` best-effort close** (25.8 deseni).

### Neden legacy `_extract_postgres_metadata` refactor edilmiyor
Legacy yol config-driven keyfi host'a (`target_pg_host`) bağlanır, `SchemaManager`/cache/filtre/RAG ile
sıkı bağlıdır ve legacy dict üretir. Onu güvenli-contract'a çevirmek 29.0 dışı büyük/kırıcı bir refactor
olurdu (unrelated scope). Yeni adapter **saf ekleme**; legacy yol olduğu gibi kalır (kendi çağıranlarını
bozmaz). *Bilinçli scope-out — sessiz düşürme yok (Bölüm 10).*

## 5. Entegrasyon testleri (gated) — seeded şemaya karşı

Yeni `backend/tests/evaluation/test_postgres_schema_adapter_integration.py`; `pytestmark = [integration, postgres]`.
Mevcut skip-gate deseni (`_local_docker_postgres_available()`) **Bölüm 3 resolver'ı** üzerinden REUSE edilir
→ Docker yoksa güvenli skip, CI'da (+ lokalde compose ile) çalışır.

- `introspect()` → `EXTRACTED`; `table_count == 3`; tablo adları `{customers, orders, order_items}`.
- `customers` kolonları + tipleri + `primary_key_columns == ["id"]` (seed ile exact-match).
- İlişkiler: `orders.customer_id -> customers.id` ve `order_items.order_id -> orders.id`, ikisi de
  `EXPLICIT`, yön doğru (source=child).
- Üretilen `DatabaseSchema` **contract-geçerli** (pydantic validation: relationships tabloları/kolonları
  gerçekten var).
- **Determinizm**: iki ardışık `introspect()` byte-identical `DatabaseSchema` (aynı sıralama).
- Credential sızıntısı yok: sonuç serileştirmesinde `sqlgen`/`localhost` geçmez.
- Gerçek çok-tablolu **JOIN** (25.8 execution adapter, aynı seeded DB): `customers ⋈ orders ⋈ order_items`
  → beklenen satır sayısı/örnek değer (seed sabit).
- `connection=None` → `NOT_IMPLEMENTED` (bu test **DB'siz** de koşar — inert yol).

Ek: `test_postgres_adapter_integration.py` seed'den **bağımsız** kalır (hâlâ `SELECT 1` vb.), yalnız
`_make_test_connection()` resolver'a delege edecek şekilde güncellenir (davranış korunur).

## 8. `DatabaseSchema` contract uyumu

Introspection çıktısı mevcut `app/schema/schema_contract.py` contract'ına birebir uyar:
`DatabaseSchema(dialect="postgresql", database_name=<dbname>, tables=[TableSchema...],
relationships=[RelationshipSchema(EXPLICIT)...])`. `graph=None` (opsiyonel). Contract validator'ı
relationships'in tablo/kolon referanslarını doğrular → adapter'ın ürettiği her ilişki gerçek kolonlara
işaret etmeli (introspection zaten gerçek FK'lerden türetir → geçer).

## 10. Bilinçli kapsam dışı (→ TECH-DEBT §18; sessiz düşürme yok)

1. **Production pipeline'a introspection wiring** — canlı Postgres'ten şema çıkarımını gerçek istek
   pipeline'ına (Excel/SQLite yolunu değiştirerek) bağlama → Phase 11 (30.2 Connection Registry / 30.3
   Schema Sync API). 29.0 inert/bağımsız kalır.
2. **Legacy `_extract_postgres_metadata` güvenli-contract'a taşınması** — büyük/kırıcı refactor; legacy yol
   olduğu gibi kalır.
3. **Uzak/production connection** — sadece local-docker (25.8 sınırı korunur).
4. ~~**Composite FK / multi-column FK introspection**~~ — **KAPSAM İÇİNE ALINDI (karar 2026-08-11, kullanıcı).**
   Task 3 review'ı, `constraint_name`-only join'in composite FK'de sessizce YANLIŞ (cross-product) ilişki
   ürettiğini ortaya çıkardı. Çözüm: FK sorgusu `referential_constraints` + `position_in_unique_constraint`
   ile ordinal-eşleştirmeli hale getirilir → composite FK'ler doğru eşleşir. Seed'e composite-FK tablo çifti
   + entegrasyon assertion eklenir (Task 4). Artık kapsam dışı DEĞİL.
5. **Non-public PG schema'ları / view'ler / materialized view'ler** — yalnız `public` BASE TABLE.
6. **Kolon zenginleştirme** (comment/description, `pg_description`, örnek değerler) — schema-only kalır.
7. **Connection Registry / çoklu bağlantı yönetimi** — 30.2'ye ait; 29.0 tek enjekte connection kullanır.
8. **29.1 execution'ın pipeline'a bağlanması** — 29.1 kapsamı.
