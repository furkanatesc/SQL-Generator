# Sprint 29.5 — MySQL Adapter Contract — Design

**Status:** Approved (brainstorm) — pending user spec review → writing-plans
**Date:** 2026-08-27
**Phase:** 10 (Real Database Adapter Layer)
**Predecessors:** Oracle 29.3 (Contract Adapter) + 29.4 (Docker/Test Harness); PostgreSQL 29.0/29.1. This sprint **bundles** the Oracle-29.3-equivalent contract adapter **and** the Oracle-29.4-equivalent Docker/test harness into one sprint, because MySQL is lower-risk than Oracle (pure-Python driver, small image, no licensing).

## 1. Purpose & scope

Deliver a real, local-Docker-only, **read-only** MySQL execution path (`PyMySQL`, driver-isolated), standalone/inert — **not** wired into the live production request pipeline — plus the full test harness (seed schema + seed applier + docker-compose service + a dedicated live CI job) that verifies it end-to-end in CI. Mirrors the PostgreSQL 29.0→29.1 and Oracle 29.3 three-layer structure, and the Oracle 29.4 harness pattern.

Unlike Oracle (which had a 25.9 all-`False` stub first), **there is no pre-existing MySQL code or stub** — this sprint starts from scratch, including adding the `MYSQL` dialect to the shared enum.

### Explicitly out of scope (deferred, no silent drops — TECH-DEBT new §23)

- MySQL schema introspection (`information_schema` → `DatabaseSchema`; Postgres 29.0 equivalent) → later sprint.
- MySQL EXPLAIN-only mode (29.2 equivalent) → later sprint.
- Live HTTP pipeline wiring / central execution router registry → 30.x.
- Connection registry / remote & production connections / TLS → Phase 11 · 30.2.
- C-based drivers (`mysqlclient` / `mysql-connector-python`) / thick mode → deferred unless needed (pure-Python `PyMySQL` only).

## 2. Shared contract change

`backend/app/evaluation/multi_database_execution.py`: add `MYSQL = "mysql"` to `SQLDatabaseDialect`. Single additive enum member; no existing behavior changes. (Oracle 29.3 needed no such change because `ORACLE` already existed from 25.9.)

## 3. Driver & image

- **Driver:** pin `PyMySQL==1.1.1` in `backend/requirements.txt` — pure-Python, no C extension or system library, so it imports lazily and stays driver-isolated (mirrors `oracledb` thin mode).
- **Image:** `mysql:8.4` (LTS, pinned). Runs `/docker-entrypoint-initdb.d/*.sql` on first init; health via `mysqladmin ping`; startup ~20–40s (far lighter than Oracle). Env: `MYSQL_ROOT_PASSWORD=sqlgen`, `MYSQL_DATABASE=sqlgen_test`, `MYSQL_USER=sqlgen`, `MYSQL_PASSWORD=sqlgen`, port 3306.

## 4. MySQL vs Oracle differences (load-bearing)

| Concern | Oracle (29.3) | MySQL (29.5) |
|---|---|---|
| Read-only tx | `SET TRANSACTION READ ONLY` | `START TRANSACTION READ ONLY` (a write raises `ER_CANT_EXECUTE_IN_READ_ONLY_TRANSACTION`, errno 1792) |
| Statement timeout | `conn.call_timeout = ms` | `SET SESSION max_execution_time = <ms>` (SELECT-only server-side cap — exactly our read-only path) + client `read_timeout` backstop |
| Connection identity | `service_name` | `database` |
| Identifier case | unquoted folds to UPPERCASE | **case preserved as-written** (Linux/Docker default `lower_case_table_names=0`) — seed + queries are all lowercase, and column-key assertions use the alias case as written (lowercase) |
| Driver | `oracledb` thin | `pymysql` |

## 5. Low-level adapter — `backend/app/evaluation/mysql_adapter.py` (new)

Mirrors Oracle 29.3's three defense layers:

- **Layer 1 — string gate (before any driver touch):** reuse the shared dialect-agnostic `validate_read_only_select(sql) -> Optional[str]` (already exported from `app.evaluation`, sourced from `app.security.sql_read_only_enforcement`). Non-None reason → deterministic `REJECTED`, with no connection/driver/network access, regardless of whether a connection is configured.
- **Layer 2 — lazy driver import:** `import pymysql` only inside the execution path (`_execute_select`). Importing the module never loads a DB driver / SQLAlchemy.
- **Layer 3 — DB-level read-only + timeout:** `pymysql.connect(..., autocommit=False, read_timeout=…)`, then on a cursor: `SET SESSION max_execution_time = <ms>` → `START TRANSACTION READ ONLY` → execute SELECT → `fetchmany(max_rows + 1)` → `cur.description`. `finally`: guarded `rollback()` then `close()`.

New surface (mirrors Oracle names):
- `SQLMySQLAdapterStatus(str, Enum)`: `NOT_IMPLEMENTED`, `REJECTED`, `EXECUTED`, `EXECUTION_ERROR`.
- `SQLMySQLAdapterCapability` (frozen dataclass of `supports_*` flags) + `default_local_docker_capability()` (only `live`/`remote`/`production` forced False; local-docker read-only allowed).
- `SQLMySQLLocalDockerConnection` (frozen): `host` (allowlist `localhost`/`127.0.0.1`/`::1`), `port`, `database`, `user`, `password`.
- `SQLMySQLAdapterConfig` (`timeout_seconds`, `max_rows`, `execution_mode`), `SQLMySQLAdapterExecutionRequest`, `SQLMySQLAdapterExecutionResult` (with `columns`, `rows`, `row_count`, `truncated`, `warnings`, `duration_ms`, `sql_sha256`, `status`, `error`).
- `SQLMySQLAdapterContract(connection=None)` with `.capability()` and `.execute(request)`.
- `_sanitize_mysql_error(exc) -> str` — never leaks host/user/password/database/DSN; timeout mapped to a distinct message.
- `SQL_MYSQL_ADAPTER_CONTRACT_VERSION`.

`execute()` order is **validate-first** (read-only gate → connection-None), preserving the "no-connection + unsafe SQL → REJECTED" contract. `connection is None` (and safe SQL) → inert `NOT_IMPLEMENTED`.

## 6. Resolver — `backend/app/evaluation/mysql_connection_resolver.py` (new)

`resolve_local_docker_connection(env=None) -> Optional[SQLMySQLLocalDockerConnection]` from the `MYSQL_TEST_*` env contract (`MYSQL_TEST_HOST` default `localhost`, `MYSQL_TEST_PORT` `3306`, `MYSQL_TEST_DB` `sqlgen_test`, `MYSQL_TEST_USER` `sqlgen`, `MYSQL_TEST_PASSWORD` `sqlgen`). Never connects, never raises: any invalid/remote/missing value → `None`. `MYSQL_CONNECTION_RESOLVER_VERSION = "v1"`. Mirrors `oracle_connection_resolver.py`.

## 7. Bridge — `backend/app/evaluation/mysql_execution_adapter.py` (new)

`MySQLDatabaseExecutionAdapter(SQLDatabaseExecutionAdapter)` — dialect-agnostic bridge:
- `dialect -> SQLDatabaseDialect.MYSQL`; `capabilities() = (CONNECTION_REF, READ_ONLY)`; **EXPLAIN_ONLY rejected** (`SQLMultiDatabaseExecutionContractError`).
- `__init__(self, connection_resolver=resolve_local_docker_connection)`.
- `execute()` validates dialect/connection_ref/fixture_ref/execution_mode; resolves connection; `None` → graceful empty `SQLDatabaseExecutionResult` with `execution_error` (never raises on that path); else builds `SQLMySQLAdapterExecutionRequest`, delegates to `SQLMySQLAdapterContract(connection=…).execute`, normalizes via `normalize_mysql_execution_result`.
- `normalize_mysql_execution_result(mysql_result, request)` + `_rows_to_dicts(rows, columns)` (dict rows from column names; `col_<i>` positional fallback + warning on arity mismatch). `sql_sha256` from the original request SQL.
- **NOT** re-exported from `app/evaluation/__init__.py` (harness-only; mirrors the Oracle resolver/execution-adapter precedent). Neither is `mysql_connection_resolver` nor `mysql_seed`. `mysql_adapter` MAY be exported like `oracle_adapter` is (optional; the plan will decide — default: export the low-level adapter surface to match the Oracle `__init__` precedent, leave resolver/execution-adapter/seed unexported).

## 8. Seed schema — `backend/tests/fixtures/mysql/seed.sql` (new)

Mirrors the 29.0/29.4 seed **shape** in MySQL dialect, with the **same deterministic rows**:
- `customers` / `orders` / `order_items` — single-column PK/FK.
- `product_variants` / `variant_stock` — composite PK/FK `(product_id, sku)`.

Dialect: `INT`, `VARCHAR(n)`, `DATETIME` (literal `'2020-01-01 00:00:00'`), `DECIMAL(10,2)`; **`ENGINE=InnoDB`** on every table (FK enforcement); all identifiers lowercase (case-consistency — MySQL preserves case); one row per `INSERT` (keeps the statement splitter trivial); no stored-procedure/`DELIMITER` blocks. Applied once against a fresh DB (compose init-script / CI seed step), so plain `CREATE TABLE` (no `DROP`). FK-declaration order: customers → orders → order_items; product_variants → variant_stock. Same row values as the Postgres/Oracle seeds (Ada/Alan; 3 orders; 4 order_items; 2 product_variants; 2 variant_stock).

## 9. Seed applier — `backend/app/evaluation/mysql_seed.py` (new)

Mirrors `oracle_seed.py`:
- `split_statements(sql) -> tuple[str, ...]` — pure; splits on `;`, strips `--` line comments and blanks. (Deliberate small duplication of `oracle_seed.split_statements` — same logic; kept per-dialect to avoid cross-dialect coupling. Noted so review does not treat it as an accidental copy.)
- `apply_seed(connection, sql) -> int` — executes each statement, commits once, returns count.
- `main(argv=None) -> int` — lazy-imports `pymysql`, connects from `MYSQL_TEST_*` env (via `resolve_local_docker_connection`), reads the seed file (default `tests/fixtures/mysql/seed.sql` relative to cwd = `backend/`), applies it. Invoked `python -m app.evaluation.mysql_seed`. `pymysql` imported lazily inside `main()` only; module NOT added to `__init__.py`. `MYSQL_SEED_VERSION = "v1"`.

## 14. Risks

- **Read-only enforcement correctness.** `START TRANSACTION READ ONLY` + the L1 string gate both apply; a write inside the tx errors at the server. Verified by the fake-driver unit test (statement order) and, live, by the read-only tx in CI.
- **Identifier case.** MySQL preserves case; all seed/query identifiers are lowercase and assertions use the alias case — no folding surprise (documented §4).
- **Driver isolation.** `pymysql` imported lazily only; subprocess test enforces absence at import time.
- **CI image weight.** `mysql:8.4` is light; separate additive job keeps the main suite unblocked.
- **`split_statements` duplication.** Deliberate per-dialect copy; flagged so review does not treat it as accidental.
