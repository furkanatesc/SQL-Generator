# Sprint 28.9 — Semantic / Result Cache · Tasarım (Design Spec)

**Phase:** 9 — Large Schema Production Scale (28.8'in ardılı; Phase 9'un SON sprinti)
**Tarih:** 2026-08-10
**Tür:** Üretim performans/maliyet — deterministik exact result cache (LLM generation kısa-devresi); saf key çekirdeği + SQLite adaptör
**Önceki:** 28.8 Embedding / RAG Re-Index Pipeline (PR #159) · **Sonraki:** Phase 10 · 29.0 PostgreSQL Docker Integration Adapter

---

## 1. Amaç ve bağlam

`SQLGenerationPipeline.run_pipeline` (`backend/app/sql_pipeline.py`) her doğal-dil sorgusu için tüm
writer-critic LLM döngüsünü (`_stage_writer_critic`) koşar — NVIDIA API çağrısı + çok denemeli critic
düzeltmesi, pipeline'ın **en pahalı ve en yavaş** parçası. Bugün generation path'inde **hiçbir cache yok**
(`search_sql_history`/`index_sql_history` yalnız manuel RAG endpoint'leri, pipeline'a bağlı değil).

28.9 deterministik bir **exact result cache** ekler: aynı sorgu (aynı `dialect` + değişmemiş şema) tekrar
geldiğinde LLM generation'ı **atlar**, cache'teki üretilmiş SQL'i **yeniden doğrulayıp** döner. Cached SQL
yalnız üretildiği şema için geçerli olduğundan cache key `schema_signature`'a (28.7/28.8'in yapısal
signature'ı) bağlanır → şema yapısal olarak değişince key uyuşmaz (doğal invalidation). "Result" =
pipeline'ın ürettiği **SQL** (execution/satır sonuçları Phase 10'a ait, şu an stub).

### Merkezi tasarım kararları (onaylı)

| Karar | Seçim |
|---|---|
| Mekanizma | **Exact result cache** (deterministik hash key); semantic cache ertelendi (§8.1) |
| Cache key | `sha256(version \x1f dialect \x1f schema_signature \x1f normalize(query))` |
| Hit davranışı | Cached SQL **`validate_sql` ile yeniden doğrulanır** (guardrail+safety+AST+semantik); geçerse döner, geçmezse miss |
| İnvalidation | `schema_signature` (28.7) key'e dahil → şema değişince doğal uyuşmazlık |
| Yerleşim | `run_pipeline`'da retrieval'dan SONRA, writer-critic'ten ÖNCE |
| Depolama | SQLite `sql_cache` tablosu (ham NL query SAKLANMAZ — yalnız hash key) |
| Config default | `sql_result_cache_enabled` **AÇIK** (re-validate'li ve güvenli; sprintin değeri budur) |
| Debug endpoint | `GET /api/debug/cache/stats` + `POST /api/debug/cache/clear` |

## 2. Saf çekirdek — `backend/app/cache/result_cache_key.py`

stdlib-only, deterministik, yan-etkisiz. Source-scan purity guard (28.6/28.7/28.8 deseni).

```
RESULT_CACHE_KEY_VERSION = "v1"
_UNIT = "\x1f"

normalize_query(q: str) -> str
    # Deterministik, minimal normalizasyon (semantik risk yok):
    #   casefold() + strip() + iç ardışık whitespace'i tek boşluğa indir (" ".join(split())).
    #   None -> "".

compute_result_cache_key(natural_query: str, dialect: str, schema_signature: str,
                         *, version=RESULT_CACHE_KEY_VERSION) -> str
    # sha256((version, dialect, schema_signature, normalize_query(natural_query)) '\x1f'-join) hex.
    # Alan boundary'leri _UNIT ile ayrılır (collision guard). dialect/signature None -> "".
```

### Test (saf)
- `normalize_query`: case-insensitive, baş/son boşluk, iç çoklu boşluk → tek; None → "".
- `compute_result_cache_key`: determinizm; `dialect`/`schema_signature`/`query` her biri değişince key değişir;
  normalize edilmiş eşdeğer sorgular (case/whitespace) **aynı** key; version bump key'i değiştirir; boş girdiler.

## 3. Kirli adaptör — `backend/app/result_cache.py` + SQLite `sql_cache` tablosu

- **Şema (migration `database.py` init'e eklenir):**
  ```sql
  CREATE TABLE IF NOT EXISTS sql_cache (
    cache_key        TEXT PRIMARY KEY,
    sql              TEXT NOT NULL,
    dialect          TEXT,
    schema_signature TEXT,
    created_at       TEXT,
    hit_count        INTEGER DEFAULT 0
  )
  ```
  **Ham doğal-dil sorgusu SAKLANMAZ** — yalnız `cache_key` (hash). Secret-free (trace redaction disiplini);
  saklanan `sql` zaten `jobs.result_sql`'de de tutulan pipeline çıktısıdır.
- **API (`app/result_cache.py`, `database.get_db_connection` reuse):**
  - `get_cached_sql(cache_key) -> str | None`
  - `put_cached_sql(cache_key, sql, dialect, schema_signature)` — INSERT OR REPLACE (created_at = caller/UTC-iso).
  - `bump_hit(cache_key)` — `hit_count += 1`.
  - `clear_cache() -> int` — tümünü sil, silinen satır sayısı.
  - `cache_stats() -> {"entries": int, "total_hits": int}`.
- `created_at` için `datetime.utcnow().isoformat()` (mevcut `create_job` deseni; saf çekirdek DEĞİL, adaptör
  katmanı — saf modül clock kullanmaz).

### Test
- tmp SQLite DB (monkeypatch `get_db_connection`): put→get round-trip; get miss → None; bump_hit artırır;
  clear siler + sayı döner; cache_stats doğru entries/total_hits.

def get_cached_schema_signature(self) -> Optional[str]:

`None` dönerse (legacy cache / cache dosyası yok / okunamıyor) → o istek için result cache **devre dışı**

cache dosyasını okuruz).

## 5. Pipeline entegrasyonu — `run_pipeline`

Retrieval'dan (§2 pruned_schema + context) sonra, writer-critic'ten (§3) önce yeni bir cache adımı:

1. `cache_enabled = is_result_cache_enabled(get_config("sql_result_cache_enabled"))` — **default AÇIK**
   (yeni dedike helper, §6; 28.7'nin `_is_truthy_config`'i None→False döndürdüğü için KULLANILMAZ — burada
   None→True gerekir). `schema_signature = self.schema_manager.get_cached_schema_signature()`.
2. `cache_active = cache_enabled and schema_signature is not None`.
3. `cache_active` ise: `q = aqr.get("natural_query", "")` (generation ile AYNI query — Excel yolu dahil,
   `_stage_writer_critic` de `aqr.get("natural_query")` kullanır); `key = compute_result_cache_key(q, dialect,
   schema_signature)`; `cached_sql = get_cached_sql(key)`.
   - **Hit** (`cached_sql`): `outcome = self.validate_sql(cached_sql, pruned_schema, dialect, log_callback)`.
     - `outcome.valid` → `result["success"]=True`, `result["generated_sql"]=outcome.sql`,
       `result["attempts"]=[{attempt:1, action:"cache_hit", sql, valid:True}]`, `bump_hit(key)`,
       writer-critic **ATLANIR**. Trace `cache_hit=True` + generation timing 0.
     - `not outcome.valid` (beklenmedik — signature eşleşti ama doğrulama düştü) → hit yok say, normal
       writer-critic (stale entry bir sonraki başarıda üzerine yazılır).
   - **Miss** → normal writer-critic.
4. writer-critic **başarı** ile döndüyse ve `cache_active` ise: `put_cached_sql(key, result["generated_sql"],
   dialect, schema_signature)`.
5. Retrieval (prune+context) **her zaman koşar** (hit'te yeniden doğrulama için `pruned_schema` gerekir);
   yalnız pahalı LLM generation atlanır. Lock/trace/redaction/known_secrets akışı DEĞİŞMEZ.

> **Güvenlik invariant'ı:** Hit'te servis edilen SQL, mevcut budanmış şemaya karşı `validate_sql`'in TAM
> zincirinden (guardrail + sandbox-safety + AST + semantik) geçer — cache asla güvenlik/doğrulama
> katmanını bypass etmez. Bu, cache-poisoning veya guardrail-config değişimine karşı korur.

### Trace / gözlemlenebilirlik
- `run_pipeline` sonucuna ve trace metadata'sına `cache_hit: bool` eklenir (redaction sonrası).
  `_capture_trace_on_exit`'e `cache_hit` iletilir; e2e/legacy trace'e işlenir (27.x observability).
  Metrics/dashboard'da cache-hit-oranı raporlaması **minimal** (yalnız flag emit); ileri agregasyon scope-out (§8).

## 6. Config

- Yeni config anahtarı `sql_result_cache_enabled` (configs tablosu). **Default AÇIK.**
- Dedike parse helper (`app/result_cache.py`, saf/deterministik fonksiyon):
  ```
  def is_result_cache_enabled(value) -> bool:
      # None (unset) VE "" (boş) -> True (default AÇIK); yalnız explicit off-token KAPATIR.
      if value is None: return True
      return str(value).strip().lower() not in {"0", "false", "no", "off"}
  ```
  (28.7'nin `_is_truthy_config`'i None→False verir; bu yüzden ayrı bir helper — burada None→True.)
  Dokümante edilir.

## 8. Bilinçli kapsam-dışı (sessiz düşürme yok → TECH-DEBT §17)

1. **Semantic cache** (embedding cosine-similarity ile parafraz eşleştirme) — near-miss'te ince-yanlış SQL
   döndürme precision-riski taşır (cache-miss'ten kötü); bilinçli ertelendi (gelecek sprint / 28.x-successor).
2. **Execution / result-set (satır) cache** — gerçek DB execution Phase 10'da (şu an stub); satır sonuçları
   cache'lemek o zamana dek anlamsız.
3. **TTL / boyut-tabanlı eviction** — yok. Şema değişince eski `schema_signature`'lı key'ler doğal olarak
   uyuşmaz (invalidation), ama eski satırlar tabloda birikir; temizlik yalnız `POST /api/debug/cache/clear`
   ile (otomatik TTL/LRU scope-out).
4. **Prompt-template / model değişiminde invalidation** — key yalnız `schema_signature`'a bağlıdır
   (correctness-kritik boyut). Prompt template veya LLM model değişimi cached SQL'i **geçersizlemez** —
   cached SQL hâlâ geçerli/güvenli (re-validate'li), yalnız "en güncel prompt'un üreteceğinden" farklı
   olabilir (tazelik-only, correctness değil). İstenirse manuel `POST /clear`.
5. **Cache-hit oranı ileri agregasyonu** (metrics/dashboard'da dedike cache paneli) — 28.9 yalnız `cache_hit`
   flag'ini trace'e emit eder; raporlama katmanı scope-out.
6. **Frontend `maxNodesLimit=5` kalıcı çözümü** (PLANNED-SPRINTS Phase 9 notu) — farklı katman (frontend
   graph limitleme); 28.9 backend cache sprinti kapsamı dışında. Faz-seviyesi not AÇIK kalır (ayrı ele alınmalı).
