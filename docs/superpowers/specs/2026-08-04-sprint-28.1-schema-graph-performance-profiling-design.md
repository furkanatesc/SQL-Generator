# Sprint 28.1 — Schema Graph Performance Profiling · Tasarım (Design Spec)

**Phase:** 9 — Large Schema Production Scale (28.0'ın ardılı)
**Tarih:** 2026-08-04
**Tür:** Profiling instrümentasyonu + benchmark genişletme (dev/CI aracı) + hedefli üretim seam'i
**Önceki:** 28.0 Large Schema Benchmark Suite (PR #150) · **Sonraki:** 28.2 Join Path Explosion Control

---

## 1. Amaç ve bağlam

28.0 büyük şemalarda dört saf hedefin maliyetini **ne kadar** olduğunu ölçtü (wall_ms
bilgilendirici + çıktı-türev deterministik metrikler). 28.1 maliyetin **nerede** olduğunu
ortaya çıkarır — *profiling*: üretim hot-path'lerine iç-patlama sayaçları ekleyerek
(`dfs_visit`, `fuzzy_comparison`, `table_scan`...). Bu sayaçlar seed-deterministiktir →
28.0'ın exact-match gate'ini genişletir ve 28.2 (Join Path Explosion Control), 28.3
(Table Selection Cost Model), 28.5 (Missing-FK v2) sprintlerine somut hedef sinyali verir.

28.0 bu instrümentasyonu **bilinçli olarak** 28.1'e erteledi (TECH-DEBT §12), çünkü üretim
hot-path'lerine dokunmayı gerektirir. 28.1 bunu **sıfır-maliyet, opsiyonel probe
enjeksiyonuyla** üstlenir (davranış birebir korunur).

### Merkezi tasarım kararı — davranış korunur, probe opsiyonel
Üç hot-path fonksiyonuna keyword-only `probe: ProfileProbe | None = None` eklenir.
`probe is None` (tüm mevcut çağıranlar) → **guarded artış atlanır → sıfır davranış/çıktı
değişikliği, ihmal edilebilir overhead**. Yalnız benchmark bir probe geçirir. İç fonksiyon
imzaları contract snapshot'larda DEĞİL (28.0'da doğrulandı) → snapshot etkilenmez.

## 3. Mimari

### 3.1 Probe (üretim seam) — `backend/app/schema/profiling.py` (SAF)

```python
class ProfileProbe:
    __slots__ = ("counts",)
    def __init__(self) -> None:
        self.counts: dict[str, int] = {}
    def incr(self, key: str, n: int = 1) -> None:
        self.counts[key] = self.counts.get(key, 0) + n
```

Saf (stdlib), deterministik, I/O yok. Üç fonksiyona keyword-only `probe=None` eklenir;
**yalnızca guarded artış** (davranışı/çıktıyı ASLA değiştirmez):

**`app/schema/graph_traversal.py` — `find_join_paths`:**
- `dfs_visit` — her `dfs()` girişinde
- `adjacency_edge` — `for rel in adjacency.get(current_table, [])` döngüsünde her rel
- `path_recorded` — bir `JoinPathCandidate` `all_paths`'e eklendiğinde

(probe iç closure `dfs`'ten erişilir; `find_join_paths(schema, source, target, *, max_depth=3, max_paths=5, allow_fuzzy=False, probe=None)`)

**`app/schema/implicit_relationships.py` — `detect_implicit_relationships`:**
- `pair_iteration` — O(tablo²) `for src_table … for tgt_table` iç döngüsünde
- `fuzzy_comparison` — her `difflib.SequenceMatcher(...).ratio()` çağrısında (Rule 2)
- `rule3_scan` — Rule 3 exact-eşleşme kolon taramasında

(`detect_implicit_relationships(schema, *, probe=None)`)

**`app/schema/schema_context_selector.py` — `select_schema_context`:**
- `table_scan` — dış `for table in schema.tables` döngüsünde
- `column_scan` — kolon eşleşme iç döngüsünde
- `related_expansion` — ilişki-geniş­letme adımında eklenen tablo başına

(`select_schema_context(schema, question, *, max_tables=8, max_join_paths=5, include_related_tables=True, probe=None)`)

> **Kritik ayrım:** `select_schema_context` probe'u içteki `find_join_paths` çağrısına
> **İLETMEZ** — her hedefin metrikleri bağımsız kalır (28.0 hedef-bağımsızlık deseni).
> Benchmark her hedefi izole profiller: `join_paths` hedefi `find_join_paths`'i doğrudan
> probe'la çağırır; `context_selection` hedefi `select_schema_context`'i probe'la çağırır.

### 3.2 Benchmark v2 — `backend/benchmarks/`

- **`bench_runner.py`:** her hot-hedef çağrısından ÖNCE bir `ProfileProbe` oluşturur, çağrıya
  geçirir, çağrıdan SONRA `probe.counts`'u o hedefin `deterministic` dict'ine **katar**
  (mevcut çıktı-türev metriklerin yanına). Yeni deterministik anahtarlar (`dfs_visit`,
  `fuzzy_comparison`, `table_scan`...) `compare_benchmark`'ın tam-dict kıyasıyla otomatik
  gate'e girer. `probe.counts` sıralı eklenir (JSON-stable).
- **`schema_generator.py`:** (değişiklikler → baseline v2)
  - (a) **Near-miss kolonlar:** bazı tablolara `<near>_id` kolonlar eklenir (explicit FK YOK)
    öyle ki prefix `<near>` **gerçek bir tablo tekili DEĞİL** (yani `singular_to_table`'da yok
    → Rule-1 atlanır, `elif prefix` dalına düşer) AMA bir hedef tablonun tekiline difflib-ratio
    ≥0.85 fuzzy-eşleşir (ör. tablo `customers`/tekil `customer` için kolon `custommer_id`,
    prefix `custommer`, ratio ≈0.94). Böylece **Rule-2 fuzzy** tetiklenir → `fuzzy_comparison`/
    `rule2_fuzzy` anlamlı olur (28.0 "rule2_fuzzy hep 0" minor'ı kapanır). Deterministik, seeded.
  - (b) `generate_schema`'nın döndürdüğü metadata değil ama **`generator_params`** (runner'da)
    `fk_density`/`hub_count` de içerir (28.0 minor).
- **`bench_contract.py`:** `BENCHMARK_SCHEMA_VERSION = "large_schema_benchmark_v2"`.
- **`bench_metrics.py`:** çıktı-türev extractor'lar değişmez; probe-türev sayaçlar runner'da
  merge edilir (extractor imzaları korunur; near-miss üreteç `rule2_fuzzy`'yi doğal doldurur).

### 3.3 NetworkX/pruner 5. hedef — `bench_runner.py` + `bench_metrics.py`

`NetworkXGraphBackend.build_graph(schema_dict)` **legacy dict'te top-level `graph.edges`**
okur (`edge["source"]`/`["target"]`). 28.0 üreteci top-level graph üretmez → mevcut
**`to_legacy_dict(schema)`** REUSE edilir (parse edilmiş `DatabaseSchema`'yı `graph.edges`
içeren legacy dict'e serialize eder). Akış (her ölçekte):
```
schema = from_legacy_schema(gen_dict)          # zaten var (validator hedefi)
graph_dict = to_legacy_dict(schema)            # graph.edges içerir
backend = NetworkXGraphBackend(); backend.build_graph(graph_dict)
backend.personalized_pagerank(seeds)           # koşulur (wall_ms); float çıktı GATE'LENMEZ
[backend.shortest_path(s, t) for (s,t) in pairs]
```
- **Seeds:** üreteçten deterministik birkaç tablo, ağırlık 1.0 (`generate_pagerank_seeds` yeni,
  veya `generate_join_path_pairs`'in kaynaklarından türetilir).
- **Pairs:** `generate_join_path_pairs` REUSE.
- **Deterministik metrikler** (`derive_graph_backend_metrics`, yeni): `graph_nodes`,
  `graph_edges`, `sp_pairs_evaluated`, `sp_pairs_with_path`, `sp_total_path_len` (hepsi
  integer, deterministik). **pagerank yalnız koşulur** (profiling/wall_ms); float sonucu
  gate'lenmez. Hedef adı: `graph_backend`. wall_ms bilgilendirici.
- networkx importu adaptör/dirty tarafta (`bench_runner`), saf modüllerde değil.

### 3.4 CI perf-gate — `.github/workflows/backend-ci.yml`

`pytest` adımından sonra (27.10 `regression_gate_cli` deseninin yanına) yeni adım:
```yaml
- name: Schema benchmark perf gate (deterministic counters)
  run: |
    cd backend
    python -m benchmarks.bench_cli --gate --scales 100,500,1000
```
- Gated committed baseline (`baselines/history.json`, v2) = **yalnız 100/500/1000** ölçekleri
  → CI koşusu bunlarla tam-eşleşir (compare_benchmark değişmeden). wall_ms gate'lenmez →
  CI/makine gürültüsü build'i patlatmaz. Deterministik sayaç drift'i → exit 1 → build kırmızı.
- **2000 ölçeği:** gated baseline'da YOK; insan `python -m benchmarks.bench_cli --scales 2000`
  ile referans/scaling eğrisi için manuel koşar (gate'siz). 28.0'ın "2000 CI'da değil"
  temkini korunur.
- **Push/onay kullanıcıya ait** (global kural): CI adımı eklenir, merge kullanıcı onayıyla.

## 5. Hata yönetimi ve determinizm

- **Probe guarded:** `if probe is not None: probe.incr(...)` — probe=None'da davranış/çıktı
  birebir; mevcut tüm testler `+N/-0` (davranış korunur invariant'ı).
- **pagerank determinizmi:** sabit graph + alpha + personalization → deterministik ama
  **float** → gate'lenmez (yalnız koşulur). shortest_path uzunlukları integer → gate'lenir.
- **Baseline v2 uyumu:** metrik seti + üreteç değişti → schema_version v2; gate en son
  (v2) entry'yi kıyaslar. Eski v1 entry history'de kalır (append-only) ama gate yalnız
  latest'ı okur → uyumsuzluk yok.
- **Boş/yok baseline** → bootstrap yeşil (28.0 semantiği korunur).
- **networkx yoksa** (pin'li, olmamalı): NetworkX hedefi import'ta patlar → runner net
  hata verir (sessiz atlama yok). CI'da networkx pinli (3.2.1) → sorun yok.
- **2000 gated değil:** CI komutu `--scales 100,500,1000`; gated baseline aynı üçlü → tam eşleşme.

## 6. Test stratejisi

- **profiling.ProfileProbe:** incr toplama, boş başlangıç, deterministik.
- **Probe seam'leri (davranış korunur):** her fonksiyon için (a) `probe=None` → çıktı,
  mevcut testlerdeki referansla BİREBİR (regresyon yok); (b) `probe=P` → beklenen sayaçlar
  küçük bilinen şemada (ör. dfs_visit > 0, fuzzy_comparison bilinen near-miss'te > 0,
  table_scan == tablo sayısı). Mevcut `app/schema` test dosyaları `+N/-0`.
- **Üreteç near-miss:** üretilen şema Rule-2 fuzzy eşleşme(ler) üretir (`rule2_fuzzy` > 0);
  determinizm korunur; `DatabaseSchema` geçerli kalır.
- **bench_runner v2:** probe sayaçları `deterministic`'e merge edilir; iki koşu (fake clock)
  aynı deterministik blok; 5 hedef (schema_validation/join_paths/implicit_fk/
  context_selection/graph_backend) × ölçek.
- **graph_backend hedefi:** küçük şemada beklenen `graph_nodes`/`graph_edges`/`sp_*`; pagerank
  koşar ama gate'lenmez; determinizm.
- **compare/CLI:** v2 baseline'a karşı `--gate --scales 100,500,1000` temiz (exit 0);
  sayaç drift → exit 1; malformed → exit 2 (27.10 dersi korunur).
- **purity guard:** `profiling.py` saf; `schema_generator`/`bench_*` saf modüller clock/
  datetime/unseeded-random içermez (28.0 §5.1 subprocess/source-scan deseni). networkx yalnız
  `bench_runner` (dirty).
- **CI adımı:** `backend-ci.yml` YAML geçerli; adım `--scales 100,500,1000` ile gate koşar.
