# Sprint 30.6 — Feedback API (Design Spec)

**Date:** 2026-09-08
**Phase:** 11 (API / Backend Productization) — seventh sprint
**Branch:** `feat/sprint-30.6-feedback-api` (from `main` `035b5ba`)
**Predecessor:** 30.5 Query History API (PR #174).

---

## 1. Purpose & motivation

Phase 11 roadmap: … Query History → **Feedback** → Admin → AuthN. 30.6 lets a user attach feedback (a verdict + optional category/note/corrected SQL) to a **query run** (30.4), on the 30.0 `/api/v1` contract.

A feedback vocabulary and invariant already exist from Sprint 27.3 (User Feedback Capture): `app/feedback/categories.py::FeedbackVerdict` (`correct`/`incorrect`) + `FeedbackCategory` (`wrong_table`/`wrong_column`/`wrong_filter`/`wrong_join`/`wrong_aggregation`/`wrong_order_limit`/`other`), and the `FeedbackSubmitRequest` invariants (a `correct` verdict carries no category/corrected_sql; a `other` category requires a note). 30.6 **reuses the enums and replicates the invariants** for a new query-run-scoped resource; the legacy 27.3 job-scoped feedback (`feedback` table + `/api/...` router) is **untouched**.

**Scope decision (user-approved: continue inert resources):** a new `/api/v1/feedback` resource, feedback **on a query_run** (30.4), inert (no execution). Mirrors the 30.4/30.5 cross-resource pattern (`query_run_id` validated on create → 400).

## 2. Scope decisions

1. **New `/api/v1/feedback` resource** scoped to a `query_run_id` (validated to exist → 400). Not a wrap of 27.3's job feedback (which stays as-is).
2. **Reuse** `FeedbackVerdict`/`FeedbackCategory` from `app.feedback`; **replicate** the 27.3 invariants in the request model (`correct` ⇒ no category/corrected_sql; `other` ⇒ note required).
3. **Append-only** history — no PATCH; DELETE allowed (bool-gated).
4. Filters: `query_run_id`, `verdict`. Unknown filter → empty page (no 400 for filters, consistent with 30.4/30.5).

## 3. Existing landscape (reused)

- `app/feedback/categories.py`: `FeedbackVerdict`, `FeedbackCategory` (StrEnum).
- 27.3 `app/api/schemas.py::FeedbackSubmitRequest` — the invariant reference (job-scoped; not reused directly, replicated for the query-run model).
- 30.4 `query_run_repository.get_query_run` (existence check).
- 30.0 contract + 30.1–30.5 patterns (repository idiom, guard `EXPECTED_V1_ROUTES`, snapshot regen, `rowid` ordering, DELETE bool-gate, `409`/`400` usage, `verify_api_key`).

## 4. Architecture

### 4.1 Persistence — `query_run_feedback` table + repository

**Table** (`database.py::init_db`, additive; + `query_run_id` index):
```
query_run_feedback(
  id            TEXT PRIMARY KEY,   -- uuid4 hex
  query_run_id  TEXT NOT NULL,      -- references query_runs(id)
  verdict       TEXT NOT NULL,      -- FeedbackVerdict value
  category      TEXT,               -- FeedbackCategory value (nullable)
  note          TEXT,               -- nullable
  corrected_sql TEXT,               -- nullable
  created_at    TEXT NOT NULL
)
```

**Repository** — `backend/app/feedback_repository.py`:
- `create_feedback(query_run_id, verdict, category, note, corrected_sql) -> dict` (stores; the router validates invariants + existence beforehand).
- `get_feedback(id)`, `list_feedback(limit, offset, query_run_id=None, verdict=None)` (ORDER BY `rowid` DESC), `delete_feedback(id) -> bool`, `row_to_response_dict(row)`.

(Named `feedback_repository`; the 27.3 job feedback lives in `app/feedback/` package + `database.py` job-feedback functions — no name clash with a new top-level `feedback_repository.py`.)

### 4.2 API — `/api/v1/feedback` router

`backend/app/api/feedback_v1.py` (distinct filename from the legacy `app/api/feedback.py`), `verify_api_key`-protected.

**Models:**
- `FeedbackCreate{ query_run_id: str, verdict: FeedbackVerdict, category: Optional[FeedbackCategory] = None, note: Optional[str] = Field(None, max_length=2000), corrected_sql: Optional[str] = Field(None, max_length=5000) }` with a `model_validator` replicating 27.3: `verdict == correct` ⇒ `category`/`corrected_sql` must be None; `category == other` ⇒ non-empty `note` required.
- `FeedbackResponse{ id, query_run_id, verdict, category: Optional[str], note: Optional[str], corrected_sql: Optional[str], created_at }`.

**Endpoints** (canonical `ApiResponse`):
- `POST /api/v1/feedback` → 201; unknown `query_run_id` → 400; invariant violation → 422 (Pydantic).
- `GET /api/v1/feedback` → 200 list + `PageMeta`; optional `?query_run_id=`, `?verdict=`.
- `GET /api/v1/feedback/{feedback_id}` → 200 (missing → 404).
- `DELETE /api/v1/feedback/{feedback_id}` → 200 (bool-gated; missing → 404).

(No PATCH — feedback is immutable.)

### 4.3 Conformance + snapshots

Guard `EXPECTED_V1_ROUTES` gains the four feedback routes; snapshots regenerated additively (verified vs main). Protected → no security-allowlist change. No new error code (400/404/422 exist).

### 4.4 What does NOT change

The 27.3 `feedback` table, `app/feedback/` package, and legacy `app/api/feedback.py` router are untouched (only the enums are imported). Only additive: new table(+index), repository, router (+1 include line), regenerated snapshots, §32.

## 5. Data flow

```
POST /api/v1/feedback {query_run_id, verdict, category?, note?, corrected_sql?}
  → verify_api_key
  → FeedbackCreate model_validator (correct⇒no category/sql; other⇒note) -> 422 on violation
  → query_run_repository.get_query_run(query_run_id) is None -> 400
  → create_feedback(...)
  → 201 ApiResponse[FeedbackResponse]
```

## 6. Testing strategy

- **Repository unit tests**: create/get; list + query_run_id/verdict filters + paginate; delete; row shape.
- **Endpoint tests**: 201 for correct + incorrect(+category+note); 400 unknown query_run_id; 422 invariant violations (correct+category; other-without-note); list filters + `PageMeta`; 404; envelope + `X-Request-ID`; 403 without key.
- **Conformance**: guard covers the feedback routes.
- `fastapi` pinned `0.115.12`.

## 7. Deliberately out of scope (→ TECH-DEBT §32)

- **Reconciliation with 27.3 job-scoped feedback** (two feedback surfaces: job-scoped legacy + query-run-scoped v1).
- **Feedback → rule-suggestion pipeline** (27.9 owns that; not wired to v1 feedback).
- **Aggregate feedback analytics** (counts by verdict/category — a later `/summary`-style addition).
- **Feedback mutation (PATCH), one-feedback-per-run uniqueness** (multiple feedback rows per run allowed).
- **Query-run-delete cascade** (dangling `query_run_id` possible; consistent with prior sprints).
- **Cursor pagination / cross-page `total`.**
