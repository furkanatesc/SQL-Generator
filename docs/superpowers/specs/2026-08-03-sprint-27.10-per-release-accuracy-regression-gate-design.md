## 1. Amaç ve tek cümlelik tanım

Mevcut **golden eval raporunu** (deterministik `app.eval.run_eval --profile golden`) sürüm başına bir **baseline** olarak kalıcı biçimde kaydeden ve sonraki koşuları önceki sürümün baseline'ıyla kıyaslayıp **regresyonda CLI `exit≠0` ile CI build'ini patlatan** bir kapı. Amaç: yeni adapter/policy/API eklendikçe doğruluğun **sessizce gerilemesini** önlemek (kalite incelemesinde "en kritik sürekli değerlendirme" olarak işaretlendi, PR #124).

Bu, Sprint 21–25'te kurulan eval harness'ını **sürdürür**: yeni bir harness/dataset yazmaz; mevcut, CI'da zaten koşan deterministik golden raporunu tüketir.

**Doğrulanmış "yok" sinyalleri (27.10'un doldurduğu boşluk):**
1. Sürüm başına kalıcı doğruluk **baseline/geçmiş dosyası YOK**.
2. **Delta-vs-önceki-sürüm** karşılaştırması YOK — mevcut gate mutlak (`1.0`), regresyon-göreli değil.
3. Sürüm kimliği: `app_version` bayat (`0.1.0`); gerçek işaret git tag ama runtime'da okunmuyor.

**Regresyon gate'in tüketeceği rapor şekli** (üretici: `app/eval/run_eval.py::suite_result_to_report_dict`, `--output` ile yazılır):

```jsonc
{
  "total": 40,
  "passed": 39,
  "failed": 1,
  "pass_rate": 0.975,
  "results": [                              // id'ye göre SIRALI
    { "id": "golden_count_orders", "passed": true, "expected_type": "success",
      "reason": null, "actual": {...}, "checks": [...], "failed_checks": [] },
    ...
  ],
  "failed_cases": [ { "id": ..., "reason": ..., "failed_checks": [...] } ]
}
```

Per-case kimlik alanı **`results[].id`**, boolean **`results[].passed`**. Regresyon gate yalnız bu iki alanı okur; `checks`/`actual`/`reason` alanlarını görmezden gelir.

## 4. Baseline formatı ve iki komut

### 4.1 `history.json` (append-only liste)

```jsonc
[
  {
    "version": "v1.0.0",
    "timestamp": "2026-08-03T12:00:00Z",   // güncelleme anında CLI'dan verilir/damgalanır
    "total": 40,
    "pass_rate": 0.975,
    "case_ids": ["golden_count_orders", "golden_join_..."],   // TÜM case id'leri, SIRALI
    "passing_case_ids": ["golden_count_orders", ...]           // geçen alt-küme, SIRALI
  }
  // sonraki sürümler append edilir
]
```

Baseline hem **tüm** `case_ids`'i hem **geçen** `passing_case_ids`'i saklar — böylece drift (yeni/çıkarılan case) ile gerçek regresyon (baseline'da geçen case'in düşmesi) doğru ayrılır. Alanlar deterministik: listeler sıralı, duvar saati yalnız güncelleme anında dışarıdan gelir.

### 4.2 Gate komutu (CI'da koşar)

```
python -m evals.regression_gate_cli <report.json> [--baseline <path>] [--max-pass-rate-drop <float>]
```

- `history.json`'daki **son** kaydı (`select_latest_baseline`) referans alır.
- `--baseline` verilmezse varsayılan `evals/baselines/history.json`.
- Regresyon sonucunu JSON olarak (`sort_keys=True`) stdout'a basar.
- **Exit:** `0` geçti / `1` regresyon / `2` bozuk girdi veya kullanım hatası.

### 4.3 Güncelleme komutu (elle, sürüm keserken)

```
python -m evals.regression_gate_cli --update-baseline --version vX.Y.Z <report.json> [--timestamp <iso8601>] [--baseline <path>]
```

- Rapordan yeni bir baseline kaydı üretip `history.json`'a **append** eder.
- `--timestamp` verilmezse CLI `datetime.now(timezone.utc)` ile damgalar (kirli katman; saf `build_baseline_entry` ts'i parametre alır).
- **CI otomatik güncellemez** — bu komut yalnız elle, sürüm keserken çalıştırılır (aksi hâlde kapı anlamsızlaşır).
- Aynı `version` zaten geçmişte varsa → hata, `exit 2` (kazara çift kayıt engeli; `append_baseline` `ValueError` fırlatır).

## 5. Regresyon semantiği (kesin algoritma)

`compare_regression(current_report, baseline, *, policy) -> dict`. `baseline` `None`/boş ise **bootstrap** (bkz. §5.3).

Küme tanımları:
- `current_ids = {r["id"] for r in current_report["results"]}`
- `current_passing = {r["id"] for r in current_report["results"] if r["passed"]}`
- `baseline_ids = set(baseline["case_ids"])`, `baseline_passing = set(baseline["passing_case_ids"])`
- **`common = baseline_ids ∩ current_ids`** — tüm karşılaştırma bu kesişim üzerinden.

### 5.1 Kapı kuralları

1. **Per-case (birincil, sıfır tolerans):**
   `newly_failing = sorted({c ∈ common : c ∈ baseline_passing AND c ∉ current_passing})`.
   Boş değilse → **REGRESYON** (`reason = "Previously-passing cases now failing"`).

2. **Aggregate (ikincil, `common` üzerinden, toleranslı):**
   `baseline_pass_rate_common = |baseline_passing ∩ common| / |common|`,
   `current_pass_rate_common = |current_passing ∩ common| / |common|` (`|common|==0` ise ikisi de `0.0`),
   `drop = baseline_pass_rate_common − current_pass_rate_common`.
   `drop > policy["max_pass_rate_drop"]` (varsayılan `0.0`) ise → **REGRESYON** (`reason = "Aggregate pass rate dropped beyond tolerance"`), ancak per-case zaten tetiklediyse per-case sebebi önceliklidir.

   > **Bilinçli tasarım notu:** Deterministik kaynak + sıfır-tolerans per-case ile aggregate-over-common, per-case'i büyük ölçüde **tekrarlar** (common'da bir baseline-passing case düşmeden `current_pass_rate_common` düşemez). Bu yüzden aggregate öncelikle **raporlanan başlık metriği** + geleceğe-dönük konfigüre edilebilir ikincil korumadır (kaynak nondeterministik hâle gelirse — subsystem C — anlam kazanır). TECH-DEBT §11'e devredilir.

### 5.2 Drift (bilgi — kapıyı ASLA patlatmaz)

- `new_cases = sorted(current_ids − baseline_ids)` — baseline'da olmayan yeni case'ler.
- `removed_cases = sorted(baseline_ids − current_ids)` — current'ta olmayan çıkarılmış case'ler.
- `newly_passing = sorted({c ∈ common : c ∉ baseline_passing AND c ∈ current_passing})` — iyileşme.

Hepsi sonuç JSON'unda açıkça listelenir (sessiz düşürme yok).

### 5.3 Bootstrap (boş baseline)

`baseline is None` (history boş/dosya yok) → `gate_passed=True`, `bootstrap=True`, `reason="No baseline recorded yet (bootstrap)"`, `exit 0` + stderr'e uyarı. İlk baseline `--update-baseline` ile ayrıca commit'lenir (§7).

### 5.4 Sonuç JSON şekli (`compare_regression` çıktısı)

```jsonc
{
  "gate_passed": true,
  "bootstrap": false,
  "reason": null,                          // regresyonda sebep string'i
  "baseline_version": "v1.0.0",
  "newly_failing": [],                     // birincil kapı sinyali
  "newly_passing": ["golden_new_win"],     // bilgi
  "new_cases": ["golden_added_case"],      // bilgi (drift)
  "removed_cases": [],                     // bilgi (drift)
  "aggregate": {
    "baseline_pass_rate_common": 0.975,
    "current_pass_rate_common": 0.975,
    "drop": 0.0,
    "tolerance": 0.0
  },
  "summary": {
    "current_total": 41, "current_pass_rate": 0.9756,
    "common_count": 40, "baseline_total": 40
  }
}
```

`reason` önceliği: per-case > aggregate > (bootstrap sebebi) > `None`.

## 6. Politika ve varsayılanlar

```python
DEFAULT_REGRESSION_POLICY = {"max_pass_rate_drop": 0.0}
```

`--max-pass-rate-drop` CLI bayrağıyla override edilebilir (mevcut `eval_gate.py`'nin policy-dict deseniyle uyumlu felsefe). Per-case sıfır-tolerans sabittir (deterministik kaynakta flakiness yok → gevşetmeye gerek yok).

## 8. Test stratejisi (TDD)

**Saf çekirdek (`test_regression_gate.py`):**
- Per-case newly-failing tespiti (common'da baseline-passing düşer → regresyon).
- Intersection kapsamı: yalnız common karşılaştırılır.
- Drift: `new_cases`/`removed_cases`/`newly_passing` doğru sınıflanır, kapıyı patlatmaz.
- Aggregate delta + tolerans (varsayılan 0.0; override ile küçük düşüş emilir).
- Bootstrap: `baseline=None` → pass.
- Determinizm: aynı girdi → aynı çıktı; sıralı listeler; `datetime.now()` çağrılmaz.
- `build_baseline_entry`: verilen ts + sıralı `case_ids`/`passing_case_ids`.
- `append_baseline`: normal append; çift `version` → `ValueError`.
- `select_latest_baseline`: boş → `None`; son kayıt.

**CLI kontratı (`test_regression_gate_cli.py`):**
- Gate exit kodları: `0` pass, `1` regresyon, `2` bozuk/eksik rapor + kullanım hatası.
- Bootstrap: boş/yok history → exit 0 + uyarı.
- `--update-baseline`: `history.json`'a append; çift version → exit 2.
- `--max-pass-rate-drop` bayrağı okunur.
- Çıktı `sort_keys=True` deterministik JSON.

Tam pytest suite (`backend/`'den) yeşil kalır. Yeni testler `backend/tests/` altında mevcut `test_eval_gate_cli*` komşularıyla tutarlı.

## 10. Planlanan TECH-DEBT §11 (Sprint 27.10 devirleri — AÇIK)

1. **Aggregate-per-case örtüşmesi:** deterministik kaynakta aggregate-over-common, sıfır-tolerans per-case'i tekrarlar; ikincil/raporlanan rol. Nondeterministik kaynağa geçilirse bağımsız değer kazanır.
2. **Gerçek accuracy değil:** kaynak deterministik sahte pipeline → gate kod-kaynaklı regresyonu yakalar, model-kaynaklı doğruluk gerilemesini değil.
3. **Sürüm etiketi elle:** git-tag runtime okunmaz; `--version` operatör tarafından verilir (yanlış/atlanmış etiket riski).
4. **CI baseline güncellemesi manuel:** sürüm keserken `--update-baseline` unutulursa baseline eskir.
5. **Case-düzeyi granülarite:** regresyon case pass/fail bazında; bir case içinde hangi check'in bozulduğu gate'e girmez (raporda mevcut ama karşılaştırılmaz).
