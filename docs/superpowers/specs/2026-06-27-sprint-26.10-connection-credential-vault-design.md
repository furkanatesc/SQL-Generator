# Sprint 26.10 — Connection Credential Vault Governance Contract · Design

Phase 7 (Security & Governance). Follows Sprint 26.9 (Result-Set Privacy &
Limits). Next: 26.11 Policy / Security Eval.

## 1. Purpose

A pure, deterministic, **secret-free**, I/O-free governance contract that decides
whether a given call context is authorized to **resolve** a connection
`secret_ref`, and raises an advisory signal when a raw secret leaks into a
reference-only field.

This contract **never holds, stores, encrypts, or resolves** raw passwords,
connection strings, or tokens. It governs the *reference* and the *decision*
only. Actual secret storage / encryption / resolution is delegated to
infrastructure outside Phase 7.

It is a hybrid in the shape of 26.9:

- **Gate (primary):** `ALLOW` / `DENY` on whether `caller_context` may resolve
  the `secret_ref`, fail-closed across six dimensions.
- **Signal (advisory):** a leak-guard that scans reference-only request fields
  for raw-secret patterns; a suspected leak forces `DENY` (fail-closed) and is
  surfaced as an advisory `CredentialLeakSignal`.

The contract reuses the existing connection types in
`app/evaluation/connection_abstraction.py` (`SQLConnectionProfile`,
`SQLConnectionSecretRef`, `SQLConnectionAuthMode`, `SQLConnectionEnvironment`,
`SQLConnectionAccessMode`) as **inputs** — it does not redefine them.

## 2. Scope

**In scope:**

- New module `app/security/connection_credential_vault.py`.
- A `evaluate(request, policy) -> ConnectionCredentialVaultResult` decision
  function (gate + advisory leak signal).
- Extraction of the raw-secret pattern detection currently inline in
  `SQLConnectionSecretRef.__post_init__` into a shared
  `app/security/_secret_pattern_scan.py` helper (single source of truth), with
  `connection_abstraction.py` refactored to call it.
- Audit interlock: `AuditCategory.CONNECTION_CREDENTIAL` +
  `from_credential_vault(...)` builder in `audit_event.py`.
- Public API exports via `app/security/__init__.py`.

**Out of scope (delegated / future):**

- Actual secret storage, encryption at rest, key management, or secret
  resolution/fetch (infrastructure; would break the secret-free invariant).
- Network/registry I/O, DB persistence, clock/ID generation (all caller-supplied).
- IAM token minting (auth_mode IAM is recognized structurally, not resolved).
- Policy evaluation harness (26.11).

## 3. Module layout

- `app/security/connection_credential_vault.py` — contract types + `evaluate`.
- `app/security/_secret_pattern_scan.py` — shared raw-secret pattern detector
  (extracted from `connection_abstraction.py`).
- `app/evaluation/connection_abstraction.py` — refactored to call the shared
  helper (behavior-preserving).
- `app/security/audit_event.py` — new category + builder.
- `app/security/__init__.py` — exports.

## 4. Shared secret-pattern helper (`_secret_pattern_scan.py`) — refactor

Extracts the detection currently inline in `SQLConnectionSecretRef.__post_init__`:

```python
SECRET_ASSIGNMENT_PATTERNS = ("password=", "token=", "secret=", "key=")

def scan_secret_patterns(value: str) -> tuple[str, ...]:
    """Return the raw-secret pattern markers found in a reference-only string.

    Detects connection-string markers ('://') and assignment patterns
    suggesting raw credential values. Returns the matched marker names
    (never the surrounding value). Empty tuple == clean.
    """
```

- Deterministic, case-insensitive on assignment patterns, no I/O.
- Returns only **marker names** (e.g. `"password="`, `"://"`), never the
  offending substring/value — preserves secret-free guarantee.
- `connection_abstraction.py` keeps raising `SQLConnectionAbstractionContractError`
  on a non-empty result (behavior preserved; regression-tested).

## 5. Enums

```python
CONNECTION_CREDENTIAL_VAULT_CONTRACT_VERSION = "connection_credential_vault_v1"

class CredentialResolutionDecision(str, Enum):
    ALLOW = "allow"
    DENY = "deny"

class CredentialCallerPurpose(str, Enum):
    EXECUTION = "execution"            # may resolve a secret_ref
    NON_EXECUTION = "non_execution"    # NL-gen / introspection — may not

class CredentialVaultReasonCode(str, Enum):
    ALLOWED = "allowed"
    SECRET_LEAK_SUSPECTED = "secret_leak_suspected"
    AUTH_MODE_INCONSISTENT = "auth_mode_inconsistent"
    PROVIDER_NOT_ALLOWED = "provider_not_allowed"
    ENVIRONMENT_MISMATCH = "environment_mismatch"
    TENANT_MISMATCH = "tenant_mismatch"
    PURPOSE_NOT_PERMITTED = "purpose_not_permitted"
```

**Relied-upon profile invariants (not re-checked):** `SQLConnectionProfile`
self-validates at construction — `access_mode` must be `READ_ONLY`, and an
`auth_mode == SECRET_REF` profile must carry a non-None `secret_ref`. A valid
profile therefore cannot violate these, so the contract does **not** emit
`ACCESS_MODE_VIOLATION` or `SECRET_REF_MISSING` reason codes (they would be dead
code). The vault layer governs only authorization dimensions the profile does
not already enforce.

## 6. Records (immutable, frozen, secret-free)

```python
@dataclass(frozen=True)
class CredentialLeakSignal:
    leak_detected: bool
    fields_flagged: Tuple[str, ...]   # field NAMES only — never values

@dataclass(frozen=True)
class ConnectionCredentialVaultPolicy:
    owner_tenant: str
    allowed_providers: Tuple[str, ...]
    allowed_environments: Tuple[SQLConnectionEnvironment, ...]

@dataclass(frozen=True)
class ConnectionCredentialVaultRequest:
    profile: SQLConnectionProfile          # from connection_abstraction
    request_environment: SQLConnectionEnvironment
    request_tenant: str
    caller_purpose: CredentialCallerPurpose

@dataclass(frozen=True)
class ConnectionCredentialVaultResult:
    decision: CredentialResolutionDecision
    reason_code: CredentialVaultReasonCode
    leak_signal: CredentialLeakSignal
    resolved_secret_ref: Optional[SQLConnectionSecretRef]  # reference only, on ALLOW
    contract_version: str
```

- All frozen; `__post_init__` validates types and raises
  `ConnectionCredentialVaultContractError` on structural violations.
- `resolved_secret_ref` carries the **reference** (provider + key) only on
  ALLOW; the resolved secret value never enters this layer.

## 7. Evaluate algorithm (deterministic precedence)

`evaluate` returns exactly one `reason_code`. With multiple violations the
**most fundamental / most critical wins**, in this fixed order (testable,
fail-closed):

1. **Leak scan** of reference-only request fields (`profile.secret_ref.provider`,
   `.key`, `profile.connection_ref`, `profile.endpoint.host`,
   `.database`) via `scan_secret_patterns`. Any hit →
   `DENY` / `SECRET_LEAK_SUSPECTED`, `leak_signal.leak_detected=True` with the
   flagged field names.
2. **Auth-mode consistency:** `auth_mode == NONE | IAM` → no vault secret to
   resolve; a resolution request is inconsistent → `DENY` /
   `AUTH_MODE_INCONSISTENT`. (For `SECRET_REF` the profile guarantees a present
   `secret_ref`, so resolution proceeds.)
3. **Provider allowlist:** `secret_ref.provider not in policy.allowed_providers`
   → `DENY` / `PROVIDER_NOT_ALLOWED`.
4. **Environment:** `request_environment` must be in
   `policy.allowed_environments` **and** equal `profile.environment`; otherwise
   `DENY` / `ENVIRONMENT_MISMATCH`. (Blocks e.g. resolving a prod profile from a
   dev context.)
5. **Tenant:** `request_tenant != policy.owner_tenant` →
   `DENY` / `TENANT_MISMATCH`.
6. **Caller purpose:** `caller_purpose == NON_EXECUTION` →
   `DENY` / `PURPOSE_NOT_PERMITTED` (least-privilege: only execution context
   resolves secrets).
7. None triggered → `ALLOW` / `ALLOWED`, `resolved_secret_ref = profile.secret_ref`.

**Output self-check:** before returning, assert the result is secret-free (no
`resolved_secret_ref` on DENY; `leak_signal` field names only). This is the
second half of the hybrid — the contract guarantees its own secret-free result.

## 8. Audit interlock (mirrors 26.6–26.9)

In `audit_event.py`:

```python
class AuditCategory(str, Enum):
    ...
    CONNECTION_CREDENTIAL = "connection_credential"   # 26.10

def from_credential_vault(result: ConnectionCredentialVaultResult, *,
    event_id: str, occurred_at: str, actor: AuditActor,
    resource: AuditResource, prev: Optional[AuditEvent] = None) -> AuditEvent:
    ...
```

- Outcome mapping (single-valued `AuditOutcome`): `ALLOW` → `ALLOWED`;
  `DENY` → `DENIED`. A leak is always a DENY (precedence #1), so its event is
  `DENIED` with `severity = HIGH`; non-leak denials carry `MEDIUM`. (`FLAGGED`
  is reserved for non-gate advisory signals and is not emitted here, since the
  leak signal always drives the gate to DENY.)
- Secret-free: the AuditEvent records `decision`, `reason_code`, and flagged
  field **names** only — never provider/key values or any secret. Time and IDs
  are caller-supplied; integrates with the existing SHA-256 hash-chain.

## 9. Error handling

- All type/shape violations raise `ConnectionCredentialVaultContractError`.
- `evaluate` never leaks exceptions for policy outcomes: a structural problem in
  inputs raises; a policy violation is a `DENY` result (not an exception).
- Fail-closed throughout: any ambiguity defaults to `DENY`.

## 10. Public API

`app/security/__init__.py` exports (26.9 pattern): the version constant, error
class, all enums, all four records, `ConnectionCredentialVaultContract` /
`evaluate`. The shared `_secret_pattern_scan` helper stays private (leading
underscore), consistent with `_pii_value_scan`.

## 11. Test matrix

`tests/security/test_connection_credential_vault.py`:

- One **ALLOW** happy path (all dimensions satisfied, EXECUTION purpose).
- One **DENY** per reason code (6 DENY reason codes).
- **Precedence:** a request violating multiple dimensions returns the
  highest-precedence reason (e.g. leak + tenant mismatch → `SECRET_LEAK_SUSPECTED`).
- **Leak-guard:** raw secret / connection-string injected into each
  reference-only field is flagged; field names (not values) reported.
- **Secret-free invariant:** result and audit event contain no secret values;
  `resolved_secret_ref` is None on every DENY.
- Auth-mode coverage: SECRET_REF (with/without ref), NONE, IAM.

`tests/security/test_credential_vault_audit.py`:

- `from_credential_vault` for ALLOW / DENY / leak; outcome + severity mapping;
  secret-free event; hash-chain links with `prev`.

`tests/security/test_secret_pattern_scan.py`:

- Shared helper detects each assignment pattern + `://`; clean input → empty;
  returns marker names only.

Regression: existing `connection_abstraction.py` tests must stay green after the
refactor (behavior-preserving extraction).

## 12. Acceptance criteria

- `evaluate` is pure, deterministic, secret-free, I/O-free; fail-closed.
- Exactly one `reason_code` per result, following the fixed precedence.
- Leak-guard forces DENY and surfaces field names only.
- Audit interlock added; events secret-free and hash-chain-compatible.
- Shared helper extracted; `connection_abstraction.py` behavior preserved.
- Full security suite green; public API exported.
