# Sprint 31.7 — Feedback UX (Design Spec)

> Frontend sprint (Vue 3). No pytest/CI — verify via `npm run build`.
> Phase 12 sekizinci (sondan bir önceki) frontend sprint'i. Kullanıcı: soru sorma, kapsam kararını kendin ver.

## 1. Problem / Brainstorm (karar)
Backend'de feedback yakalama VAR (Sprint 27.3 legacy job-scoped `POST /api/jobs/{job_id}/feedback` +
30.6 query-run-scoped `/api/v1/feedback`) ama **frontend'de hiç feedback UI'ı yok** (`api.ts`'te feedback
metodu bile yok). Kullanıcı üretilen SQL'in doğru/yanlış olduğunu bildiremiyor → 27.9 feedback→kural
önerisi döngüsü beslenmez.

**Karar (kapsam):** 31.7 = ChatView'de tamamlanmış SQL yanıtına **👍 Doğru / 👎 Hatalı** geri bildirim +
👎'de opsiyonel **kategori + not** mini-formu; **legacy 27.3 job-scoped endpoint'e** POST (mesajda zaten
`jobId` var — satır 162; 30.6 query-run-scoped'a bağlamak connection/query-run kurulumu gerektirir, kapsam
dışı). `api.ts`'e feedback tipleri + `submitFeedback` metodu eklenir. Backend invariant'larına client-side
uyulur: verdict=correct → category/corrected_sql yok; category=other → note zorunlu.

## 2. Design
- **`api.ts`:** `FeedbackVerdict = 'correct' | 'incorrect'`; `FeedbackCategory` (7 değer: wrong_table/
  wrong_column/wrong_filter/wrong_join/wrong_aggregation/wrong_order_limit/other — backend enum aynası);
  `FeedbackPayload { verdict; category?; note?; corrected_sql? }`; `submitFeedback(jobId, payload):
  Promise<{status; feedback}>` → `POST /api/jobs/{jobId}/feedback` (mevcut fetch/`getHeaders` deseni).
- **`ChatView.vue`:** feedback yalnız `msg.status==='completed' && msg.sql && msg.jobId` iken görünür.
  Per-message UI durumu `feedbackUi = ref<Record<number, { open?: boolean; sending?: boolean;
  submitted?: boolean; error?: string; category?: FeedbackCategory; note?: string }>>({})`.
  - 👍 Doğru → anında `submitFeedback(jobId, {verdict:'correct'})` (invariant: category/note yok) → submitted.
  - 👎 Hatalı → mini-form aç (kategori `<select>` opsiyonel + not `<textarea>`); "Gönder" →
    `{verdict:'incorrect', category?, note?}`. Client-side invariant: category==='other' && !note.trim()
    → inline uyarı, gönderme. corrected_sql bu sürümde YOK (not yeterli, dar tut).
  - sending → butonlar disabled + spinner; başarı → "Geri bildiriminiz için teşekkürler" (aria-live);
    hata → inline hata + tekrar dene.
- Türkçe kategori etiketleri (wrong_table→"Yanlış tablo" vb.). Salt eklenti; mevcut copy/açıklama/sonuç/
  hata akışı DEĞİŞMEZ.

## 3. Verify (frontend — pytest/CI yok)
`cd frontend && npm run build` → **0 hata, exit 0**. Akış görsel akıl-yürütme: 👍→anında gönderim+teşekkür;
👎→form; other+boş not→uyarı; başarı→teşekkür; hata→tekrar.
