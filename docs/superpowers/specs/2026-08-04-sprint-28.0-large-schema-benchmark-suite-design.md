## 1. Amaç ve bağlam

Phase 9, ~2000 tabloya yaklaşan enterprise şemalarda schema selection, join path
control, missing-FK inference ve graph performance problemlerini production-grade
çözmeyi hedefler. Bunları **çözmeden önce ölçmek** gerekir. 28.0, fazın geri kalanının
(28.1 profiling, 28.2 join-path explosion control, 28.3 table-selection cost model,
28.5 missing-FK v2 …) üzerine ölçüm yapacağı **tekrarlanabilir benchmark temelini**
kurar.

**Kilit gerçek (keşifle doğrulandı):** Kod tabanında **mevcut benchmark/perf harness
YOK** ve **büyük şema fixture'ı YOK** (en büyük fixture ~10 tablo / 116 satır).
Ölçülecek dört saf alt-sistem mevcut ve temiz ayrık. Dolayısıyla 28.0 iki şey üretir:
(1) **sentetik büyük-şema üreteci**, (2) bu üreteci dört sıcak hedefe koşturup metrik
raporlayan **benchmark harness'ı + baseline**.

### Determinizm gerilimi (tasarımın çekirdek kararı)

Bu proje determinizme dayanır (saf paketlerde `datetime.now()` yasak, zaman dışarıdan
enjekte). Ama **duvar-saati (wall-clock) süresi non-deterministiktir ve CI'da
gürültülüdür** → ondan tam-eşleşen golden baseline üretilemez. Buna karşılık DFS'in
ürettiği path sayısı, seçilen tablo sayısı, kurulan kenar sayısı gibi **karmaşıklık
metrikleri seed-deterministiktir** ve tam gate'lenebilir.

**Karar (onaylı):** İki metrik sınıfı **ayrık** ele alınır:
- **Deterministik metrikler** (girdi/çıktı-türevi) → `history.json`'a TAM-eşleşme
  gate'i (27.10 `compare_regression` deseni). Bir kod değişikliği ölçekte üretilen işi
  değiştirirse (ör. seçici 3× fazla tablo seçmeye başlarsa) bu drift yakalanır.
- **wall_ms** → her hedef×ölçek için ölçülür, rapora yazılır, **gate'lenmez**
  (bilgilendirici; scaling eğrisini insan/28.1 profiler inceler).

## 3. Mimari

Saf-yaprak + kirli adaptör düzeni (projenin yerleşik konvansiyonu), `backend/evals/`'in
kardeşi bir dev/CI aracı olarak:

```
backend/benchmarks/
  __init__.py
  schema_generator.py     # SAF, seeded: parametreli sentetik DatabaseSchema + benchmark girdileri
  bench_contract.py       # SAF: frozen metrik/rapor record'ları + SIRALI to_dict
  bench_metrics.py        # SAF: 4 hedef için girdi/çıktı-türev deterministik metrik çıkarıcılar
  bench_compare.py        # SAF: compare_benchmark(baseline, current) -> drift kararı (27.10 deseni)
  bench_runner.py         # KİRLİ: 4 hedef × 4 ölçek koşturur, perf_counter (clock enjekte), rapor kurar
  bench_cli.py            # KİRLİ CLI: rapor bas + --update-baseline + --gate (exit 0/1/2)
  baselines/
    history.json          # committed, append-only, seeded baseline (deterministik metrik + wall_ms bilgi)
```

**Saflık sınırı:** `schema_generator.py`, `bench_contract.py`, `bench_metrics.py`,
`bench_compare.py` yalnız **stdlib + `app.schema.*`** import eder; `datetime.now()` /
`perf_counter` / global `random` YOK (seed'li `random.Random(seed)` kullanılır). Zaman
ve wall_ms ölçümü yalnızca kirli `bench_runner.py`/`bench_cli.py`'de. Taze-alt-süreç
purity guard'ı test edilir (27.11 §5.1 deseni).

> **Not — üreteç bağımlılığı:** Saf üreteç `app.schema.*` import eder. Bu, evals/'ın
> `app`'e bağımlılığıyla tutarlıdır (benchmarks/ bir üst-seviye dev aracıdır, `app`'i
> tüketir). Purity guard "no `datetime.now`/`perf_counter`/global-random/impure-I-O"
> anlamındadır; `app.schema` contract'ını import etmek serbesttir.

### 3.1 `schema_generator.py` (saf, seeded)

```python
def generate_schema(
    *,
    table_count: int,
    seed: int,
    cols_per_table: int = 8,
    fk_density: float = 0.6,     # explicit FK'ya sahip tablo oranı
    hub_count: int = 3,          # yüksek fan-out hub tablo sayısı
    hub_fanout: int = 40,        # hub başına gelen kenar sayısı (yaklaşık)
    dialect: str = "postgres",
) -> DatabaseSchema: ...

def generate_join_path_pairs(schema: DatabaseSchema, *, seed: int,
                             count: int = 20) -> list[tuple[str, str]]: ...

def generate_selection_questions(schema: DatabaseSchema, *, seed: int,
                                 count: int = 20) -> list[str]: ...
```

- `random.Random(seed)` ile **tamamen deterministik**. Aynı (params, seed) → birebir
  aynı `DatabaseSchema`.
- Üretilen şema **gerçekçi iş yükü** sağlamalı:
  - Bir kısım **explicit** FK (`RelationshipType.EXPLICIT`) → validator + join-path'e iş.
  - Bir kısım kolon **isim-örüntülü** (`<singular>_id`) ama explicit FK'sız →
    `detect_implicit_relationships`'in Rule-1/Rule-2/Rule-3 yollarına iş.
  - Birkaç **hub** tablo (yüksek fan-out) → join-path branching + hub davranışı.
  - Tablo/kolon isimleri deterministik ve `select_schema_context` token eşleşmesine
    elverişli (`orders`, `customers`, `order_items` gibi çoğul/tekil örüntüler).
- `generate_join_path_pairs`: benchmark için (source, target) çiftleri — bir kısmı
  bağlı (path var), bir kısmı uzak → DFS'e gerçek iş.
- `generate_selection_questions`: şema tablo/kolon isimlerinden türetilen deterministik
  doğal-dil soruları (ör. "list all orders for each customer").

### 3.2 `bench_contract.py` (saf)

Frozen `@dataclass` record'lar + SIRALI `to_dict` (JSON-stable, deterministik anahtar
sırası; 27.x contract deseni):

```python
@dataclass(frozen=True)
class BenchmarkMetric:
    target: str            # "join_paths" | "implicit_fk" | "context_selection" | "schema_validation"
    scale: int             # 100 | 500 | 1000 | 2000
    deterministic: dict    # {metric_name: int}  — gate'lenen
    wall_ms: float         # bilgilendirici, gate'siz
    def to_dict(self) -> dict: ...   # sıralı

@dataclass(frozen=True)
class BenchmarkReport:
    schema_version: str    # "large_schema_benchmark_v1"
    generator_params: dict # seed + scale + fk_density + hub_* (tekrarlanabilirlik için)
    metrics: tuple[BenchmarkMetric, ...]
    def to_dict(self) -> dict: ...
```

### 3.3 `bench_metrics.py` (saf) — deterministik metrik çıkarıcılar

Her çıkarıcı **girdi (schema) + çıktı (operation result)** alır, üretim koduna
DOKUNMADAN deterministik metrik döndürür:

| Hedef | Deterministik metrikler (girdi/çıktı-türevi) |
|---|---|
| `schema_validation` | `tables`, `columns_total`, `relationships_validated`, `valid` (bool→int) |
| `join_paths` | `pairs_evaluated`, `paths_found_total`, `path_edges_total`, `pairs_with_path`, `adjacency_edges` (=`len(relationships)`) |
| `implicit_fk` | `implicit_rels_found`, `by_rule` kırılımı (`rule1_singular_id`, `rule2_fuzzy`, `rule3_exact` — `RelationshipSchema.raw['rule']`'dan) |
| `context_selection` | `questions_evaluated`, `focus_tables_total`, `selected_tables_total`, `join_paths_total`, `fallback_used_count` |

Hepsi seed-deterministik → aynı seed'de baseline'a tam-eşleşme.

**Semantik:** deterministik metrikler için **sıfır tolerans, tam-eşleşme** (bu metrikler

baseline → bootstrap yeşil. wall_ms asla kıyaslanmaz.

### 3.5 `bench_runner.py` (kirli)

```python
def run_benchmark(*, scales=(100, 500, 1000, 2000), seed=1729,
                  clock: Callable[[], float] = time.perf_counter) -> BenchmarkReport: ...
```

- 4 üretim fonksiyonunu **REUSE** eder (reimplementasyon yok):
  `find_join_paths`, `detect_implicit_relationships`, `select_schema_context`,
  `DatabaseSchema` model doğrulaması (`from_legacy_schema` round-trip ya da doğrudan
  `DatabaseSchema(...)` validasyonu).
- Her ölçek için üreteci bir kez çağırır, dört hedefi koşturur.
- `clock` enjekte → test edilebilir (wall_ms'i deterministik yapmak için fake clock).
- `bench_metrics` çıkarıcılarını çağırır, `BenchmarkReport` kurar.

### 3.6 `bench_cli.py` (kirli)

```
python -m benchmarks.bench_cli                    # raporu stdout'a (JSON) bas
python -m benchmarks.bench_cli --scales 100,500   # alt-küme koştur
python -m benchmarks.bench_cli --gate             # baseline'a karşı deterministik gate; exit 0/1/2
python -m benchmarks.bench_cli --update-baseline  # yeni entry'yi history.json'a append
```

- `--gate`: `compare_benchmark` çağırır; mismatch → exit 1; bad-input/malformed baseline
  → exit 2; temiz → exit 0 (27.10 `regression_gate_cli` exit-kodu deseni).
- `--update-baseline`: raporu (deterministik + wall_ms) `baselines/history.json`'a
  **append-only** ekler. Elle çağrılır (CI otomatiği yok).
- Timestamp/`schema_version` operatörden/sabitten gelir; `datetime.now()` yalnız kirli
  CLI'de ve yalnız kayıt damgası için (gate'lenen veride değil).

### 3.7 `baselines/history.json` (committed, seeded)

`evals/baselines/history.json` deseni: append-only entry listesi. İlk entry sprint
içinde **seed'li koşuyla** üretilir (deterministik). Her entry: `{schema_version,
generator_params (seed dahil), metrics:[{target, scale, deterministic, wall_ms}]}`.
Gate yalnız `deterministic`'i okur; `wall_ms` insan referansı için saklanır.

## 4. Veri akışı

```
generate_schema(table_count, seed) ──► DatabaseSchema (in-memory, deterministik)
        │
        ├─► [validator]           DatabaseSchema doğrulaması ─► derive_validation_metrics
        ├─► [join_paths]          find_join_paths(pairs)      ─► derive_join_path_metrics
        ├─► [implicit_fk]         detect_implicit_relationships ─► derive_implicit_fk_metrics
        └─► [context_selection]   select_schema_context(qs)   ─► derive_selection_metrics
                                        │
        (kirli runner her adımı perf_counter ile sarar → wall_ms)
                                        ▼
                              BenchmarkReport (deterministic + wall_ms)
                                        │
                    ┌───────────────────┴───────────────────┐
                    ▼                                        ▼
         --gate: compare_benchmark(report,             --update-baseline:
                 latest_baseline) → exit 0/1/2          append → history.json
```

## 5. Hata yönetimi ve sınır durumları

- **Boş/yok baseline** → `compare_benchmark` bootstrap yeşil (exit 0). İlk koşu böyle.
- **Malformed baseline / eksik alan** → CLI exit 2 (bad-input), "regresyon" (exit 1)
  ile karıştırılmaz (27.10 `_load_report` dersinin doğrudan uygulaması).
- **wall_ms hiçbir zaman** gate/compare'e girmez → CI/makine gürültüsü gate'i patlatamaz.
- **Determinizm invariant'ı**: aynı (seed, params) iki koşu birebir aynı `deterministic`
  bloğunu üretmeli. Test bunu iki ardışık koşuyla doğrular.
- **2000 ölçek maliyeti**: naive DFS/fuzzy'nin yavaş olması **beklenen** (28.1+ optimize
  edecek). 28.0 bunu CI'da zorlamaz; suite testleri küçük ölçeklerde (ör. 20–50 tablo)
  koşar, tam 4-kademe koşu CLI ile manuel.

## 6. Test stratejisi

- **schema_generator**: determinizm (aynı seed → aynı şema), parametre etkisi
  (table_count/fk_density/hub_fanout beklenen sayıları üretir), üretilen şemanın
  `DatabaseSchema` olarak **geçerli** olduğu, isim-örüntülü kolonların
  `detect_implicit_relationships` tarafından yakalandığı.
- **bench_metrics**: her çıkarıcının bilinen küçük şemada beklenen deterministik
  metrikleri döndürdüğü.
- **bench_compare**: bootstrap (baseline yok → yeşil), tam-eşleşme (yeşil), mismatch
  (kırmızı + doğru mismatch listesi), eksik/fazla case, malformed baseline.
- **bench_runner**: fake clock enjekte edilince deterministik `deterministic` blok; 4
  hedefin de rapora girdiği; küçük ölçekte hızlı.
- **bench_cli**: exit kodları (0 temiz / 1 mismatch / 2 bad-input), `--update-baseline`
  append davranışı (mevcut entry'leri korur), `--scales` alt-küme.
- **purity guard**: `benchmarks.schema_generator`/`bench_contract`/`bench_metrics`/
  `bench_compare` taze alt-süreçte import edildiğinde `datetime`/`time.perf_counter`/
  global `random` çekmez (27.11 §5.1 subprocess deseni).
