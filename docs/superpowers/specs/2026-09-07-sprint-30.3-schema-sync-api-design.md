# Sprint 30.3 — Schema Sync API (Design Spec)

**Date:** 2026-09-07
**Phase:** 11 (API / Backend Productization) — fourth sprint
**Branch:** `feat/sprint-30.3-schema-sync-api` (from `main` `0955e88`)
**Predecessor:** 30.2 Connection Registry API (PR #171). 30.3 adds the third `/api/v1` resource and links to a **connection**.

---

## 1. Purpose & motivation

Phase 11 roadmap: Workspace → Connection Registry → **Schema Sync** → Query Run → … Schema Sync records, per connection, the structure of the database schema over time and detects **structural drift** between successive syncs.

**Scope choice (user-approved): per-connection sync, a NEW `/api/v1` surface.** Because a 30.2 connection is inert (the registry opens no live DB connection), 30.3 is likewise inert: a "sync" does **not** live-introspect the database. Instead the schema structure is **provided in the sync request** (the payload a future live introspector — the 29.x resolvers / pipeline wiring — will supply); 30.3 normalizes it, computes a signature, diffs it against the connection's previous snapshot, and stores an append-only sync record. Live introspection is deferred. The legacy 28.7 `/api/debug/schema/*` drift surface (single global schema) is **untouched**.

**Reuse, don't rebuild:** the Phase 9 drift engine (`app/schema/schema_signature.py`: `normalize_structure`, `compute_schema_signature`, `diff_structures` → `StructuralDrift.as_dict()`) is reused verbatim.

## 2. Scope decisions (user-approved / author-decided; documented for veto)

1. **NEW `/api/v1/schema-syncs` resource** on the 30.0 contract (not a wrap of legacy 28.7). *(User-approved: "per-connection sync".)*
2. **Inert:** schema structure is supplied in the request; 30.3 does not connect to a live DB or resolve secrets. Live introspection deferred.
3. **Per-connection, append-only history:** each sync references a `connection_id` (validated to exist → 400) and stores a snapshot + drift-vs-previous. No PATCH (records are immutable history); DELETE allowed for cleanup.
4. **Reuse the Phase 9 drift engine** (`schema_signature.py`) unchanged.
5. **Flat resource + `connection_id` field/filter** (mirrors 30.2's `workspace_id` pattern), not nested routing.

## 3. Existing landscape (reused, not rebuilt)

- `app/schema/schema_signature.py`: `normalize_structure(schema)` (expects `{"tables": {name: {"columns": [{name,type,primary_key,nullable}], "foreign_keys": [{column,referenced_table,referenced_column}]}}}`), `compute_schema_signature(normalized) -> sha256 hex`, `diff_structures(old_norm, new_norm) -> StructuralDrift` (`.has_drift`, `.as_dict()` → added/removed/changed tables/columns/fks).
- 28.7 `app/api/schema_sync_api.py` (legacy `/api/debug/schema/drift|sync`, single global schema) — **left untouched**.
- 30.2 `app/connection_repository.py::get_connection` (connection existence check).
- 30.0 contract (`app/api/contract.py`) + 30.1/30.2 patterns (repository idiom, guard `EXPECTED_V1_ROUTES`, snapshot regen, `409`/`400` usage, DELETE bool-gate).

## 4. Architecture

### 4.1 Persistence — `schema_syncs` table + repository

**Table** (`database.py::init_db`, additive; + `connection_id` index):
```
schema_syncs(
  id                 TEXT PRIMARY KEY,          -- uuid4 hex
  connection_id      TEXT NOT NULL,             -- references connections(id)
  signature          TEXT NOT NULL,             -- schema signature of this snapshot
  previous_signature TEXT,                      -- prior snapshot's signature (nullable)
  drifted            INTEGER NOT NULL,          -- 0/1 vs previous (1 when no previous)
  structure_json     TEXT NOT NULL,             -- normalized structure (JSON)
  drift_json         TEXT NOT NULL,             -- StructuralDrift.as_dict() (JSON)
  created_at         TEXT NOT NULL
)
```

**Repository** — `backend/app/schema_sync_repository.py`:
- `create_schema_sync(connection_id, schema) -> dict` — `normalize_structure(schema)`; `compute_schema_signature`; fetch `get_latest_for_connection`; if a previous exists, `diff_structures(prev_norm, new_norm)` and `drifted = prev_sig != new_sig` (or `drift.has_drift`); if none, `drifted = True`, empty drift; store row; return dict. (`schema` is validated to be a dict with a `tables` mapping — else `ValueError` → 422.)
- `get_schema_sync(id)`, `list_schema_syncs(limit, offset, connection_id=None)` (ORDER BY created_at DESC, id), `get_latest_for_connection(connection_id) -> dict | None`, `delete_schema_sync(id) -> bool`.
- `row_to_response_dict(row)` — parse `structure_json`/`drift_json` back to objects; shape `{id, connection_id, signature, previous_signature, drifted (bool), drift, structure, created_at}`.

### 4.2 API — `/api/v1/schema-syncs` router

`backend/app/api/schema_syncs.py`, `verify_api_key`-protected.

**Models:**
- `SchemaSyncCreate{ connection_id: str, schema: dict }` (schema is a free-form structure object; `{"tables": {...}}`).
- `SchemaSyncResponse{ id, connection_id, signature, previous_signature: str|None, drifted: bool, drift: dict, structure: dict, created_at }`.

**Endpoints** (canonical `ApiResponse`):
- `POST /api/v1/schema-syncs` → 201; unknown `connection_id` → 400; malformed `schema` (no `tables` mapping) → 422.
- `GET /api/v1/schema-syncs` → 200 list + `PageMeta`; optional `?connection_id=` filter.
- `GET /api/v1/schema-syncs/{sync_id}` → 200 (missing → 404).
- `DELETE /api/v1/schema-syncs/{sync_id}` → 200 (returns the record; bool-gated; missing → 404).

(No PATCH — sync records are immutable history.)

### 4.3 Conformance + snapshots

Guard `EXPECTED_V1_ROUTES` gains the four schema-sync routes; snapshots regenerated additively (verified no removed/modified existing schema/path). Protected → no security-allowlist change.

### 4.4 What does NOT change

`schema_signature.py` and the legacy 28.7 `schema_sync_api.py` are imported/left as-is. Only additive: new table (+index), repository, router (+1 include line), regenerated snapshots, TECH-DEBT §29. No new error code needed (400/404/422 already exist).

## 5. Data flow

```
POST /api/v1/schema-syncs {connection_id, schema:{tables:{...}}}
  → verify_api_key
  → connection_repository.get_connection(connection_id) is None -> 400
  → schema has no "tables" mapping -> 422
  → normalize_structure -> compute_schema_signature
  → get_latest_for_connection -> diff_structures(prev, new) (or first-sync: drifted=True)
  → store append-only row
  → 201 ApiResponse[SchemaSyncResponse]  (signature, previous_signature, drifted, drift, structure)
```

## 6. Testing strategy

- **Repository unit tests**: first sync (drifted True, no previous); second identical sync (drifted False, empty drift); second changed sync (drift lists added/removed tables/columns); list + connection filter + paginate; get/delete; malformed schema → ValueError.
- **Endpoint tests**: CRUD-ish round-trip; canonical envelope + `X-Request-ID`; 201/400(unknown connection)/422(bad schema)/404; drift reported across two syncs; `?connection_id` filter + `PageMeta`; 403 without key.
- **Conformance**: guard covers the schema-sync routes.
- `fastapi` pinned `0.115.12`.

## 7. Deliberately out of scope (→ TECH-DEBT §29)

- **Live schema introspection** — the schema is provided in the request; connecting to a live DB / resolving a `secret_ref` to introspect is deferred (30.4 / resolver wiring).
- **Triggering sync from the connection registry / scheduling / auto-sync.**
- **Workspace-scoping of syncs, retention/pruning of history, sync record mutation (PATCH).**
- **Cascade on connection delete** — deleting a connection leaves its sync records with a dangling `connection_id` (documented; consistent with 30.2's workspace-cascade deferral).
- **Reconciling with the legacy 28.7 global-schema drift surface** (two surfaces coexist).
- **Cursor pagination / cross-page `total`.**
