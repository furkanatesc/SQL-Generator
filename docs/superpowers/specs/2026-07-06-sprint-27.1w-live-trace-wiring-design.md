## §0. Amaç ve tek cümlelik özet

Saf `EndToEndTrace` sözleşmesini canlı pipeline'a örmek: `request_id` HTTP
katmanından `run_pipeline`'a taşınır, her stage `perf_counter` ile ölçülür,
`_capture_trace_on_exit` legacy `NL2SQLTrace`'in YANINA bir `EndToEndTrace`
kaydı emit eder ve `run_pipeline` orta dozda modülerleştirilir (stage
metodları). Ayrıca 27.1'den devreden 3 Minor builder düzeltmesi kapatılır.

Sprint sonunda `TraceQuery(request_id=...)` ile canlı bir isteğin 7 span'lik
uçtan uca trace'i sorgulanabilir olur.

## §1. Kapsam kararları (kullanıcı onaylı, 2026-07-06)

1. **Refactor dozu = ORTA.** `run_pipeline` (~440 satır, `sql_pipeline.py:129-569`)
   stage **metodlarına** bölünür: `_stage_intent`, `_stage_retrieval`,
   `_stage_writer_critic` (prompt+generation+validation döngüsü TEK metod
   olarak kalır — writer-critic iç yapısına dokunulmaz). Her stage metodu
   `(sonuç, süre_ms)` döner; `run_pipeline` ~80 satırlık orkestratöre iner.
   Davranış birebir korunur — bu bir davranış değişikliği DEĞİL, taşımadır.
   Stage-nesne mimarisi (Protocol/class-per-stage) bilinçli olarak YAPILMAZ.

2. **request_id = HTTP'den taşı + fallback mint.** Job'u yaratan HTTP isteğinin
   `request.state.request_id`'si (middleware `request_logging.py:33-36` zaten
   üretiyor) `BackgroundTasks.add_task(process_job_pipeline, job_id,
   request_id=rid)` ile taşınır; `run_pipeline(..., request_id: str | None)`
   parametresi eklenir. HTTP dışı çağrılarda (local_test, eval, testler)
   `request_id` verilmezse `f"req_{uuid4().hex}"` mint edilir. `job_id` ayrı
   alan olarak kalır (`EndToEndTrace.job_id`); ikisi asla birbirine eşitlenmez.

3. **Emisyon = DUAL-EMIT.** `_capture_trace_on_exit` mevcut legacy
   `NL2SQLTrace` kaydını aynen üretmeye devam eder (debug API bozulmaz) ve EK
   olarak `build_end_to_end_trace(...)` → `TraceRecord(trace_type="end_to_end",
   request_id=..., job_id=..., payload=e2e.to_payload())` kaydeder. İki kayıt
   da `_save_trace_safely` üzerinden gider (exception yutma davranışı korunur —
   trace kaydı pipeline'ı ASLA düşüremez). Legacy'nin emekliliği 27.2+ kararı.

4. **Span kapsamı = 7 SABİT SPAN.** Her trace'te 7 stage'in span'i bulunur;
   koşmayan stage SKIPPED (builders'ın mevcut None→SKIPPED sözleşmesi).
   - EXECUTION: Faz-1'de canlı çalıştırma yok → **her zaman SKIPPED**.
     `build_execution_span(None)` KULLANILMAZ (builder status doğrulamasında
     `EndToEndTraceError` fırlatır — builders.py:37-39); SKIPPED span doğrudan
     `TraceSpan(stage=TraceStageKind.EXECUTION, status=SKIPPED,
     duration_ms=None, detail=None)` olarak kurulur.
   - SECURITY: guardrail (`SQLGuardrailValidator`) + sandbox safety
     (`SqlSafetyValidator`) sonuçları **duck-typed adaptörle** audit-event
     şekline (`category/outcome/severity/reason_code/entry_hash` attribute'ları)
     çevrilip `build_security_span`'a verilir; guardrail/safety fail → ERROR.
     Adaptör saf bir fonksiyondur, `app.security.*` import ETMEZ.

## §2. Mimari — stage örgüsü

`SQLGenerationPipeline` içinde (dosya: `backend/app/sql_pipeline.py`):

```
run_pipeline(..., request_id=None)          # orkestratör (~80 satır)
  rid = request_id or f"req_{uuid4().hex}"
  spans: dict[TraceStageKind, TraceSpan] birikimi için stage sonuçları toplanır
  ├─ _stage_intent(...)        -> (intent_result | None, ms)
  │    mevcut 174-241 bloğu: Excel AQR parse / NL passthrough
  ├─ _stage_retrieval(...)     -> (retrieval_ctx, ms)
  │    mevcut 243-352 bloğu: prune_schema + select_schema_context
  ├─ _stage_writer_critic(...) -> (wc_result, ms_breakdown)
  │    mevcut 354-537 bloğu OLDUĞU GİBİ tek metodda: attempt döngüsü
  │    (prompt build + _generate_sql + guardrail + safety + AST + semantic)
  │    ms_breakdown: {prompt_ms, generation_ms, validation_ms} — döngü içi
  │    perf_counter deltalarının attempt'ler üzerinden TOPLAMI
  └─ _capture_trace_on_exit(..., request_id=rid, stage_results, stage_timings)
```

Kurallar:
- Her stage metodu kendi `time.perf_counter()` çiftini alır; süreler int ms.
- Erken çıkış (mevcut 5 hata call-site'ı) korunur: hangi stage'de çıkılırsa
  o stage'e kadarki sonuçlar span'lenir, sonrakiler SKIPPED.
- Stage metodları `self` üzerindeki mevcut bağımlılıkları kullanır; imzalar
  mevcut yerel değişken akışını parametre/dönüş değerine çevirir. Yeni
  bağımlılık, yeni davranış, yeni log mesajı YOK (log_callback çağrıları
  taşındıkları metodda aynen kalır).
- Writer-critic döngüsündeki per-attempt prompt/generation/validation süreleri
  attempt'ler üzerinden toplanır; span'lere bu toplamlar yazılır (per-attempt
  kırılım 27.8 Cost Telemetry işine kalır — kapsam dışı).

## §4. Emisyon — `_capture_trace_on_exit` genişletmesi

Mevcut imzaya `request_id`, stage sonuçları ve stage süreleri eklenir. Akış:

1. Legacy yol AYNEN: `build_trace_from_pruned_schema(...)` → `_save_trace_safely`.
2. Yeni yol: 7 span kurulur (builders 27.0/27.1'den; SECURITY adaptörü §1.4),
   `build_end_to_end_trace(trace_id=f"e2e_{uuid4().hex}", request_id=rid,
   spans=..., job_id=..., dialect=..., nl_query_sha256=sha256(natural_query),
   total_duration_ms=total_ms)` → `TraceRecord(trace_type="end_to_end",
   payload=e2e.to_payload())` → `_save_trace_safely`.
3. Yeni yolun TAMAMI kendi try/except'i içindedir: e2e kurulumu patlarsa
   legacy kayıt zaten atılmıştır, hata `logger.error` ile yutulur —
   **trace emisyonu pipeline sonucunu asla etkilemez** (27.0 ilkesi).
4. Secret hijyeni: e2e yoluna giren her serbest metin mevcut
   `redact_sensitive`/`redact_sensitive_text` süzgecinden geçer; SQL asla ham
   taşınmaz (yalnız sha256 — mevcut builder sözleşmesi).
