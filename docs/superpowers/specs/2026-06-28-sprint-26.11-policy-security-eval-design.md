# Sprint 26.11 — Policy / Security Eval · Design

Phase 7 (Security & Governance). Follows Sprint 26.10 (Connection Credential
Vault). This is the **final Phase 7 sprint**: a continuous-evaluation harness
that guards the whole 26.0–26.10 security/governance contract surface against
silent behavioral regression as adapters, policies, and APIs evolve.

## 1. Purpose

A pure, deterministic, **secret-free**, I/O-free **meta-evaluation** harness that
runs the security/governance contracts (26.0–26.10) against a curated, in-code
**blessed golden case set**, and produces a single release decision plus a
coverage signal.

It is a hybrid of two checks:

- **Regression / drift gate (primary):** each blessed case declares its expected
  normalized outcome; the harness runs the contract and compares **exactly**.
  Any drift (an expected code disappearing, or an unexpected one appearing) is a
  failure. This catches silent behavior changes that unit tests for an
  individual contract may not — the suite is the cross-contract behavioral
  baseline.
- **Coverage-completeness (advisory by default):** every *reachable* verdict /
  reason-code / category / disposition symbol across the contracts must be
  demonstrated by at least one passing blessed case. A reachable symbol with no
  case is a coverage gap — a blind spot where a new or changed symbol could
  regress unnoticed.

The harness **does not** re-implement or replace the contracts' own unit tests.
It adds a unified, declarative behavioral baseline and a single PASS/WARN/FAIL
aggregator over the entire security surface.

## 2. Scope

**In scope:**

- New modules under `app/evaluation/` (keeps `app.security` driver-free):
  `security_policy_eval.py`, `security_policy_eval_projectors.py`,
  `security_policy_eval_cases.py`, `security_policy_eval_coverage.py`,
  `security_policy_eval_gate.py`.
- A normalized `SecurityEvalOutcome(verdict, codes)` envelope + a per-contract
  **projector** (native result → outcome) for each of the 11 contracts.
- In-code, typed **blessed case** registry (`SecurityEvalCase`): each case builds
  the real typed request/policy in code and declares its expected outcome.
- A **runner** that dispatches each case to its contract, projects, and
  exact-matches against the expected outcome.
- A **coverage** computation: introspected symbol universe + a declared
  exclusion list of intentionally-unreachable symbols → reachable-but-uncovered
  gaps.
- A **`SecurityEvalGateAggregator`** producing a `SecurityEvalGateDecision`
  (PASS / WARN / FAIL), mirroring the shape of the existing
  `SQLEvalGateAggregator` / `SQLEvalGateDecision`.
- Coverage of **all 11 contracts**, thin: a projector + 1–2 canonical cases +
  coverage wiring for each.

**Out of scope (deliberate / future):**

- **No audit interlock** (no `from_security_eval` / new `AuditCategory`). This is
  a CI/dev release gate, not a runtime governance decision over user data; there
  is no governed *event* to record. A deliberate departure from the 26.0–26.9
  per-contract audit pattern.
- **No JSON/YAML loader.** The case set is in-code and typed (richer than JSON,
  type-safe at construction, no per-contract deserializer surface, no risk of
  embedding secret material). A pluggable external loader can be added later
  without changing the harness core.
- **Deep case sets.** Each contract gets 1–2 canonical cases this sprint; broad
  per-symbol depth is iterative (later sprints / config flag to FAIL on gaps).
- Live execution, network/registry I/O, DB persistence, clock/ID generation.

## 3. Module layout

- `app/evaluation/security_policy_eval.py` — `SecurityEvalOutcome`,
  `SecurityEvalCase`, `SecurityEvalCaseResult`, `SecurityEvalRunResult`,
  `run_security_eval`, the eval error class.
- `app/evaluation/security_policy_eval_projectors.py` — the 11 projectors +
  `PROJECTOR_REGISTRY` (`contract_id → projector`).
- `app/evaluation/security_policy_eval_cases.py` — `SECURITY_EVAL_CASES` blessed
  registry (in-code typed cases).
- `app/evaluation/security_policy_eval_coverage.py` — symbol universe registry
  (`contract_id → enum classes`), declared exclusions, `compute_coverage`,
  `CoverageReport`.
- `app/evaluation/security_policy_eval_gate.py` — `SecurityEvalGateConfig`,
  `SecurityEvalGateAggregator`, `SecurityEvalGateDecision`, gate enums.

Rationale for the split: each file has one purpose (envelope/runner vs
projectors vs data vs coverage vs gate), keeping every unit small and
independently testable.

## 4. Normalized outcome envelope

```python
SECURITY_POLICY_EVAL_CONTRACT_VERSION = "security_policy_eval_v1"

@dataclass(frozen=True)
class SecurityEvalOutcome:
    verdict: str                  # primary verdict symbol, e.g. "DENY", "HIGH", "BLOCK"
    codes: frozenset[str]         # reason codes / categories / signal markers
```

- Carries only **symbol names**, never values → secret-free by construction.
- The common currency for both comparison (§6) and coverage (§7).
- `verdict` is the contract's primary decision/level/disposition rendered as a
  stable string; `codes` is the set of secondary symbols (reason codes,
  risk-signal flags, detected categories, flagged-field markers).

## 5. Projectors (native result → outcome)

One pure function per contract, registered by `contract_id`:

| contract_id | source result | verdict | codes |
|---|---|---|---|
| `26.0-permission-policy` | `SQLPermissionPolicyResult` | decision (ALLOW/DENY/REQUIRES_APPROVAL) | {reason_code} |
| `26.1-tenant-boundary` | `TenantWorkspaceBoundaryResult` | decision | {reason_code} |
| `26.2-read-only` | `SQLReadOnlyEnforcementResult` | decision | {reason_code} |
| `26.3-risk-classifier` | `SQLQueryRiskResult` | risk level (LOW…CRITICAL) | signal flags |
| `26.4-sensitive-data` | `SQLSensitiveDataPolicyResult` | decision | {reason_code} ∪ matched-resource markers |
| `26.5-pii-phi` | `SQLPiiPhiDetectionResult` | data-class summary (e.g. SAFE/PII/PHI) | detected categories |
| `26.6-audit-event` | `AuditEvent` | outcome (ALLOWED/DENIED/FLAGGED) | {category, severity} |
| `26.7-approval` | `ApprovalRequest` | state (PENDING/APPROVED/…) | transition markers |
| `26.8-prompt-injection` | `PromptInjectionDefenseResult` | disposition (ALLOW/REVIEW/BLOCK) | matched categories |
| `26.9-result-set-privacy` | `ResultSetPrivacyLimitsResult` | disposition (ALLOW/TRUNCATE/DENY) | pii-signal markers |
| `26.10-credential-vault` | `ConnectionCredentialVaultResult` | decision (ALLOW/DENY) | {reason_code} (+ leak marker) |

- Projectors are pure and total; an unknown/contract-error input raises
  `SecurityPolicyEvalError` (a harness bug, not a case outcome).
- The exact verdict/codes mapping per contract is fixed in the projector and is
  itself unit-tested, so the projection is part of the behavioral baseline.

## 6. Case model, runner, and exact match

```python
@dataclass(frozen=True)
class SecurityEvalCase:
    case_id: str
    contract_id: str                       # selects the projector
    run: Callable[[], object]              # builds typed request/policy, calls contract.evaluate
    expected: SecurityEvalOutcome
    adjudication_status: EvalAdjudicationStatus  # APPROVED | NEEDS_REVIEW

@dataclass(frozen=True)
class SecurityEvalCaseResult:
    case_id: str
    contract_id: str
    passed: bool
    expected: SecurityEvalOutcome
    actual: SecurityEvalOutcome
    mismatch_detail: Optional[str]         # verdict and/or code-set diff, symbol names only
```

`run_security_eval(cases) -> SecurityEvalRunResult`:

1. For each case: call `case.run()` → native result; apply
   `PROJECTOR_REGISTRY[case.contract_id]` → `actual`.
2. **Exact match:** `passed = (actual.verdict == expected.verdict and
   actual.codes == expected.codes)`. Any difference → fail with a symbol-only
   `mismatch_detail`.
3. Aggregate into `SecurityEvalRunResult(total, passed, failed, case_results,
   per_contract_breakdown)`.

The runner is pure except for invoking the contracts. Invoking the 26.10 case
triggers that contract's lazy import of `connection_abstraction` (drivers) — this
is acceptable here because the harness lives in `app.evaluation` (already a
driver-loading package); `import app.security` stays driver-free.

**Secret-free in cases:** leak/PII/credential cases use **synthetic** patterns
(as the contracts' own tests do); no real secret material is embedded. The
outcome envelope carries marker names only.

## 7. Coverage-completeness

```python
@dataclass(frozen=True)
class CoverageReport:
    universe_size: int
    covered: frozenset[str]            # symbols demonstrated by passing APPROVED cases
    excluded: frozenset[str]           # declared intentionally-unreachable
    gaps: frozenset[str]               # (universe - excluded) - covered
    per_contract: Mapping[str, ...]    # covered/gap breakdown
```

`compute_coverage(run_result, universe, exclusions) -> CoverageReport`:

- **Universe (introspection):** a `COVERAGE_UNIVERSE` registry maps each
  `contract_id` to the enum classes whose members form that contract's
  verdict/code symbol space. The universe is the union of all member symbols.
  Introspection means a newly-added enum value is automatically pulled in — you
  cannot forget to register it (directly addressing the "silent regression as
  new symbols are added" fear).
- **Exclusions (declared):** `COVERAGE_EXCLUSIONS` is a frozen set of
  intentionally-unreachable symbols, each with a documented rationale
  (e.g. 26.9 inert PHI categories, defense-in-depth branches unreachable via a
  valid input, audit `FLAGGED` where the gate always denies). Excluded symbols
  are not gaps.
- **Covered:** the union of `expected.verdict ∪ expected.codes` over cases that
  are **APPROVED and passing** (a symbol only counts as covered if a green case
  actually demonstrates it).
- **Gaps:** `(universe − exclusions) − covered`.

**Projector ↔ universe invariant:** every symbol a projector can emit (any
`verdict` or `code`) MUST be a member of an enum registered for that contract in
`COVERAGE_UNIVERSE` (so `covered ⊆ universe` always holds). Where a projector's
primary `verdict` is derived rather than a raw enum value (e.g. 26.5's
SAFE/PII/PHI data-class summary, or 26.6's audit outcome), the deriving enum is
the one registered, and the projector emits exactly its member names. A meta
test asserts `covered ⊆ universe` for the shipped suite to catch any projector
that emits an unregistered symbol.

If introspection cannot resolve a registered enum (a wiring bug), raise
`SecurityPolicyEvalError` rather than silently undercount the universe.

## 8. Aggregator gate

```python
class SecurityEvalGateStatus(str, Enum):
    PASS = "pass"
    WARN = "warn"
    FAIL = "fail"

@dataclass(frozen=True)
class SecurityEvalGateConfig:
    case_mismatch_status: SecurityEvalGateStatus = FAIL    # any failed case
    coverage_gap_status: SecurityEvalGateStatus = WARN     # any reachable uncovered symbol
    fail_on_empty: bool = True

@dataclass(frozen=True)
class SecurityEvalGateDecision:
    version: str
    status: SecurityEvalGateStatus       # worst of the rule outcomes
    passed: bool                         # status == PASS or WARN (WARN does not block)
    summary: str
    rules_evaluated: Tuple[str, ...]
    failed_rules: Tuple[str, ...]
    warning_rules: Tuple[str, ...]
    decision_reason: str
```

`SecurityEvalGateAggregator.aggregate(run_result, coverage_report, config) ->
SecurityEvalGateDecision`. Rules:

- **CASE_MISMATCH** — any failed case ⇒ `config.case_mismatch_status`
  (default FAIL). These cases are deterministic and must be 100% green; a
  mismatch is a real regression, so there is no pass-rate tolerance (unlike the
  fuzzy-LLM SQL eval gate).
- **COVERAGE_GAP** — any reachable uncovered symbol ⇒ `config.coverage_gap_status`
  (default WARN; raise to FAIL once the baseline is complete).
- **EMPTY_DATASET** — no cases and `fail_on_empty` ⇒ FAIL.

`status` is the worst rule outcome; `passed = status in {PASS, WARN}` (WARN
surfaces but does not block merge). Mirrors `SQLEvalGateDecision`'s shape
(version, status, passed, rules_evaluated, failed_rules, warning_rules,
decision_reason) for consistency with the existing harness.

## 9. Error handling

- Harness/wiring bugs (unknown `contract_id`, unprojectable result, unresolved
  coverage enum, malformed case) raise `SecurityPolicyEvalError`.
- A case whose contract returns a different-but-valid outcome is **not** an
  exception — it is a failed `SecurityEvalCaseResult` (the gate's job).
- Deterministic and I/O-free except the contract calls the cases make.

## 10. Public API

`app/evaluation/security_policy_eval*.py` modules export their public types and
functions directly. Because the harness lives in `app.evaluation` (not
`app.security`), it does **not** go through `app/security/__init__.py` and does
not affect the driver-isolation invariant. No new public surface is added to
`app.security`.

## 11. Test matrix

`tests/evaluation/test_security_policy_eval.py`:

- Runner: a passing case → `passed=True`; a deliberately-wrong `expected` →
  `passed=False` with a symbol-only `mismatch_detail`.
- Exact-match semantics: extra code, missing code, and verdict mismatch each
  fail; identical sets pass.

`tests/evaluation/test_security_policy_eval_projectors.py`:

- Each of the 11 projectors maps a known native result to the expected
  `SecurityEvalOutcome` (verdict + codes).

`tests/evaluation/test_security_policy_eval_coverage.py`:

- Universe introspection collects expected symbols; a declared exclusion is not
  a gap; an uncovered reachable symbol is a gap; only passing APPROVED cases
  count as covered.

`tests/evaluation/test_security_policy_eval_gate.py`:

- CASE_MISMATCH → FAIL; COVERAGE_GAP → WARN by default and FAIL when configured;
  EMPTY_DATASET → FAIL; clean run → PASS; `passed` reflects WARN-not-blocking.

`tests/evaluation/test_security_policy_eval_suite.py` (meta):

- The bundled `SECURITY_EVAL_CASES` all pass, and aggregating them yields a gate
  decision of PASS or WARN (never FAIL) under the default config — the shipped
  baseline is green.
- `covered ⊆ universe` for the shipped suite (no projector emits a symbol that is
  not registered in `COVERAGE_UNIVERSE` or declared in exclusions).

## 12. Acceptance criteria

- Harness is pure, deterministic, secret-free, I/O-free (except the contract
  calls the cases make).
- All 11 contracts have a projector + ≥1 passing canonical blessed case.
- Exact-match comparison; any drift in verdict or code set fails the case.
- Coverage computed from introspected universe minus declared exclusions;
  reachable-but-uncovered symbols reported as gaps.
- `SecurityEvalGateAggregator` yields PASS/WARN/FAIL mirroring the existing eval
  gate; case mismatch ⇒ FAIL, coverage gap ⇒ WARN by default (configurable).
- No audit interlock, no JSON loader, no change to `app.security` public surface
  or the driver-isolation invariant.
- Full backend suite green; the shipped baseline suite is PASS/WARN.
