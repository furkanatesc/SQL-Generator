# Sprint 32.6 — Rate Limiting (Design)

Phase 13 · Branch `feat/32.6-rate-limiting` · Önceki: 32.5 (kuyruk, global eşzamanlılık limiti).

## 1. Problem & karar

- **API'de hiç hız sınırı yok.** Tek bir istemci (ya da sızmış bir key) API'yi ve özellikle LLM maliyeti üreten
  job oluşturmayı sınırsız çağırabilir. 429 için kanonik hata kodu da yok (`HTTP_ERROR`'a düşer).
- **LLM limiter'ı etkisiz.** `NVIDIAClient` içindeki `TokenBucket` (15/dk, burst 3) sabit kodlu ve **istemci
  örneğine** bağlı; `SQLGenerationPipeline` her job'da yeni `NVIDIAClient` yarattığı için job'lar arasında hiçbir
  şey sınırlanmıyor.

**Karar (kapsam):**
1. **API rate limit middleware'i** (`app/rate_limit.py`): istemci başına (API key'in SHA-256 özeti; key yoksa
   istemci IP'si) iki token bucket: genel istekler `NL2SQL_RATE_LIMIT_REQUESTS_PER_MINUTE` ve job oluşturma
   (`POST /api/files/upload`, `POST /api/jobs/without-file`) `NL2SQL_RATE_LIMIT_JOBS_PER_MINUTE`. `0` = kapalı
   (varsayılan — dev/test/CI'ı etkilemez); **prod compose açık değerlerle sabitler** (300 / 20).
   Aşımda **429 + `Retry-After`** + kanonik hata zarfı, kod **`RATE_LIMITED`** (30.0 sözleşmesine additive);
   başarılı yanıtlarda `X-RateLimit-Limit`/`X-RateLimit-Remaining`. `/health`, `/ready` ve `OPTIONS` muaf.
   Middleware CORS'un **içinde** (429 yanıtı CORS başlıklarını taşır, tarayıcı okuyabilir) ve request-logging'in
   içinde (429 loglanır, `X-Request-ID` alır).
2. **LLM çağrı hızı process-geneli**: tek paylaşılan limiter (`get_llm_rate_limiter()`), ayarlanabilir
   `NL2SQL_LLM_REQUESTS_PER_MINUTE` (15) / `NL2SQL_LLM_BURST` (3); `NVIDIAClient` onu kullanır (davranış
   değerleri aynı, ama artık job'lar arasında gerçekten paylaşılıyor).

Seçilmeyen:
- (a) Redis tabanlı dağıtık limiter — yeni servis; API tek uvicorn process'i (Dockerfile `CMD`), bellek-içi kesin.
  Çok-replika API'de limit replika başına olur (TECH-DEBT §42).
- (b) SQLite paylaşımlı sayaç — her istekte yazma kilidi; API gecikmesine maliyet > fayda.
- (c) `slowapi` bağımlılığı — 60 satırlık token bucket için yeni bağımlılık ve dekoratör tabanlı yayılım; tek
  middleware + mevcut `TokenBucket` deseni yeterli.
- (d) Varsayılan açık limit — mevcut test süiti ve yerel geliştirme yüzlerce istek/dk üretir; güvenli varsayılan
  prod compose'ta sabitlenir (32.0 deseni: prod-güvenli değerler compose'ta pinned).

## 2. Design

### 2.1 `app/rate_limit.py`
- `TokenBucket` yeniden kullanılmaz (bekleme süresi döndürür, `sleep` eder); yeni saf `Bucket` (capacity,
  refill/sn, `try_acquire(now) -> (allowed, retry_after, remaining)`), saat enjekte edilebilir (test).
- `RateLimiter(per_minute, burst=None, max_clients=10_000)`: istemci anahtarı → bucket; `burst` varsayılanı
  `per_minute` (1 dakikalık patlama). İstemci sayısı tavanı aşılınca en uzun süredir kullanılmayan yarı silinir
  (bellek sınırı).
- `client_key(request)`: `X-API-Key` header ya da `api_key` query → `key:` + sha256[:16] (ham key bellekte
  tutulmaz/loglanmaz); yoksa `ip:` + `request.client.host`.
- `RateLimitMiddleware`: ayarları istekte `get_settings()`'ten okur (test/env değişikliği), limiter'ları değer
  değişince yeniden kurar. Job yolu iki bucket'tan da düşer.

### 2.2 Hata sözleşmesi
`STATUS_TO_CODE[429] = "RATE_LIMITED"`, `_REQUIRED_ERROR_CODES += ("RATE_LIMITED",)` (30.0 drift testi ikisini
senkron tutar); snapshot additive regenerate. 429 gövdesi `http_exception_handler` ile aynı şekil.

### 2.3 LLM limiter
`app/llm_client.py::get_llm_rate_limiter()` — ayarlardan kurulan modül-geneli `TokenBucket` (ayar değişirse
yeniden kurulur); `NVIDIAClient.limiter` property'si onu döndürür.

### 2.4 Ayarlar
`NL2SQL_RATE_LIMIT_REQUESTS_PER_MINUTE` (0), `NL2SQL_RATE_LIMIT_JOBS_PER_MINUTE` (0),
`NL2SQL_LLM_REQUESTS_PER_MINUTE` (15, >0), `NL2SQL_LLM_BURST` (3, ≥1). Prod compose backend: 300 / 20.

## 3. Verify
`backend/tests/test_rate_limit.py`: bucket matematiği (saat enjekte), istemci anahtarı (hash, ham key yok),
limit aşımında 429 + `Retry-After` + `RATE_LIMITED` zarfı + `X-Request-ID`, istemciler arası izolasyon, job
limiti genel limitten ayrı, health/ready/OPTIONS muaf, 0 = kapalı, CORS başlığı 429'da, bellek tavanı, LLM
limiter'ın job'lar arası paylaşımı. Sözleşme testleri + snapshot. Full suite + CI 5/5 (smoke prod limitlerle).

## 4. Out of scope (TECH-DEBT §42)
- Dağıtık / çok-replika limit (Redis); worker process'leri arası LLM limiti (32.5 `MAX_CONCURRENT` kısmen karşılar).
- Key başına farklı kota / plan; reverse-proxy `X-Forwarded-For` güveni (proxy yok — §36.1).
- Upload boyutu / istek gövdesi sınırı.
