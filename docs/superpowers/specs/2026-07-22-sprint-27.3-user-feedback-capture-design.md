# Sprint 27.3 — User Feedback Capture (design)

**Tarih:** 2026-07-22
**Faz:** 8 (Observability & Debuggability)
**Öncül:** Sprint 27.2.1 (Error Taxonomy Boundary, PR #138 merged). Gözlemlenebilirlik
katmanı artık `error_code`'u iş/API/frontend sınırından geçiriyor. Bu sprint,
**öğrenen sistemin tohumunu** atar: bir SQL üretimine kullanıcı feedback'ini toplar.

## 1. Amaç

Bir SQL üretimine (`job`) dair kullanıcı feedback'ini **topla + sakla + tüketiciye
(27.9) okunabilir hale getir**. Feedback, üretilen SQL'in *semantik olarak* doğru mu
yanlış mı olduğunu ve yanlışsa nesinin yanlış olduğunu yakalar. Bu, 27.2'nin
*sistem/pipeline hatası* taksonomisinden **farklı bir eksendir** (başarıyla üretilmiş
ama yanlış SQL).

Bu sprint feedback'i yalnız **toplar**; tüketen (feedback → kural önerisi) minimal
adım `27.9 Feedback Review → Rule Suggestion`'dır ve kapsam dışıdır.

## 2. Kapsam

### 3.3 API — `backend/app/api/feedback.py` (dedicated router)

`api/debug_traces.py` deseni: kendi `APIRouter`'ı, `main.py`'de mount edilir.
main.py'yi şişirmez, izole test edilir.

**Schema'lar (`backend/app/api/schemas.py`):**
```python
class FeedbackSubmitRequest(BaseModel):
    verdict: FeedbackVerdict
    category: Optional[FeedbackCategory] = None
    note: Optional[str] = Field(default=None, max_length=2000)
    corrected_sql: Optional[str] = Field(default=None, max_length=5000)

    @model_validator(mode="after")
    def _check_invariants(self):
        if self.verdict == FeedbackVerdict.CORRECT:
            if self.category is not None or self.corrected_sql is not None:
                raise ValueError("verdict=correct ile category/corrected_sql verilemez")
        if self.category == FeedbackCategory.OTHER and not (self.note and self.note.strip()):
            raise ValueError("category=other için note zorunludur")
        return self

class FeedbackDetailResponse(BaseModel):
    id: str
    job_id: str
    verdict: str
    category: Optional[str] = None
    note: Optional[str] = None
    corrected_sql: Optional[str] = None
    created_at: str

class FeedbackEnvelopeResponse(BaseModel):
    status: Literal["success"]
    feedback: FeedbackDetailResponse
```
Response alanları **string** taşır (enum değil) — API sözleşmesi tipsiz string kod
taşır, 27.2.1 deseni.

**Endpoint:**
```
POST /api/jobs/{job_id}/feedback   [Depends(verify_api_key)]
    response_model=FeedbackEnvelopeResponse
    responses={404: ErrorResponse, 422: ErrorResponse}
```
Akış: Pydantic + invariant doğrula → `get_job(job_id)` None ise **404**
(`raise HTTPException(status_code=404, detail=f"Job with ID '{job_id}' not found.")`
— mevcut job endpoint'leriyle birebir aynı desen, main.py:259/267/314; global
`http_exception_handler` bunu ErrorResponse envelope'una sarar) → `create_feedback(
uuid4, ...)` → `{"status":"success","feedback":{...}}`. Başarı status kodu **kardeş
`/api/jobs/{id}/cancel` endpoint'iyle aynı** — envelope + default **200** (POST-create
için 201 kullanılmıyor; repo konvansiyonu 200 envelope).

### 3.4 Validation invariant'ları (özet)
1. `verdict` zorunlu; yalnız `correct|incorrect`.
2. `verdict=correct` → `category` ve `corrected_sql` **None** olmalı (422). *(doğru
   SQL'in hata kategorisi/düzeltmesi olmaz)*
3. `category=other` → `note` **zorunlu** (422). *(aksi halde 27.9 için ölü sinyal)*
4. `note` ≤ 2000, `corrected_sql` ≤ 5000 char — sınırsız depolamayı önle.

## 4. Veri akışı

```
Kullanıcı → POST /api/jobs/{id}/feedback (API key)
          → Pydantic + cross-field invariant (422)
          → get_job(id) yok mu? → 404
          → create_feedback(...) [append-only satır]
          → {status:"success", feedback:{...}}

27.9 (gelecek) → get_feedback_for_job(id) → kural önerisi madenciliği
```
