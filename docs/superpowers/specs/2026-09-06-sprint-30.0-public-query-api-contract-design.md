# Sprint 30.0 — Public Query API Contract (Design Spec)

**Date:** 2026-09-06
**Phase:** 11 (API / Backend Productization) — **first sprint of Phase 11**
**Branch:** `feat/sprint-30.0-public-query-api-contract` (from `main` `d39c683`)
**Predecessor:** 29.7 Adapter Conformance Eval Suite (PR #168). Phase 10 closed; every connection dialect has a contract-first execution adapter plus single-source conformance verification.

---

## 1. Purpose & motivation

Per the roadmap (`docs/PLANNED-SPRINTS.md`, Phase 11 — "Internal backend'i product-grade public/backend API yüzeyine dönüştürmek"): 30.0 is the **first** Phase 11 sprint and the "Contract" sprint. It establishes the cross-cutting API conventions that every subsequent 30.x surface (Workspace, Connection Registry, Schema Sync, Query Run, History, Feedback, Admin, Auth) will conform to.

Today the `/api/*` surface is functional but **ad-hoc**: 15+ bespoke `*EnvelopeResponse` models in `app/api/schemas.py`, each with a differently-named payload key (`job`, `feedback`, `metrics`, …); no API versioning (`/api/v1`); no single pagination convention; and **nothing that enforces** a new endpoint follows any convention. The error contract is the one mature, canonical piece already (`{"error":{code,message,details}}` + `X-Request-ID`).

30.0 delivers a **single source of truth for the public API contract**: a declarative contract module (canonical success envelope, versioning, pagination, re-exported canonical error) that drives (a) a machine-readable reference `GET /api/v1` discovery endpoint that conforms to it, and (b) a deterministic 29.7-style conformance guard that holds the declared public surface to the contract and forces future non-conforming routes to either conform or be explicitly grandfathered.

**This sprint asserts contract-shape conformance only** — it does NOT migrate the existing endpoints, add authentication, or change any existing behavior.

## 2. Scope decisions (locked with the user during brainstorming)

1. **Cross-cutting contract convention layer** (not a concrete `/query` business endpoint). Defines the shape; adds no business endpoint. *(User-approved.)*
2. **Enforcement posture = contract + guard, existing surface grandfathered.** The canonical contract is defined as a single-source module + a 29.7-style conformance guard. The 20+ existing `/api/*` endpoints are **unchanged** (an explicit grandfathered allowlist); the guard applies only to the declared public set. One small reference `/api/v1` meta endpoint concretizes the contract. Non-breaking; unblocks 30.1+. Mirrors the 29.x inert philosophy. *(User-approved.)*
3. **Canonical success envelope uses a single `data` key** (not a per-resource-named key like `job`/`feedback`). *(User-approved.)*
4. **The reference endpoint is `GET /api/v1`, returning the contract descriptor** — a machine-readable "what is this API's contract" discovery document (the 29.7 report-emitter-as-demonstrator analogue). *(User-approved.)*
5. **The guard fails when a new non-conforming route appears outside the allowlist** — forcing future sprints to conform or explicitly grandfather (no silent drift). *(User-approved.)*
6. **Offset-based pagination** (`limit`/`offset`/`count`), consistent with the existing jobs-list; **no cursor pagination** (YAGNI, deferred). *(User-approved.)*
7. **Reuse the existing error contract** (`ErrorResponse`/`ErrorBody`) — re-export as THE canonical error, do not redefine. *(User-approved.)*

## 3. Existing landscape (as mapped)

- **Success envelopes** — `backend/app/api/schemas.py`: 15+ `*EnvelopeResponse` models, all `{"status": "success", "<named-key>": <payload>}` with an inconsistent payload key. Grandfathered.
- **Error contract** — `app/api/schemas.py::ErrorResponse`/`ErrorBody` (`{"error":{code,message,details}}`) + `app/api/errors.py` exception handlers (`http_exception_handler`, `validation_exception_handler`, `unhandled_exception_handler`): status→code map (`BAD_REQUEST`/`UNAUTHORIZED`/`FORBIDDEN`/`NOT_FOUND`/`VALIDATION_ERROR`/`INTERNAL_SERVER_ERROR`), every error response carries an `X-Request-ID` header sourced from `request.state.request_id`. **Already canonical — reused, not changed.**
- **Domain error taxonomy** — `app/errors/{categories,codes,registry}.py` (27.2 Error Taxonomy v2): a richer internal taxonomy used inside the pipeline, distinct from the HTTP status→code map. **Out of scope** for 30.0 (mapping the taxonomy into the HTTP error `code` is a later concern; noted in §7).
- **Routes** — `app/main.py` (`@app.<verb>` for health/ready/configs/files/jobs/schema/rag) plus feature routers in `app/api/*_api.py` (cache, dashboard, debug_bundle, debug_replay, debug_traces, feedback, llm_usage, metrics, rule_suggestions, schema_sync). All under bare `/api/*` or root (`/health`, `/ready`). **No `/api/v1`.** All grandfathered.
- **Request-id middleware** — `app/middleware/request_logging.py` sets `request.state.request_id`; handlers echo it as `X-Request-ID`.
- **App assembly** — `create_app()`/module-level `app` in `app/main.py`; exception handlers registered there; routers `include_router`-ed there.
- **Tests / CI** — `backend/tests/` (pytest; markers in `pytest.ini`: `manual_llm, integration, postgres, oracle, mysql, sqlserver`). CI `backend-tests` job runs the full non-marked suite. There is an existing api-surface/OpenAPI-shape test family (referenced by the fastapi-pin note); the new guard joins it.

## 4. Architecture

### 4.1 The canonical contract module (single source of truth)

New module `backend/app/api/contract.py`. Pure, import-safe, no FastAPI app import at module top (only pydantic + typing), so the guard and the app both import it cheaply.

**Constants**
```
API_VERSION = "v1"
API_V1_PREFIX = "/api/v1"
REQUEST_ID_HEADER = "X-Request-ID"
```

**Canonical success envelope** — a pydantic generic:
```
DataT = TypeVar("DataT")
class ApiResponse(BaseModel, Generic[DataT]):
    status: Literal["success"] = "success"
    data: DataT
    meta: Optional[ResponseMeta] = None
```
- Single `data` key holds the payload (object, list, or scalar-wrapping model).
- `meta` optional; present when pagination (or future cross-cutting metadata) applies.

**Pagination**
```
class PageMeta(BaseModel):
    limit: int
    offset: int
    count: int          # number of items in THIS page's data
class ResponseMeta(BaseModel):
    pagination: Optional[PageMeta] = None
```
(`count` = items returned now; a `total` across all pages is deferred — YAGNI, noted §7.)

**Canonical error** — re-export, do not redefine:
```
from app.api.schemas import ErrorResponse, ErrorBody   # THE canonical error shape
```

**Declarative descriptor** (the 29.7 `CONFORMANCE_PROFILES` analogue — the single declaration the guard and the meta endpoint both read):
```
@dataclass(frozen=True)
class ApiContract:
    version: str                              # "v1"
    prefix: str                               # "/api/v1"
    request_id_header: str                    # "X-Request-ID"
    success_envelope_fields: tuple[str, ...]  # ("status", "data", "meta")
    error_envelope_shape: dict                # {"error": ("code","message","details")}
    pagination_fields: tuple[str, ...]        # ("limit","offset","count")
    required_error_codes: tuple[str, ...]     # the status→code vocabulary
API_CONTRACT = ApiContract(...)               # built from the models above (fields derived, not hand-typed twice)
```
A pure `contract_descriptor() -> dict` renders `API_CONTRACT` into the JSON-serializable discovery document the meta endpoint returns (and that a test snapshots).

### 4.2 The reference meta endpoint

New router `backend/app/api/v1_meta.py`, `include_router`-ed in `app/main.py`.
- `GET /api/v1` → `ApiResponse[ContractDescriptor]` where the body is `{"status":"success","data": contract_descriptor(), "meta": null}`.
- `ContractDescriptor` is a pydantic model mirroring `contract_descriptor()` (so the response is fully typed and appears correctly in OpenAPI).
- No auth dependency (public discovery), no side effects, deterministic. This is the **one** route that must satisfy the guard.
- Rationale: a public, machine-readable contract-discovery endpoint is the smallest real artifact that proves the contract exists and is self-describing — the 29.7 report-emitter demonstrator pattern, as an endpoint.

### 4.3 The conformance guard (29.7-style, deterministic)

New test module `backend/tests/api/test_public_api_contract_conformance.py`. Marker-less → runs in `backend-tests` on every CI run. Uses FastAPI's `app` + `TestClient` + the generated OpenAPI schema; no Docker, no network, no DB.

**Declared sets (single-source, in the guard):**
- `EXPECTED_V1_ROUTES` = the known-conforming public surface (initially `{("GET","/api/v1")}`). The guard asserts the app's actual set of `/api/v1` routes equals this — adding a v1 route without updating the guard **FAILS**, forcing a conformance review.
- Legacy `/api/*` (and `/health`, `/ready`, …) is **grandfathered** — not checked. Route-addition anywhere is already caught by the existing `tests/test_api_surface.py` + `openapi_snapshot.json` tripwire (any new route fails that snapshot until regenerated with review), so the guard does not re-enumerate the ~40 legacy routes (refinement discovered in planning — less brittle, same anti-drift guarantee).

**Assertions:**
1. **Known-conforming v1 allowlist** — the app's `/api/v1` route set equals `EXPECTED_V1_ROUTES`; a new v1 route not in the allowlist → **FAIL** (the anti-drift belt for the public surface). Accidental route additions elsewhere are caught by the existing OpenAPI snapshot test.
2. **Versioned prefix** — every public route path starts with `/api/v1`.
3. **Success envelope** — each public route's success (2xx) response schema, resolved through the OpenAPI components, has exactly the canonical top-level fields (`status`, `data`, optional `meta`) with `status` const `"success"`.
4. **Error responses** — declared error responses on public routes reference the canonical `ErrorResponse` model (`{"error":{code,message,details}}`).
5. **Request-id** — the app has the three canonical exception handlers registered and they emit `REQUEST_ID_HEADER` (assert via a `TestClient` round-trip on a forced error + on the meta endpoint success response, both carry `X-Request-ID`).
6. **Descriptor is live** — `GET /api/v1` returns `contract_descriptor()` verbatim inside the canonical envelope, and `contract_descriptor()` is internally consistent with the pydantic models (envelope fields, pagination fields, error shape derived from the actual models, not a hand-copied literal).

**Plus unit tests** (`backend/tests/api/test_api_contract_models.py`): `ApiResponse` round-trips with/without `meta`; `PageMeta`/`ResponseMeta` shapes; `ApiResponse[SomeModel]` and `ApiResponse[list[SomeModel]]` serialize with the single `data` key; `contract_descriptor()` shape.

### 4.4 What does NOT change

- No existing endpoint, model, handler, or route path is modified. `git diff` on every `*_api.py` and on `errors.py` stays empty.
- No frontend change. No new pytest marker. No new CI job/workflow.
- `app/api/schemas.py` gains nothing except (optionally) nothing — `contract.py` imports the existing `ErrorResponse`; it does not edit schemas.py.

## 5. Data flow

```
client GET /api/v1
  → v1_meta router
  → contract_descriptor()  (pure, reads API_CONTRACT)
  → ApiResponse[ContractDescriptor](status="success", data=<descriptor>, meta=None)
  → 200 JSON, X-Request-ID header (via request-id middleware/handlers)

CI (backend-tests, every run)
  → import app + generate OpenAPI
  → partition routes {public vs grandfathered}
  → assert public routes conform to API_CONTRACT
  → TestClient round-trips assert envelope + X-Request-ID
```

## 6. Testing strategy

- **Deterministic, Docker-free, marker-less** — the guard + model unit tests run in `backend-tests` on every CI run (the 29.7 deterministic-core discipline).
- Full backend suite stays green; the only new passing tests are the guard + model/endpoint units. No test is deleted.
- `fastapi` pinned to `0.115.12` before running the full suite (project note: api-surface/OpenAPI-shape tests drift on fastapi version).

## 7. Deliberately out of scope (→ TECH-DEBT §26, no silent drops)

- **Migrating the 20+ legacy `/api/*` endpoints** to `/api/v1` + the canonical `data` envelope (a large, breaking change; each future 30.x sprint migrates its own surface, or a dedicated migration sprint does it).
- **Deprecation / sunset of the legacy `/api/*` paths** (needs a client-migration story).
- **Authentication / API keys / sessions** — 30.8 owns AuthN; 30.0 adds no auth to the meta endpoint.
- **Rate limiting, quotas, request-signing.**
- **Cursor pagination** and a cross-page `total` count (offset + per-page `count` only).
- **Mapping the `app/errors/` domain taxonomy into the HTTP error `code`** (the HTTP layer keeps its status→code map; richer codes are a later enhancement).
- **OpenAPI doc publishing / SDK generation / a human API reference site.**
- **A concrete public `POST /api/v1/query` business endpoint** (explicitly deferred at scope-decision time; a later sprint builds it on this contract).
