# Sprint 31.2 — Relationship Graph UX (Design Spec)

> Frontend sprint (Vue 3 + D3). No pytest/CI — verify via `npm run build` (build artık tam yeşil, §35).
> Phase 12 üçüncü frontend sprint'i. Kullanıcı direktifi: soru sorma, kapsam kararını kendin ver.

## 1. Problem / Brainstorm (karar)
`SchemaManager.vue`'deki D3 ilişki graph'ı (force-simulation, zoom, drag, physics toggle, hover 1-hop
komşu aydınlatma, node→kart odak) olgun ama **graph ↔ sol tablo listesi bağı TEK YÖNLÜ**:
- Graph node'una tıklayınca (`focusNode`, satır ~990/1017) sol kart açılır + kamera node'a zoom'lar. ✓
- **Sol paneldeki tablo kartına tıklayınca** (`toggleTable`) yalnız kart açılıp kapanır — graph'taki
  karşılık gelen node'a **odaklanmaz/zoom yapmaz**. ✗
Ayrıca **kalıcı seçim göstergesi yok**: hover vurgusu `mouseover`/`mouseout` ile geçici; fare
ayrılınca graph düzleşir, o an hangi tablonun seçili/açık olduğu graph'ta görünmez.

**Karar (kapsam):** 31.2 = **çift-yön seçim bağı + kalıcı seçili-node vurgusu**, ikisi de tek
`watch(expandedTable)` üzerinden. Bu, mevcut node→kart davranışının simetriği ve "Relationship Graph
UX" için en net, en yüksek-değerli, düşük-riskli boşluk. Görsel dil mevcut hover paletini yeniden
kullanır (indigo stroke + glow). Force/physics/layout motoru DEĞİŞMEZ.

## 2. Design
`frontend/src/components/SchemaManager.vue` (tek dosya):
- **Module seviyesinde** `let repaintGraphSelection: (() => void) | null = null;` (initGraph dışından
  çağrılabilsin diye closure tutucu).
- **`zoomToGraphNode(tableName: string)`** yeni helper: `simulation.nodes()` içinde `id===tableName`
  node'u bulur; yoksa (izole/limit dışı, graph'a çizilmemiş) **nazikçe no-op** (kart yine açık kalır);
  varsa mevcut `focusNode` zoom transform'unu (center + scale 1.2, 750ms transition) uygular. Guard:
  `svgRef`/`zoomBehavior`/`simulation` null ise çık.
- **`focusNode(node)` sadeleşir** (graph→kart): `expandedTable.value = node.id` + kartı `scrollIntoView`.
  Zoom artık watcher'dan gelir (tekrar yok).
- **`initGraph` içinde** (node selection'ları scope'ta): `const paintSelectedRing = () => {...}` —
  tüm `nodeCircles`'ın stroke/stroke-width/filter'ını `expandedTable.value`'ya göre boyar (seçili:
  indigo `#818cf8` + `url(#glow)` + width 3; diğerleri: neutral `#3f3f46` + drop-shadow + width 2).
  `repaintGraphSelection = paintSelectedRing` atanır ve bir kez çağrılır (mevcut seçimi yansıt).
  `mouseout` handler'ının SONUNA `paintSelectedRing()` eklenir → fare seçili node'dan ayrılınca ring
  geri gelir (aksi hâlde mouseout neutral'a sıfırlıyor). `r` (yarıçap) sıfırlaması mouseout'ta olduğu
  gibi kalır; ring yalnız stroke/filter'ı yönetir → çakışma yok.
- **`watch(expandedTable, (id) => { repaintGraphSelection?.(); if (id) zoomToGraphNode(id); })`** —
  her iki yön de buradan: kart tıklanınca (toggleTable → expandedTable değişir) ve node tıklanınca
  (focusNode → expandedTable değişir) aynı repaint+zoom. Collapse (id=null) → ring temizlenir, zoom yok.
- `toggleTable` değişmez (zaten expandedTable'ı toggle'lıyor; watcher gerisini halleder).

Runtime davranış değişimi yalnız bu bağ/vurgu; force simülasyonu/drag/physics/hover-komşu-aydınlatma
aynen korunur.
