# Sprint 31.5 — Error / Warning UX (Design Spec)

> Frontend sprint (Vue 3). No pytest/CI — verify via `npm run build`.
> Phase 12 altıncı frontend sprint'i. Kullanıcı direktifi: soru sorma, kapsam kararını kendin ver.

## 1. Problem / Brainstorm (karar)
`ChatView.vue` hata gösterimi tek düz kırmızı kutu (`msg.error` ham metni). Backend **zengin bir hata
taksonomisi** taşıyor (`api.ts::Job.error_code` — Sprint 27.2/27.2.1) ama api.ts yorumu der ki
"şu an UI'da gösterilmiyor, yalnız taşınıyor". Dahası `ChatView::checkJobCompletion` `job.error_code`'u
mesaja hiç yazmıyor (`activeMsg.error = job.error_message` yalnız). Yani kullanıcı hatanın **kategorisini**
(girdi mi? güvenlik mi? çalıştırma mı?) ve ne yapması gerektiğini göremiyor.

Backend taksonomisi (`backend/app/errors/codes.py` + `categories.py` + `registry.py::_CATEGORY_BY_CODE`):
7 kategori (INPUT/RETRIEVAL/GENERATION/VALIDATION/SECURITY/EXECUTION/INTERNAL) ve ~25 kod.

**Karar (kapsam):** 31.5 = `error_code`'u UI'da **kullanıcı-okur Türkçe kategori + etiket + kısa ipucuna**
eşleyip hata kutusunda göster; kategoriye göre **ton** ayır (EXECUTION = amber "uyarı"; diğerleri kırmızı
"hata") — sprint'in "Error / Warning" boyutu bu. Saf util (`errorInfo.ts`) + `ChatMessage.errorCode`
yakalama + zenginleştirilmiş kutu. Backend değişmez; bilinmeyen/null kod → nazik fallback ("Hata").

## 2. Design
- **Yeni saf util `frontend/src/utils/errorInfo.ts`:**
  - `CODE_TO_CATEGORY: Record<string, ErrorCategory>` — backend `_CATEGORY_BY_CODE`'un birebir aynası.
  - `CODE_LABEL: Record<string, { label: string; hint?: string }>` — her kod için Türkçe kısa etiket
    (+ birkaçında eyleme dönük ipucu, ör. missing_table→"Tablo adını kontrol edin").
  - `CATEGORY_LABEL: Record<ErrorCategory, { label: string; tone: 'error' | 'warning' }>` — EXECUTION
    tone='warning', diğerleri 'error'.
  - `describeError(code?: string | null, fallbackMessage?: string): { code; category; categoryLabel; label; hint?; tone }`
    — kod bilinmiyor/null ise category='internal' benzeri fallback, label=fallbackMessage ?? "Hata".
- **`ChatView.vue`:** `ChatMessage`'a `errorCode?: string`; `checkJobCompletion`'da
  `activeMsg.errorCode = job.error_code ?? undefined` (failed dalında). Hata kutusu `describeError`
  ile zenginleşir: `tone`'a göre renk (error=kırmızı, warning=amber), kategori rozeti + etiket (başlık),
  altında ham `msg.error` mesajı, varsa ipucu satırı. `error_code` yoksa mevcut düz görünüme yakın
  fallback (ham mesaj). Erişilebilir (`role="alert"`).

Runtime davranış değişimi yok; yalnız zaten taşınan `error_code` görünür kılınır + yakalanır.

## 3. Verify (frontend — pytest/CI yok)
`cd frontend && npm run build` → **0 hata, exit 0**. `errorInfo.ts` saf util → `node --experimental-strip-types`
ile örnek kodlarla doğrula (bilinen kod→doğru kategori/ton; bilinmeyen→fallback; null→fallback).

## 4. Out of scope (TECH-DEBT — sessiz düşürme yok)
- Backend'in her hata yolunda `error_code` set etmesini garanti etmek (bazı yollar hâlâ boş kod
  döndürebilir → fallback devreye girer); taksonomi tamlığı backend işi.
- Warning'lerin (fatal-olmayan) ayrı akışı — şu an tüm hatalar job-failure; EXECUTION yalnız görsel ton.
- Retry/otomatik düzeltme aksiyonları, i18n altyapısı (Türkçe sabit).
- Frontend test altyapısı + CI + toast (§35).
