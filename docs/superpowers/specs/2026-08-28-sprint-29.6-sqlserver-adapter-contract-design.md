# Sprint 29.6 — SQL Server Adapter Contract — Design

**Status:** Approved (brainstorm) — pending user spec review → writing-plans
**Date:** 2026-08-28
**Phase:** 10 (Real Database Adapter Layer)
**Predecessors:** Oracle 29.3 (Contract Adapter) + 29.4 (Docker/Test Harness); MySQL 29.5 (Contract + Harness bundled); PostgreSQL 29.0/29.1. This sprint **bundles** the contract adapter **and** the Docker/test harness into one sprint, exactly like MySQL 29.5 — SQL Server is manageable-risk because `pymssql` is pip-installable (FreeTDS bundled in the wheel, no system ODBC package), so the harness stays additive. The one added weight vs MySQL is the heavier `mcr.microsoft.com/mssql/server` image.

## 1. Purpose & scope

Deliver a real, local-Docker-only, **read-only** SQL Server execution path (`pymssql`, driver-isolated), standalone/inert — **not** wired into the live production request pipeline — plus the full test harness (seed schema + seed applier that also provisions a read-only login + docker-compose service + a dedicated live CI job) that verifies it end-to-end in CI. Mirrors the PostgreSQL 29.0→29.1, Oracle 29.3, and MySQL 29.5 three-layer structure, and the 29.4/29.5 harness pattern.

Like MySQL (and unlike Oracle, which had a 25.9 all-`False` stub), **there is no pre-existing SQL Server code or stub** — this sprint starts from scratch, including adding the `SQLSERVER` dialect to the shared enum.

**Naming convention.** The dialect **value** is `"sqlserver"` (public string) and the pytest marker is `sqlserver`; the **code token** throughout modules/classes/env vars is `mssql` / `MSSQL` (Microsoft SQL Server shorthand — shorter, avoids `SQLSQLServer…` awkwardness). Files: `mssql_adapter.py`, `mssql_connection_resolver.py`, `mssql_execution_adapter.py`, `mssql_seed.py`, `tests/fixtures/mssql/seed.sql`. This value-vs-token split is deliberate and documented so review does not flag it.

### Explicitly out of scope (deferred, no silent drops — TECH-DEBT new §24)

- SQL Server schema introspection (`INFORMATION_SCHEMA` / `sys.*` → `DatabaseSchema`; Postgres 29.0 equivalent) → later sprint.
- SQL Server EXPLAIN-only mode (`SET SHOWPLAN_XML`/`SET SHOWPLAN_ALL`; 29.2 equivalent) → later sprint.
- Live HTTP pipeline wiring / central execution router registry → 30.x.
- Connection registry / remote & production connections / TLS encryption (`Encrypt=yes`) / Azure AD auth → Phase 11 · 30.2.
- `pyodbc` / ODBC-driver path / thick features → deferred unless needed (pure-wheel `pymssql` only).

## 2. Shared contract change

`backend/app/evaluation/multi_database_execution.py`: add `SQLSERVER = "sqlserver"` to `SQLDatabaseDialect` (currently `SQLITE`/`POSTGRESQL`/`ORACLE`/`MYSQL`). Single additive enum member; no existing behavior changes.

## 3. Driver & image

- **Driver:** pin `pymssql==2.3.2` in `backend/requirements.txt` — ships manylinux + Windows wheels with FreeTDS statically bundled, so **no system ODBC/unixODBC package** is needed (this is why pymssql was chosen over pyodbc). It is a C-extension (no pure-Python SQL Server driver exists), but it imports lazily and stays driver-isolated. (The plan verifies the exact latest wheel available for cp311 manylinux + the user's Windows dev box.)
- **Image:** `mcr.microsoft.com/mssql/server:2022-latest` (pinned by the plan to a digest/tag it verifies). Env: `ACCEPT_EULA=Y`, `MSSQL_SA_PASSWORD=Sqlgen_Str0ng!Pass` (meets SQL Server complexity: ≥8 chars, upper+lower+digit+symbol), `MSSQL_PID=Developer` (free edition). Port 1433. Needs ~2GB RAM (`--memory` in CI is fine on ubuntu-latest). **Readiness:** the 2022 server image does **not** reliably bundle `sqlcmd`, so container readiness is owned by a **bounded connect-retry in the seed applier** (`login_timeout` + retry loop) rather than a compose/CI `sqlcmd` healthcheck; the compose service gets a best-effort healthcheck (sqlcmd at `/opt/mssql-tools18/bin/` **if present**, else a TCP probe) — the plan confirms what the pinned image actually ships and picks the working form. The retry-in-applier is the load-bearing mechanism either way.

## 4. SQL Server vs Oracle/MySQL differences (load-bearing)

| Concern | Oracle (29.3) | MySQL (29.5) | SQL Server (29.6) |
|---|---|---|---|
| Read-only enforcement (L3) | `SET TRANSACTION READ ONLY` (server tx) | `START TRANSACTION READ ONLY` (server tx) | **no server-side read-only tx exists** → connect as a **read-only login** (`db_datareader` role only) + always `rollback()`; a write is rejected at the server by role permission |
| Statement timeout | `conn.call_timeout = ms` (driver) | `SET SESSION max_execution_time = ms` (server) | **`pymssql.connect(..., timeout=<ceil(s)>, login_timeout=<s>)`** — driver query timeout (Oracle `call_timeout` spirit; SQL Server has no per-statement server time cap) |
| Connection identity | `service_name` | `database` | `server` + `port` + `database` (dataclass shape unchanged: `host`/`port`/`database`/`user`/`password`) |
| Identifier case | unquoted folds UPPERCASE | preserved as-written (lowercase) | **preserved as-written (lowercase)** — default collation is case-insensitive for *comparison*, but result column/alias names return as written; seed + queries all lowercase, column-key assertions lowercase |
| Driver | `oracledb` thin | `pymysql` | `pymssql` |
| Read-only provisioning | single user | single user | **two credential sets** — an admin (SA) connection that the applier uses to seed + create the read-only login; the read-only login the adapter/resolver use |

## 5. Low-level adapter — `backend/app/evaluation/mssql_adapter.py` (new)

Mirrors the three defense layers:

- **Layer 1 — string gate (before any driver touch):** reuse the shared `validate_read_only_select(sql) -> Optional[str]` (exported from `app.evaluation`). Non-None → deterministic `REJECTED`, no connection/driver/network, regardless of configured connection.
- **Layer 2 — lazy driver import:** `import pymssql` only inside `_execute_select`. Importing the module never loads a DB driver / SQLAlchemy.
- **Layer 3 — read-only login + timeout + rollback:** `pymssql.connect(server=host, port=port, user=user, password=password, database=database, login_timeout=<s>, timeout=<ceil(timeout_seconds)>)` where `user` is the **read-only login** (`db_datareader`). On a cursor (`as_dict=False`): execute SELECT → `fetchmany(max_rows + 1)` → `cursor.description`. `finally`: guarded `rollback()` then `close()`. Read-only is enforced by (a) the L1 string gate and (b) the server rejecting any write for a `db_datareader`-only login; rollback guarantees non-persistence as a third backstop.

New surface (mirrors Oracle/MySQL names, `MSSQL` token):
- `SQLMSSQLAdapterStatus(str, Enum)`: `NOT_IMPLEMENTED`, `REJECTED`, `EXECUTED`, `EXECUTION_ERROR`.
- `SQLMSSQLAdapterCapability` (frozen `supports_*` flags) + `default_local_docker_capability()` (only `live`/`remote`/`production` forced False).
- `SQLMSSQLLocalDockerConnection` (frozen): `host` (allowlist `localhost`/`127.0.0.1`/`::1`), `port`, `database`, `user`, `password`.
- `SQLMSSQLAdapterConfig` (`timeout_seconds`, `max_rows`, `execution_mode`), `SQLMSSQLAdapterExecutionRequest`, `SQLMSSQLAdapterExecutionResult` (`columns`, `rows`, `row_count`, `truncated`, `warnings`, `duration_ms`, `sql_sha256`, `status`, `error`).
- `SQLMSSQLAdapterContract(connection=None)` with `.capability()` and `.execute(request)`.
- `_sanitize_mssql_error(exc) -> str` — never leaks host/user/password/database/server; timeout mapped to a distinct message (pymssql raises `OperationalError`/`_mssql.MSSQLDatabaseException` with number/severity — map the query-timeout signature to the distinct message, everything else to `f"SQL Server execution failed ({type(exc).__name__})."`).
- `SQL_MSSQL_ADAPTER_CONTRACT_VERSION`.

`execute()` is **validate-first** (read-only gate → connection-None), preserving "no-connection + unsafe SQL → REJECTED". `connection is None` (safe SQL) → inert `NOT_IMPLEMENTED`.

## 6. Resolver — `backend/app/evaluation/mssql_connection_resolver.py` (new)

`resolve_local_docker_connection(env=None) -> Optional[SQLMSSQLLocalDockerConnection]` from the `MSSQL_TEST_*` env contract (`MSSQL_TEST_HOST` default `localhost`, `MSSQL_TEST_PORT` `1433`, `MSSQL_TEST_DB` `sqlgen_test`, `MSSQL_TEST_USER` `sqlgen_ro`, `MSSQL_TEST_PASSWORD` `Sqlgen_Ro0!Pass`). Returns the **read-only** connection only. Never connects, never raises: invalid/remote/missing → `None`. `MSSQL_CONNECTION_RESOLVER_VERSION = "v1"`. Mirrors `mysql_connection_resolver.py`.

## 7. Bridge — `backend/app/evaluation/mssql_execution_adapter.py` (new)

`MSSQLDatabaseExecutionAdapter(SQLDatabaseExecutionAdapter)` — dialect-agnostic bridge:
- `dialect -> SQLDatabaseDialect.SQLSERVER`; `capabilities() = (CONNECTION_REF, READ_ONLY)`; **EXPLAIN_ONLY rejected** (`SQLMultiDatabaseExecutionContractError`).
- `__init__(self, connection_resolver=resolve_local_docker_connection)`.
- `execute()` validates dialect/connection_ref/fixture_ref/execution_mode; resolves connection; `None` → graceful empty `SQLDatabaseExecutionResult` + `execution_error` (never raises on that path); else builds `SQLMSSQLAdapterExecutionRequest`, delegates to `SQLMSSQLAdapterContract(connection=…).execute`, normalizes via `normalize_mssql_execution_result`.
- `normalize_mssql_execution_result(mssql_result, request)` + `_rows_to_dicts(rows, columns)` (`col_<i>` positional fallback + warning on arity mismatch). `sql_sha256` from the original request SQL.
- **NOT** re-exported from `app/evaluation/__init__.py` (harness-only), nor is `mssql_connection_resolver`/`mssql_seed`. `mssql_adapter` MAY be exported like `oracle_adapter`/`mysql_adapter` (plan decides — default: export the low-level adapter surface, leave resolver/execution-adapter/seed unexported).

## 8. Seed schema — `backend/tests/fixtures/mssql/seed.sql` (new)

Mirrors the 29.0/29.4/29.5 seed **shape** in SQL Server dialect, with the **same deterministic rows**:
- `customers` / `orders` / `order_items` — single-column PK/FK.
- `product_variants` / `variant_stock` — composite PK/FK `(product_id, sku)`.

Dialect: `INT`, `NVARCHAR(n)`, `DATETIME2` (literal `'2020-01-01T00:00:00'`), `DECIMAL(10,2)`; PK/FK via `PRIMARY KEY`/`FOREIGN KEY` constraints (SQL Server enforces by default). All identifiers lowercase; one row per `INSERT`; **no `GO` batch separators** (statements are applied one-by-one by the driver, split on `;` — same splitter as the others); no `DROP`. FK-declaration order: customers → orders → order_items; product_variants → variant_stock. Same row values as Postgres/Oracle/MySQL seeds (Ada/Alan; 3 orders; 4 order_items; 2 product_variants; 2 variant_stock). **Statement count: 5 CREATE + 13 INSERT = 18** (read-only-login provisioning is NOT here — see §9, keeping this a clean mirror).

## 9. Seed applier — `backend/app/evaluation/mssql_seed.py` (new)

Mirrors `mysql_seed.py`, with the SQL Server read-only-user delta:
- `split_statements(sql) -> tuple[str, ...]` — pure; splits on `;`, strips `--` line comments and blanks. (Deliberate per-dialect duplication of `mysql_seed.split_statements` — same logic, kept per-dialect to avoid cross-dialect coupling. Flagged so review does not treat it as an accidental copy.)
- `apply_seed(connection, sql) -> int` — executes each statement, commits once, returns count.
- `provision_readonly_login(connection, *, login, password, database) -> None` — **new SQL Server delta**: run (as the admin/SA connection) `CREATE LOGIN <login> WITH PASSWORD = '<pw>', CHECK_POLICY = OFF;` then `USE <database>; CREATE USER <login> FOR LOGIN <login>; ALTER ROLE db_datareader ADD MEMBER <login>;`. Idempotent-guarded (`IF NOT EXISTS (SELECT … sys.server_principals …)`) so a re-run against an existing volume does not fail.
- `main(argv=None) -> int` — lazy-imports `pymssql`; connects as the **admin** connection from `MSSQL_TEST_ADMIN_USER`/`MSSQL_TEST_ADMIN_PASSWORD` (default `sa` / `Sqlgen_Str0ng!Pass`) with a **bounded connect-retry** (login_timeout + N attempts) to own container readiness; applies the seed file (default `tests/fixtures/mssql/seed.sql` relative to cwd = `backend/`); then calls `provision_readonly_login` for `MSSQL_TEST_USER`/`MSSQL_TEST_PASSWORD`. Invoked `python -m app.evaluation.mssql_seed`. `pymssql` imported lazily inside `main()` only; module NOT added to `__init__.py`. `MSSQL_SEED_VERSION = "v1"`.

## 14. Risks

- **Read-only enforcement correctness.** No server read-only tx exists; the guarantee rests on (a) L1 string gate, (b) the `db_datareader`-only login, (c) always-rollback. The two-credential provisioning (admin seeds + creates RO login) is the novel piece — covered by the seed test (`provision_readonly_login` issues the role grant) and, live, by CI running the adapter as the RO login.
- **Image weight / readiness.** mcr 2022 is ~2GB and has no reliable in-image `sqlcmd`; readiness is owned by the applier's bounded connect-retry, not a healthcheck. Separate additive job (`timeout-minutes: 20`) keeps the main suite unblocked.
- **Driver isolation.** `pymssql` (and `_mssql`) imported lazily only; subprocess test enforces absence at import time.
- **`split_statements` duplication.** Deliberate per-dialect copy; flagged so review does not treat it as accidental.
- **Naming value-vs-token split.** Dialect value `"sqlserver"` / marker `sqlserver` vs code token `mssql`/`MSSQL` — documented (§1) so review does not flag the mismatch.
- **`pymssql` wheel availability.** Plan verifies the pinned version ships cp311 manylinux + Windows wheels with bundled FreeTDS (the whole reason it was chosen over pyodbc).
