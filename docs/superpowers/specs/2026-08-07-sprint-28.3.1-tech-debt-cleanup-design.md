## 3. Kalemler (bundle bazında)

### A) Trace/observability doğruluğu

**§5.3 — SECURITY span outcome'u stage değil kategori/severity'den türetilir.**
`backend/app/trace/live_trace_assembly.py:162-175`. Bugün `security_issues` (stage ∈
`_SECURITY_STAGES = {sql_guardrail, sql_sandbox_safety}`) her girdisi hardcoded
`outcome="denied"` alır → kategorisi VALIDATION olan bir hata (ör. `sql_parse_error`) canlı
trace'te yanıltıcı "güvenlik reddi" görünür. Düzeltme: her girdinin outcome'u **27.2 error
registry'den** türetilir (`e["type"]` error-code → `ErrorCategory`/severity), `build_security_span`'in
mevcut `_DENY_OUTCOMES`/`_WARN_OUTCOMES` mantığına uygun bir outcome string'ine map'lenir.
`_SECURITY_STAGES` SELECTION değişmez (pinning testi `test_security_stages_set_is_still_stages_not_codes`
yeşil kalır, spec §3.3 kategori/stage ayrımı korunur). Registry bu modülde zaten import edili
(INPUT/RETRIEVAL dalları kullanıyor). ~5 outcome-assert testi (`test_live_trace_assembly.py`)
güncellenir. Determinizm/kontrat korunur; yalnız outcome doğruluğu düzelir.

**§8.1 — feedback pencere sınırı trace yoluyla tutarlı normalize edilir.**
`backend/app/database.py:324-347` (`list_feedback`). Bugün `created_after/before` ham string
lexicographic karşılaştırılır; `feedback.created_at` naive-UTC ISO (`utcnow().isoformat()`)
saklanır; trace store ise sınırı `fromisoformat(...).astimezone(utc)` ile normalize eder →
offset-aware bir sınır feedback'i 3 saat kaydırabilir. Düzeltme: `list_feedback`'te sınırlar
karşılaştırmadan önce **naive-UTC'ye normalize edilir** (ISO parse → UTC'ye çevir → tzinfo
strip; parse edilemezse ham string'e düş — geriye-uyumlu). Böylece offset-aware sınır, naive-UTC
feedback damgalarıyla aynı instant'ı filtreler. `test_database_list_feedback.py`'ye offset-aware
case eklenir; naive-sınır case'leri değişmez. 2 prod caller (dashboard/rule_suggestions) naive
sınırda davranış korur.

**§8.4a — debug-gate param validation'dan önce çalışır (geçersiz bucket → 404, debug kapalıyken).**
`backend/app/api/dashboard_api.py:29-43`. Bugün `bucket: Literal["hour","day"]` FastAPI param
validation'ı fonksiyon gövdesindeki `ensure_debug_enabled()`'dan ÖNCE koşar → debug kapalıyken
geçersiz `bucket` 404 yerine 422 döner (endpoint varlığını sızdırır). Düzeltme: `ensure_debug_enabled`
bir `Depends(...)`'e taşınır (gövdeden ve dolayısıyla param-coercion 422'sinden bağımsız olarak,
FastAPI dependency çözümünde çalışır — 404'ü önce döndürür). Debug AÇIKken geçersiz bucket hâlâ
422 döner. 1 contract testi koşullu güncellenir (`test_dashboard_invalid_bucket_422`: debug kapalı
→ 404, açık → 422). Kardeş `metrics_api` (kısıtlı param'ı yok) kapsam dışı.

**§8.4c — sözleşme-doc notu.** Dashboard sözleşme dokümanına bir cümle: `bucket.error_count`
(terminal-status bazlı) ≠ `metrics.errors` (span-code bazlı) — ikisi de doğru, toplamları farklı.
Doc-only, kod değişikliği yok.

### B) Debug bundle sağlamlığı

**§6.1 — `_latest_debug_trace` trace_type ile doğrudan sorgular.**
`backend/app/bundle_service.py:38-47`. Bugün `TraceQuery(limit=5, job_id=...)` çekip Python'da
`end_to_end` olmayanı arar → bir job'un ≥5 `end_to_end` kaydı debug trace'ten önce gelirse debug
trace pencere dışı kalır, bundle `sql`'i null döner. Düzeltme: `TraceQuery(trace_type="nl2sql",
job_id=..., limit=...)` ile debug trace türü DOĞRUDAN sorgulanır (`TraceQuery.trace_type` +
`DebugTraceAdapter` zaten destekliyor; kardeş `_latest_end_to_end_payload` aynı deseni kullanıyor).
Pencere-kaçırma kapanır. Adanmış test yok → düşük risk; bundle-composition testleriyle dolaylı kapsanır.

### C) 28.3 cost-model takipleri

**§12.16 — fallback yolu cost_budget'a gate edilir + çelişkili bayraklar tutarlılaştırılır.**
`backend/app/schema/schema_context_selector.py` fallback dalı. Bugün fallback satırları
(`fallback_used=True`, ≤5 tablo) `cost_budget` kontrolü YAPMADAN eklenir; patolojik geniş-tek-aday
durumunda `budget_exhausted=True` ile `fallback_used=True` çelişkili görünür ve fallback satırları
bütçeyi aşabilir. Düzeltme: fallback append'leri de bütçeye gate edilir (bütçeyi aşan fallback
satırı atlanır, `max_fallback_tables`/`fallback_limit` korunur) VE bayrak tutarlılığı sağlanır
(fallback path'e girildiğinde `budget_exhausted` fallback'in kendi bütçe davranışını yansıtır).
Patolojik geniş-tek-aday testi eklenir. Golden eval/benchmark davranışı DEĞİŞMEZ (default budget=30
altında bu yol golden/benchmark'ta tetiklenmiyor — 28.3'te doğrulandı).

**§12.17 — uçtan-uca pipeline wiring testi.**
`backend/tests/schema/test_cost_model_pipeline_wiring.py` (mevcut, parse-only). Yeni test:
pipeline'ın config kaynağını (`get_config`) monkeypatch'leyip override'lı bir cost-model JSON
döndürür, seçim path'ini çalıştırır ve sonucun override'ı **fiilen yansıttığını** assert eder
(ör. override'lı ağırlık/bütçe DEFAULT'tan farklı bir seçim üretir). Test-only; kaza sonucu
call-site kablolamasının silinmesini yakalar.

**§12.6 — scipy-yokluğu zarifçe ele alınır (dep yok).**
