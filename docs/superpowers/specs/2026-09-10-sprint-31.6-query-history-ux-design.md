# Sprint 31.6 — Query History UX (Design Spec)

> Frontend sprint (Vue 3). No pytest/CI — verify via `npm run build`.
> Phase 12 yedinci frontend sprint'i. Kullanıcı direktifi: soru sorma, kapsam kararını kendin ver.

## 1. Problem / Brainstorm (karar)
`History.vue` (340 satır) job listesini tablo + detay modalı ile gösteriyor (`listJobs(100,0)`; dialect
rozeti, status rozeti, iptal, SQL kopya). İki net UX boşluğu:
1. **Arama/filtre YOK** — 100'e kadar job yüklenirken belirli bir sorguyu bulmanın yolu yok.
2. **Failed detay modalı** yalnız ham `error_message` gösteriyor; 31.5'te eklenen `describeError`
   (kategori + Türkçe etiket + ipucu + ton) burada kullanılmıyor (tutarsız hata UX'i).

**Karar (kapsam):** 31.6 = **client-side metin araması + status filtresi** (yüklenmiş joblar üzerinde,
yeni API çağrısı yok) + **filtreli-boş durumu** (hiç geçmiş yok ≠ eşleşme yok) + failed detay modalında
**31.5 `describeError` reuse** (tutarlı hata gösterimi). Dar, düşük-risk, mevcut tablo/modalı korur.

## 2. Design
`History.vue` (tek dosya):
- `import { computed } from 'vue'` + `import { describeError } from '../utils/errorInfo'`.
- `searchText = ref('')`, `statusFilter = ref<'all' | Job['status']>('all')`.
- `filteredJobs = computed(...)`: `jobs` üzerinden — status 'all' değilse `job.status===statusFilter`;
  `searchText` doluysa `natural_query` **veya** `result_sql` içinde case-insensitive alt-dize eşleşmesi.
- **Filtre barı** (tablo kartının üstünde): metin arama input'u (placeholder "Sorgu veya SQL'de ara…",
  temizle butonu) + status `<select>` (Tümü/Başarılı/Hatalı/İşleniyor/İptal/Beklemede) + sonuç sayacı
  ("N / M sorgu"). Tablo `v-for`'u `filteredJobs` kullanır.
- **Boş durumlar:** `jobs.length===0` → mevcut "Geçmiş Bulunmamaktadır"; `jobs.length>0 &&
  filteredJobs.length===0` → yeni "Eşleşen sorgu yok" (filtreyi temizle ipucu).
- **Failed detay modalı:** ham `error_message` bloğunun üstüne `describeError(selectedJob.error_code,
  selectedJob.error_message)` ile kategori rozeti + etiket + (varsa) ipucu; ton'a göre renk. Ham mesaj
  altında korunur.

Yeni API çağrısı yok (30.5 `/query-history` gelecekte bağlanabilir, bu sprint client-side filtre yeterli);
mevcut listJobs/iptal/kopya/modal akışı korunur; yeni bağımlılık yok.
