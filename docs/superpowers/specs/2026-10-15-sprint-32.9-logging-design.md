# Sprint 32.9 — Logging (Design)

Phase 13 · Branch `feat/32.9-logging` · Önceki: 32.4 (worker), 32.2 (secret resolver), 27.x (trace/redaction).

## 1. Problem & karar

API process'inde **merkezi log yapılandırması yok**. Uvicorn yalnız kendi `uvicorn.*` logger'larını kuruyor; `app.*`
logger'ları root'a yayılıyor ve root'ta handler olmadığı için Python'un "last resort" handler'ı yalnız WARNING+
basıyor → `RequestLoggingMiddleware`'in INFO istek logları (request_id, süre, durum) ve tüm INFO uygulama logları
**prod'da hiç görünmüyor**. Worker kendi `basicConfig`'ini kuruyor (düz metin). Log seviyesi/formatı ayarlanamıyor;
JSON log'lar tek satırlık JSON string olarak mesaja gömülü; log'larda secret maskelemesi yok (trace'lerde var);
request_id yalnız istek log satırında, job yürütürken worker log'larında job_id yok; birkaç yerde `print()`.

**Karar (kapsam):** tek `app/logging_config.py::configure_logging()` — API (import'ta), worker ve CLI'lar çağırır.
- `NL2SQL_LOG_LEVEL` (INFO) ve `NL2SQL_LOG_FORMAT` (`text` | `json`; varsayılan `text`, **prod compose `json`**).
- **JSON formatter**: satır başına bir obje — `ts` (UTC ISO), `level`, `logger`, `message`, bağlam (`request_id`,
  `job_id`), `exc_info` (traceback). Mesaj zaten bir JSON objesi ise (mevcut `http_request`/`http_error` olayları)
  alanları **birleştirilir** (iç içe string değil).
- **Bağlam**: `contextvars` — `RequestLoggingMiddleware` `request_id`'yi, job executor `job_id`'yi (ve job'un
  `request_id`'sini) ayarlar; her log kaydına filtre ile eklenir (text formatında da `[req=… job=…]`).
- **Redaction filtresi**: her kayıt mesajı ve exception metni `redact_sensitive_text` (27.x desenleri: `api_key=`,
  `token=`, `sk-…`, `nvapi-…`) + bilinen secret değerleri (`known_secret_values()`, 60 sn önbellekli) ile maskelenir.
- **Uvicorn**: `uvicorn` / `uvicorn.error` aynı handler'a yönlendirilir; `uvicorn.access` WARNING'e çekilir (istek
  başına satırı zaten `http_request` olayı — request_id'li — veriyor; çift satır yok).
- `main.py` başlangıç `print()`'leri logger'a.
- Idempotent: yalnız kendi kurduğu handler'ı değiştirir (pytest `caplog` vb. diğer handler'lara dokunmaz).

Seçilmeyen:
- (a) `structlog`/`python-json-logger` bağımlılığı — 80 satırlık formatter için yeni bağımlılık; stdlib yeterli.
- (b) Log dosyasına yazma / rotasyon — konteynerde stdout/stderr standart; toplama (Loki/ELK) platformun işi.
- (c) Prometheus `/metrics` — 27.6 metrik sözleşmesi + 32.7 bileşen durumları var; exporter ayrı iş (TECH-DEBT §45).
- (d) Tüm modüllerdeki `print()`'leri dönüştürmek (`schema_manager.py` 13 adet, eval/seed CLI'ları kullanıcı çıktısı) —
  yalnız sunucu yolu (`main.py`); kalanlar §45.

## 2. Verify
`backend/tests/test_logging.py`: JSON alanları + gömülü JSON birleştirme + exception; text formatı bağlamı; seviye;
request_id istek içi log'a akar (middleware + endpoint log'u); job_id executor'da; redaction (desen + dosya-tabanlı
secret değeri + traceback); uvicorn yönlendirme/access seviyesi; idempotent kurulum (caplog korunur); geçersiz
ayar reddi; sözleşme+docs. Full suite + CI smoke: prod compose backend log'unda JSON `http_request` satırı
`request_id` ile görünür.

## 3. Out of scope (TECH-DEBT §45)

- Kalan `print()`'ler (`schema_manager.py` vb.).
- Log örnekleme / hız sınırlama; denetim (audit) log'unun ayrı kanala yazılması.
