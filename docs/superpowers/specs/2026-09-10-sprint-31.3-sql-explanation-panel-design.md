# Sprint 31.3 — SQL Explanation Panel (Design Spec)

> Frontend sprint (Vue 3). No pytest/CI — verify via `npm run build`.
> Phase 12 dördüncü frontend sprint'i. Kullanıcı direktifi: soru sorma, kapsam kararını kendin ver.

## 1. Problem / Brainstorm (karar)
Query composer (`ChatView.vue`) üretilen SQL'i tek `<pre>` bloğunda ham gösteriyor. Kullanıcı
(özellikle SQL'e hâkim olmayan) sorgunun **ne yaptığını** okumak için tüm metni ayrıştırmak zorunda.
"SQL Explanation Panel" bunu okunur kılmalı.

**Backend araştırması (önemli karar girdisi):** Backend **bilinçle yalnız ham SQL döndürür** —
`llm_client.py`/`sql_prompt_builder.py` "Return only SQL. No explanation." talimatı verir,
`structured_output_parser.py` prose/açıklama satırlarını **reddeder**. `Job` modelinde
(`api.ts::Job`) explanation/reasoning alanı YOK. Yani **sunulacak backend açıklaması yoktur** ve
bu frontend sprint'i backend desenini değiştirmez. → Açıklama **deterministik, client-side** üretilmeli
(LLM yok, ağ yok).

**Karar (kapsam):** 31.3 = üretilen SQL'i **üst-düzey clause'lara** ayıran saf bir client-side
ayrıştırıcı (`explainSql`) + SQL bloğunun altında **katlanabilir "Sorgu Açıklaması" paneli**. Her
clause (SELECT / FROM / JOIN / WHERE / GROUP BY / HAVING / ORDER BY / LIMIT / OFFSET / UNION…)
Türkçe okunur bir etiketle + kendi metniyle listelenir. Deterministik, salt-okunur, additive (ham
SQL bloğu değişmez). LLM tabanlı doğal-dil açıklama bilinçle kapsam dışı (güvenilmez, backend-değişikliği
+ maliyet gerektirir).

## 2. Design
**Yeni saf util `frontend/src/utils/sqlExplain.ts`:**
- `export interface ExplainClause { keyword: string; label: string; body: string }`
- `export function explainSql(sql: string): ExplainClause[]` — tek geçişli tarayıcı: paren derinliği
  (`depth`) ve tırnak durumunu (`'`, `"`) izler; clause anahtar kelimelerini **YALNIZ depth 0 ve tırnak
  dışında**, kelime-sınırında (`\b`) tanır → string literal / alt-sorgu içindeki kelimeler bölmez.
  Tanınan üst-düzey anahtarlar (sırayla, çoklu-kelime öncelikli): `SELECT`, `FROM`,
  `LEFT JOIN`/`RIGHT JOIN`/`INNER JOIN`/`FULL JOIN`/`CROSS JOIN`/`JOIN`, `WHERE`, `GROUP BY`,
  `HAVING`, `ORDER BY`, `LIMIT`, `OFFSET`, `UNION ALL`/`UNION`, `INTERSECT`, `EXCEPT`. Her sınırda
  {keyword, label, body} kaydı üretilir; body = bir sonraki üst-düzey anahtara kadarki metin (trim'li).
  Girdi boş/parse edilemezse `[]` döner (panel gösterilmez → güvenli fallback).
- Türkçe etiketler: SELECT→"Seçilen sütunlar", FROM→"Kaynak tablo(lar)", JOIN ailesi→"Birleştirme (JOIN)",
  WHERE→"Filtre koşulu (WHERE)", GROUP BY→"Gruplama (GROUP BY)", HAVING→"Grup filtresi (HAVING)",
  ORDER BY→"Sıralama (ORDER BY)", LIMIT→"Satır limiti (LIMIT)", OFFSET→"Atlama (OFFSET)",
  UNION→"Birleşim (UNION)", INTERSECT→"Kesişim (INTERSECT)", EXCEPT→"Fark (EXCEPT)".

**`ChatView.vue`:**
- `import { explainSql } from '../utils/sqlExplain'`.
- Per-message açık/kapalı durum: `expandedExplanationId = ref<number | null>(null)` (aynı anda tek
  panel açık; `msg.id`'ye keyed — 31.0 copy-state deseni).
- SQL bloğunun altına (`</pre>` sonrası, kart içinde) katlanabilir panel: başlık butonu
  ("Sorgu Açıklaması", chevron, `aria-expanded`), açıkken `explainSql(msg.sql)` çıktısını satır
  listesi olarak render (etiket + `<code>` body). Varsayılan KAPALI. Panel yalnız `explainSql`
  boş-olmayan döndürünce anlamlı; boşsa buton yine görünür ama "Açıklama üretilemedi" der (nadir).
- `prefers-reduced-motion` saygılı (chevron rotate dışında motion yok).

Runtime davranış değişimi yok (yeni salt-okunur görünüm); mevcut SQL bloğu/copy/log akışı aynen kalır.
