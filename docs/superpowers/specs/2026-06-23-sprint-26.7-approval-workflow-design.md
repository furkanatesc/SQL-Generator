# Sprint 26.7 — Approval Workflow Contract · Design

**Phase 7 (Security & Governance) · Contract-first, no I/O · 2026-06-23**

## 1. Purpose

Sprints 26.0 (permission policy) and 26.4 (sensitive-data policy) can return a
`REQUIRES_APPROVAL` decision — a point-in-time verdict that "a human must sign off
before this runs." Nothing in the stack yet **orchestrates** that sign-off: the
signal is raised (and recorded by 26.6 audit as `AuditOutcome.REQUIRES_APPROVAL`)
but there is no contract that opens a request, collects approver decisions, and
settles it.

26.7 defines an **Approval Workflow Contract**: a pure, deterministic **approval
state machine**. A `REQUIRES_APPROVAL` signal opens an immutable `ApprovalRequest`;
the request collects approver decisions and settles into a terminal state under
two governance rules:

* **Quorum (N-of-M):** `required_approvals` distinct approvers must approve.
* **Separation of duties (SoD):** the requester can never approve their own request.

It is a **state machine + normalizer**, not a sink: it performs **no I/O, calls no
clock, uses no randomness**. Time (`occurred_at`, `expires_at`, `now`) and ids
(`request_id`) are caller-supplied so every transition is deterministic and
reproducible — exactly the 26.6 posture. Persistence, notification, scheduling, and
real RBAC are out of scope (later phases).

## 2. Scope

**In scope:** the contract — state/decision/category/reason enums; immutable
`ApprovalDecision` and `ApprovalRequest` records with secret-free `to_dict()`;
pure transition functions (`open`, `approve`, `reject`, `cancel`, `expire`) that
each return a **new** frozen request; two `from_permission` / `from_sensitive`
builders that open a request from a `REQUIRES_APPROVAL` source result (fail-closed
guard + sensitivity→quorum mapping); fail-closed edge semantics (SoD, duplicate
vote, terminal-state immutability, `N>=1`); and an extension to the merged 26.6
`audit_event.py` adding `AuditCategory.APPROVAL` and a `from_approval` builder so
every transition links into the existing tamper-evident hash chain. Exhaustive unit
tests.

**Out of scope (later / deliberate):** persistence, file/DB/network I/O,
notification/transport (Phase 13); scheduling/real timers (expiry is caller-driven,
§6); **approver eligibility / RBAC roles** — *who* is allowed to approve a given
category/severity is the policy-driven layer explicitly deferred (this sprint
enforces quorum + SoD only, not role eligibility); asymmetric signing / its own
hash chain (audit integrity is reused from 26.6, not duplicated); clocks, id
generation, or any nondeterminism; API/UI; concurrency/locking (caller owns
ordering by threading the returned request).

## 3. Module layout

- `backend/app/security/approval_workflow.py`
- `backend/tests/security/test_approval_workflow.py`
- Exported from `backend/app/security/__init__.py` (mirrors 26.0–26.6).
- Contract version: `approval_workflow_contract_v1`
  (constant `APPROVAL_WORKFLOW_CONTRACT_VERSION = "approval_workflow_contract_v1"`).
- **Import direction (no cycle):** `approval_workflow.py` imports the 26.0 / 26.4
  result and decision types to type and guard its `from_*` builders. The merged 26.6
  `audit_event.py` is extended to import `approval_workflow` for its new
  `from_approval` builder. The graph stays one-way:
  `audit → approval → {permission, sensitive}`. `approval_workflow` **never** imports
  `audit_event`, so no cycle is introduced.
- stdlib only (`dataclasses`, `enum`, `typing`). No I/O, no clock, no randomness, no
  new dependency. House style mirrors 26.0–26.6: frozen dataclasses, `__post_init__`
  validation, version-checked, secret-free.

## 4. Enums

```python
class ApprovalState(str, Enum):          # lifecycle; only PENDING is non-terminal
    PENDING   = "pending"
    APPROVED  = "approved"
    REJECTED  = "rejected"
    EXPIRED   = "expired"
    CANCELLED = "cancelled"

class ApprovalDecisionType(str, Enum):   # one approver's vote
    APPROVE = "approve"
    REJECT  = "reject"

class ApprovalCategory(str, Enum):       # origin of the approval requirement
    PERMISSION     = "permission"        # 26.0
    SENSITIVE_DATA = "sensitive_data"    # 26.4

class ApprovalReasonCode(str, Enum):     # WHY the request is in its current state
    OPENED            = "opened"               # PENDING, freshly opened
    APPROVAL_RECORDED = "approval_recorded"    # PENDING, an approve recorded, quorum not yet met
    QUORUM_MET        = "quorum_met"           # APPROVED
    REJECTED_VETO     = "rejected_veto"        # REJECTED (single reject vetoes)
    CANCELLED         = "cancelled"            # CANCELLED
    EXPIRED           = "expired"              # EXPIRED
```

`TERMINAL_STATES = {APPROVED, REJECTED, EXPIRED, CANCELLED}`; `PENDING` is the only
state any transition may act on.

## 5. Records (immutable, secret-free)

```python
@dataclass(frozen=True)
class ApprovalDecision:                   # one approver's vote
    approver: str                         # required, non-empty
    decision: ApprovalDecisionType
    occurred_at: str                      # caller-supplied ISO-8601 UTC string (shape-checked)
    def to_dict(self) -> Dict[str, Any]: ...

@dataclass(frozen=True)
class ApprovalRequest:
    schema_version: str                   # must == APPROVAL_WORKFLOW_CONTRACT_VERSION
    request_id: str                       # caller-supplied, non-empty
    requester: str                        # WHO asked — SoD anchor, non-empty
    category: ApprovalCategory            # origin (26.0 / 26.4)
    required_approvals: int               # quorum N, >= 1
    state: ApprovalState
    decisions: Tuple[ApprovalDecision, ...]   # append-only history (approves + the veto reject)
    reason_code: ApprovalReasonCode
    sql_sha256: Optional[str]             # copied from source (sensitive carries it; permission None)
    resource_id: Optional[str]            # e.g. a table/query id — never raw SQL
    opened_at: str                        # caller-supplied ISO-8601 UTC string
    expires_at: Optional[str]             # caller-supplied; compared in expire()
    def to_dict(self) -> Dict[str, Any]: ...   # JSON-safe; enum .value's; no raw SQL
```

**Validation (`__post_init__`, raises `ApprovalWorkflowContractError`):**
- `schema_version` must equal `APPROVAL_WORKFLOW_CONTRACT_VERSION`.
- `request_id`, `requester`, `opened_at` must be non-empty strings; `resource_id`,
  `expires_at` non-empty-or-`None`.
- `required_approvals` must be an `int >= 1`.
- `category`, `state`, `reason_code` must be the real enum types.
- `decisions` must be a tuple of `ApprovalDecision`; each approver non-empty.
- `sql_sha256`, when not `None`, must match `^[a-f0-9]{64}$`.
- `ApprovalDecision`: `approver`, `occurred_at` non-empty; `decision` an
  `ApprovalDecisionType`.

The `count_approvals()` helper (distinct APPROVE votes) and `is_terminal` are derived
read-only conveniences, not stored fields.

## 7. Fail-closed edge semantics

1. **Separation of duties:** in `approve`/`reject`, `approver == request.requester`
   → raise `ApprovalWorkflowContractError`. A requester can never vote on their own
   request.
2. **Duplicate vote:** in `approve`/`reject`, an `approver` already present in
   `request.decisions` → raise. No approver is counted twice toward quorum.
3. **Terminal immutability:** `approve`/`reject`/`cancel`/`expire` on a request whose
   `state` is not `PENDING` → raise. Terminal states never transition again.
4. **Quorum bound:** `required_approvals` must be an `int >= 1`; `0`/negative/non-int
   → raise (a request that needs zero approvals would auto-approve, defeating the
   gate).

These mirror the 26.0–26.6 fail-closed bias: an ambiguous or out-of-protocol call
raises rather than silently degrading.

## 8. Secret-freedom

The contract carries **no raw SQL and no free-text payload**. There is deliberately
**no approver comment/note field**: free text is an uncontrolled channel through
which raw SQL or PII could leak into the record, breaking the secret-free invariant
every 26.x result holds. The only payloads are ids, enum values, and `sql_sha256` /
`resource_id` — copied verbatim from source results already proven secret-free in
26.0/26.4. `to_dict()` emits enum `.value`s and nested `to_dict()`s — JSON-safe, no
objects, no statement text. Tests assert a planted secret (SSN / raw SQL) never
appears in `to_dict()`.

## 9. Audit interlock (extends merged 26.6 `audit_event.py`)

To link approval transitions into the existing tamper-evident chain rather than
build a second one, 26.6 is extended (not duplicated):

```python
class AuditCategory(str, Enum):
    ...                                   # existing six
    APPROVAL = "approval"                 # 26.7

def from_approval(request: ApprovalRequest, *, event_id, occurred_at,
                  actor: AuditActor, resource: AuditResource,
                  prev: Optional[AuditEvent] = None) -> AuditEvent:
    # category=APPROVAL, action="orchestrate_approval".
    # state -> outcome via _APPROVAL_STATE_OUTCOME:
    #   APPROVED -> ALLOWED, REJECTED -> DENIED, PENDING -> REQUIRES_APPROVAL,
    #   EXPIRED -> DENIED, CANCELLED -> DENIED.
    # state -> severity via _APPROVAL_STATE_SEVERITY:
    #   APPROVED -> INFO, PENDING -> MEDIUM, REJECTED -> HIGH,
    #   EXPIRED -> MEDIUM, CANCELLED -> LOW.
    # reason_code=request.reason_code.value, reason= a fixed per-state human string
    #   from a _APPROVAL_STATE_REASON table (e.g. APPROVED -> "approval quorum met"),
    # contract_source=APPROVAL_WORKFLOW_CONTRACT_VERSION,
    # sql_sha256=request.sql_sha256, details=request.to_dict().
```

`audit_event.py` gains an import of `approval_workflow` (one-way; §3). The mapping
tables are small module-level dicts, unit-tested per state. The chain machinery
(`link`/`verify_chain`) is reused unchanged.

## 10. Errors

`ApprovalWorkflowContractError(ValueError)` mirrors the sibling `*ContractError`
hierarchy. Raised on: `schema_version` mismatch; missing/empty required strings;
`required_approvals` not `int >= 1`; wrong enum types; bad `sql_sha256` hex;
non-`ApprovalDecision` in `decisions`; a `from_*` builder whose source decision is
not `REQUIRES_APPROVAL`; an SoD violation, a duplicate vote, a terminal-state
transition, or an `expire` whose precondition is unmet.

## 11. Documented limitations (26.x honesty)

- **Clockless / caller-driven expiry.** The contract never reads time. `expire`
  compares caller-supplied `now` to `expires_at` as **plain string comparison** of
  ISO-8601 UTC strings; it does not parse timezones or validate real timestamp
  semantics. Lexicographic compare is correct only for same-shape UTC `Z` strings —
  documented as the caller's responsibility, same posture as 26.6.
- **No persistence / ordering authority.** The contract does not store requests or
  assign sequence; the caller threads each returned request into the next transition.
  Concurrency and durable storage are Phase 13.
- **Quorum + SoD, not RBAC.** It enforces *how many* distinct non-requester approvers
  are needed, not *who is eligible*. Role/permission-based approver eligibility (e.g.
  "RESTRICTED needs a security-role approver") is the policy-driven layer deferred to
  a later sprint.
- **Integrity is inherited, not re-proven.** Tamper-evidence comes from the 26.6
  chain via `from_approval`; 26.7 adds no new integrity machinery and no new raw-SQL
  surface.

## 12. Test matrix

- **Record validation:** each required field empty/wrong-type → raises; good record
  builds; `required_approvals` `0`/negative/non-int → raises; bad `sql_sha256` hex →
  raises; non-`ApprovalDecision` in `decisions` → raises; `schema_version` mismatch →
  raises.
- **Immutability:** `ApprovalRequest`/`ApprovalDecision` mutation →
  `FrozenInstanceError`; transitions return a new object, input unchanged.
- **`to_dict()` secret-free + JSON-safe:** `json.dumps(request.to_dict())` succeeds;
  enums are strings; a planted SSN / raw SQL string is absent.
- **Open + builders:** `open` yields PENDING/`OPENED`/empty decisions;
  `from_permission` on a REQUIRES_APPROVAL result → N=1, category PERMISSION,
  `sql_sha256 is None`; non-REQUIRES_APPROVAL result → raises;
  `from_sensitive` maps CONFIDENTIAL→1, RESTRICTED→2, copies `sql_sha256`;
  non-REQUIRES_APPROVAL result → raises.
- **Quorum:** N=1 single approve → APPROVED; N=2 first approve → PENDING/
  `APPROVAL_RECORDED`, second distinct approve → APPROVED/`QUORUM_MET`;
  `count_approvals` tracks distinct approves.
- **Reject veto:** one reject (even with approvals pending) → REJECTED/`REJECTED_VETO`.
- **Cancel / expire:** `cancel` → CANCELLED; `expire` with `now >= expires_at` →
  EXPIRED; `expire` with no `expires_at` or `now < expires_at` → raises.
- **SoD:** `approver == requester` on approve/reject → raises.
- **Duplicate vote:** same approver twice → raises.
- **Terminal immutability:** approve/reject/cancel/expire on every terminal state →
  raises.
- **Audit interlock (extends 26.6 tests):** `from_approval` for each state yields the
  mapped outcome/severity, `category == APPROVAL`, `details == request.to_dict()`,
  `sql_sha256` copied; chaining `from_approval` events with `link` → `verify_chain`
  returns `None`; tampering one → returns its index. `AuditCategory.APPROVAL` exists.
