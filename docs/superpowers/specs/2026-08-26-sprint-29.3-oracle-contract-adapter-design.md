# Sprint 29.3 — Oracle Contract Adapter (Design)

**Phase:** 10 — Real Database Adapter Layer
**Date:** 2026-08-26
**Predecessors:** 25.9 (Oracle adapter contract **stub** — tüm execution flag'leri
`False`, `execute()` her zaman `NOT_IMPLEMENTED`/`REJECTED`), 29.0/29.1/29.2
(PostgreSQL adapter deseni — connection resolver + low-level adapter + shared-contract
bridge + gated integration testleri).
**Successor:** 29.4 (Oracle Docker/Test Harness Strategy — imaj + seed + CI job).

## Amaç

25.9'un yalnız *sözleşmeyi* kilitlediği (hiç execution yok) yerden devam edip,
PostgreSQL 29.0→29.1 desenini **birebir Oracle'a taşımak**: gerçek `oracledb`
(thin mode) tabanlı read-only SELECT execution path'i + connection resolver +
dialect-agnostic paylaşılan execution sözleşmesine bağlı yeni
`OracleDatabaseExecutionAdapter`. Adapter — 29.0/29.1/29.2 gibi — **yalnızca
local Docker, standalone/inert**: canlı production pipeline'a wire EDİLMEZ.

**29.3 ile 29.4 sınırı (bilinçli):** 29.3 *kodu* ve *unit + gated integration
testlerini* teslim eder; gerçek Oracle Docker imajı, seed şeması ve CI job'ı
**29.4'e** kalır. Bu yüzden 29.3'ün gated integration testleri bugün her CI
koşusunda **safe-skip** eder (Docker yok); 29.4 imajı + CI job'ı ekleyince
kendiliğinden koşmaya başlar. Bu, "Oracle daha yüksek risk (driver/lisans/imaj
boyutu), harness ayrı sprint" olan 25.9 kararının doğrudan sonucudur.

## Kararlar (brainstorm, 2026-08-26)

1. **Kapsam: Postgres 29.0→29.1 deseni.** Gerçek `oracledb` execute() + connection
   resolver + shared-contract bridge; unit testler fake-cursor ile, canlı
   integration testleri gated/safe-skip. Schema introspection (Postgres 29.0
   dengi) ve EXPLAIN (29.2 dengi) **kapsam dışı** (→ ileri sprint / TECH-DEBT §21).
2. **Sürücü: `oracledb` thin mode.** Saf-Python, Oracle Instant Client
   **gerektirmez**; tek pip paketi. CI/Docker'da en hafif, driver-izolasyon en
   temiz. Thick mode / Instant Client / wallet **kapsam dışı**.
3. **DB-seviyesi read-only: `SET TRANSACTION READ ONLY`.** Birincil savunma yine
   26.2 string-level SELECT gate; DB-seviyesi belt-and-suspenders olarak
   `SET TRANSACTION READ ONLY` + `autocommit=False` + sonda `rollback()`.
4. **Timeout: `connection.call_timeout` (ms).** thin mode round-trip timeout —
   Postgres'in `statement_timeout`'unun Oracle dengi.
5. **Gated testler seed'siz.** bare-Oracle sorguları (`DUAL`, `CONNECT BY LEVEL`,
   yavaş sorgu) kullanır; seed şeması + JOIN testleri 29.4'e.

## Mimari

Katman haritası (Postgres deseninin Oracle aynası):

```
multi_database_execution.py   (DEĞİŞMEZ — SQLDatabaseDialect.ORACLE zaten mevcut)
        ▲ implements SQLDatabaseExecutionAdapter
oracle_execution_adapter.py   (YENİ — shared ↔ 25.9 köprü: normalize + _to_oracle_config)
        │ gerçek SELECT'i delege eder
oracle_adapter.py             (25.9 stub → gerçek oracledb SELECT, 3 savunma, driver-izolasyon)
        │ connection'ı alır
oracle_connection_resolver.py (YENİ — env → SQLOracleLocalDockerConnection | None, asla raise etmez)
```

### Katman 1 — `oracle_adapter.py` (25.9 stub → gerçek execute)

25.9 stub'ının contract yüzeyi **korunur** (geriye-uyum); üzerine gerçek path
eklenir:

- **`SQLOracleAdapterStatus`'a ekle:** `EXECUTED = "executed"`,
  `EXECUTION_ERROR = "execution_error"` (mevcut `NOT_IMPLEMENTED`, `REJECTED`
  korunur).
- **Yeni `default_local_docker_capability() -> SQLOracleAdapterCapability`:**
  Postgres `default_local_docker_capability()` dengi — `supports_live_execution`,
  `supports_remote_execution`, `supports_production_execution` = `False`;
  `supports_local_docker_execution`, `supports_driver_execution`,
  `supports_network_execution`, `supports_read_only_queries` = `True`;
  `supports_oracle_execution` = `True`. Eski `default_oracle_stub_capability()`
  (hepsi `False`) **korunur** — `connection=None` inert path onu kullanır.
- **`SQLOracleAdapterCapability.__post_init__` invariant'ı gevşetilir
  (bölümleme):** 25.9 stub'ı **her** flag `is not False` ise raise ediyordu —
  bu, hem all-`False` stub'ı hem True-karışımı local-docker capability'sini aynı
  anda geçerli kılamaz. Yeni invariant: `supports_live_execution`,
  `supports_remote_execution`, `supports_production_execution` `True` olamaz
  (raise); geri kalan dört flag (`local_docker`/`driver`/`network`/`read_only`)
  + `supports_oracle_execution` serbest boolean'dır (yalnız `bool` tipi
  doğrulanır). Böylece hem `default_oracle_stub_capability()` (hepsi `False`) hem
  `default_local_docker_capability()` (True-karışımı) geçerli olur. Not: Oracle'ın
  invariant'ı Postgres'inkinden **zorunlu olarak daha gevşek** — Postgres dört
  local-docker flag'inin `True` olmasını *şart koşar*, ama Oracle'ın hâlâ geçerli
  bir all-`False` stub'a ihtiyacı var, bu yüzden onları serbest bırakır (tehlikeli
  live/remote/production yine kilitli). **Test etkisi:** all-`False` stub
  fabrikasını doğrulayan 25.9 testleri **geçmeye devam eder**; ancak "bir
  local-docker flag'i `True` yapılınca raise" diyen 25.9 testi (varsa) **güncellenir**
  — o davranış 29.3'te bilinçli kaldırılır (sessiz düşürme yok, spec'te işaretli).
- **Yeni `SQLOracleLocalDockerConnection`** frozen dataclass — canlı bağlantıyı
  sağlamanın TEK yolu (Postgres `SQLPostgresLocalDockerConnection` dengi). Alanlar:
  `host`, `port`, `service_name`, `user`, `password=""`,
  `environment="local_docker"`. `__post_init__`: `environment != "local_docker"`
  → reddet; `host` local-docker allowlist'te değilse (`localhost`/`127.0.0.1`/
  `::1`) → reddet; `port` int ve 1..65535 değilse → reddet; boş `service_name`/
  `user`, non-str `password` → reddet. (Postgres'in `dbname`'i yerine Oracle
  `service_name`.)
- **`SQLOracleAdapterExecutionResult`'a `columns: Tuple[str, ...] = ()`** eklenir
  (29.1'in 25.8'e yaptığı geriye-uyumlu ekleme gibi — dict satırlar gerçek kolon
  adı taşısın). `to_dict()` `columns`'ı da serialize eder. Mevcut alanlar
  (positional tuple `rows`, `row_count`, `truncated`, `error`, `warnings`,
  `duration_ms`) korunur.
- **`SQLOracleAdapterContract.__init__(capability=None, connection=None)`** —
  Postgres gibi `connection` parametresi eklenir. `connection is None` iken
  capability default'u `default_oracle_stub_capability()` (inert); `connection`
  verildiğinde `default_local_docker_capability()`.
- **`execute()`** akışı: `sql_sha256 = sha256(request.sql)`; `connection is None`
  → `NOT_IMPLEMENTED` inert (bugünkü davranış korunur); `validate_read_only_select`
  (savunma katmanı 1) reason döndürürse → `REJECTED`; aksi halde `_execute_select`.
- **`_execute_select`** — gerçek path, üç savunma katmanı:
  1. **String-level read-only SELECT gate** (26.2 shared enforcer) — herhangi bir
     driver dokunuşundan ÖNCE (zaten `execute()`'ta koşar).
  2. **Lazy `import oracledb`** metodun İÇİNDE (`try/except ImportError` →
     `EXECUTION_ERROR` "Oracle driver (oracledb) is not available."). Import-time'da
     ASLA yüklenmez.
  3. **DB-enforced read-only + timeout:** `oracledb.connect(user=, password=,
     dsn=f"{host}:{port}/{service_name}")`; `conn.autocommit = False`;
     `conn.call_timeout = int(timeout_seconds * 1000)`; cursor açılır,
     `cur.execute("SET TRANSACTION READ ONLY")`, sonra `cur.execute(request.sql)`;
     `cur.fetchmany(max_rows + 1)` ile truncation tespiti; `columns` =
     `[d[0] for d in cur.description]`; `finally` bloğunda `conn.rollback()` +
     `conn.close()`.
- **Yardımcılar:** `_normalize_value`/`_normalize_row` (JSON-safe olmayan değeri
  `str`'e çevirir — Oracle `Decimal`/`datetime`/`LOB` için gerekli),
  `_sanitize_oracle_error(exc) -> str` (kimlik-bilgisi-ayıklı mesaj; oracledb
  timeout hatası — `DPY-4011`/`ORA-...` call_timeout kesmesi — ayrı, deterministik
  bir timeout mesajına eşlenir).

**Not (execution_mode):** 25.9 config'i `execution_mode ∈ {"read_only",
"explain_only"}` kabul ediyor. 29.3'te `_execute_select` yalnız `read_only`
uygular; `explain_only` bu katmanda **desteklenmez** — köprü katmanı (aşağıda)
EXPLAIN_ONLY request'ini reddeder, dolayısıyla low-level'a hiç ulaşmaz. Low-level
`execute()` doğrudan `explain_only` config ile çağrılırsa `_execute_select` yine
düz SELECT gibi read-only koşar (EXPLAIN prefix'i **eklenmez**) — bu, 29.3'ün
canlı pipeline'a wire olmadığı için erişilemez bir yoldur; net davranış 29.2
Oracle-EXPLAIN sprint'ine bırakılır (TECH-DEBT §21).

### Katman 2 — `oracle_execution_adapter.py` (YENİ — shared-contract köprü)

Postgres `postgres_execution_adapter.py`'nin birebir dengi:

- **`OracleDatabaseExecutionAdapter(SQLDatabaseExecutionAdapter)`**:
  - `dialect` → `SQLDatabaseDialect.ORACLE`.
  - `capabilities()` → `(CONNECTION_REF, READ_ONLY)` — **EXPLAIN_ONLY YOK** (29.1
    postürü; Oracle EXPLAIN ileriye).
  - `__init__(connection_resolver=resolve_local_docker_connection)` — resolver
    enjekte edilebilir (testler `lambda env=None: None` geçer).
  - `execute(request)`: tip doğrulaması; `dialect == ORACLE`; `connection_ref is
    not None` (zorunlu); `fixture_ref is None` (reddedilir); `execution_mode ==
    READ_ONLY` (EXPLAIN_ONLY → `SQLMultiDatabaseExecutionContractError` raise —
    "Oracle EXPLAIN-only mode is not supported in this contract version").
    `connection = self._resolve()`; `None` → graceful `SQLDatabaseExecutionResult`
    (`execution_error="No local Docker Oracle connection available"`, boş rows,
    **raise yok**). Aksi halde `_to_oracle_config` → `SQLOracleAdapterConfig`,
    `SQLOracleAdapterExecutionRequest(dialect="oracle", ...)`,
    `SQLOracleAdapterContract(connection=connection).execute(...)` →
    `normalize_oracle_execution_result(oracle_result, request)`.
  - `_to_oracle_config(config)` → `SQLOracleAdapterConfig(timeout_seconds,
    max_rows, execution_mode=config.execution_mode.value)`.
- **`normalize_oracle_execution_result(oracle, request)`**: `sql_sha256`'yı
  `request.sql`'den yeniden hesaplar; `oracle.status == EXECUTED` ise
  `_rows_to_dicts(oracle.rows, oracle.columns)`; aksi halde boş rows +
  `execution_error = oracle.error or f"Oracle execution not completed
  ({oracle.status.value})."`.
- **`_rows_to_dicts(rows, columns)`**: arity uyuşmazlığı **veya** boş columns →
  positional `{f"col_{i}": v}` fallback (+ satır varsa uyarı); aksi halde her satır
  için `dict(zip(columns, row))`. Veri asla düşürülmez. (Postgres bridge'in birebir
  dengi.)

**Shared contract (`multi_database_execution.py`) DEĞİŞMEZ:** `ORACLE` dialect'i,
`READ_ONLY` modu, `CONNECTION_REF`/`READ_ONLY` capability'leri zaten mevcut. Yeni
adapter `SQLDatabaseExecutionRouter`'a takılabilir (bir unit testte gösterilir) ama
**canlı bir registry'ye kaydedilmez** (standalone/inert).

### Katman 0 — `oracle_connection_resolver.py` (YENİ)

`ORACLE_CONNECTION_RESOLVER_VERSION = "v1"`. Tek fonksiyon:
`resolve_local_docker_connection(env=None) -> Optional[SQLOracleLocalDockerConnection]`.
Env (default'larla): `ORACLE_TEST_HOST`→`localhost`, `ORACLE_TEST_PORT`→`1521`,
`ORACLE_TEST_SERVICE`→`FREEPDB1`, `ORACLE_TEST_USER`→`sqlgen`,
`ORACLE_TEST_PASSWORD`→`sqlgen`. **Asla connect etmez, asla raise etmez:** port
int-parse edilemezse → `None`; `SQLOracleAdapterContractError`/`ValueError` (uzak
host, kötü port, boş alan, non-local env) yakalanır → `None`. Uzak/geçersiz →
`None` (inert), 25.9'un `connection=None` inert path'iyle eşleşir.

## Güvenlik & değişmezler

- **Read-only enforcement (üç katman):** 26.2 string-level SELECT gate (iç SQL
  üzerinde, driver dokunuşundan önce) + `SET TRANSACTION READ ONLY` +
  `autocommit=False`/`rollback()`. Non-SELECT/multi-statement/PL-SQL/DDL →
  `REJECTED`, hiç connect etmez.
- **Driver-isolation invariant:** modül import'u hiçbir Oracle driver/socket
  yüklemez; `oracledb` yalnız `_execute_select` içinde lazy import edilir.
  Subprocess import testi bunu kilitler (forbidden-list `oracledb`, `cx_Oracle`,
  `sqlalchemy`).
- **Timeout güvenliği:** `call_timeout` runaway sorguyu keser; kesme
  `EXECUTION_ERROR` + sanitize mesaj döner, raise etmez.
- **Secret-free:** sonuç yalnız `sql_sha256` + sanitize `execution_error` + kolon
  adları + JSON-safe scalar satır değerleri taşır; DSN/host/user/password/service
  ASLA. `_sanitize_oracle_error` kimlik bilgisi sızdırmaz.
- **Determinizm:** aynı seeded/bare veri + sorgu için satırlar deterministik;
  `duration_ms` monotonic ölçüm (non-deterministik, assert edilmez).

## Test planı

**Unit (docker'sız, her CI koşusunda):**

- `SQLOracleAdapterCapability`: `default_oracle_stub_capability()` hâlâ hepsi-`False`
  (immutability + all-disabled testleri korunur); `default_local_docker_capability()`
  doğru `True`/`False` karışımı; `live/remote/production=True` → raise (korunur).
  **Değişen 25.9 testleri:** `rejects_{driver,network,read_only_queries}_execution_true`
  ve parametrize `rejects_any_execution_flag_true` — bu dört flag artık `True`
  kabul edilir, dolayısıyla bu testler yalnız `live/remote/production` için raise
  bekleyecek şekilde daraltılır/çevrilir (`rejects_live_execution_true` aynı kalır).
- `SQLOracleLocalDockerConnection`: local-docker host kabul, uzak host/kötü port/
  boş service → raise.
- `oracle_connection_resolver`: default env → connection; uzak host/kötü port →
  `None`; asla raise etmez.
- **Fake-`oracledb` harness** (`monkeypatch.setitem(sys.modules, "oracledb", fake)`
  ile `_FakeConn`/`_FakeCursor`): (a) çalıştırılan SQL sırası
  `["SET TRANSACTION READ ONLY", "<sql>"]`; (b) `conn.call_timeout` doğru ms'e
  set edildi; (c) `autocommit=False` + `rollback()` çağrıldı; (d) `max_rows`
  truncation (`fetchmany(max_rows+1)` → `truncated=True`, fazladan satır düşürülür);
  (e) `columns` `cur.description`'dan; (f) fake cursor timeout hatası fırlatınca →
  `EXECUTION_ERROR` (sanitize timeout mesajı), raise yok; (g) driver ImportError →
  `EXECUTION_ERROR`.
- **Read-only gate:** `INSERT`/`UPDATE`/multi-statement/PL-SQL bloğu → `REJECTED`,
  fake driver'a hiç ulaşmaz (socket açılmaz — monkeypatch ile doğrulanır).
- **`connection=None`** → `NOT_IMPLEMENTED` inert (raise yok).
- **Bridge:** `normalize_oracle_execution_result` happy-path (adlandırılmış dict
  satırlar); arity-mismatch/boş-columns → `col_<i>` fallback + uyarı; resolver
  `None` → graceful boş sonuç + `execution_error`; `EXPLAIN_ONLY` request → raise;
  `fixture_ref` verilmesi → raise; router-pluggability (ORACLE adapter router'a
  takılır, `get_adapter(ORACLE)` döner).
- **Driver-isolation subprocess testi:** taze subprocess `oracle_adapter` +
  `oracle_execution_adapter` import eder, `sys.modules`'ta `oracledb`/`cx_Oracle`/
  `sqlalchemy` YOK. (Network-client listesi Postgres'teki aynı pydantic re-export
  false-positive nedeniyle **portlanmaz** — gerekçe test yorumunda.)

**Gated integration (docker, safe-skip; 29.4'te seeded Oracle ile CI'da koşar):**

- Skip predicate `_local_docker_oracle_available()`: `import oracledb` başarısız →
  skip; `resolve_local_docker_connection() is None` → skip; kısa timeout'lu gerçek
  `oracledb.connect` denemesi hata → skip. Modül `pytestmark = [integration,
  oracle]`; her test `adapter` fixture'ını alır (yoksa `pytest.skip`).
- **Seed GEREKMEZ** (bare-Oracle sorguları):
  - `SELECT 1 AS n FROM DUAL` → tek adlandırılmış dict satır (`{"N": 1}` —
    Oracle büyük-harf kolon adı).
  - `SELECT LEVEL AS lvl FROM DUAL CONNECT BY LEVEL <= 5` → çok satır; `max_rows=2`
    ile truncation → `truncated=True` + uyarı.
  - Yavaş sorgu (ör. ağır `CONNECT BY LEVEL <= 100000000` veya
    `DBMS_SESSION.SLEEP`) + `timeout=0.05` → `execution_error` (timeout), raise yok.
  - Çok kolonlu `SELECT 1 AS a, 'x' AS b FROM DUAL` → dict satır iki adlandırılmış
    kolon.
