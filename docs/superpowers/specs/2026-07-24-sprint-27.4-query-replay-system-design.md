# Sprint 27.4 — Query Replay System (design)

**Tarih:** 2026-07-24
**Faz:** 8 (Observability & Debuggability)
**Öncül:** Sprint 27.3 (User Feedback Capture, PR #139 merged; doküman senkronu PR #140).
Gözlemlenebilirlik katmanı artık her koşunun `end_to_end` trace'ini yazıyor (27.1w),
hataları tek registry'den kodluyor (27.2/27.2.1) ve kullanıcı feedback'ini topluyor (27.3).
Bu sprint bir sonraki soruyu cevaplar: **"bugünkü kod, geçmişteki bu sorguyu hâlâ aynı
şekilde ele alıyor mu?"**

## 1. Amaç

Geçmişte koşmuş tek bir `job`'ı, bugünün kodu ve bugünün şemasıyla **deterministik
olarak yeniden koşturmak** ve sonucu o günkü `end_to_end` trace baseline'ıyla
karşılaştırıp makine-okur bir **verdict + delta** üretmek.

Cevapladığı somut sorular:
- Şema/kod değişikliğim bu sorgunun **tablo seçimini** kaydırdı mı?
- O gün geçerli olan SQL bugün **hâlâ geçerli** mi (AST + semantik)?
- Bugün bir **güvenlik reddi** doğuyor mu (guardrail / sandbox safety)?

Replay **yan etkisizdir**: hiçbir şey yazılmaz, hiçbir trace emit edilmez, LLM'e
gidilmez.

## 3. Tasarım

### 3.1 Saf yaprak paket — `backend/app/replay/`

İzinli import yüzeyi: **stdlib** + `app.trace.end_to_end_trace` + `app.errors`
(ikisi de zaten saf yaprak). Yasak: `pydantic`, `fastapi`, `sqlglot`, `app.database`,
herhangi bir DB driver. Purity guard testi ile kilitlenir (`errors`/`feedback`
kardeşleriyle aynı desen).

`app.trace.end_to_end_trace` importu **yalnız** `TraceStageKind` / `TraceSpanStatus`
literal'lerini tek kaynaktan okumak içindir (`"retrieval"`, `"skipped"` gibi
string'leri kopyalamamak). Baseline çıkarımı yine de **dict üzerinde** çalışır —
`EndToEndTrace` nesnesi kurulmaz, deserialize edilmez.

```python
# backend/app/replay/verdicts.py
from enum import StrEnum

REPLAY_CONTRACT_VERSION = "query_replay_v1"

class ReplayVerdict(StrEnum):
    INPUT_UNAVAILABLE = "input_unavailable"
    BASELINE_UNAVAILABLE = "baseline_unavailable"
    REPLAY_FAILED = "replay_failed"
    SECURITY_REGRESSION = "security_regression"
    VALIDATION_REGRESSION = "validation_regression"
    RETRIEVAL_DRIFT = "retrieval_drift"
    VALIDATION_RECOVERY = "validation_recovery"
    IDENTICAL = "identical"
```

**Verdict önceliği (yukarıdan aşağı, ilk eşleşen kazanır).** Birden fazla boyut
değişebilir; verdict **en ciddi olanı** adlandırır, delta'lar **hepsini** taşır —
hiçbir değişiklik sessizce düşmez.

1. `input_unavailable` — girdi artık yok (Excel dosyası silinmiş); replay hiç koşamadı
2. `baseline_unavailable` — bu job'ın `end_to_end` trace'i yok; kıyas tarafı yok
3. `replay_failed` — bugün retrieval hata verdi; `error_code` (27.2 registry) taşınır
4. `security_regression` — baseline'da güvenlik reddi yokken bugün var
5. `validation_regression` — baseline'da geçerli SQL bugün geçersiz
6. `retrieval_drift` — seçilen tablo **kümesi** değişti
7. `validation_recovery` — baseline'da geçersiz SQL bugün geçerli
8. `identical` — hiçbir boyutta fark yok

```python
# backend/app/replay/contract.py  (frozen dataclass'lar, JSON-safe to_payload)
@dataclass(frozen=True)
class RetrievalDelta:
    baseline_tables: Tuple[str, ...] = ()
    observed_tables: Tuple[str, ...] = ()
    added: Tuple[str, ...] = ()
    removed: Tuple[str, ...] = ()
    changed: bool = False

@dataclass(frozen=True)
class ValidationDelta:
    applicable: bool = True
    baseline_valid: Optional[bool] = None
    observed_valid: Optional[bool] = None
    baseline_issue_types: Tuple[str, ...] = ()
    observed_issue_types: Tuple[str, ...] = ()
    changed: bool = False

@dataclass(frozen=True)
class SecurityDelta:
    baseline_denied: Tuple[str, ...] = ()
    observed_denied: Tuple[str, ...] = ()
    changed: bool = False

@dataclass(frozen=True)
class ReplayResult:
    version: str                       # REPLAY_CONTRACT_VERSION
    job_id: str
    verdict: ReplayVerdict
    baseline_trace_id: Optional[str] = None
    retrieval: Optional[RetrievalDelta] = None
    validation: Optional[ValidationDelta] = None
    security: Optional[SecurityDelta] = None
    error_code: Optional[str] = None   # yalnız replay_failed'de
    notes: Tuple[str, ...] = ()        # koşulamayan boyutların gerekçesi
```

**Karşılaştırma kuralları (saf, `compare.py`):**
- Tablo karşılaştırması **küme tabanlı**; sıra farkı drift sayılmaz (sıra prompt'a
  girer ama anlamlı regresyon sinyali küme farkıdır). Tüm çıktı tuple'ları
  **sıralıdır** → aynı girdi her zaman aynı payload'ı üretir.
- `issue_types` karşılaştırması da küme tabanlı ve sıralıdır; issue **mesajları**
  karşılaştırmaya girmez (redaksiyon/formatlama gürültüsü).
- `applicable=False` olan boyut verdict'i etkilemez ve gerekçesi `notes`'a yazılır.

**Baseline çıkarımı (saf, `baseline_extraction.py`):** girdi bir `end_to_end`
`TraceRecord.payload` **dict'idir** (I/O yok):
- RETRIEVAL span → `detail.candidates[*].object_id` (`object_type == "table"`) → baseline tabloları
- VALIDATION span → `detail.valid`, `detail.issues[*].type` (mesaj yok)
- SECURITY span → `detail.checks[*]`, `outcome == "denied"` olanların `reason_code`'ları
- Envelope → `trace_id`, `terminal_status`
- Span `SKIPPED` ise o boyut `applicable=False` işaretlenir (baseline o gün koşmamış).

### 3.2 Doğrulama seam'i — `backend/app/sql_pipeline.py` (hedefli refactor)

**Sorun:** guardrail → sandbox safety → sqlglot AST → semantik doğrulama zinciri
`_stage_writer_critic` içindeki **LLM retry döngüsünün gövdesine gömülü**
(bugün ~`:404-505`). Çağrılabilir bir "şu SQL'i doğrula" yüzeyi yok. Replay bu zinciri
**kopyalarsa yalan söyler** — tam da güvenilmesi gereken anda üretimden sapar ve bu
sapma sessizdir.

**Çözüm:** zincir tek bir public metoda ayıklanır; writer-critic onu çağırır.

`ValidationOutcome` **`sql_pipeline.py` içinde** tanımlanır, `app/replay/` içinde
değil: bu bir üretim yüzeyidir ve pipeline replay semantiğinden habersiz kalmalıdır.

```python
@dataclass
class ValidationOutcome:
    sql: str                       # normalize/pretty-print sonrası
    valid: bool
    validation_errors: List[dict]  # guardrail + AST + semantik, üretimdeki şekliyle
    retry_disposition: str         # "ok" | "retry" | "abort"
    timings: Dict[str, int]        # {"validation": ms, "security": ms}

def validate_sql(self, sql: str, pruned_schema: dict, dialect: str) -> ValidationOutcome
```

**Kritik davranış kuralı:** retry döngüsünün `continue`/`break` ayrımı davranışın
parçasıdır ve seam bunu **veri olarak** döndürmezse akış sessizce değişir:

| Durum | Bugünkü akış | `retry_disposition` |
|---|---|---|
| Guardrail hatası, `type == "sql_parse_error"` | `continue` | `retry` |
| Guardrail hatası, diğer | `break` | `abort` |
| Sandbox safety reddi | `break` | `abort` |
| sqlglot AST parse hatası | `continue` | `retry` |
| Semantik doğrulama hatası | `continue` | `retry` |
| Hepsi geçti | `break` (başarı) | `ok` |

Oracle büyük-harf zorlaması (`enforce_oracle_case`) ve başarı sonrası pretty-print
seam'in **içinde** kalır — replay'in gördüğü SQL üretimin gördüğüyle aynı olmalıdır.

**Kanıt disiplini (27.1w deseni):** branch genelinde mevcut pipeline test dosyaları
`+N/-0`; hiçbir mevcut assert'in **anlamı** değişmez. Ek olarak her
`retry_disposition` dalını doğrudan kilitleyen yeni testler yazılır.

### 3.3 Kirli adaptör — `backend/app/replay_service.py`

Saf paketin **dışında**, çünkü I/O yapar. Tek public fonksiyon:

```python
def replay_job(job_id: str, *, pipeline: SQLGenerationPipeline,
               trace_store: TraceStore) -> ReplayResult
```

Akış:
1. `get_job(job_id)` → `None` ise `ReplayJobNotFound` (bu modülde tanımlı, stdlib
   `Exception` türevi) fırlatılır; router onu `HTTPException(404, ...)`'a çevirir.
   `ReplayResult` bu durum için bir verdict **taşımaz** — "job yok" bir replay
   sonucu değil, bir kaynak hatasıdır.
2. Baseline: `trace_store.list_traces(TraceQuery(job_id=..., trace_type="end_to_end", limit=1))`
   → **en yeni** kayıt. Yoksa `baseline_unavailable`.
3. Girdi kontrolü: `natural_query` boş **ve** (`file_path` yok ya da dosya diskte
   yok) → `input_unavailable`.
4. Gözlenen retrieval: üretimin **kendi** `_stage_intent` + `_stage_retrieval`
   metotları çağrılır (kopya mantık yok). Hata dönerse → `replay_failed` + `error_code`.
5. Gözlenen doğrulama: `pipeline.validate_sql(job["result_sql"], pruned_schema, dialect)`.
   `result_sql` boşsa (o gün fail olmuş job) → `ValidationDelta.applicable = False`,
   gerekçe `notes`'a.
6. `compare_replay(baseline, observed)` → `ReplayResult`.
7. **Hiçbir yazma yok:** job/trace güncellenmez, yeni trace emit edilmez, feedback
   yazılmaz.

## 4. Veri akışı

```
POST /api/debug/jobs/{id}/replay
  → verify_api_key + ensure_debug_enabled
  → replay_service.replay_job
        ├── database.get_job(id)                 [ham girdi: natural_query, dialect,
        │                                          previous_sql, file_path, result_sql]
        ├── trace_store  → end_to_end payload    [baseline]
        │      └── replay.extract_baseline(payload)      (SAF)
        ├── pipeline._stage_intent / _stage_retrieval    [bugünün şeması]
        ├── pipeline.validate_sql(...)                   [bugünün doğrulaması]
        └── replay.compare_replay(baseline, observed)    (SAF)
  → 200 {"status": "success", "replay": {...}}   [hiçbir kalıcı iz yok]
```

## 5. Hata yönetimi — neyin HTTP hatası, neyin verdict olduğu

| Durum | Sonuç |
|---|---|
| Job yok | **404** (`HTTPException`, global handler envelope'a sarar) |
| `debug_endpoints_enabled=False` | **404** (`debug_traces` ile aynı) |
| API key yok/yanlış | **403** (router dependency) |
| Baseline trace yok | **200** + `baseline_unavailable` |
| Girdi (Excel) yok | **200** + `input_unavailable` |
| Retrieval bugün çöktü | **200** + `replay_failed` + `error_code` |
| Beklenmedik exception | **500** envelope — yukarı fırlar |

Son satır bilinçlidir: bir debug aracının hatayı yutup `identical` demesi mümkün olan
en kötü davranıştır.

## 6. Test stratejisi (her görev TDD)

1. **Saf çekirdek:** verdict öncelik matrisi tablo-güdümlü; boş/`None` baseline
   halleri; küme farkının sıradan bağımsızlığı; `to_payload()` JSON-safe ve
   deterministik (aynı girdi → aynı çıktı).
2. **Purity guard:** `app.replay` import edilince `pydantic`/`fastapi`/`sqlglot`
   yüklenmiyor (`sys.modules` save/delete/restore deseni, `feedback` kardeşiyle aynı).
3. **Seam refactor:** mevcut pipeline test dosyaları `+N/-0` (kanıt: branch diff'i);
   `validate_sql` için her `retry_disposition` dalını kilitleyen yeni testler.
4. **Adaptör:** fake trace store + fake schema manager; LLM'e hiç gidilmez.
   `input_unavailable` / `baseline_unavailable` / `replay_failed` dalları ayrı ayrı.
5. **Endpoint:** 200 / 404 (job yok) / 404 (debug kapalı) / 403 (key yok);
   replay'in **hiçbir şey yazmadığı** testle kanıtlanır (öncesi-sonrası satır sayıları).
6. **Contract snapshot:** salt-ekleme doğrulanır; mevcut `required`/`properties`
   değişmez; `status_contract_snapshot.json` dokunulmaz.
