# Sprint 29.2 — PostgreSQL EXPLAIN-Only Mode (Design)

**Phase:** 10 — Real Database Adapter Layer
**Date:** 2026-08-14
**Predecessors:** 25.8 (local-Docker read-only adapter, `explain_only` config kabul ama inert),
29.0 (Docker introspection + connection resolver), 29.1 (read-only execution adapter, `EXPLAIN_ONLY` reddediyor)

## Amaç

29.1'in yalnız `READ_ONLY` mode kabul edip `EXPLAIN_ONLY`'yi reddettiği yerden devam edip,
PostgreSQL için **gerçek EXPLAIN(-only) execution path'ini** eklemek. 25.8'in
`execution_mode="explain_only"` config'i şu an kabul ediliyor ama `execute()` tarafından
**tamamen yok sayılıyor** (her zaman ham `SELECT` koşuyor) — 29.2 bunu gerçek bir EXPLAIN
path'ine bağlar.

Postgres'te `EXPLAIN <sql>` sorguyu **çalıştırmadan** planlayıcının tahmini planını döndürür
(tek-kolonlu `"QUERY PLAN"` result set'i) — pahalı/yan-etkili sorgular için bile güvenli.
`EXPLAIN ANALYZE <sql>` ise sorguyu **gerçekten koşar** (gerçek süre/satır sayıları). 29.2
ikisini de destekler; ANALYZE **opt-in** bir flag'le açılır, default güvenli düz EXPLAIN kalır
(sessiz side-effect yok).

Sınırlar (bilinçli, korunur — 29.0/29.1 postürü):

- **Local-Docker-only, read-only.** Uzak/production connection yok.
- **Driver-izole.** Modül import-time'da `psycopg2` yüklemez (lazy, 25.8 üzerinden).
- **Yan-etkisiz** (düz EXPLAIN). ANALYZE opt-in; read-only transaction writes'ı bloklar.
- **Canlı HTTP pipeline'a değmez.** Adapter standalone/inert kalır → Phase 11 (30.x).

## Karar özeti (brainstorm, 2026-08-14)

1. **Plan gösterimi: `rows` olarak taşınır — kontrat değişmez.** Postgres EXPLAIN zaten
   tek-kolonlu `"QUERY PLAN"` result set'i döndürür; her plan satırı bir dict-row
   (`{"QUERY PLAN": "..."}`) olur. Yeni contract alanı **yok**; mevcut
   `rows`/`columns`/`fetchmany` plumbing'i olduğu gibi kullanılır.
2. **EXPLAIN varyantı: düz EXPLAIN + EXPLAIN ANALYZE.** ANALYZE opt-in flag ile.
3. **Wiring: iki katman, standalone (29.1 deseni).** 25.8 adapter'a gerçek EXPLAIN path'i
   + 29.1 execution adapter `EXPLAIN_ONLY` kabul eder. Canlı pipeline'a wire **edilmez**.

## Mimari

### Katman 1 — 25.8 `postgres_adapter.py` (gerçek EXPLAIN path'i)

**Config'e geriye-uyumlu ekleme.** `SQLPostgresAdapterConfig`'e:

- `explain_analyze: bool = False` — default güvenli düz EXPLAIN; validation:
  `isinstance(bool)`.

`execute()` şu an `execution_mode`'u **yok sayıyor**. Yeni davranış:

1. **Read-only gate değişmeden aynı kalır.** `validate_read_only_select(request.sql)`
   **iç SELECT** üzerinde koşar (EXPLAIN prefix'i üzerinde değil). Non-SELECT/multi-statement
   → `REJECTED`. Gate'e (26.2 shared contract) **dokunulmaz** — EXPLAIN'i biz güvenli iç
   SQL'in önüne ekliyoruz.
2. **Mode dallanması** `_execute_select` içinde (ya da yeni `_execute_explain`):
   - `execution_mode == "read_only"` → mevcut davranış (`cur.execute(request.sql)`).
   - `execution_mode == "explain_only"` → çalıştırılacak metin
     `EXPLAIN <sql>` (analyze kapalı) ya da `EXPLAIN (ANALYZE) <sql>` (`explain_analyze=True`).
     `request.sql` sondaki tek `;`'den arındırılır (EXPLAIN prefix + trailing `;`
     kombinasyonu sözdizimi bozmasın — read-only gate tek trailing `;`'e izin veriyor).
3. **DB-level savunma korunur:** `default_transaction_read_only=on` + `statement_timeout`
   her iki mode'da aynı. Düz EXPLAIN sorguyu koşmaz; ANALYZE koşar ama read-only tx writes'ı
   bloklar.
4. **Sonuç plumbing'i değişmez:** EXPLAIN çıktısı tek-kolonlu `"QUERY PLAN"` result set'i
   → mevcut `cur.fetchmany(max_rows + 1)` truncation, `cur.description`'dan `columns`
   yakalama (`("QUERY PLAN",)`), `_normalize_row` aynen kullanılır. `status=EXECUTED`.

> **Neden gate'i değiştirmiyoruz:** `validate_read_only_select` iç SELECT'i doğruluyor;
> "EXPLAIN " prefix'ini biz string olarak, doğrulanmış güvenli SQL'in önüne koyuyoruz.
> Böylece "EXPLAIN"in kendisi SELECT ile başlamasa da gate mantığı bozulmaz ve write
> sızması imkânsız kalır.

### Katman 2 — 29.1 `postgres_execution_adapter.py` (EXPLAIN_ONLY kabulü)

**Shared config'e ekleme.** `SQLDatabaseExecutionConfig` (`multi_database_execution.py`)'e
geriye-uyumlu `explain_analyze: bool = False` (validation: bool). `SQLExecutionMode.EXPLAIN_ONLY`
ve `SQLExecutionAdapterCapability.EXPLAIN_ONLY` enum'ları **zaten tanımlı** — yeni enum yok.

`PostgresDatabaseExecutionAdapter` değişiklikleri:

- `capabilities()` → `(CONNECTION_REF, READ_ONLY, EXPLAIN_ONLY)`.
- `execute()`'teki hard-reject (`config.execution_mode != READ_ONLY → raise`) kaldırılır;
  yerine `execution_mode in {READ_ONLY, EXPLAIN_ONLY}` kabul edilir, diğerleri (ileride
  eklenecek) reddedilir.
- 25.8 config eşlemesi `execution_mode`'u ve `explain_analyze`'ı taşır:
  `SQLPostgresAdapterConfig(..., execution_mode=request.config.execution_mode.value, explain_analyze=request.config.explain_analyze)`.
- **Normalizer değişmez.** `normalize_postgres_execution_result` `EXECUTED` sonucunu zaten
  dict-row'a çeviriyor; EXPLAIN plan satırları `{"QUERY PLAN": "..."}` olarak aynı yoldan akar.
  `connection=None` graceful boş-sonuç yolu aynen korunur.

### Router / pipeline

Değişmez. Canlı router/registry wiring 30.x'e kalır (29.1 sınırı korunur). Adapter'ın
router'a takılabilirliği zaten 29.1 testinde gösteriliyor; 29.2 buna EXPLAIN_ONLY request'i
eklemez (standalone).

## Güvenlik & değişmezler

- **Read-only enforcement:** 25.8'in üç katmanı korunur (26.2 string-level SELECT gate iç
  SQL üzerinde, `default_transaction_read_only=on`, `statement_timeout`). Düz EXPLAIN hiç
  çalıştırmaz; ANALYZE çalıştırır ama read-only tx + timeout writes'ı ve runaway'i bloklar.
- **Driver-isolation invariant:** yeni/değişen modüllerin import'u hiçbir DB driver/socket
  yüklemez (subprocess import testi korunur/genişletilir).
- **Secret-free:** sonuç yalnız `sql_sha256` + sanitize `execution_error` + kolon adları
  (`"QUERY PLAN"`) + plan metin satırları taşır; connection detayı asla. Plan metni tablo/
  index adları içerebilir — bunlar zaten şemada mevcut, kimlik bilgisi değil.
- **Determinizm:** düz EXPLAIN planı deterministik; ANALYZE'ın `duration_ms`/gerçek-süre
  alanları non-deterministiktir → testte gerçek süreye **assert edilmez**, yalnız plan
  yapısının varlığına bakılır. `duration_ms` monotonic ölçüm (mevcut paritesi).

## Test planı

**Unit (docker'sız, her CI koşusunda):**
- `SQLDatabaseExecutionConfig.explain_analyze` default `False`; bool validation; geriye
  uyumlu (mevcut çağıranlar kırılmaz).
- `SQLPostgresAdapterConfig.explain_analyze` default `False`; bool validation.
- `capabilities()` → `(CONNECTION_REF, READ_ONLY, EXPLAIN_ONLY)`.
- `execute()` `EXPLAIN_ONLY` mode'u **kabul eder** (artık raise etmez); bilinmeyen/ileri
  mode reddedilir.
- Mode/flag → çalıştırılan SQL metni eşlemesi (fake cursor ile): `explain_only` +
  `explain_analyze=False` → `EXPLAIN <sql>`; `+True` → `EXPLAIN (ANALYZE) <sql>`;
  `read_only` → değişmemiş `<sql>`. Trailing `;` doğru arındırılır.
- Explain mode'da da read-only gate uygulanır: `INSERT`/multi-statement → `REJECTED`
  (EXPLAIN prefix'i eklenmez).
- `connection=None`/resolver `None` → graceful (raise yok) — 29.1 paritesi.
- Import-time driver-isolation (subprocess; `psycopg2`/socket yüklenmez).

**Gated integration (docker, safe-skip; CI'da seeded Postgres ile koşar):**
- Seeded şemada `EXPLAIN <JOIN>` → tek-kolonlu `"QUERY PLAN"` dict satırları; plan metni
  beklenen node'u (ör. `Seq Scan`/`Join`) içerir; **altındaki sorgunun data satırları
  sızmaz** (dönen satırlar plan metnidir, `customers` verisi değil).
- `EXPLAIN (ANALYZE) <JOIN>` → plan + gerçek-execution satırları (ör. `actual time`);
  gerçek süreye assert edilmez, yapı/anahtar-kelime varlığına bakılır.
- `max_rows` truncation plan satırlarına uygulanır → `truncated=True` (+ warning).
- Çok kısa `timeout` (ANALYZE ile pahalı sorgu) → `execution_error` (timeout), raise yok.
