## 3. Kalem-başı tasarım

### §5.1 — Purity guard'ları aynı süreçte ölçüyor (errors + feedback)

**Sorun:** `backend/tests/errors/test_errors_package_purity.py` ve `backend/tests/feedback/test_feedback_package_purity.py` importu **aynı süreçte** yapıp `sys.modules` diff'ine bakar. Sızan bir modül başka bir test tarafından zaten import edildiyse guard sessizce yanlış-negatif verir — o iki yaprak paketin saflığı bugün fiilen ölçülmüyor.

**Fix:** İki testi de `backend/tests/rule_suggestions/test_rule_suggestions_package_purity.py` referansındaki **taze-alt-süreç** desenine taşı: `subprocess.run([sys.executable, "-c", _PROBE], cwd=backend)`, probe içinde `sys.modules` diff'i, `ast.literal_eval` ile geri oku, `leaked_app == []` ve `drivers == []` assert et.
- `app.errors` allow-list: `("app.errors",)`. Driver blocklist: `psycopg, psycopg2, oracledb, cx_Oracle, sqlglot, sqlite3, fastapi` (mevcut liste).
- `app.feedback` allow-list: `("app.feedback",)`. Driver blocklist mevcut listeye **`pydantic` dahil** (feedback FastAPI/pydantic'siz kalmalı).
- Probe, bare `app` namespace'ini hariç tutar (`m != "app"`) ve allow-prefix predikatı `m == p or m.startswith(p + ".")` kullanır.

**Doğrulama (guard'ın gerçekten koruduğunu göster):** yeni testlerin, ilgili pakete kasıtlı `import app.trace` enjekte edildiğinde FAIL ettiği elle doğrulanır (sonra geri alınır) — 27.4'teki yöntemle. (Testin kendisi bu enjeksiyonu içermez; bu bir implementasyon-anı doğrulama adımıdır.)

**Dosyalar:** `backend/tests/errors/test_errors_package_purity.py`, `backend/tests/feedback/test_feedback_package_purity.py` (ikisi de yeniden yazılır).

### §5.2 — `expected_routes` OpenAPI snapshot'ından türemiyor

**Sorun:** `backend/tests/test_api_surface.py::test_public_api_surface` runtime route'ları **elle bakımlı 40-tuple literal** `expected_routes` ile karşılaştırır. Tam-eşitlik olduğundan yeni endpoint testi kırar (sessizce kaçmaz) ama her endpoint'te iki yerde elle güncelleme gerekir (surface literal + snapshot) — DRY ihlali, 27.3/27.4'te iki kez yapıldı.

**Fix:** `expected_routes` literal'ini **committed openapi snapshot'ından türetilen** setle değiştir:
```python
HTTP_VERBS = {"get", "post", "put", "patch", "delete", "options", "head", "trace"}

def _snapshot_api_routes() -> set[tuple[str, str]]:
    snap = json.loads((CONTRACTS_DIR / "openapi_snapshot.json").read_text(encoding="utf-8"))
    return {(method.upper(), path)
            for path, item in snap["paths"].items()
            for method in item if method in HTTP_VERBS}

# OpenAPI paths'te OLMAYAN framework route'lari (docs/openapi/redoc + HEAD) - kucuk, acik sabit
FRAMEWORK_ROUTES = { ... }   # implementer: current discovered - _snapshot_api_routes() ile bulunur

def test_public_api_surface():
    discovered = {(m.upper(), r.path) for r in app.routes ...}   # mevcut kesif mantigi korunur
    assert discovered == _snapshot_api_routes() | FRAMEWORK_ROUTES
```
Böylece yeni endpoint eklerken tek kaynak snapshot'tır (regen script zaten koşuluyor). Testin koruyucu değeri korunur: runtime route'lar = snapshot API route'ları + framework route'ları; herhangi bir sapma FAIL eder. `FRAMEWORK_ROUTES` implementasyon anında `discovered − _snapshot_api_routes()` ile ampirik belirlenir ve yorumlu küçük bir sabit olarak yazılır.

**Not:** İkinci test `test_openapi_snapshot_matches_contract` (runtime openapi == snapshot) korunur — bu, snapshot'ın kendisinin güncel olduğunu ayrıca garanti eder, dolayısıyla türetme döngüsel değildir.

**Dosyalar:** `backend/tests/test_api_surface.py` (yalnız `expected_routes` tarafı değişir; keşif mantığı ve ikinci test korunur).

### §3 — SKIPPED span'lerde `duration_ms` düşürülüyor (5 builder tutarlı)

**Sorun:** `build_intent_span`, `build_retrieval_span`, `build_prompt_span`, `build_generation_span`, `build_validation_span` `result is None` (SKIPPED) erken-dönüş dalında verilen `duration_ms`'i **kullanmıyor** — ölçülen duvar saati happy path'te payload'a inmez. `build_security_span` bu dalı zaten doğru taşır (option a).

**Karar (onaylı):** **Option (a)** — SKIPPED span de ölçülen gerçek duvar saatini taşır (security precedent'i ile birebir tutarlı). Sözleşme: "SKIPPED span, stage koştuysa ölçülen `duration_ms`'i taşır."

**Fix:** Beş builder'ın SKIPPED dönüşüne `duration_ms=duration_ms` ekle (ya da security gibi tek-return'e refactor et — davranış aynı). Caller'lar (`live_trace_assembly.py`) zaten `duration_ms=timings.get(<stage>)` veriyor; değişiklik yalnız builder'larda.

**Test:** Her builder için `test_<stage>_span_accepts_duration_ms_when_skipped` ekle (mevcut `test_security_span_accepts_duration_ms_when_skipped` deseni): SKIPPED span'in `duration_ms`'i taşıdığını assert et. Mevcut SKIPPED testleri (`test_intent_none_is_skipped` vb.) status/detail assert'lerini korur.

**Dosyalar:** `backend/app/trace/end_to_end_trace_builders.py`, `backend/tests/trace/test_end_to_end_trace_builders.py`.

### §9.3 — `model_id=None` üç yüzeyde tutarsız (llm_usage)

**Sorun:** `compute_llm_usage`'da bir GENERATION span `model_id=None` taşırsa: (a) `totals.unpriced_request_count` onu sayar; (c) `by_model`'da `"unknown"` satırı olarak görünür; ama (b) `pricing.models_missing_price` onu **listelemez** (`seen_models = {... if e.get("model_id")}` falsy `None`'ı düşürür). Request-seviyesi sayım (a) ile model-seviyesi liste (b) uzlaşmaz.

**Fix:** Null-model **unpriced** olayı varken `models_missing_price`'a `"unknown"` sentinel'ini ekle (sıralı tuple'da). Böylece üç yüzey uzlaşır: `unpriced_request_count > 0` iken `by_model`'ın `"unknown"` satırı `models_missing_price`'ta karşılığını bulur.
- Uygulama: `missing_models` hesaplanırken, `events` içinde `model_id` falsy olan en az bir olay varsa `"unknown"` ekle; sonuç sıralı kalır.

**Test:** `compute_llm_usage`'a `model_id=None` olay içeren girdi ver; `models_missing_price`'ın `"unknown"` içerdiğini ve `unpriced_request_count` ile tutarlı olduğunu assert et. Mevcut adlı-model testleri değişmez.

**Dosyalar:** `backend/app/llm_usage/compute.py`, ilgili test dosyası (`backend/tests/llm_usage/...`).

### §8.2 — `feedback_truncated` bayrağı yok (dashboard)

**Sorun:** `dashboard_service.build_dashboard` feedback'i `limit=scan_cap` ile çeker (over-fetch yok) → pencere >`scan_cap` feedback içerirse `feedback.total` sessizce kapaklanır; trace (`truncated`) ve timeseries (`timeseries_truncated`) eksenlerinin aksine sinyal yok. "Sessiz kesme yok" invariant'ının feedback ekseninde ihlali.

**Fix:**
- `dashboard_service.py`: feedback'i `limit=scan_cap + 1` ile çek, `feedback_truncated = len(feedback_rows) > scan_cap`, `feedback_rows = feedback_rows[:scan_cap]`, ve `feedback_truncated`'ı `window_base`'e ilet.
- `dashboard/contract.py::DashboardWindow`: `feedback_truncated: bool = False` alanı ekle (default → geri-uyum, mevcut constructor'lar kırılmaz) + `to_payload`'a `"feedback_truncated"` ekle.
- `compose.py::compose_dashboard`'daki `dataclasses.replace(window_base, timeseries_truncated=...)` yalnız `timeseries_truncated`'ı override ettiğinden `feedback_truncated` korunur (ek değişiklik gerekmez).

**Contract snapshot:** `feedback_truncated` yeni bir **response payload alanı** — bu debug endpoint response'u `to_payload` sözlüğüdür; DashboardWindow bir Pydantic response şeması **değil** (saf dataclass → dict). API surface/openapi snapshot **değişmez** (yeni route/şema yok). Yalnız dashboard'ın kendi contract testi (varsa `to_payload` şeklini assert eden) güncellenir. Bu bilinçli olarak doğrulanır: `git diff backend/tests/contracts/` **boş** olmalı.

**Test:** `build_dashboard`'a >`scan_cap` feedback (mock) ver → `window.feedback_truncated is True`, `feedback.total == scan_cap`. Az feedback → `False`. `DashboardWindow.to_payload`'ın alanı taşıdığını assert et.

**Dosyalar:** `backend/app/dashboard_service.py`, `backend/app/dashboard/contract.py`, ilgili testler.

### §8.4(b) — `_floor_iso` non-datetime `created_at` guard'ı yok (dashboard timeseries)

**Sorun:** `dashboard/compose.py::_floor_iso` `created_at.tzinfo`'ya doğrudan erişir; `created_at` string/`None` ise `AttributeError`. `shape_recent` `hasattr(...,"isoformat")` guard'ına sahip ama `bucket_timeseries`→`_floor_iso` yolu değil. `llm_usage`'ın `bucket_usage_timeseries` caller'ı `if created_at is None or not hasattr(created_at,"tzinfo"): continue` ile korur — dashboard'da eşdeğeri yok.

**Fix:** `bucket_timeseries`'te (caller-side, llm_usage deseniyle simetrik) her trace item için `created_at` datetime değilse (`created_at is None or not hasattr(created_at, "tzinfo")`) o item'ı **atla** (skip), `_floor_iso`'ya vermeden. (Alternatif: `_floor_iso`'ya guard; caller-side tercih edilir çünkü atlanan item timeseries'e hiç girmemeli ve llm_usage ile simetrik.)

**Test:** `bucket_timeseries`'e string/`None` `created_at` taşıyan bir item karışık ver → `AttributeError` yok, geçerli item'lar bucket'lanır, bozuk item atlanır.

**Dosyalar:** `backend/app/dashboard/compose.py`, ilgili test.
