# Sprint 28.5 — Missing Foreign Key Inference v2 · Tasarım (Design Spec)

**Phase:** 9 — Large Schema Production Scale (28.4'ün ardılı)
**Tarih:** 2026-08-07
**Tür:** Üretim çıkarım-kalitesi iyileştirmesi (PK-aware implicit FK inference) — schema-only, deterministik
**Önceki:** 28.4 Relationship Confidence Scoring (PR #155) · **Sonraki:** 28.6 Schema Cache Invalidation

---

## 1. Amaç ve bağlam

`detect_implicit_relationships` (v1, `app/schema/implicit_relationships.py`) üç name-only kural
kullanır:
- **Rule 1** `singular_table_id_pattern` (conf 0.90): kaynak `<singular_table>_id` → hedef tabloda
  literal `"id"` kolonu.
- **Rule 2** `fuzzy_prefix_match` (IMPLICIT_FUZZY, 0.75/0.65): prefix, hedef singular ada difflib
  ratio ≥ 0.85; yine hedefte literal `"id"`.
- **Rule 3** `exact_column_match` (conf 0.60): iki tabloda **herhangi** bir non-generic kolonun
  aynı adı.

Bu, kontratta MEVCUT olan PK bilgisini (`TableSchema.primary_key_columns`,
`ColumnSchema.primary_key`) yok sayar → iki kusur:
1. **Recall:** Rule 1/2 yalnız literal `"id"` hedef kolonunu bulur; non-"id" PK'li tablolar
   (ör. PK'si `user_id` olan `users`) kaçar.
2. **Precision:** Rule 3 anahtar-olmayan kolonları da eşler (ör. iki tabloda da `hub0_id` olması)
   → gerçek FK olmayan spurious edge'ler.

28.5 çıkarımı **PK-farkında** yapar (bir FK gerçek bir anahtara işaret eder): hedefin çözülmüş
primary key'ini kullanır (yalnız "id" değil) ve Rule 3'ün hedef kolonunun bir anahtar olmasını
zorunlu kılar. Schema-only ve deterministik kalır (veri örneklemesi yok).

### Merkezi tasarım kararı — PK-only hedef anahtar + sıkı Rule 3
Yeni saf `resolve_target_key(table)` hedefin tek-kolon primary key'ini çözer (deklare PK; yoksa
"id"/`<singular>_id` konvansiyon fallback; composite PK → skip). Rule 1/2 hedef kolon olarak bunu
kullanır (recall); Rule 3 yalnız hedef kolon çözülmüş anahtarsa edge üretir (precision). Confidence
değerleri ve reason string'leri korunur (benchmark bucketing etkilenmez).

## 3. `resolve_target_key(table) -> str | None` (yeni saf yardımcı)

Deterministik, schema-only. Sıra:
1. **Deklare PK kolonları** topla: `ColumnSchema.primary_key == True` olanlar ∪
   `TableSchema.primary_key_columns` içindekiler (isim eşleştirme, case-insensitive).
2. Tam **bir** PK kolonu varsa → onun adı (`source="declared_pk"`).
3. **Birden çok** PK kolonu (composite) → `None` (tek-kolon FK çıkarımı uygulanmaz; scope-out).
4. **Sıfır** deklare PK → konvansiyon fallback:
   a. `"id"` adlı kolon varsa → `"id"` (`source="convention_id"`).
   b. yoksa `"<singular_table>_id"` adlı kolon varsa → o (`source="convention_table_id"`).
   c. yoksa → `None`.

`None` dönerse tablo FK hedefi olamaz (o hedef için hiçbir kural edge üretmez).

## 4. Kural değişiklikleri — `detect_implicit_relationships`

Döngü yapısı, `singular_to_table` inverted index, `is_seen_or_explicit` dedup (explicit + seen),
çift-yön koruması, `probe` sayaçları (`pair_iteration`/`fuzzy_comparison`/`rule3_scan`) DEĞİŞMEZ.

- **Rule 1** (`prefix in singular_to_table` ve hedef tablo eşleşiyor): hedef kolon =
  `resolve_target_key(tgt_table)`; `None` ise atla; değilse edge (conf 0.90, reason
  `singular_table_id_pattern`, raw'a `target_key` + `key_source` eklenir). Literal `"id"` araması
  KALDIRILIR.
- **Rule 2** (fuzzy prefix): aynı — hedef kolon `resolve_target_key(tgt_table)`; `None` ise atla;
  değilse IMPLICIT_FUZZY edge (conf 0.75/0.65, reason `fuzzy_prefix_to_table_match`).
- **Rule 3** (exact non-generic column match): `src_col_lower == tgt_col_lower` (non-generic) VE
  `tgt_col.name` (case-insensitive) == `resolve_target_key(tgt_table)` → edge (conf 0.60, reason
  `exact_non_generic_column_match`). Aksi halde edge YOK. Anahtar-olmayan cross-table isim
  eşleşmeleri düşer.

Reason string'leri ve `raw["rule"]` değerleri (`singular_table_id_pattern`/`fuzzy_prefix_match`/
`exact_column_match`) KORUNUR → `derive_implicit_fk_metrics` bucketing çalışmaya devam eder.

## 5. Davranış-değişimi yönetimi

- **Production** (`schema_manager.py` `detect_implicit_relationships`'i kullanır): çıkarılan FK'ler
  iyileşir — Rule 1/2 non-"id" PK'leri yakalar (recall ↑), Rule 3 spurious anahtar-olmayan
  eşleşmeleri düşürür (precision ↑). Bilinçli iyileştirme.
- **Benchmark:** yalnız `implicit_fk` hedefi etkilenir. Sentetik şemada her tablo PK'si `"id"`
  (`primary_key: True`) → **Rule 1/2 DEĞİŞMEZ** (çözülen anahtar = "id"). Rule 3 ise `<x>_id`
  cross-table eşleşmelerini artık üretmez (hedef kolon anahtar değil, tek anahtar "id" ve generic)
  → **rule3_exact sayısı düşer** → `implicit_fk` metrikleri değişir → `BENCHMARK_SCHEMA_VERSION =
  "large_schema_benchmark_v5"` + gated baseline (100/500/1000) regen + version-literal testleri
  (test_bench_contract/test_bench_metrics) v5. `context_selection`/`join_paths`/`graph_backend`
  ETKİLENMEZ (`select_schema_context` şemanın explicit FK'lerini kullanır, detect çıktısını değil).
  28.3/28.4 benchmark deseni.
- **Unit testler** (`test_implicit_relationships.py`, `test_implicit_relationships_probe.py`):
  Rule 1/2 hedef-PK, Rule 3 anahtar-şartı güncellenir; yeni testler: non-"id" PK hedefi (recall),
  Rule 3 spurious-drop (precision), composite-PK skip, no-PK id-fallback, no-key hedef atlanır.
  Mevcut testlerden anahtar-olmayan Rule-3 edge bekleyenler curate edilir (gerekçeyle; v1'in
  spurious davranışıydı).

   anahtar ise edge (precision). Confidence/reason string'leri korunur.

   `join_paths`/`context_selection`/`graph_backend` değişmez; gate yeşil.
4. Tam suite yeşil; spurious-Rule3 bekleyen mevcut testler gerekçeyle curate edilir (sessiz
   düşürme yok); final opus review = SHIP.
