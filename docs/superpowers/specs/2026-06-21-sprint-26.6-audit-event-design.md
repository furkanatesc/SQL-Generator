# Sprint 26.6 — Audit Event Contract · Design

**Phase 7 (Security & Governance) · Contract-first, no I/O · 2026-06-21**

## 1. Purpose

Sprints 26.0–26.5 each answer one governance question and return a typed,
secret-free result:

| Sprint | Question | Result |
|---|---|---|
| 26.0 | May this run? (RBAC) | `SQLPermissionPolicyResult` |
| 26.1 | Right tenant/workspace? | `TenantWorkspaceBoundaryResult` |
| 26.2 | Is it read-only? | `SQLReadOnlyEnforcementResult` |
| 26.3 | How risky? | `SQLQueryRiskResult` |
| 26.4 | Touches declared-sensitive data (and what to do)? | `SQLSensitiveDataPolicyResult` |
| 26.5 | Plausibly PII/PHI, what kind, how sure? | `SQLPiiPhiDetectionResult` |

Each of those is a **point-in-time judgement** that vanishes once consumed. 26.6
answers the orthogonal, after-the-fact question:

* **What happened, who did it, when, where, why, and with what outcome — recorded
  in a form that cannot be silently altered?**

26.6 defines an **Audit Event Contract**: a single immutable, secret-free record
type that any of the 26.0–26.5 judgements (and future gates) can be normalized
into, plus a **tamper-evident hash chain** linking records in sequence so that any
later edit, deletion, or reordering of the log is detectable. It is the
canonical "this is what the system decided and did" artifact.

It is **not** a logger, a sink, or a transport. It produces records and verifies
chains; it never writes anywhere. Persistence, shipping, retention, and querying
are Phase 13 (observability/storage) concerns, deliberately out of scope here, so
the contract stays deterministic, dependency-free, and unit-testable.

## 2. Scope

**In scope:** the contract — category/outcome/severity enums; immutable nested
value objects (actor, resource); the immutable `AuditEvent` record with a
secret-free `to_dict()`; a deterministic canonical-JSON serializer; the SHA-256
**hash-chain** primitives (`compute_entry_hash`, `link`, `verify_chain`); an
explicit **normalizer** with one builder per 26.0–26.5 result type; and exhaustive
unit tests including tamper detection.

**Out of scope (later / deliberate):** any persistence, file/DB/network I/O, log
shipping, or transport (Phase 13); retention, rotation, or PII-in-log redaction
beyond the secret-free guarantee already enforced by each source result; approval
orchestration (26.7); signing with asymmetric keys / external timestamping
authority / Merkle trees (the chain is integrity-evident, not non-repudiation —
noted as a limitation, §10); clocks, UUID generation, or any nondeterminism (time
and IDs are caller-supplied, §6); querying/aggregation/SIEM mapping; API/UI.

## 3. Module layout

- `backend/app/security/audit_event.py`
- `backend/tests/security/test_audit_event.py`
- Exported from `backend/app/security/__init__.py` (mirrors 26.0–26.5).
- Contract version: `audit_event_contract_v1`
  (constant `AUDIT_EVENT_CONTRACT_VERSION = "audit_event_contract_v1"`).
- **Import direction (no cycle):** `audit_event.py` imports the six sibling result
  types (and their enums) from their modules to type its builders. The siblings
  **never** import `audit_event`. The dependency graph stays one-way
  (audit → siblings), so there is no import cycle.
- stdlib only (`dataclasses`, `enum`, `json`, `hashlib`, `typing`). No I/O,
  no clock, no randomness, no new dependency. House style mirrors 26.0–26.5:
  frozen dataclasses, `__post_init__` validation, version-checked, secret-free.

## 4. Enums (OWASP-style named categories, not OCSF numeric uids)

```python
class AuditCategory(str, Enum):          # what kind of governance event
    AUTHZ_PERMISSION = "authz_permission"   # 26.0
    TENANT_BOUNDARY  = "tenant_boundary"    # 26.1
    READ_ONLY        = "read_only"          # 26.2
    QUERY_RISK       = "query_risk"         # 26.3
    SENSITIVE_DATA   = "sensitive_data"     # 26.4
    PII_PHI          = "pii_phi"            # 26.5

class AuditOutcome(str, Enum):           # the effect / disposition
    ALLOWED            = "allowed"
    DENIED             = "denied"
    REQUIRES_APPROVAL  = "requires_approval"
    FLAGGED            = "flagged"          # a signal was raised, no gate decision
    ERROR              = "error"           # contract/evaluation error path

class AuditSeverity(str, Enum):          # ordered low -> high
    INFO     = "info"
    LOW      = "low"
    MEDIUM   = "medium"
    HIGH     = "high"
    CRITICAL = "critical"
```

**Why OWASP-style names, not OCSF:** OCSF (AWS/Splunk) uses numeric class/activity
uids designed for large SIEM normalization; that is heavier than this contract
needs and obscures intent in source. We adopt the **OWASP Logging Vocabulary**
posture — short, named, self-describing categories — over the **NIST SP 800-92**
six-question core (who/what/when/where/why/outcome) realized in the record (§5).
A `_SEVERITY_ORDER` map gives `INFO < LOW < MEDIUM < HIGH < CRITICAL` for any
ordering needs and deterministic comparison.

## 5. The record (immutable, audit-grade, secret-free)

Nested value objects keep the six NIST questions structured rather than a flat bag:

```python
@dataclass(frozen=True)
class AuditActor:                        # WHO
    subject: str                         # required, non-empty (e.g. user/service id)
    tenant: Optional[str] = None
    workspace: Optional[str] = None
    source_ip: Optional[str] = None      # NO default beyond None; caller-supplied
    request_id: Optional[str] = None     # NO default beyond None; caller-supplied
    def to_dict(self) -> Dict[str, Any]: ...

@dataclass(frozen=True)
class AuditResource:                     # WHAT was acted on
    type: Optional[str] = None           # e.g. "table", "query"
    id: Optional[str] = None             # e.g. "users", a query id — NOT raw SQL
    dialect: Optional[str] = None
    def to_dict(self) -> Dict[str, Any]: ...

@dataclass(frozen=True)
class AuditEvent:
    schema_version: str                  # must == AUDIT_EVENT_CONTRACT_VERSION
    event_id: str                        # WHO/uniqueness — caller-supplied UUID string
    occurred_at: str                     # WHEN — caller-supplied ISO-8601 UTC string
    category: AuditCategory              # WHAT KIND
    action: str                          # WHAT — short verb, e.g. "evaluate_permission"
    outcome: AuditOutcome                # OUTCOME
    severity: AuditSeverity              # OUTCOME weight
    actor: AuditActor                    # WHO
    resource: AuditResource              # WHAT (target)
    reason_code: str                     # WHY (machine) — source result's reason_code value
    reason: str                          # WHY (human) — source result's reason
    contract_source: str                 # provenance — e.g. "sql_permission_policy_contract_v1"
    sql_sha256: Optional[str]            # WHAT (the SQL, hashed — never raw)
    details: Dict[str, Any]              # the source result's secret-free to_dict()
    prev_hash: Optional[str]             # chain link to previous entry (None = genesis)
    entry_hash: str                      # SHA-256 over canonical payload incl. prev_hash
    def to_dict(self) -> Dict[str, Any]: ...   # JSON-safe; enum .value's; no raw SQL
```

**Validation (`__post_init__`, raises `AuditEventContractError`):**
- `schema_version` must equal `AUDIT_EVENT_CONTRACT_VERSION` (version violation).
- `event_id`, `occurred_at`, `action`, `reason_code`, `reason`, `contract_source`
  must be non-empty strings.
- `category`, `outcome`, `severity` must be the real enum types (not bare strings).
- `actor` must be an `AuditActor` with non-empty `subject`; `resource` an
  `AuditResource`.
- `sql_sha256`, when not `None`, must match `^[a-f0-9]{64}$` (same regex the
  siblings enforce).
- `details` must be a `dict`; `entry_hash` a 64-hex string.
- `prev_hash`, when not `None`, must be a 64-hex string.

**Secret-free invariant:** the record carries **no raw SQL** — only `sql_sha256`
(copied verbatim from the source result, which already computed it secret-free) and
`details` (the source result's own `to_dict()`, already proven secret-free in 26.0–
26.5). `to_dict()` emits enum `.value`s, nested `to_dict()`s, and the hash fields —
JSON-serializable, no objects, no raw statement text.

## 6. Time and identity are caller-supplied (determinism)

The contract **never** calls a clock or RNG. `occurred_at` (ISO-8601 UTC string)
and `event_id` (UUID string) are passed in by the caller. Rationale, in the 26.x
house style:

- **Determinism / testability:** same inputs → byte-identical record and hash.
  Tests need no clock mocking; the hash chain is reproducible.
- **Single source of truth:** the calling layer (request handler) already owns the
  request timestamp and correlation/request id; the contract should not invent a
  second, divergent one.
- **No hidden nondeterminism in a hashed structure:** because `occurred_at` and
  `event_id` feed `entry_hash`, generating them inside the contract would make the
  hash depend on wall-clock — defeating reproducibility and chain verification.

The contract validates **format/shape** (non-empty strings; `sql_sha256` hex) but
does **not** parse or enforce real ISO-8601/UUID semantics (kept light, documented
limitation §10). Helper signatures take them as required arguments.

## 7. Canonical serialization + hash chain

**Canonical payload.** `entry_hash` is computed over a deterministic JSON encoding
of every record field **except `entry_hash` itself**, and **including `prev_hash`**.
Canonical = `json.dumps(payload, sort_keys=True, separators=(",", ":"),
ensure_ascii=False)` — sorted keys, no whitespace, stable across runs. Enum values
are reduced to their `.value`; nested value objects to their `to_dict()`. A private
`_canonical_payload(event_without_hash) -> str` builds it.

**Entry hash.**
```
entry_hash = sha256( canonical_payload_bytes ).hexdigest()
```
where the payload already contains `prev_hash` (or the genesis sentinel). Because
`prev_hash` is *inside* the hashed payload, each entry's hash transitively commits
to the entire prior chain — editing any earlier record breaks every hash after it.

**Genesis.** The first event has `prev_hash = None`; its canonical payload encodes
`prev_hash` as JSON `null`. There is no separate genesis record.

**Public hash-chain API.**
```python

def link(prev: Optional[AuditEvent], **event_fields) -> AuditEvent

    #   * recompute entry_hash from its fields; if != stored entry_hash -> return i
    #     (the record was mutated after hashing).
    #   * check continuity: events[i].prev_hash == events[i-1].entry_hash
```

`verify_chain` detects **mutation** (any field changed → recomputed hash differs),
**reordering** (continuity breaks), and **insertion/deletion** (continuity breaks at
the splice). It returns the first bad index so callers can pinpoint the break.

## 8. Normalizer — explicit per-source builders

One public builder per source result type. Each takes the source result plus the
caller-supplied envelope (`event_id`, `occurred_at`, `actor`, `resource`, optional
`prev` for chaining) and returns a linked `AuditEvent`. Builders are explicit (no
reflection / isinstance dispatch) so the mapping is auditable and type-checked.

`details` is always the source result's own `to_dict()` (secret-free).
`contract_source` is the source's `*_CONTRACT_VERSION`. `sql_sha256` is copied from
the result **when that result type carries it** (read-only, risk, sensitive,
pii/phi); permission and tenant results have **no** `sql_sha256`, so the audit
field is `None` for those builders. `reason_code`/`reason` are copied from the
result (risk has no `reason_code` → use the `risk_level.value` as the audit
`reason_code`, documented in the builder).

| Builder | Source | category | outcome mapping | severity |
|---|---|---|---|---|
| `from_permission(result, …)` | `SQLPermissionPolicyResult` | `AUTHZ_PERMISSION` | `decision` → ALLOW→ALLOWED, DENY→DENIED, REQUIRES_APPROVAL→REQUIRES_APPROVAL | DENIED→HIGH, REQUIRES_APPROVAL→MEDIUM, ALLOWED→INFO |
| `from_tenant(result, …)` | `TenantWorkspaceBoundaryResult` | `TENANT_BOUNDARY` | `decision` → ALLOW→ALLOWED else DENIED | DENIED→HIGH else INFO |
| `from_read_only(result, …)` | `SQLReadOnlyEnforcementResult` | `READ_ONLY` | `decision` → ALLOW→ALLOWED else DENIED | DENIED→HIGH else INFO |
| `from_risk(result, …)` | `SQLQueryRiskResult` | `QUERY_RISK` | always `FLAGGED` (signal, no gate) | from `risk_level` (e.g. LOW→LOW … CRITICAL→CRITICAL) |
| `from_sensitive(result, …)` | `SQLSensitiveDataPolicyResult` | `SENSITIVE_DATA` | `decision` → ALLOW→ALLOWED, DENY→DENIED, REQUIRES_APPROVAL→REQUIRES_APPROVAL | from `sensitivity_level` |
| `from_pii_phi(result, …)` | `SQLPiiPhiDetectionResult` | `PII_PHI` | always `FLAGGED` (detector, no gate) | from `has_phi` + `highest_confidence` (PHI→HIGH/CRITICAL; PII high-conf→MEDIUM; none→INFO) |

- The exact decision/level → enum mapping lives in small module-level dicts so it is
  data, not branching, and is unit-tested per source.
- A source result on its **error/fail-closed** path (e.g. unusable input) maps
  outcome to `ERROR` or the result's own decision as appropriate, severity from the
  table; builders never raise on a well-formed source result — only the `AuditEvent`
  validation (§5) can raise, on a malformed envelope.

## 9. Errors

`AuditEventContractError(ValueError)` (mirrors the sibling `*ContractError`
hierarchy). Raised on: `schema_version` mismatch, missing/empty required strings,
wrong enum types, bad `sql_sha256`/`prev_hash`/`entry_hash` hex, non-dict `details`,
or a bad `actor`/`resource`. Builders themselves do not raise for valid source
results; verification returns an index rather than raising.

## 10. Documented limitations (26.x-style honesty)

- **Integrity-evident, not non-repudiation.** The hash chain detects tampering by
  anyone who does **not** rebuild the whole suffix. An attacker who can rewrite the
  entire chain after a point (and any external anchor) could forge a consistent
  chain. True non-repudiation needs asymmetric signing and/or an external
  timestamping/anchor — explicitly Phase 13, out of scope here.
- **No persistence/ordering authority.** The contract does not store events or
  assign sequence; the caller supplies order by passing `prev`. Concurrency and
  durable append are Phase 13.
- **Shape-only validation of time/id.** `occurred_at`/`event_id` are checked
  non-empty, not parsed as real ISO-8601/UUID. Garbage-but-nonempty strings are
  accepted (and faithfully hashed); semantic validation is the caller's job.
- **Secret-freedom is inherited, not re-proven.** `details`/`sql_sha256` come from
  source results already proven secret-free in 26.0–26.5; 26.6 adds no new raw-SQL
  surface, and tests assert a known secret never appears in `to_dict()`.

## 11. Test matrix

- **Record validation:** each required field empty/wrong-type → raises; good record
  builds; `sql_sha256`/`prev_hash`/`entry_hash` non-hex → raises; bad
  `actor`/`resource` → raises; `schema_version` mismatch → raises.
- **Immutability:** `AuditEvent`/`AuditActor`/`AuditResource` mutation →
  `FrozenInstanceError`.
- **`to_dict()` secret-free + JSON-safe:** `json.dumps(event.to_dict())` succeeds;
  enums are strings; a planted secret SSN/SQL string is absent from the dict.
- **Canonical determinism:** same fields → identical canonical string and
  `entry_hash` across two builds; key order in input dict does not change the hash.
- **Per-builder mapping (all six):** correct `category`, `outcome` for each decision
  value, `severity` for each level, `contract_source`, `reason_code`/`reason`
  copied, `sql_sha256` present for read-only/risk/sensitive/pii-phi and `None` for
  permission/tenant, `details == source.to_dict()`.
- **Hash chain — genesis:** first event `prev_hash is None`; `verify_chain([e0])`
  → `None`.
- **Hash chain — multi-link:** build e0→e1→e2 via `link`; `verify_chain` → `None`;
  each `prev_hash == previous.entry_hash`.
- **Tamper — mutation:** rebuild a chain, replace one middle event with a copy whose
  field differs (recompute nothing) → `verify_chain` returns that index.
- **Tamper — reorder:** swap two events → `verify_chain` returns the first broken
  index.
- **Tamper — deletion/insertion:** drop or splice an event → continuity break index
  returned.
- **`verify_chain` edge:** empty sequence → `None`; single intact event → `None`.
