# Sprint 30.1 — Workspace API (Design Spec)

**Date:** 2026-09-06
**Phase:** 11 (API / Backend Productization) — second sprint
**Branch:** `feat/sprint-30.1-workspace-api` (from `main` `804457e`)
**Predecessor:** 30.0 Public Query API Contract (PR #169) — established the canonical `/api/v1` contract (`ApiResponse[T]` envelope, `PageMeta`, error re-export, conformance guard). 30.1 is the **first real resource** built on that contract.

---

## 1. Purpose & motivation

Phase 11 turns the internal backend into a product-grade API. Its roadmap sequence is Workspace → Connection Registry → Schema Sync → Query Run → History → Feedback → Admin → Auth. The **workspace** is the top-level container every later resource will belong to (connections, schema syncs, query runs, history live inside a workspace).

Today the backend is entirely **single-tenant / global**: `configs`, `jobs`, `synonym_rules`, `query_traces`, `feedback`, `sql_cache` are all global tables with no workspace scoping. 30.1 introduces the workspace as a **new, standalone resource** exposed at `/api/v1/workspaces`, conforming to the 30.0 contract — the first route family (beyond the `GET /api/v1` discovery endpoint) to actually exercise the conformance guard. It does **not** retro-scope the existing global tables (that is a large, breaking change deferred to later sprints); later sprints add `workspace_id` references as they build their own resources.

## 2. Scope decisions (author-decided under the user's "full authority" directive; documented for veto)

1. **CRUD for a standalone `workspaces` resource** under `/api/v1/workspaces`, using the 30.0 canonical `ApiResponse` envelope + offset `PageMeta`. No retro-scoping of existing global tables.
2. **Entity fields:** `id` (uuid4 hex), `name` (required, 1–200 chars), `slug` (unique; provided or auto-derived from `name`), `description` (optional, ≤2000), `created_at`, `updated_at` (ISO-8601 UTC).
3. **Protected** (`verify_api_key`) — unlike the public `GET /api/v1` discovery endpoint, workspace management mutates state, so it requires the API key like every other `/api/*` mutating route.
4. **Duplicate slug → 409 CONFLICT.** This adds a single, additive `409 -> "CONFLICT"` mapping to `app/api/errors.py::STATUS_TO_CODE` (currently 409 falls back to the generic `HTTP_ERROR`). The 30.0 descriptor derives `required_error_codes` from `STATUS_TO_CODE`, and the guard's drift test asserts they stay in sync, so both update together — additively demonstrating the contract's extensibility.
5. **Dogfood the guard:** the five workspace routes are added to the conformance guard's `EXPECTED_V1_ROUTES`; each must use the canonical envelope. Contract snapshots are regenerated (additive).

## 3. Existing landscape (as mapped)

- **No workspace/tenant/project concept exists.** All persistence is global.
- **Persistence** — `backend/app/database.py`: raw `sqlite3` via `get_db_connection()` context manager (row factory yields dict-able rows); `init_db()` runs `CREATE TABLE IF NOT EXISTS` + additive `ALTER TABLE` migrations; data-access functions (`create_job`/`get_job`/`update_job_status`) use `cursor.execute` + `conn.commit()`, `dict(row)`, and a **column whitelist** for dynamic `UPDATE SET` (no user input becomes a column name — the injection-safe pattern to mirror).
- **30.0 contract** — `app/api/contract.py`: `ApiResponse[T]` = `{status:"success", data:T, meta:ResponseMeta|None}`, `PageMeta{limit,offset,count}`, `API_V1_PREFIX="/api/v1"`, `API_CONTRACT`/`contract_descriptor()`, re-exported `ErrorResponse`.
- **Router pattern** — `app/api/*_api.py`: `router = APIRouter(prefix=..., tags=..., dependencies=[Depends(verify_api_key)])`, imported into `app/main.py` as `<name>_router` and `include_router`-ed.
- **Error handling** — `app/api/errors.py`: `STATUS_TO_CODE` (400/401/403/404/422/500) + handlers rendering `{error:{code,message,details}}` + `X-Request-ID`.
- **Conformance guard** — `tests/api/test_public_api_contract_conformance.py`: `EXPECTED_V1_ROUTES` allowlist + canonical-envelope/error/request-id assertions.
- **Contract snapshots** — `tests/contracts/*.json`, regenerated via `python scripts/generate_contract_snapshots.py`.

## 4. Architecture

### 4.1 Persistence — `workspaces` table + repository

**Table** (added to `database.py::init_db`, additive `CREATE TABLE IF NOT EXISTS`):
```
workspaces(
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  slug TEXT NOT NULL UNIQUE,
  description TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
)
```

**Repository** — new `backend/app/workspace_repository.py` (single-responsibility data access, mirroring the `database.py` sqlite idiom via `get_db_connection`):
- `create_workspace(name, slug, description) -> dict` — inserts with a new uuid4 hex id + ISO-UTC timestamps; raises `WorkspaceSlugConflict` if the slug exists (pre-check + rely on the UNIQUE constraint / `IntegrityError` as backstop).
- `get_workspace(workspace_id) -> dict | None`
- `get_workspace_by_slug(slug) -> dict | None`
- `list_workspaces(limit, offset) -> list[dict]` — ordered by `created_at DESC, id` (stable).
- `count_workspaces() -> int`
- `update_workspace(workspace_id, name=None, description=None) -> dict | None` — dynamic `SET` from a **column whitelist** (`name`, `description`), `updated_at` bumped; `None` fields untouched; returns updated row or `None` if not found. (Slug is immutable in 30.1 — deferred.)
- `delete_workspace(workspace_id) -> bool` — True if a row was deleted.
- `class WorkspaceSlugConflict(Exception)` — repository-level signal the router maps to HTTP 409.
- `slugify(name) -> str` — pure helper: lowercase, non-alphanumeric runs → single `-`, strip leading/trailing `-`, collapse; empty → falls back to the uuid (guaranteed non-empty, unique).

### 4.2 API — `/api/v1/workspaces` router

New `backend/app/api/workspaces.py`, `include_router`-ed in `main.py`. `router = APIRouter(prefix=f"{API_V1_PREFIX}/workspaces", tags=["workspaces"], dependencies=[Depends(verify_api_key)])`.

**Models:**
- `WorkspaceCreate{ name: str(1..200), slug: Optional[str]=None (validated pattern ^[a-z0-9]+(-[a-z0-9]+)*$ when provided), description: Optional[str]=Field(None, max_length=2000) }`
- `WorkspaceUpdate{ name: Optional[str]=None(1..200), description: Optional[str]=None(≤2000) }` — at least one field required (model_validator).
- `WorkspaceResponse{ id, name, slug, description, created_at, updated_at }`

**Endpoints** (all return the canonical `ApiResponse` envelope; the guard enforces it):
- `POST   /api/v1/workspaces` → 201 `ApiResponse[WorkspaceResponse]` — create; slug auto-derived from name when omitted; duplicate slug → 409.
- `GET    /api/v1/workspaces` → 200 `ApiResponse[list[WorkspaceResponse]]` with `meta.pagination` = `PageMeta{limit,offset,count}`; query params `limit`(default 50, 1..200) / `offset`(default 0, ≥0).
- `GET    /api/v1/workspaces/{workspace_id}` → 200 `ApiResponse[WorkspaceResponse]`; missing → 404.
- `PATCH  /api/v1/workspaces/{workspace_id}` → 200 `ApiResponse[WorkspaceResponse]`; missing → 404.
- `DELETE /api/v1/workspaces/{workspace_id}` → 200 `ApiResponse[WorkspaceResponse]` (returns the resource as it was, so every 2xx body stays canonical); missing → 404.

Error mapping: not-found → `HTTPException(404)`; duplicate slug (`WorkspaceSlugConflict`) → `HTTPException(409)`; request-body invalid → FastAPI 422. All render through the existing canonical error handlers.

### 4.3 Contract extension — 409 CONFLICT

`app/api/errors.py`: add `409: "CONFLICT"` to `STATUS_TO_CODE` (additive; `map_status_to_code` behavior for 400/401/403/404/422/500 unchanged; 409 previously returned `HTTP_ERROR`). Because `contract.py::_REQUIRED_ERROR_CODES` and the descriptor derive from / are drift-checked against this set, `GET /api/v1`'s advertised `required_error_codes` gains `CONFLICT` automatically and the guard's sync test keeps them aligned.

### 4.4 Conformance + snapshots

- Guard `EXPECTED_V1_ROUTES` gains the five workspace routes (`{("POST","/api/v1/workspaces"), ("GET","/api/v1/workspaces"), ("GET","/api/v1/workspaces/{workspace_id}"), ("PATCH","/api/v1/workspaces/{workspace_id}"), ("DELETE","/api/v1/workspaces/{workspace_id}")}` plus the existing `("GET","/api/v1")`). Each is held to the canonical envelope by the existing `test_every_v1_route_success_uses_canonical_envelope`.
- Regenerate `tests/contracts/*.json` (additive: new paths + `WorkspaceResponse`/`WorkspaceCreate`/`WorkspaceUpdate`/`ApiResponse_WorkspaceResponse_`/`ApiResponse_list_WorkspaceResponse__` schemas + the 409-code change in `status_contract_snapshot` if captured).

### 4.5 What does NOT change

- No existing table is altered; no existing endpoint/model/handler behavior changes (only the additive 409 mapping + the additive router + the additive table). Existing global data (jobs/feedback/traces) is untouched and unscoped.
- No frontend change, no new pytest marker, no new CI job.

## 5. Data flow

```
POST /api/v1/workspaces {name}         GET /api/v1/workspaces?limit&offset
  → verify_api_key                        → verify_api_key
  → slugify(name) if slug omitted         → list_workspaces(limit,offset) + count_workspaces()
  → create_workspace(...)                 → ApiResponse[list[WS]](data=..., meta=PageMeta(limit,offset,count))
    → WorkspaceSlugConflict? → 409
  → 201 ApiResponse[WS](data=ws)
```

## 6. Testing strategy

- **Repository unit tests** (`tests/test_workspace_repository.py`): create/get/list(paginate)/update(whitelist)/delete/count, slug uniqueness → `WorkspaceSlugConflict`, `slugify` cases (spaces, punctuation, unicode-ish, empty→uuid fallback). Uses the test DB fixture.
- **Endpoint tests** (`tests/api/test_workspaces_api.py`): full CRUD round-trip via `TestClient` with `verify_api_key` overridden; canonical envelope shape on every response; pagination `meta`; 404 on missing; 409 on duplicate slug; 422 on invalid body; `X-Request-ID` present; 403 without API key.
- **Conformance** — the existing guard now covers the workspace routes; `EXPECTED_V1_ROUTES` updated. Marker-less, deterministic, Docker-free, runs in `backend-tests`.
- `fastapi` pinned to `0.115.12` before the full suite.

## 7. Deliberately out of scope (→ TECH-DEBT §27, no silent drops)

- **Retro-scoping existing global tables** (jobs/feedback/traces/cache) to `workspace_id` — large, breaking; later sprints.
- **Linking connections/schema/history to a workspace** — 30.2+ add the FKs as they build those resources.
- **Workspace membership / roles / per-workspace permissions** — needs AuthN (30.8).
- **Slug mutation, soft-delete/archival, workspace-level settings/quotas, name uniqueness** (only slug is unique).
- **Cursor pagination / cross-page `total`** (inherits 30.0's offset-only `PageMeta`).
- **Cascade semantics** on delete (no child resources reference a workspace yet).
