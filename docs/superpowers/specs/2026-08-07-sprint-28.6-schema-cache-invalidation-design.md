# Sprint 28.6 — Schema Cache Invalidation · Tasarım (Design Spec)

**Phase:** 9 — Large Schema Production Scale (28.5'in ardılı)
**Tarih:** 2026-08-07
**Tür:** Üretim önbellek doğruluğu iyileştirmesi (content-fingerprint invalidation) — self-contained, deterministik
**Önceki:** 28.5 Missing Foreign Key Inference v2 (PR #156) · **Sonraki:** 28.7 Incremental Schema Sync

---

## 1. Amaç ve bağlam

`SchemaManager.load_schema` (`app/schema_manager.py:469`) işlenmiş şemayı + embeddingleri
`schema_cache.json`'da (`{db_type, schema, embeddings}`) önbellekler. Cache YALNIZ iki durumda
geçersizlenir: (1) `force_refresh=True` (elle), (2) `cache_data["db_type"] != current db_type`.

Sessiz staleness kaynakları (cache eski şemayı sunar):
- **`hidden_tables_{db_type}` / `hidden_columns_{db_type}` config değişimi** (configs DB'den okunur,
  `extract_schema_metadata`'da uygulanır) — kullanıcı bir tabloyu/kolonu gizler/gösterir ama cache
  eski filtrelenmiş şemayı sunar.
- **Embedding modeli değişimi** — cache `embeddings["model"]` saklar ama load'da karşılaştırmaz.
- **Çıkarım kodu değişimi** — ör. 28.5'in PK-aware inference'ı; eski cache eski davranışı taşır.

28.6 bunları **content fingerprint** ile otomatik geçersizleştirir: cache'in bağlı olduğu girdilerin
deterministik bir hash'i cache'e yazılır, load'da güncel girdilerden yeniden hesaplanıp karşılaştırılır;
uyumsuzsa geçersizleştirilir. **Self-contained** — yeni DB sorgusu YOK (ham DB şema drift'i bilinçli
kapsam dışı).

### Merkezi tasarım kararı — config + embedding + kod-versiyonu fingerprint, DB sorgusu yok
Saf `compute_cache_fingerprint(...)` girdileri kanonik birleştirip sha256'lar. `load_schema` mevcut
config + embedding-model'den güncel fingerprint hesaplar, cache'teki ile karşılaştırır; uyumsuz/eksik
→ re-extract. `db_type` kontrolü fingerprint'e sübsüme edilir. Global lock / cache-stampede koruması /
deepcopy / RAG indexleme DEĞİŞMEZ.

## 3. `compute_cache_fingerprint` (yeni saf yardımcı)

Saf, deterministik (stdlib `hashlib` + `json`; I/O yok):
```python
SCHEMA_CACHE_VERSION = "v1"   # cikarim/cache format'i degisince bump

def compute_cache_fingerprint(*, db_type, hidden_tables_raw, hidden_columns_raw,
                              embedding_model, cache_version=SCHEMA_CACHE_VERSION) -> str:
    payload = "\x1f".join([
        cache_version,
        db_type or "",
        hidden_tables_raw or "",
        hidden_columns_raw or "",
        embedding_model or "",
    ])
    return hashlib.sha256(payload.encode("utf-8")).hexdigest()
```
- `hidden_tables_raw`/`hidden_columns_raw`: `get_config("hidden_tables_{db_type}")` /
  `get_config("hidden_columns_{db_type}")` **ham string'leri** (parse edilmemiş — string eşitliği
  yeterli ve daha basit; None → `""`).
- `embedding_model`: yapılandırılan embedding model kimliği (aşağıda §4).
- Ayırıcı olarak `\x1f` (unit separator) kullanılır ki girdi içeriği ayırıcıyla çakışmasın.
- Yeni modül konumu: `app/schema_cache_fingerprint.py` (saf; `schema_manager` bunu import eder) — saf
  çekirdeği kirli manager'dan ayırır (27.8/28.3 deseni).

## 4. `load_schema` değişikliği (kirli wiring)

`schema_manager.py:469-517` bölgesi:
1. **Embedding model'i ucuza elde et** (build ETMEDEN): `SchemaEmbeddingIndex()` (ya da eşdeğeri)
   instantiate edilip `embedding_client.model` okunur — index BUILD edilmez (embedding hesabı yok).
   Yan-etki riski varsa (provider bağlantısı vb.) fallback: fingerprint'e cache'teki
   `embeddings["model"]`'i dahil etmeyip embedding modelini AYRI karşılaştır (stored `embeddings["model"]`
   != current model → embeddings'i rebuild). Plan aşamasında instantiate'in ucuz/yan-etkisiz olduğu
   doğrulanır; öyleyse fingerprint'e dahil edilir.
2. **Güncel fingerprint hesapla:** `compute_cache_fingerprint(db_type=..., hidden_tables_raw=get_config(...),
   hidden_columns_raw=get_config(...), embedding_model=...)`.
3. **Cache oku + karşılaştır:** `not force_refresh and os.path.exists(CACHE_PATH)` iken cache_data
   yüklenir; `cache_data.get("cache_fingerprint") == current_fingerprint` ise `base_schema`/`embeddings`
   cache'ten alınır. Aksi halde (uyumsuz/eksik/force_refresh) → `base_schema=None` bırakılır → re-extract.
   Eski ayrı `db_type` kontrolü KALDIRILIR (db_type fingerprint girdisi).
4. **Yeniden yaz:** re-extract dalında `cache_payload`'a `cache_fingerprint=current_fingerprint` eklenir.
   `db_type` alanı geriye-uyum/okunabilirlik için korunabilir (fingerprint zaten kapsar).

Global `_schema_lock`, cache-stampede koruması, `copy.deepcopy`, `schema["embeddings"]` giydirme,
RAGManager indexleme — HEPSİ DEĞİŞMEZ.

## 5. Davranış-değişimi yönetimi

- **Backward-compat:** mevcut `schema_cache.json`'da `cache_fingerprint` yok → `.get(...)` None döner
  → güncel fingerprint ile uyumsuz → bir kez re-extract + fingerprint'li yeniden yazma. Beklenen
  tek-seferlik maliyet; sonraki loadlar cache'i kullanır.
- **Config drift artık otomatik yakalanır:** hidden_tables/columns config değişince fingerprint değişir
  → cache geçersizlenir → yeni filtrelenmiş şema.
- **Kod drift'i:** `SCHEMA_CACHE_VERSION` bump edilince tüm cache'ler geçersizlenir (çıkarım mantığı
  değiştiğinde kullanılır).
- **Test:** saf helper unit testleri (deterministik; her girdi ekseninin değişimi hash'i değiştirir;
  None→"" normalizasyonu). `load_schema` invalidation testleri: `get_config` + `CACHE_PATH` +
  `extract_schema_metadata`/embedder monkeypatch ile — (a) fingerprint eşleşince cache kullanılır
  (extract çağrılmaz), (b) hidden_tables config değişince re-extract, (c) fingerprint'siz eski cache
  → re-extract, (d) force_refresh her zaman re-extract. `schema_cache.json` gitignore'da olduğu doğrulanır.

## 7. Bilinçli kapsam DIŞI (TECH-DEBT'te işaretlenir)

- **Ham DB şema drift'i** (DB'de tablo/kolon değişimi) — hafif DB fingerprint sorgusu (per-dialect
  information_schema / metadata) ister; self-contained fingerprint bunu yakalamaz. Ayrı kalem (belki 28.7
  Incremental Schema Sync ile örtüşür).
- **TTL / zaman-tabanlı geçersizleştirme.**
- **Explicit invalidation endpoint / event.**
- **Cache'in embedding kısmını config'ten bağımsız granüler geçersizleştirme** (şu an tüm cache
  yeniden yazılır).

## 8. Başarı ölçütleri

1. `compute_cache_fingerprint` saf/deterministik; her girdi ekseni hash'i etkiler; None→"" normalize;
   unit-test'li.

   `db_type` kontrolü fingerprint'e sübsüme. Global lock / stampede / RAG davranışı korunur.
3. Config drift (hidden_tables/columns) artık otomatik geçersizleştirir; embedding-model değişimi
   embeddings'i tazeler.
4. Backward-compat: fingerprint'siz eski cache bir kez re-extract, sonra fingerprint'li.
