# Sprint 32.12 API Load / Concurrency Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove and harden the API under concurrent load: fix the app-DB/breaker/async concurrency gaps, add in-process concurrency tests, a stdlib HTTP load harness, and a CI load gate.

**Architecture:** Small fixes in `app/database.py`, `app/llm/failover.py`, `app/main.py`; a thread-pool pytest module; a standalone stdlib package `backend/loadtest/` (pure `core.py` + `http_runner.py` + CLI); CI runs the harness against the prod compose stack with a rate-limit-off overlay.

**Tech Stack:** Python 3.12, FastAPI/TestClient, sqlite3, stdlib `urllib`/`concurrent.futures`, uvicorn (integration test), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-19-sprint-32.12-api-load-concurrency-design.md`

## Global Constraints

- `backend/loadtest/` imports **only the stdlib** (runs on the CI runner with `python3` and no pip install).
- New setting `NL2SQL_DB_BUSY_TIMEOUT_MS`, `Settings.db_busy_timeout_ms: int = Field(default=5000, ge=0)`, registered in `app/config_contract.py` and `docs/env-contract.md`.
- No LLM calls anywhere in tests or the load run.
- Commit messages: plain, no trailer lines. Tests: `backend/venv/Scripts/python -m pytest -q` from `backend/`.
- CI gate: error rate `0`, p95 ≤ `2000` ms; scenario `mixed`, concurrency `16`, duration `20` s.

## Review Focus

1. A connection opened before `init_db` (fresh file) still gets `busy_timeout` → pragma test on a brand-new DB path (Task 1).
2. Harness against an unreachable base URL → every request counted as an error (`status=None`), exit code 1, no traceback (Task 4).
3. Zero completed requests (duration shorter than one request) → summary has `requests=0`, `error_rate=1.0` treated as violation, not ZeroDivisionError (Task 4).
4. Same-slug parallel workspace creation → exactly one 201, rest 409, never 500 (Task 3).
5. API key must never appear in the JSON report or stdout (Task 4).

### Task 4: Stdlib load harness

**Files:**
- Create: `backend/loadtest/__init__.py`, `backend/loadtest/core.py`, `backend/loadtest/http_runner.py`, `backend/loadtest/__main__.py`
- Test: `backend/tests/test_loadtest_core.py`, `backend/tests/test_loadtest_http.py`

**Interfaces (Produces):**
- `core.RequestSpec(name: str, method: str, path: str, expected: frozenset[int], weight: int = 1, body: Callable[[int], dict] | None = None)` (frozen dataclass; `body(seq)` gives the JSON body).
- `core.SCENARIOS: dict[str, tuple[RequestSpec, ...]]` with `read` (`health` GET `/health` {200}; `ready` GET `/ready` {200}; `jobs_list` GET `/api/jobs` {200}; `query_history` GET `/api/v1/query-history` {200}; `workspaces_list` GET `/api/v1/workspaces` {200}), `write` (`workspace_create` POST `/api/v1/workspaces` body `{"name": f"load-{run}-{seq}", "slug": f"load-{run}-{seq}"}` {201}; `job_create` POST `/api/jobs/without-file` body `{"natural_query": "load test"}` {200}), `mixed` = read specs weight 3 + write specs weight 1.
- `core.Result(name: str, status: int | None, latency_ms: float)`; error ⇔ `status is None or status not in spec.expected` (runner records `ok: bool` too: `Result(..., ok: bool)`).
- `core.percentile(values: Sequence[float], p: float) -> float` nearest-rank, `0.0` for empty.
- `core.schedule(specs, n: int) -> list[RequestSpec]` deterministic weighted round-robin (expand by weight, cycle).
- `core.summarize(results, duration_s: float) -> dict`: `{"requests", "errors", "error_rate", "throughput_rps", "latency_ms": {"p50","p95","p99","max"}, "status_counts": {str: int}, "endpoints": {name: same-shape-without-endpoints}}`; `requests == 0` → `error_rate = 1.0`.
- `core.evaluate(summary, max_error_rate: float, max_p95_ms: float) -> list[str]` human-readable violations.
- `http_runner.run(base_url: str, api_key: str, specs, concurrency: int, duration_s: float, timeout_s: float = 10.0) -> tuple[list[Result], float]` — `concurrency` threads, each loops until the deadline taking the next spec from a shared `schedule` cursor (lock); `urllib.request` with `X-API-Key`, JSON body; `HTTPError` → its code; `URLError`/timeout → `None`.
- CLI `python -m loadtest --base-url URL (--api-key-file PATH | env NL2SQL_API_KEY) --scenario {read,write,mixed} --concurrency N --duration S [--json PATH] [--max-error-rate F=0] [--max-p95-ms F=2000]` prints a summary table, writes JSON (`{"scenario","concurrency","duration_s","summary","violations"}`), exit 1 on violations; key never printed/written.

- [ ] **Step 1: Write failing core tests** — `percentile([1..100],95)==95`, `percentile([],50)==0.0`; `schedule(mixed, 8)` names deterministic and read:write ratio 3:1 over 32; `summarize` counts/rates/per-endpoint on a hand-built result list; empty → `error_rate==1.0`; `evaluate` returns two violations when both thresholds broken, `[]` when fine.
- [ ] **Step 2: Run** `pytest tests/test_loadtest_core.py -v` → FAIL (module missing). Implement `core.py`. → PASS.
- [ ] **Step 3: Write failing HTTP tests** (`test_loadtest_http.py`): fixture starts `uvicorn.Server(uvicorn.Config(app, host="127.0.0.1", port=<free>, log_level="warning"))` in a daemon thread (worker job mode, rate limits 0), waits for `started`, stops in teardown.
  - `test_run_against_live_server`: specs = `jobs_list`, `workspaces_list`, `workspace_create`, `job_create`; concurrency 8, duration 2 → `requests > 0`, `errors == 0`.
  - `test_unreachable_server_counts_errors`: base URL on a closed port, duration 0.5 → all `status is None`, `evaluate` non-empty.
  - `test_cli_writes_json_and_hides_key(tmp_path, capsys)`: call `loadtest.__main__.main([...])` with `--api-key-file` → returns 0, JSON has `summary`, key string absent from file text and captured output; with `--max-p95-ms 0` returns 1.
