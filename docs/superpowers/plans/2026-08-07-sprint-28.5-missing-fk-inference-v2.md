**Goal:** Make `detect_implicit_relationships` PK-aware — match a target's actual resolved primary key (not just a literal `"id"` column) and require Rule-3 exact-name matches to point at that key — improving recall (non-`id` PKs) and precision (no spurious non-key matches).

**Architecture:** A new pure `resolve_target_key(table)` resolves a target table's single-column primary key (declared PK; else `"id"`/`"<singular>_id"` convention; composite PK → `None`). Rules 1/2 use it as the target column; Rule 3 fires only when the matched column IS the resolved key. Confidence values and reason strings are preserved so the benchmark's `implicit_fk` bucketing keeps working. Schema-only and deterministic.

**Tech Stack:** Python 3.11 (CI)/3.12 (local), pydantic 2.13.4 (pinned), pytest, stdlib `difflib`. No new dependencies.

```python
def resolve_target_key(table):
    """Single-column primary key of `table` for FK-target matching. Deterministic,
    schema-only. Declared single PK -> its name; composite PK -> None; no declared PK
    -> 'id', then '<singular_table>_id' convention; else None."""
    pk = []
    declared_names = {c.lower() for c in getattr(table, "primary_key_columns", [])}
    for c in table.columns:
        if c.primary_key or c.name.lower() in declared_names:
            if c.name.lower() not in {p.lower() for p in pk}:
                pk.append(c.name)
    if len(pk) == 1:
        return pk[0]
    if len(pk) >= 2:
        return None  # composite -> single-column FK inference does not apply
    by_lower = {c.name.lower(): c.name for c in table.columns}
    if "id" in by_lower:
        return by_lower["id"]
    conv = get_singular(table.name) + "_id"
    if conv in by_lower:
        return by_lower[conv]
    return None
```
