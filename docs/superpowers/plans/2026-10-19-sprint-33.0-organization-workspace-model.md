# Sprint 33.0 Organization / Workspace Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Introduce an Organization (tenant) above Workspace: new table + `/api/v1/organizations` CRUD, workspaces owned by an organization with per-organization slugs, existing data moved to a default organization, and delete-integrity guards.

**Architecture:** App-DB migration v4 creates `organizations`, a default org, and rebuilds `workspaces` with `organization_id NOT NULL` + `UNIQUE(organization_id, slug)`. New `app/organization_repository.py` + `app/api/organizations.py` mirror the 30.1 workspace modules. Workspace repo/API gain `organization_id` (optional on create → default org).

**Tech Stack:** Python 3.12, FastAPI, raw sqlite3, pytest.

**Spec:** `docs/superpowers/specs/2026-10-19-sprint-33.0-organization-workspace-model-design.md`

## Global Constraints

- Mirror `app/workspace_repository.py` / `app/api/workspaces.py` style exactly (ids `uuid4().hex`, ISO-8601 UTC timestamps, `ApiResponse` envelope, `PageMeta` pagination `limit` default 50 range 1–200, `offset` ≥ 0, router-level `Depends(verify_api_key)`, Turkish error details in the same style).
- Default organization: `slug="default"`, `name="Default"`, created by migration v4 on every DB (fresh or upgraded); cannot be deleted (409).
- No SQL FOREIGN KEY constraints (repo convention); integrity enforced in repositories.
- Never edit migrations 1–3; add `Migration(4, "organizations", _organizations)`.
- New `/api/v1` routes must be added to `EXPECTED_V1_ROUTES` in `backend/tests/api/test_public_api_contract_conformance.py`; regenerate snapshots with `backend/venv/Scripts/python scripts/generate_contract_snapshots.py` (from `backend/`) and commit them.
- Commits plain, no trailer lines. Tests: `backend/venv/Scripts/python -m pytest -q` from `backend/`. Never read/write `.env*` files.

## Review Focus

1. Upgrading a v3 DB that already has workspaces: every row keeps id/name/slug/description/timestamps and gets the default org id; the run is idempotent (Task 1).
2. Two orgs creating the same workspace slug → both 201; same org → 409; a slug conflict never leaks across orgs (Task 3).
3. `POST /workspaces` without `organization_id` keeps working exactly as before 33.0, plus the new response field (Task 3).
4. Deleting the default org, an org with workspaces, or a workspace with connections → 409 and nothing deleted (Tasks 2, 3).
5. Concurrent same-slug org creation → exactly one 201 (UNIQUE + IntegrityError mapping, like workspaces) (Task 2).
